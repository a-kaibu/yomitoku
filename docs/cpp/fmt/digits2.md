## ひとことで

`digits2(value)` は、0〜99 の整数を受け取り、その 2 桁の文字列（`"07"` や `"42"`）がある場所へのポインタを返します。

中身は **「00」「01」…「99」を順に並べた 200 文字の表** を引くだけです。{fmt} が整数を文字列にするとき、この関数で 2 桁ずつまとめて書き出しています。

## コード

::: code-group

```cpp:line-numbers=1216 [日本語訳]
// [0, 100) の範囲の値を文字列に変換する。value がポインタと同じ大きさだと
// GCC が少し良いコードを生成する (https://www.godbolt.org/z/5fEPMT1cc)。
inline auto digits2(size_t value) noexcept -> const char* {
  // ハードウェア固有の境界をまたぐと非整列アクセスが遅くなることが
  // あるので、データを整列させる。
  alignas(2) static constexpr char data[] =
      "0001020304050607080910111213141516171819"
      "2021222324252627282930313233343536373839"
      "4041424344454647484950515253545556575859"
      "6061626364656667686970717273747576777879"
      "8081828384858687888990919293949596979899";
  return &data[value * 2];
}
```

## 前提知識

- **ポインタと `const char*`**: `const char*` は「書き換えない文字が並んでいる場所」を指す値（アドレス）です。C++ の文字列リテラルは文字の配列で、その途中を指すこともできます。
- **`&data[i]`**: 配列 `data` の i 番目の要素のアドレスです。`data + i` と同じ意味です。
- **文字列リテラルの連結**: `"ab" "cd"` のように並べて書いたリテラルは、コンパイル時に `"abcd"` へつながります。長い表を行に分けて書けます。
- **`static constexpr`**: 表はプログラムの中に 1 つだけ埋め込まれ、呼び出しのたびに作られません。
- **`alignas(2)`**: 配列の先頭アドレスを 2 の倍数にそろえる指定です。
- **`noexcept`**: この関数は例外を投げない、という約束です。
- **`size_t`**: 配列の添字やサイズに使う符号なし整数型です。

## 何をしているか

### 1. 表の作り

```cpp:line-numbers=1220
  // あるので、データを整列させる。
  alignas(2) static constexpr char data[] =
      "0001020304050607080910111213141516171819"
      "2021222324252627282930313233343536373839"
      "4041424344454647484950515253545556575859"
      "6061626364656667686970717273747576777879"
```

表は 2 文字 1 組で、**i 番目の組が数 i の 2 桁表記** になるように並んでいます。

```
位置: 0 1 | 2 3 | 4 5 | ... | 84 85 | ...
文字: 0 0 | 0 1 | 0 2 | ... |  4  2 | ...
```

### 2. 2 倍した位置を返す

```cpp:line-numbers=1227
  return &data[value * 2];
```

`value = 42` なら `&data[84]` を返します。そこから 2 文字読むと `'4'`, `'2'` です。

呼び出し側（同じファイルの `write2digits`）は、このポインタから `memcpy` で 2 バイトをそのまま出力先にコピーします。

## ここがすごい

- **割り算を半分にする**: 整数を文字列にする素直な方法は「10 で割った余りを 1 桁ずつ書く」です。この表があると「100 で割った余りを 2 桁ずつ書く」に変えられ、割り算の回数が半分になります。`do_format_decimal` の `write2digits(out + n, static_cast<unsigned>(value % 100))` がまさにそうしています。
- **計算より表引き**: `'0' + value / 10` と `'0' + value % 10` を計算する代わりに、メモリから 2 バイト読むだけです。200 バイトの表は CPU のキャッシュに収まりやすい大きさです。
- **アラインメントへの気配り**: 表の直前のコメントのとおり、2 バイトの読み出しがハードウェアの境界をまたぐと遅くなることがあるため、`alignas(2)` で先頭をそろえています。表の中の組はすべて偶数位置から始まるので、どの 2 バイトも境界をまたぎません。
- **引数を `size_t` にした理由**: 関数の直前のコメントによると、引数をポインタと同じ大きさの型にすると GCC が少し良いコードを出すそうです。小さな型選びにも理由があります。

## まとめ

- 小さな範囲の変換は、計算するより表を引いたほうが速いことがある。
- 「2 桁ずつ」処理すると、整数→文字列変換の割り算が半分になる。
- 表の要素の大きさに合わせてアラインメントをそろえると、読み出しが安定して速い。
- 文字列リテラルの連結を使うと、長い表を読みやすく書ける。
