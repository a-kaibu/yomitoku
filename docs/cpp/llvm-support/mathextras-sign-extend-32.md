## ひとことで

`SignExtend32<B>(X)` は、`X` の**下位 B ビットを「B ビットの符号付き整数」とみなして**、32 ビットの符号付き整数に広げます。

たとえば 4 ビットの `1111` は、符号付きで読むと `-1` です。`SignExtend32<4>(0b1111)` は `-1` を返します。`SignExtend32<4>(0b0111)` は `7` です。

機械語の命令には「12 ビットの即値」のような中途半端な幅の数が埋め込まれています。それを読み出すときに欠かせない処理です。

## コード

::: code-group

```cpp:line-numbers=552 [日本語訳]
/// X の下位 B ビットの数を、32 ビット整数に符号拡張する。
/// B <= 32 であること。
template <unsigned B> constexpr int32_t SignExtend32(uint32_t X) {
  static_assert(B <= 32, "Bit width out of range.");
  if constexpr (B == 0)
    return 0;
  return int32_t(X << (32 - B)) >> (32 - B);
}
```

```cpp:line-numbers=552 [原文]
/// Sign-extend the number in the bottom B bits of X to a 32-bit integer.

    return 0;

}
```

## 前提知識

- **非型テンプレート引数 `template <unsigned B>`**: 型ではなく**値**をテンプレート引数にできます。`SignExtend32<4>(x)` のように呼ぶと、`B = 4` がコンパイル時に決まります。
- **`static_assert`**: コンパイル時のチェックです。`B` が 32 を超えるとコンパイルエラーになります。
- **`if constexpr`**: コンパイル時に条件を判定する `if` です。`B == 0` のときだけ `return 0;` が残り、それ以外では消えます。
- **2 の補数**: 符号付き整数の表し方です。最上位ビットが 1 なら負の数になります。4 ビットなら `1111` が `-1`、`1000` が `-8` です。
- **符号拡張**: 狭い幅の符号付き整数を広い幅にするとき、**最上位ビット（符号ビット）を上の桁にコピー**する操作です。`1111`（-1）を 8 ビットにすると `11111111`（-1）になります。
- **算術右シフト**: 符号付き整数を右シフトすると、左から**符号ビットと同じ値**が入ってきます。C++20 からはこの動作が規格で保証されています。

## 何をしているか

`B = 4`、`X = 0b1111`（15）で追います。

### 1. 左シフトで符号ビットを最上位に置く

```cpp:line-numbers=558
  return int32_t(X << (32 - B)) >> (32 - B);
```

```
X               = 0000 0000 ... 0000 1111
X << 28         = 1111 0000 ... 0000 0000
```

4 ビットの数の最上位（符号ビット）が、32 ビットの最上位に来ました。`X` は `uint32_t` なので、このシフトは符号を気にせず安全に行えます。

### 2. 符号付きとして読み替える（`int32_t(...)`）

最上位ビットが 1 なので、`int32_t` として見ると負の数です。

### 3. 算術右シフトで元の位置に戻す（`>> (32 - B)`）

```
int32_t(...) >> 28 = 1111 1111 ... 1111 1111   = -1
```

右シフトのとき、左から符号ビット（1）が入ってくるので、上の桁がすべて 1 で埋まります。これが符号拡張そのものです。

`X = 0b0111` なら、左シフト後の最上位は 0 なので、戻すときも 0 が入り、`7` のままです。

また、`X` の B ビットより上にゴミが入っていても、最初の左シフトで押し出されて消えます。

### 4. B が 0 の場合

```cpp:line-numbers=556
  if constexpr (B == 0)
    return 0;
```

`B = 0` だとシフト量が 32 になり、32 ビットの値を 32 ビットずらす**未定義動作**になってしまいます。そこで `if constexpr` で先に `0` を返しています。

## ここがすごい

素直に書くと、次のように符号ビットを調べて分岐することになります。

```cpp
uint32_t Mask = (1u << B) - 1;
X &= Mask;
if (X & (1u << (B - 1))) X |= ~Mask;   // 負なら上を 1 で埋める
return int32_t(X);
```

マスクを作って、上位を消して、符号を調べて、埋める。手順が多く、`B = 32` のときに `1u << 32` で未定義動作になる落とし穴もあります。

この関数は「**左に寄せれば上位のゴミは消え、右に戻せば CPU が符号を埋めてくれる**」という性質を使い、2 回のシフトだけで済ませています。分岐がありません。`B` がコンパイル時定数なので、シフト量も定数になり、多くの CPU では 2 命令程度になります。

同じファイルには、`B` を実行時に受け取る版（`SignExtend32(uint32_t X, unsigned B)`）や 64 ビット版もあり、同じ考え方で書かれています。

## まとめ

- 符号拡張は「左シフトで符号ビットを最上位へ → 算術右シフトで戻す」で書ける。
- 最初の左シフトで、不要な上位ビットも自然に消える。
- シフト量が型の幅に等しくなる境界（B = 0）は未定義動作なので別扱いにする。
- 値をテンプレート引数にすると、定数として最適化されやすい。
