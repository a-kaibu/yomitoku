## ひとことで

`KeyMayMatch` は、ブルームフィルタ（少ないメモリで「絶対にない」か「あるかもしれない」を答えるビットの並び）に、あるキーが含まれうるかを調べる関数です。
フィルタを作ったときと同じ手順で k 個のビット位置を計算し、**1 つでも 0 のビットがあれば「ない」** と答えます。全部 1 なら「あるかもしれない」です。

## コード

  bool KeyMayMatch(const Slice& key, const Slice& bloom_filter) const override {
    const size_t len = bloom_filter.size();
    if (len < 2) return false;

    const char* array = bloom_filter.data();
    const size_t bits = (len - 1) * 8;

    // 記録された k を使うので、別のパラメータで作られた
    // フィルタも読める。
    const size_t k = array[len - 1];
    if (k > 30) {
      // 短いフィルタ用の新しい形式のために予約している。
      // 一致したとみなす。
      return true;
    }

    uint32_t h = BloomHash(key);
    const uint32_t delta = (h >> 17) | (h << 15);  // 右に 17 ビット回転
    for (size_t j = 0; j < k; j++) {
      const uint32_t bitpos = h % bits;
      if ((array[bitpos / 8] & (1 << (bitpos % 8))) == 0) return false;
      h += delta;
    }
    return true;
  }

  bool KeyMayMatch(const Slice& key, const Slice& bloom_filter) const override {
    const size_t len = bloom_filter.size();
    if (len < 2) return false;

    const char* array = bloom_filter.data();
    const size_t bits = (len - 1) * 8;

    // Use the encoded k so that we can read filters generated by
    // bloom filters created using different parameters.
    const size_t k = array[len - 1];
    if (k > 30) {
      // Reserved for potentially new encodings for short bloom filters.
      // Consider it a match.
      return true;
    }

    uint32_t h = BloomHash(key);
    const uint32_t delta = (h >> 17) | (h << 15);  // Rotate right 17 bits
    for (size_t j = 0; j < k; j++) {
      const uint32_t bitpos = h % bits;
      if ((array[bitpos / 8] & (1 << (bitpos % 8))) == 0) return false;
      h += delta;
    }
    return true;
  }

## 前提知識

- **`const Slice&`**: `Slice` は「バイト列の先頭ポインタと長さ」の組です。`&` は参照で、コピーせずに元のオブジェクトをそのまま渡します。`const` なので中身は変えません。
- **`bloom_filter.data()` / `size()`**: `Slice` が指すバイト列の先頭と長さです。
- **`array[len - 1]`**: バイト列の最後の 1 バイトです。`char` として読み、`size_t`（符号なし整数）に変換して `k` に入れています。
- **`(h >> 17) | (h << 15)`**: 32 ビットの値の右 17 ビット回転です。
- **`array[i] & (1 << b)`**: i バイト目の b ビット目が立っているかを調べます。0 なら立っていません。
- **`override`**: 親クラス `FilterPolicy` の仮想関数を上書きしていることを示します。

## 何をしているか

フィルタは「ビットの並び（n バイト）＋末尾 1 バイトの k」という形です（`CreateFilter` で作られます）。

### 1. 形が正しいか確かめる

```cpp:line-numbers=57
    const size_t len = bloom_filter.size();
    if (len < 2) return false;
```
長さが 2 未満では、ビットの並びも k も入りません。壊れたデータなので `false` を返します。

### 2. ビット数と k を読む

```cpp:line-numbers=60
    const char* array = bloom_filter.data();
    const size_t bits = (len - 1) * 8;

    // 記録された k を使うので、別のパラメータで作られた
    // フィルタも読める。
    const size_t k = array[len - 1];
```
最後の 1 バイトを除いた部分がビットの並びです。9 バイトのフィルタなら `bits = 8 × 8 = 64` です。k は最後のバイトから読みます。

### 3. 知らない形式なら「あるかも」

```cpp:line-numbers=66
    if (k > 30) {
      // 短いフィルタ用の新しい形式のために予約している。
      // 一致したとみなす。
      return true;
    }
```
k が 30 を超えるのは、今のコードが作らない値です。コメントによれば、将来の新しい形式のために予約されています。読み方がわからないときは、`true`（あるかもしれない）を返します。

### 4. ビットを順に確かめる

```cpp:line-numbers=72
    uint32_t h = BloomHash(key);
    const uint32_t delta = (h >> 17) | (h << 15);  // 右に 17 ビット回転
    for (size_t j = 0; j < k; j++) {
      const uint32_t bitpos = h % bits;
      if ((array[bitpos / 8] & (1 << (bitpos % 8))) == 0) return false;
      h += delta;
    }
    return true;
```
作ったときと同じハッシュ関数・同じ `delta` で、k 個の位置を順に計算します。
たとえば k = 6 で、3 個目の位置のビットが 0 だったとします。このキーを登録していれば、そのビットは必ず 1 になっているはずです。だからその場で `false` を返し、残りの 3 個は調べません。
6 個すべて 1 なら `true` を返します。別のキーがたまたま同じビットを立てていた可能性もあるので、これは「あるかもしれない」という意味です。

## ここがすごい

- **間違えてもいい方向を決めている**: ブルームフィルタの答えが「ない」なら、LevelDB はディスクを読みません。だから「本当はあるのに、ないと答える」誤りは絶対に許されません。逆に「ないのに、あるかもと答える」のは、ディスクを無駄に読むだけで正しさは保たれます。壊れたデータは `false`（長さ不足）、未知の形式は `true` と、どちらも整合した選び方をしています。
- **早期終了**: 0 のビットが 1 つ見つかればすぐ終わるので、ないキーの判定はたいてい数回の確認で済みます。
- **作る側と同じ計算をくり返す**: 位置の作り方は `CreateFilter` と同じ「ハッシュ 1 回 + 回転した値を足していく」方式です。キーごとの計算は軽く、k 回のハッシュ計算は要りません。
- **形式を後から拡張できる**: k を末尾に保存し、範囲外の値を予約にしておくことで、古いプログラムが新しい形式に出会っても誤った「ない」を返さずに済みます。

## まとめ

- ブルームフィルタは「1 つでも 0 なら確実にない、全部 1 ならあるかも」。
- 誤りの方向を決めておき、わからないときは安全なほう（ここでは「あるかも」）に倒す。
- データ形式に予約領域を残すと、将来の拡張に古いコードが安全に対応できる。
