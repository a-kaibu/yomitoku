## ひとことで

`reducePathComponents` は、パスを `/` で区切った部品の配列から、**`.`（今のディレクトリ）と `..`（1 つ上のディレクトリ）を取り除いて** 実際の場所を表す配列にします。

```
["/", "a", "b", "..", "c", ".", "d"] → ["/", "a", "c", "d"]   （/a/b/../c/./d → /a/c/d）
["", "..", "a"]                      → ["", "..", "a"]          （相対パスの ../a はそのまま）
["/", ".."]                          → ["/"]                    （ルートより上には行けない）
```

配列の 0 番目は「ルート」（`/` や `c:/`、相対パスなら空文字）と決められていて、この約束を活かして場合分けをしています。

## コード

```ts:line-numbers=538
export function reducePathComponents(components: readonly string[]): string[] {
    if (!some(components)) return [];
    const reduced = [components[0]];
    for (let i = 1; i < components.length; i++) {
        const component = components[i];
        if (!component) continue;
        if (component === ".") continue;
        if (component === "..") {
            if (reduced.length > 1) {
                if (reduced[reduced.length - 1] !== "..") {
                    reduced.pop();
                    continue;
                }
            }
            else if (reduced[0]) continue;
        }
        reduced.push(component);
    }
    return reduced;
}
```

## 前提知識

- **パスの部品**: `/a/b/c` を `["/", "a", "b", "c"]` のように分けたものです。TypeScript コンパイラでは、0 番目に必ずルートが入ります。相対パスならルートは `""`（空文字）です。
- **`.` と `..`**: ファイルのパスで、`.` は今いるディレクトリ、`..` は 1 つ上のディレクトリを表します。
- **スタック**: 最後に入れたものから取り出すデータ構造です。配列の `push`（末尾に追加）と `pop`（末尾を取り除く）で表せます。
- **`some(components)`**: 同じプロジェクトの関数で、配列が空でないかを調べます。
- **`if (!component) continue;`**: 空文字の部品（`a//b` のように `/` が重なったときに生まれる）を飛ばします。

## 何をしているか

ルートを最初に入れ（540 行目）、残りの部品を 1 つずつ見ていきます。

- 空文字や `.` は飛ばす（543〜544 行目）。
- `..` が来たら（545 行目）:
  - ルート以外の部品が積まれていて、最後が `..` でなければ、**最後の部品を取り消す**（546〜550 行目）。`a/b/..` → `a`。
  - ルートしか積まれていない場合、**ルートが空文字でなければ**（絶対パスなら）、ルートより上には行けないので `..` を捨てる（552 行目）。
  - それ以外（相対パスで戻る先がない、または最後も `..`）は、`..` を積む（554 行目）。
- 普通の部品は積む（554 行目）。

相対パス `../../a/..` を追ってみます。

```
["", "..", "..", "a", ".."]
"..": ルートだけ・ルートは空 → 積む     ["", ".."]
"..": 最後が ".." → 積む               ["", "..", ".."]
"a" : 積む                             ["", "..", "..", "a"]
"..": 最後が "a" → 取り消す             ["", "..", ".."]
```

## ここがすごい

- **スタックで素直に表現**: 「`..` は直前の 1 つを取り消す」という規則が、`pop` 1 回でそのまま書けています。
- **相対パスの `..` を勝手に消さない**: 相対パス `../a` の `..` は「今いる場所の 1 つ上」という大事な情報で、どこが上なのかはこの時点ではわかりません。なので消さずに残します。一方、`..` が続くとき（`../..`）は前の `..` を取り消してはいけないので、547 行目で「最後が `..` なら取り消さない」と確認しています。
- **絶対パスはルートで止まる**: `/..` はルートそのものと同じ場所です。ルートが空文字かどうかで、絶対パスと相対パスを 1 つの条件で見分けています。0 番目は必ずルートという約束が、この判定を簡単にしています。

## まとめ

- `.` と `..` の処理は、配列をスタックとして使うと素直に書ける。
- 相対パスの先頭の `..` は、行き先がわからないので残す必要がある。
- 「0 番目は必ずルート」のような約束があると、場合分けが単純になる。
