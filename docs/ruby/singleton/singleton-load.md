## ひとことで

Ruby の `Marshal` は、オブジェクトをバイト列にして保存し、後で読み戻すための仕組みです。
シングルトンを読み戻すと、普通は新しいオブジェクトが作られてしまいます。
`Singleton` は `_load` を上書きして、読み戻した結果を、いつも同じ `instance` にしています。

## コード

```ruby:line-numbers=123
    def _load(str)
      instance
    end
```

## 前提知識

- **`Marshal`**: Ruby のオブジェクトを、バイト列に変換して保存し、そこから元に戻すための標準ライブラリです。`Marshal.dump` と `Marshal.load` の組で使います。
- **`_dump` と `_load`**: オブジェクトが、`Marshal` での保存と読み戻しの方法を、自分で決めるためのフックです。`_dump` は保存する文字列を返し、`_load` はその文字列から値を作ります。
- **引数の `str`**: `_load` に渡される、保存されていた文字列です。この実装では使っていません。
- **`instance`**: シングルトンの唯一のインスタンスを返すメソッドです。
- **フック**: あるできごとの途中で、利用者が決めた処理を差し込める仕組みです。

## 何をしているか

### 1. 保存するときは、中身を持たない

`Singleton` のインスタンス側には、`_dump` が定義されています。その中身は、空の文字列を返すだけです。
つまり、保存されるのは「シングルトンである」という印だけで、データは入りません。

### 2. 読み戻すときは、`instance` を返す

```ruby:line-numbers=124
      instance
```

`Marshal.load` が、保存された文字列を見ると、`_load` が呼ばれます。その結果として、`instance` が返されます。
`str` は使われません。どの内容が保存されていても、同じシングルトンが返ります。

### 3. 結果として、2 つ目のインスタンスができない

`Marshal.load` の戻り値は、新しく作られたオブジェクトではなく、既存の唯一のインスタンスです。
プログラムのどこでデータを読み戻しても、同じオブジェクトを指すことになります。

## ここがすごい

### 保存されたデータに、頼らない

ふつう、読み戻しは保存された中身を使って、オブジェクトを作り直します。
シングルトンは、中身を持たないという前提があるので、中身を使う必要がありません。
`str` を無視して `instance` を返すことは、「1 つだけ」という設計と完全に一致しています。

### 保存の中身を空にしておく、という工夫

`_dump` が空の文字列を返すことで、保存ファイルに余分なデータが増えません。
保存と読み戻しが、どちらも最小限の形で済んでいます。

### 「読んだら同じもの」が、型の問題にならない

利用者は、`Marshal.load` で読んだ結果を、ふつうのオブジェクトと同じように扱えます。
同じシングルトンが返ることを、特別に気にする必要がありません。

## まとめ

- `_dump` は空の文字列を返し、保存されるのは「シングルトンである」という印だけです。
- `_load` は引数を使わず、いつも `instance` を返します。
- 読み戻しても、新しいオブジェクトは作られず、唯一のインスタンスが使われます。
- 保存の内容を無視することで、「1 つだけ」という前提を、読み戻しの場面でも守っています。
