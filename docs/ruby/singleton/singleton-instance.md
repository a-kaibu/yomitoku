## ひとことで

`Singleton` は、クラスのインスタンスを 1 つだけに保つための標準ライブラリです。
`instance` メソッドは、最初に呼ばれたときだけ `new` でインスタンスを作り、以降は同じものを返します。
この 1 行は、ロックを使いながら、ふつうの呼び出しではロックを取らないように書かれています。

## コード

```ruby:line-numbers=128
      @singleton__instance__ || @singleton__mutex__.synchronize { @singleton__instance__ ||= new }
```

## 前提知識

- **シングルトン**: アプリケーションの中で、同じクラスのインスタンスを 1 つだけ使うという設計パターンです。設定やログの管理などに使われます。
- **`||`（論理和）と `||=`**: `a || b` は、`a` が真ならそれを、偽なら `b` を返します。`a ||= b` は、`a` が偽のときだけ `b` を代入します。
- **`Mutex` と `synchronize`**: ロックを取って、ブロックを排他的に実行するための仕組みです。`synchronize` は、ブロックの前後でロックを取得・解放します。
- **インスタンス変数**: `@singleton__instance__` のように、オブジェクトやクラスに属する値を入れる変数です。
- **二重チェック（double-checked locking）**: ロックの前に一度調べ、ロックの中でもう一度調べる書き方です。

## 何をしているか

### 1. ロックなしで、作成済みかを確かめる

```ruby:line-numbers=128
      @singleton__instance__ || @singleton__mutex__.synchronize { @singleton__instance__ ||= new }
```

行の最初で、`@singleton__instance__` が真かを見ます。すでに作られていれば、`||` の右側は実行されません。
つまり、2 回目以降の呼び出しは、ロックを取らずに、保存しておいたインスタンスを返すだけです。

### 2. まだ無いときだけ、ロックを取って作る

`@singleton__instance__` が `nil` のときは、右側の `synchronize` が呼ばれます。
ブロックの中で、もう一度 `@singleton__instance__ ||= new` を実行します。ここで `new` は、一度だけ呼ばれます。

### 3. ロックの中でもう一度確かめる理由

ロックを取る前に、2 つのスレッドが同時に「まだ無い」と判断することがあります。
ロックの中で `||=` を使うと、後から入ったスレッドは、先に作られたインスタンスを受け取ります。
結果として、`new` が 2 回呼ばれることは起きません。

## ここがすごい

### 作成後の呼び出しは、ロックの待ちがない

インスタンスを使うのは、ほとんどが作成後です。その場合、ロックの取得も解放も発生しません。
ふつうの `synchronize` だけで書くと、毎回ロックを取ることになり、遅くなります。

### 1 行に、確認と作成をまとめている

`||` で「あれば返す」を、`||=` で「無ければ作る」を、1 行で書いています。
読み手は、この 1 行を見れば、初期化の順番が分かります。

### 同じ確認を 2 回書く、という安全策

最初の確認は速さのため、ロックの中の確認は正しさのためです。
2 つの役割を、同じ式で分けて書くことで、速さと安全さの両方を保っています。

## まとめ

- `instance` は、インスタンスが作成済みなら、ロックを取らずに返します。
- 作成されていなければ、`synchronize` の中で `||=` により 1 回だけ作ります。
- ロックの前後で 2 回確かめることで、同時に呼ばれても `new` は 1 回だけです。
- 速さ（作成済みの場合）と正しさ（同時に作る場合）を、1 行で両立しています。
