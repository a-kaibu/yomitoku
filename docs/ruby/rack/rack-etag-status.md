## ひとことで

`Rack::ETag#etag_status?` は、応答のステータスコードが **ETag を付けてよいもの**かを判定するメソッドです。
ステータスが `200 OK` か `201 Created` のときだけ `true` を返します。
エラーや、リダイレクトなどの応答には、ETag を付けません。

## コード

```ruby:line-numbers=52
      def etag_status?(status)
        status == 200 || status == 201
      end
```

## 前提知識

- **ETag**: 応答の内容の識別子です。内容が変わるたびに値も変わるので、クライアントは同じ内容かどうかを確かめられます。
- **Rack ミドルウェア**: アプリの前後で、リクエストや応答に手を加える部品です。`Rack::ETag` は、応答に ETag を付けるミドルウェアです。
- **ステータスコード**: 応答の結果を表す番号です。200 は成功、201 は作成成功、404 は見つからない、を表します。
- **`||`**: どちらかが真なら真になります。

## 何をしているか

### 1. 200 か 201 かを判定する

```ruby:line-numbers=53
        status == 200 || status == 201
```

ステータスが `200` か `201` のときだけ、`true` を返します。どちらも「本文が意味のある成功の応答」です。

### 2. それ以外は、偽を返す

```ruby:line-numbers=53
        status == 200 || status == 201
```

ほかのステータスは、`false` になります。例えば 404 の本文に ETag を付けても、利用者にとって意味がないので、付けません。

## ここがすごい

### 対象を、成功の応答に絞る

ETag は、同じ資源が変わったかを確かめる仕組みです。
エラーの応答は、資源の内容を表していないので、付けても役に立ちません。このメソッドは、その判断を 1 か所に書いています。

### 判定を 1 つの式にまとめる

`status == 200 || status == 201` の 1 行で、対象の範囲が読めます。
ステータスの一覧を配列に入れて `include?` で調べる書き方もありますが、対象が 2 つだけなら、この形のほうが簡単です。

### 判断の入口を、名前で示す

`etag_status?` という名前は、「ETag を付けてよいステータスか」という問いを表します。
呼び出し側は、中身を読まずに、何を判断しているかを理解できます。

## まとめ

- キャッシュの識別子は、成功の応答だけに付けると、無駄や誤りを減らせます。
- 対象のステータスが少ないときは、比較を `||` で並べると、読みやすくなります。
- 判断を専用の名前のメソッドに分けると、呼び出し側の意図が伝わりやすくなります。
