## ひとことで

`filesize_format` は、バイト数（整数）を **人が読める単位の文字列** に直すメソッドです。
`2048` は `"2.0K"`、`1572864` は `"1.5M"` になります。ディレクトリの一覧ページでファイルの大きさを表示するために使われています。
1 キロバイトは 1024 バイトとして計算します。

## コード

```ruby:line-numbers=205
    def filesize_format(int)
      FILESIZE_FORMAT.each do |format, size|
        return format % (int.to_f / size) if int >= size
      end

      "#{int}B"
    end
```

単位の表は、同じファイルの少し上で次のように定義されています。

```ruby:line-numbers=197
    FILESIZE_FORMAT = [
      ['%.1fT', 1 << 40],
      ['%.1fG', 1 << 30],
      ['%.1fM', 1 << 20],
      ['%.1fK', 1 << 10],
    ]
```

## 前提知識

- **`1 << 10`**: ビットを左にずらす計算です。`1 << 10` は 2 の 10 乗、つまり 1024 です。1 キロバイトは 1024 バイトとして扱います。
- **`%` による書式化**: `'%.1fK' % 2.0` は `"2.0K"` になります。`%.1f` は小数点以下 1 桁の数字です。
- **`each do |format, size|`**: 配列の要素（ここでは `[書式, 大きさ]` の組）を 2 つの変数に分けて受け取ります。
- **`return`**: メソッドの途中で値を返して、その時点で終わります。ブロックの中で使うと、メソッド全体から抜けられます。
- **`int.to_f`**: 整数を小数にします。割り算の結果を小数で得るためです。

## 何をしているか

### 1. 大きい単位から順に試す

```ruby:line-numbers=206
      FILESIZE_FORMAT.each do |format, size|
        return format % (int.to_f / size) if int >= size
      end
```

表は T（テラ）、G、M、K の順に並んでいます。`int` がその単位の大きさ以上なら、その単位で割って書式を当てはめ、`return` で即座に返します。

`1572864`（1.5 メガバイト）の場合、T（1 << 40）、G（1 << 30）は大きすぎるので飛ばされます。M（1 << 20 ＝ 1048576）が当てはまり、`1572864 / 1048576.0 = 1.5` なので `"1.5M"` を返します。

### 2. どの単位にも届かなければ、バイトのまま

```ruby:line-numbers=210
      "#{int}B"
```

1024 より小さい値は、どの単位にも当てはまりません。そのときは `"500B"` のように、バイトのまま返します。

## ここがすごい

### 表を見るだけの、短いコード

単位ごとに `if` を並べる代わりに、表を 1 つ用意して順に見ていくだけにしています。単位を増やすときは表に 1 行足すだけで済みます。

### 大きい順に並べることが前提

この書き方は、表が大きい順に並んでいるときだけ正しく動きます。`return` で最初に当てはまったものを返すので、並び順がそのまま「どの単位を優先するか」になっています。

### 小数で割って表示を整える

`int.to_f` で小数にしてから割るので、`1536`（1.5K）のような途中の値も、整数の割り算で切り捨てられずに表示できます。

## まとめ

- 単位の変換は、大きい単位から順に見て最初に当てはまるものを使うと、短く書けます。
- 表で持っておくと、単位を増やしたいときに表だけを直せます。
- 割り算の前に小数にすると、切り捨てを避けられます。
