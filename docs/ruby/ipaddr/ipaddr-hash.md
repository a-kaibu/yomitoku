## ひとことで

`IPAddr#hash` は、IP アドレスをハッシュ（Hash や Set で使う、ほぼ一意の数）に変えるメソッドです。
ハッシュ値の一番下のビットを、IPv4 か IPv6 かで変えて、同じ数値のアドレスどうしが衝突しないようにしています。
`eql?` と組になって、Hash や Set のキーとして安全に使えるようにします。

## コード

```ruby:line-numbers=532
  def hash
    return ([@addr, @mask_addr, @zone_id].hash << 1) | (ipv4? ? 0 : 1)
  end
```

## 前提知識

- **ハッシュ値**: 任意の値から計算される、整数の要約です。同じ値なら同じハッシュ値になります。
- **`eql?` と `hash`**: Ruby では、Hash や Set のキーになるとき、`hash` の値が等しく、かつ `eql?` が真のときに同じものとみなされます。
- **ビットシフト（`<<`）**: 数を左にずらすことです。`x << 1` は、`x` を 2 倍にすることと同じです。
- **ビットの OR（`|`）**: 対応するビットのどちらかが 1 なら 1 になる演算です。
- **衝突**: 違うキーが同じハッシュ値になることです。少ないほど、Hash は速く動きます。

## 何をしているか

### 1. アドレス・マスク・ゾーン ID をまとめてハッシュにする

```ruby:line-numbers=533
    return ([@addr, @mask_addr, @zone_id].hash << 1) | (ipv4? ? 0 : 1)
```

まず、`[@addr, @mask_addr, @zone_id]` という配列のハッシュ値を求めます。
アドレスだけでなく、マスク（ネットワークの大きさ）とゾーン ID（IPv6 の接続先の区別）も含めています。
同じアドレスでも、マスクが違えば別の範囲なので、ハッシュ値も違うべきだからです。

### 2. 1 ビット左にずらして、末尾を空ける

`<< 1` によって、ハッシュ値の一番下のビットが 0 になります。
この空いたビットに、次の判定の結果を入れます。

### 3. IPv4 なら 0、IPv6 なら 1 を入れる

`(ipv4? ? 0 : 1)` で、IPv4 は 0、IPv6 は 1 になります。
これを `|`（OR）で入れると、IPv4 と IPv6 のハッシュ値は、末尾のビットだけで必ず違う値になります。

## ここがすごい

### 同じ数値でも、系統が違えば別物になる

IPv4 の `0.0.0.1` と、IPv6 の `::1` は、アドレスの数値が同じ 1 です。
数値だけでハッシュを作ると、この 2 つが同じ値になりやすくなります。
末尾の 1 ビットで系統を分けておくと、この衝突が必ず避けられます。

### ビットを 1 つ使うだけで済む

ハッシュ値の全体を作り直す必要はありません。1 ビットを空けて OR を取るだけで、系統の区別を付けられます。
追加の計算がほとんど要らないので、速さを損ないません。

### `eql?` と対になっている

このメソッドは、`eql?` が真になるものだけを同じハッシュ値にします。
ゾーン ID やマスクまで含めることで、「等しいと判定されたのに、ハッシュ値が違う」という不整合を防いでいます。

## まとめ

- ハッシュ値は、Hash や Set でキーを見つけるための要約です。
- 1 ビット左にずらすと、末尾のビットを、系統の区別に使えます。
- IPv4 は 0、IPv6 は 1 を OR で入れると、同じ数値でも衝突を避けられます。
- `hash` と `eql?` は組で正しく作る必要があり、この実装もそれに従っています。
