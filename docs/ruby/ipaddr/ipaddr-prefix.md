## ひとことで

`IPAddr#prefix` は、ネットワークの指定が何ビットか（`/24` なら 24）を返します。
マスクには、ネットワーク部分が 1、ホスト部分が 0 で並んでいます。
そのため、「ホスト部分の 1 の数」を求めて、全体のビット数から引けば、答えが出ます。

## コード

```ruby:line-numbers=542
  def prefix
    case @family
    when Socket::AF_INET
      n = IN4MASK ^ @mask_addr
      i = 32
    when Socket::AF_INET6
      n = IN6MASK ^ @mask_addr
      i = 128
    else
      raise AddressFamilyError, "unsupported address family"
    end
    while n.positive?
      n >>= 1
      i -= 1
    end
    i
  end
```

## 前提知識

- **プレフィックス長**: `/24` のように、ネットワーク部分のビット数を表す値です。IPv4 は 0 から 32、IPv6 は 0 から 128 の範囲です。
- **マスクの反転**: `IN4MASK ^ @mask_addr` で、ネットワーク部分の 1 とホスト部分の 0 を入れ替えます。すると、残るのはホスト部分の 1 だけです。
- **`>>=`（右シフト代入）**: 数を 1 ビット右にずらして、その結果を同じ変数に入れる演算です。
- **`positive?`**: 数が 0 より大きいかを返すメソッドです。
- **ビット数の対応**: IPv4 は 32 ビット、IPv6 は 128 ビットの数です。その全体から、ホスト部分のビット数を引くと、プレフィックス長になります。

## 何をしているか

### 1. ホスト部分を 1 にした数を作る

```ruby:line-numbers=545
      n = IN4MASK ^ @mask_addr
```

`/24` の IPv4 なら、マスクは `0xffffff00` です。反転すると `0x000000ff` になります。下位 8 ビットが 1 で、ここがホスト部分の大きさです。
`i` は、全体のビット数 32 で初期化されています。

### 2. 1 ビットずつ右にずらして数える

```ruby:line-numbers=553
    while n.positive?
      n >>= 1
      i -= 1
    end
```

`n` が 0 になるまで、右に 1 ビットずつずらします。ずらすたびに `i` を 1 減らします。
`0x000000ff` は 8 回ずらすと 0 になるので、`i` は `32 - 8 = 24` になります。
つまり、残りの 1 の数が、ホスト部分のビット数です。

### 3. 全体のビット数から引いた値を返す

```ruby:line-numbers=557
    i
```

`i` は、ネットワーク部分のビット数です。`/24` なら 24 を返します。

## ここがすごい

### マスクを反転させるだけで、数える対象が決まる

ネットワーク部分の 1 を数えるより、ホスト部分の 1 を数えるほうが、ループの回数が少なくて済みます。
`IN4MASK ^ @mask_addr` という 1 行で、「数えるべきビット」だけを残しています。

### 1 ビット右にずらすだけの単純な数え方

ビットの 1 を数えるのに、難しいアルゴリズムは使っていません。`n >>= 1` を繰り返すだけです。
ホスト部分は、ふつう多くても 32 ビット（IPv6 でも 128 ビット）なので、ループは必ず短く終わります。読みやすさと速さが両立しています。

### 系統ごとに、全体のビット数を変える

IPv4 は 32、IPv6 は 128 から数えます。同じ仕組みを使い、初期値だけを変えています。
`case` で系統を分けるのは、マスクの大きさと全体のビット数を決めるためだけです。

## まとめ

- マスクを反転すると、数えるべきホスト部分のビットだけが残ります。
- 1 ビットずつ右にずらして 0 になるまで数えると、ホスト部分のビット数が分かります。
- 全体のビット数（32 か 128）から、それを引くと、プレフィックス長になります。
- ループは、最大 128 回で必ず終わります。
