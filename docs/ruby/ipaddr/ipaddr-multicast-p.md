## ひとことで

`IPAddr#multicast?` は、そのアドレスがマルチキャスト（同じ相手の群に一度に送るための特別な範囲）かを調べます。
IPv4 では `224.0.0.0/4`、IPv6 では `ff00::/8` が、その範囲です。
範囲を列挙せず、先頭の数ビットを見るだけで判定しています。

## コード

::: code-group

```ruby:line-numbers=396 [日本語訳]
  def multicast?
    case @family
    when Socket::AF_INET
      (@addr & 0xf0000000 == 0xe0000000) && prefix >= 4 # IPv4 のマルチキャスト範囲 224.0.0.0/4
    when Socket::AF_INET6
      (@addr & 0xff00_0000_0000_0000_0000_0000_0000_0000 == 0xff00_0000_0000_0000_0000_0000_0000_0000) && prefix >= 8 || # IPv6 のマルチキャスト範囲 ff00::/8
        (@addr >> 32 == 0xffff &&
          (@addr & 0xf0000000 == 0xe0000000) && prefix >= 100 # IPv4 を埋め込んだ ::ffff:224.0.0.0/100（224.0.0.0/4 と同じ）
        )
    else
      raise AddressFamilyError, "unsupported address family"
    end
  end
```

## 前提知識

- **マルチキャスト**: 1 つの送信を、同じ群に入っている複数の相手へ届けるための宛先です。普通の一対一の宛先とは区別されます。
- **先頭ビットの一致**: IPv4 の `224.0.0.0/4` は、先頭 4 ビットが `1110` のアドレスの集まりです。上位ビットだけで範囲が決まります。
- **`&` と `==` の優先順位**: Ruby では、`&` が `==` より先に計算されます。`@addr & 0xf0000000 == 0xe0000000` は、`(@addr & 0xf0000000) == 0xe0000000` と読まれます。
- **`prefix`**: IP アドレスが表すネットワークの、ネットワーク部分のビット数です。`/24` なら 24 です。
- **`||` と `&&`**: 論理和と論理積です。`&&` が `||` より先に評価されます。

## 何をしているか

### 1. IPv4 の判定は、上位 4 ビットだけを見る

```ruby:line-numbers=399
      (@addr & 0xf0000000 == 0xe0000000) && prefix >= 4 # 224.0.0.0/4
```

`0xf0000000` で AND を取ると、上位 4 ビットだけが残ります。それが `0xe0000000`（二進数で `1110`）なら、先頭が `224` から `239` の範囲に入ります。
さらに `prefix >= 4` で、指定したネットワークが `/4` 以上に絞られていることを確かめます。`/4` より広いネットワークは、マルチキャスト範囲の外にも広がるからです。

### 2. IPv6 は、上位 8 ビットで判定する

```ruby:line-numbers=401
      (@addr & 0xff00_0000_0000_0000_0000_0000_0000_0000 == 0xff00_0000_0000_0000_0000_0000_0000_0000) && prefix >= 8 || # ff00::/8
```

IPv6 のマルチキャストは、先頭 8 ビットが `11111111` のアドレスです。その 8 ビットを残して、`0xff` に等しいかを見ます。

### 3. IPv4 を埋め込んだ IPv6 の場合は、別に確かめる

```ruby:line-numbers=402
        (@addr >> 32 == 0xffff &&
          (@addr & 0xf0000000 == 0xe0000000) && prefix >= 100 # ::ffff:224.0.0.0/100 (224.0.0.0/4)
        )
```

`::ffff:` で始まる IPv6 は、IPv4 のアドレスを下位 32 ビットに入れた形です。上位 32 ビットを右にずらして `0xffff` と比べ、残りの 32 ビットを IPv4 として判定します。

## ここがすごい

### 範囲の列挙をせず、上位ビットの比較で済ませている

マルチキャストの範囲は、IPv4 では 2 億個以上のアドレスを含みます。すべてを数えるのは現実的ではありません。
この実装は、先頭の数ビットを見るだけなので、範囲の大きさに関係なく同じ速さで判定できます。

### `prefix` を確かめて、範囲の内側かを判定する

アドレスの先頭が `224` でも、`/0` のような広いネットワークは、マルチキャストだけではありません。`prefix` を比べることで、「指定した範囲全体が、その範囲に収まっているか」を確かめています。
単に先頭を比べるより、正確な判定になっています。

### 埋め込みの IPv4 も、同じ考え方で扱う

`::ffff:224.0.0.0/100` は、IPv4 のマルチキャストを IPv6 の中に入れた形です。下位 32 ビットに対して、IPv4 と同じ判定を繰り返しています。

## まとめ

- マルチキャストは、先頭の数ビットの一致で判定できます。
- Ruby の `&` は `==` より先に計算されるので、括弧がなくても意図どおりに読めます。
- `prefix` を比べて、指定したネットワークが範囲の内側に収まっているかも確かめます。
- IPv4 を埋め込んだ IPv6 は、下位 32 ビットに同じ判定を当てはめます。
