## ひとことで

Caffeine は、Java のキャッシュライブラリです。どのデータを残すかを決めるために、各データが **どのくらい頻繁に使われたか** を小さなカウンタで記録します。`FrequencySketch.reset()` は、そのカウンタをすべて **半分にする** 処理です。

定期的に半分にすると、古い人気は次第に薄れ、最近よく使われたものが残りやすくなります。この関数は、1 つの `long`（64 ビット）に **4 ビットのカウンタを 16 個** 詰めた表を、ループ 1 回で一度に半分にします。

## コード

```java:line-numbers=224
  void reset() {
    @Var long count = 0;
    for (int i = 0; i < table.length; i++) {
      count += Long.bitCount(table[i] & ONE_MASK);
      table[i] = (table[i] >>> 1) & RESET_MASK;
    }
    size = Math.max(0, (int) ((size - (count >>> 2)) >>> 1));
  }
```

このコードが使う定数は、同じファイルで次のように定義されています。

```java:line-numbers=68
  static final long RESET_MASK = 0x7777777777777777L;
  static final long ONE_MASK = 0x1111111111111111L;
```

## 前提知識

- **4 ビットのカウンタ**: 4 ビットは 0〜15 の値を表せます。Caffeine ではこれ以上増やさないよう、上限を 15 にしています。
- **`long[] table`**: 64 ビットの整数の配列です。1 つの `long` に 4 ビットのカウンタが 16 個入ります。
- **`@Var`**: Error Prone というツールの注釈で、「この変数は後で変わる」ことを示します。Java 本来の `final` の逆の意味で、読み手に変化する変数だと伝えています。
- **`Long.bitCount(x)`**: `x` の中の 1 のビットの数を返します。
- **`>>>`（符号なし右シフト）**: 左端に 0 を入れて右にずらします。

## 何をしているか

### 1. 各カウンタの「奇数かどうか」を数える

```java:line-numbers=227
      count += Long.bitCount(table[i] & ONE_MASK);
```

`ONE_MASK`（`0x1111…`）は、4 ビットごとの **最下位ビット** だけを残すマスクです。その AND の 1 の数は、「値が奇数だったカウンタの数」になります。これは後で、全体の `size` を調整するために使います。

### 2. 全体を 1 ビット右にずらす

```java:line-numbers=228
      table[i] = (table[i] >>> 1) & RESET_MASK;
```

ここが核心です。4 ビットのカウンタを、`>>> 1` で 1 ビットずらすと、**1 つ上のカウンタの最下位ビットが、1 つ下のカウンタの最上位ビットの位置に入ってしまいます**。

そこで `& RESET_MASK`（`0x7777…`）で、各 4 ビットの最上位ビットを消します。`0x7` は `0111` なので、各カウンタの上 1 ビットだけを 0 にするのです。これで隣のカウンタからの混入がなくなります。

### 3. 具体的な値で追う

1 つのカウンタを取り出して考えます。

- 値 `5`（`0101`）: `>>> 1` で `0010`。マスクしても `0010`（2）。`5 / 2 = 2` の切り捨てと一致します。
- 値 `15`（`1111`）: `>>> 1` で `0111`。マスクしても `0111`（7）。`15 / 2 = 7` です。
- 値 `8`（`1000`）: `>>> 1` で `0100`。マスクしても `0100`（4）。

どのカウンタも、ちょうど半分（切り捨て）になりました。

## ここがすごい

- **16 個をまとめて処理**: 1 回のシフトと 1 回の AND で、16 個のカウンタを同時に半分にします。カウンタを 1 つずつ取り出して計算すると、16 回の処理が必要です。
- **隣との混入を 1 つのマスクで防ぐ**: 4 ビットの箱どうしが混ざる問題を、`0x777…` という 1 つの定数で解決しています。ビット演算ならではの、短くて正確な書き方です。
- **キャッシュの性能を支える**: `size` は、どれだけ多くの記録が行われたかを表します。奇数だったカウンタの数を使って、`size` も同時に補正します。集計を別に持たずに、ほぼ同じ働きを得ています。
- **メモリの効率**: 1 つのカウンタに 1 バイトや 1 `int` を使うより、4 ビットに詰めた方がメモリを 2〜8 分の 1 に抑えられます。大量のキーを追跡するキャッシュでは、この差が効きます。

## まとめ

- 複数の小さなカウンタを 1 つの整数に詰めると、まとめて演算できる。
- 詰めた箱どうしの混入は、マスクで防げる。
- 「半分にする」のような一括の操作は、シフトと AND の組み合わせで書けることが多い。
