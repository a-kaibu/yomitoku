## ひとことで

`FrequencySketch.spread(x)` は、キーの `hashCode()` が返す `int` を、もう一度 **かき混ぜる** 関数です。コメントには、「質の悪いハッシュ値から守るための補助的なハッシュ関数」と書かれています。

`hashCode()` は、クラスによっては散らばりがよくないことがあります。たとえば数値が連続するだけのキーでは、下位ビットがほとんど同じ値になります。この関数は、その偏りを消して、キャッシュのカウンタの位置を散らすために使われます。

## コード

```java:line-numbers=190
  static int spread(@Var int x) {
    x ^= x >>> 17;
    x *= 0xed5ad4bb;
    x ^= x >>> 11;
    x *= 0xac4c1b51;
    x ^= x >>> 15;
    return x;
  }
```

## 前提知識

- **ハッシュ値の偏り**: ハッシュ値が一部の値に集中すると、表の一部だけが使われて、衝突が増えます。
- **`x >>> 17`**: 17 ビット右にずらし、左端に 0 を入れます。上位ビットの情報を下位に運びます。
- **`^=`**: `x = x ^ ...` の省略形です。XOR で値を混ぜます。
- **`*=`**: `x = x * ...` の省略形です。`int` の掛け算は上位がはみ出しますが、エラーにはなりません。
- **奇数の掛け算**: 奇数を掛けると、下位ビットの情報が上位に広がり、その操作は逆算できます。
- **`@Var`**: 変数が後で変わることを示す注釈です（Error Prone というツールの注釈）。

## 何をしているか

### 1. 上位を下位へ、下位を上位へ混ぜる

```java:line-numbers=191
    x ^= x >>> 17;
    x *= 0xed5ad4bb;
    x ^= x >>> 11;
    x *= 0xac4c1b51;
    x ^= x >>> 15;
    return x;
```

このコードは、「右シフトの XOR」と「掛け算」を 2 回ずつ交互に行い、最後に右シフトの XOR で仕上げています。

- **右シフトの XOR**: 上位ビットの情報を下位に運びます。
- **掛け算**: 下位ビットの情報を上位に広げます。

片方だけでは、情報が一方向にしか流れません。両方を重ねると、どのビットの変化も、全体に行き渡ります。

### 2. 小さい入力の変化が全体に広がる

たとえば `x = 2`（`10`）と `x = 3`（`11`）のように、1 ビットだけ違う入力を考えます。

- `x = 2` と `x = 3` は、最下位のビットしか違いません。
- 右シフトの XOR で、その違いが下位のビットに影響します。
- 掛け算で、違いが上位に広がります。
- 繰り返すと、結果の多くのビットが変わります。

これが「雪崩効果（アバランシェ効果）」と呼ばれる性質です。小さな入力の差が、大きな出力の差になります。

### 3. 次の段階で使う

`frequency` メソッドでは、`spread(e.hashCode())` の結果を使い、さらに `rehash` という軽い変換をかけて、カウンタの位置を決めます。

## ここがすごい

- **定数の探索**: クラスのドキュメントには、ハッシュ関数を設計するために「Hash Function Prospector」というプロジェクトの結果を参照すると書かれています。掛ける定数やシフト量は、混ぜ具合を測定して選ばれています。
- **分岐とメモリアクセスなし**: 5 回の演算だけで、表を参照せずに値を作れます。キャッシュへの読み書きの中で何度も呼ばれる処理なので、この速さは重要です。
- **補助として使う**: `hashCode()` の質を信用せず、キャッシュの中で使う前に、必ず混ぜ直しています。外からのハッシュ値を盲目的に信用しないための、防御的な設計です。
- **2 段階の混ぜ方**: 1 段目の `spread` と、2 段目の `rehash` で役割を分けています。`spread` は強く混ぜ、`rehash` は軽く追加の変化を加えます。同じ値から複数の位置を取り出すときに役立ちます。

## まとめ

- 右シフトの XOR と奇数の掛け算を交互に重ねると、小さな違いが全体に広がる。
- 外から受け取ったハッシュ値は、そのまま信用せず、補助的に混ぜ直す。
- 定数やシフト量は、混ざり具合を測って決めると、理屈と実際の性能の両方を保てる。
