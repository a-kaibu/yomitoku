## ひとことで

`Util.highbits(x)` は、`int` の上位 16 ビットを取り出して `char` として返します。RoaringBitmap は、32 ビットの整数を扱うときに、この上位 16 ビットで「どのコンテナ（箱）に入るか」を決めます。

同じように、`Util.lowbits(x)` は下位 16 ビットを取り出します。コンテナの中では、この下位 16 ビットで位置を表します。

## コード

```java:line-numbers=439
  protected static char highbits(int x) {
    return (char) (x >>> 16);
  }
```

`lowbits` は、同じクラスで続けて定義されています。

```java:line-numbers=485
    return (char) x;
  }
```

## 前提知識

- **RoaringBitmap**: 整数の集合を圧縮して持つデータ構造です。値の上位 16 ビットごとに、「コンテナ」と呼ばれる箱を用意します。
- **`char`**: Java の 16 ビットの型です。ここでは、0 から 65535 の値を表すのに使われます。
- **`>>>`（符号なし右シフト）**: 右へずらし、左端は 0 で埋めます。負の数でも、上位ビットが符号に影響されません。
- **`(char)` キャスト**: 値を 16 ビットに切り詰めます。上位のビットは捨てられます。
- **集合**: 同じ値を重複して持たない入れ物です。値が入っているかどうかを速く調べたいときに使われます。

## 何をしているか

### 1. 上位 16 ビットを取り出す

```java:line-numbers=440
    return (char) (x >>> 16);
```

`x >>> 16` で、下位 16 ビットを捨てて上位 16 ビットを下へ移します。これだけで、0 から 65535 の範囲の値が得られます。同じ上位 16 ビットを持つ数は、同じコンテナに入ります。

### 2. 下位 16 ビットを取り出す

`lowbits(x)` は `(char) x` だけを書いています。`char` は 16 ビットなので、キャストで上位のビットが自然に捨てられます。マスクを書かなくても、下位 16 ビットだけが残ります。

### 3. 分割で位置が決まる

たとえば `0x0001_0005` という値は、`highbits` が `1`（コンテナの番号）、`lowbits` が `5`（コンテナの中の位置）になります。2 つを組み合わせると、元の値を 1 つずつ復元できます。

## ここがすごい

- **分割が 1 命令で済む**: 上位と下位の分け方が、シフトとキャストだけです。ハッシュ表のように計算を重ねずに、どの箱に入るかが一瞬で決まります。
- **キャストで切り捨てる**: `lowbits` は、マスクを使わずに `(char)` で下位だけを残しています。短く、意図がはっきり伝わる書き方です。
- **圧縮の土台になる**: 上位 16 ビットでコンテナを分けるので、同じ上位を持つ値は一緒に圧縮されます。この分割が、RoaringBitmap の省メモリの要です。
- **負の数も一貫して扱える**: `>>>` を使うので、符号ビットが上位の値に紛れ込みません。整数を符号なしの値として扱えます。

## まとめ

- `x >>> 16` が上位 16 ビット、`(char) x` が下位 16 ビットになる。
- 上位がコンテナの番号、下位がコンテナの中の位置を表す。
- この分割によって、同じ上位を持つ値をまとめて圧縮できる。
