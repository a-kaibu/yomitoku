## ひとことで

`BitUtil.align(value, alignment)` は、`value` を `alignment` の **次の倍数** に切り上げます。たとえば `align(13, 8)` は `16`、`align(16, 8)` は `16`（すでに倍数なので変わらない）です。

メモリ上のデータを 8 バイト境界や 64 バイト境界に並べるときによく使われます。この関数は `if` を使わず、**足し算 1 回と AND 1 回** で答えを作ります。

## コード

```java:line-numbers=156
    public static int align(final int value, final int alignment)
    {
        return (value + (alignment - 1)) & -alignment;
    }
```

## 前提知識

- **境界（アライメント）**: メモリのデータを、ある大きさの倍数の位置に置くことです。CPU のキャッシュや命令の都合で、そろっていると速くなることがあります。
- **倍数の切り上げ**: `value` 以上で最小の `alignment` の倍数を求める計算です。
- **`&`（AND）**: 両方が 1 の桁だけ 1 になります。特定の桁を消すときに使います。
- **`-alignment`**: 符号を反転した値です。2 の補数では、2 のべき乗 `2^k` の `-2^k` は、下位 `k` ビットだけが 0 で、それより上が 1 のビット列になります。
- **`alignment - 1`**: 2 のべき乗から 1 を引くと、下位 `k` ビットが全部 1 になります。

## 何をしているか

### 1. 余裕を足す

```java:line-numbers=158
        return (value + (alignment - 1)) & -alignment;
```

`value` に `alignment - 1` を足します。`align(13, 8)` なら `13 + 7 = 20` です。

- `13` は `0000 1101`
- `7` は `0000 0111`
- 和は `0001 0100`（20）

`13` は 8 の倍数ではありませんが、この和は「次の境界を越えるのに十分な余裕」を持っています。

### 2. 下位ビットを消す

同じ式の `& -alignment` が、下位ビットを消します。`-8` のビット列は `1111 1000` で、下位 3 ビットが 0 です。

- `20` は `0001 0100`
- `-8` は `…1111 1000`
- AND の結果は `0001 0000`（16）

下位 3 ビットが消えたので、答えは 8 の倍数になり、しかも元の値より小さくならない最小の倍数です。

### 3. 倍数の値は変わらない

`align(16, 8)` では、`16 + 7 = 23`（`0001 0111`）です。AND で下位 3 ビットを消すと `16` が残ります。すでに倍数だった値は、そのまま戻ります。

## ここがすごい

- **分岐がない**: 「余りがあれば切り上げる」を `if` で書くと、余りの計算と比較が必要です。この式は、足し算と AND だけで、どんな値でも同じ速さで動きます。
- **割り算を使わない**: 倍数の切り上げを割り算で書くと、`(value + alignment - 1) / alignment * alignment` となり、割り算は遅い命令です。`alignment` が 2 のべき乗なら、AND で代わりにできます。
- **前提の明示**: この式は `alignment` が 2 のべき乗のときにだけ正しく動きます。たとえば `alignment = 6` だと `-6` の下位ビットは 0 にならず、結果が倍数になりません。Javadoc にも、高速な経路で使う関数だと書かれています。
- **負の数は対象外**: Javadoc に、負の数は未定義の動作になると書かれています。性能のために入力の範囲を狭めて、その分だけ式を単純にしているのです。

## まとめ

- 倍数への切り上げは、`(value + (alignment - 1)) & -alignment` の 1 行でできる。
- この形は `alignment` が 2 のべき乗のときに成り立つ。
- 性能を優先する関数では、入力の前提を Javadoc に書いて、分岐や割り算を省くのが一般的。
