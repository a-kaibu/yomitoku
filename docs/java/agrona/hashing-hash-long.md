## ひとことで

`Hashing.hash(long)` は、64 ビットの整数を、32 ビットの「指紋」（ハッシュ値）に変えるメソッドです。Agrona は、ハッシュ表のキーや、コレクションの添字を作るときに、このメソッドを使います。

入力が少し違うだけでも、出力のビットが大きく変わりやすいように作られています。そうすると、連番のような入力でも、表の中に偏りなく散らばります。

## コード

```java:line-numbers=55
    public static int hash(final long value)
    {
        long x = value;

        x = (x ^ (x >>> 30)) * 0xbf58476d1ce4e5b9L;
        x = (x ^ (x >>> 27)) * 0x94d049bb133111ebL;
        x = x ^ (x >>> 31);

        return (int)x ^ (int)(x >>> 32);
    }
```

## 前提知識

- **ハッシュ値**: 大きなデータから作る、短い整数の要約です。同じ入力からは同じ値が出ます。
- **XOR（排他的論理和）**: 2 つのビットが違うときだけ 1 になる演算です。`^` と書きます。
- **符号なしの右シフト `>>>`**: 左側を 0 で埋めながら、ビットを右へずらします。`x >>> 30` は、`x` の上の桁を下の桁へ持ってきます。
- **定数の掛け算**: 64 ビットの定数を掛けると、下の桁の変化が上の桁へ広がります。掛け算のあとに XOR と右シフトを入れると、上の桁の変化が下へ戻ってきます。

## 何をしているか

### 1. 上の桁と下の桁を、掛け算で混ぜる

```java:line-numbers=57
        long x = value;

        x = (x ^ (x >>> 30)) * 0xbf58476d1ce4e5b9L;
        x = (x ^ (x >>> 27)) * 0x94d049bb133111ebL;
```

`x ^ (x >>> 30)` で、上の 30 ビットを下へ混ぜます。そのあと定数を掛けて、下の桁の変化を上の桁へ広げます。この操作を、別の定数と右シフトで 2 回繰り返します。

### 2. 最後の XOR で、上の桁を下へ戻す

```java:line-numbers=61
        x = x ^ (x >>> 31);
```

`x ^ (x >>> 31)` は、上位のビットを下位に混ぜ込みます。これで、64 ビットの値の全体が、下の桁に影響するようになります。

### 3. 64 ビットを 32 ビットに畳む

```java:line-numbers=63
        return (int)x ^ (int)(x >>> 32);
    }
```

`(int)x` は下位 32 ビット、`(int)(x >>> 32)` は上位 32 ビットです。両者を XOR すると、64 ビットの情報を 32 ビットに畳み込めます。上位と下位のどちらの変化も、結果に残ります。

## ここがすごい

- **連番の入力でも散らばる**: `0, 1, 2, ...` のような連続した値は、普通の掛け算だけでは下の桁が偏りやすいです。XOR と右シフトを挟むことで、その偏りを崩します。
- **特別な関数を使わない**: 掛け算と XOR と右シフトだけで書かれているので、単純な命令の組み合わせで速く動きます。
- **同じ式を再利用する**: `hash(long, mask)` は、この値に `& mask` を掛けるだけで、表の添字を求めます。表の大きさを変えても、ハッシュの式は変わりません。
- **定数は SplitMix64 系**: `0xbf58476d1ce4e5b9` と `0x94d049bb133111eb` は、SplitMix64 という乱数の生成法で使われる混ぜ方と同じ形です。この組み合わせは、コードにはその由来が書かれていません。

## まとめ

- `hash(long)` は、64 ビットの値を、XOR と掛け算で 2 回混ぜる。
- 最後に、上位 32 ビットと下位 32 ビットを XOR して、32 ビットにまとめる。
- 連番のような入力でも、ハッシュ表の中で偏りにくい値になる。
