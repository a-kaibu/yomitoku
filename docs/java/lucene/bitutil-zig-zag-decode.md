## ひとことで

`BitUtil.zigZagDecode(i)` は、ZigZag 方式で符号化された整数を、元の正負の数に戻します。たとえば `1` は `-1`、`2` は `1`、`3` は `-2` に戻ります。

ZigZag の目的は、`-1` のような小さな負の数を、ビットの少ない小さな正の数に変えることです。その結果、可変長の整数形式で、小さな負の数も短いバイト列で保存できるようになります。この関数は、その逆の変換を行います。

## コード

```java:line-numbers=296
  public static int zigZagDecode(int i) {
    return ((i >>> 1) ^ -(i & 1));
  }
```

## 前提知識

- **ZigZag 符号化**: 正の数を偶数に、負の数を奇数に割り当てる方式です。`0 → 0`、`-1 → 1`、`1 → 2`、`-2 → 3` と並びます。
- **2 の補数**: 負の数を表すビットの仕組みです。`-x` は `x` のビットを反転させて 1 を足した値です。
- **`>>>`（符号なし右シフト）**: 1 ビット右へずらし、左端には必ず 0 を入れます。符号を気にせず、ビットを 1 つ下へ移します。
- **`^`（XOR）**: 同じ桁が違うときに 1 になります。反転したいビットを切り替えるのに使います。
- **`-(i & 1)`**: `i & 1` は最下位ビットです。それを符号にすると、奇数なら `-1`（全ビット 1）、偶数なら `0` になります。

## 何をしているか

### 1. 最下位ビットから符号を作る

```java:line-numbers=297
    return ((i >>> 1) ^ -(i & 1));
```

`i & 1` で最下位ビットを取り出します。ZigZag では、この 1 ビットが「負の数だったかどうか」を表しています。`-(i & 1)` は、奇数なら `-1`（すべてのビットが 1）、偶数なら `0` になります。

### 2. 残りのビットを 1 つ右へずらす

同じ式の `i >>> 1` で、最下位ビット（符号の情報）を取り除き、残りのビットを 1 つ下へ移します。これで、元の大きさを表す部分が取り出せます。

### 3. XOR で負の数にする

`(i >>> 1) ^ -(i & 1)` で、奇数のときだけ、大きさの部分を全ビット反転させます。全ビットの反転は、2 の補数では「マイナスにして 1 を引く」と同じ意味を持ちます。そのため、奇数の入力は負の数に戻ります。

- `i = 1`（奇数）: `0 ^ -1 = -1`。
- `i = 2`（偶数）: `1 ^ 0 = 1`。
- `i = 3`（奇数）: `1 ^ -1 = -2`。

## ここがすごい

- **分岐がない**: 「偶数なら正、奇数なら負」という判定を `if` で書かずに、`-(i & 1)` と XOR で表しています。CPU の分岐予測に影響されず、速く動きます。
- **符号化と対になっている**: `zigZagEncode` は `(i >> 31) ^ (i << 1)` で、この関数は逆向きの処理です。どちらも 1 行で、往復しても元の値に戻ります。
- **小さな負の数が短くなる**: `-1` を `1` に変えるので、可変長整数（VarInt）で保存したとき、1 バイトで済みます。Lucene はこの仕組みで、インデックスのデータを小さく保っています。
- **long 版もある**: 同じ式を `long` に書いたものが、続けて定義されています。型に合わせて同じ考え方を使えます。

## まとめ

- ZigZag の復号は、最下位ビットで符号を決め、残りを右へずらして XOR で反転させる。
- 分岐なしで、正の数と負の数を正しく戻せる。
- 符号化と対になっていて、小さな負の数を短く保存する仕組みを支える。
