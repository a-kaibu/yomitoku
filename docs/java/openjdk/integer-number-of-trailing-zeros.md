## ひとことで

`Integer.numberOfTrailingZeros(i)` は、整数を 2 進数で書いたとき **右端（下位）から `0` が何個続くか** を返します。`8` は `1000` なので `3`、`12` は `1100` なので `2`、奇数なら `0` です。これは「`i` が 2 で何回割り切れるか」と同じ意味です。

この関数の見どころは 最初の `~i & (i - 1)` です。この式は **末尾に続く 0 の部分だけを 1 にし、ほかを全部 0 にした値** を作ります。

## コード

::: code-group

```java:line-numbers=1619 [日本語訳]
    @IntrinsicCandidate
    public static int numberOfTrailingZeros(int i) {
        // HD: 末尾の 0 を数える
        i = ~i & (i - 1);
        if (i <= 0) return i & 32;
        int n = 1;
        if (i > 1 << 16) { n += 16; i >>>= 16; }
        if (i > 1 <<  8) { n +=  8; i >>>=  8; }
        if (i > 1 <<  4) { n +=  4; i >>>=  4; }
        if (i > 1 <<  2) { n +=  2; i >>>=  2; }
        return n + (i >>> 1);
    }
```

## 前提知識

- **`~`（ビット反転）**: すべてのビットの `0` と `1` を入れ替えます。`~0b1100` は `…11110011` です。
- **`i - 1` のビットの変化**: 2 進数で 1 を引くと、**いちばん右の `1` が `0` になり、その右にあった `0` がすべて `1` になります**。`1100 - 1 = 1011` です。繰り下がりのしくみそのものです。
- **`&`（AND）**: 両方が `1` の桁だけ `1` になります。
- **`>>>=`**: `i >>>= 16` は「`i` を左に 0 を入れながら 16 ビット右へずらして代入」です。
- **`int` の符号**: 最上位ビットが `1` だと負の数です。Java の `int` は 32 ビットです。

## 何をしているか

### 1. 末尾の 0 を 1 に変える

```java:line-numbers=1622
        i = ~i & (i - 1);
```
`i = 0b0110_1000`（104）で試します。

```
i       = 0110 1000
i - 1   = 0110 0111   ← いちばん右の 1 が 0 に、その右の 0 が 1 に
~i      = 1001 0111   （上位は 1 で埋まる）
~i & (i-1) = 0000 0111
```

`i - 1` と `~i` の両方で `1` になるのは、**もともと末尾の 0 だった部分だけ** です。それより左は、`i - 1` では元のまま、`~i` では反転しているので、AND を取ると必ず 0 になります。結果、「末尾の 0 の個数ぶんだけ下位に 1 が並んだ数」（この例では `111` = 3 個）ができます。

### 2. 特別な場合

```java:line-numbers=1623
        if (i <= 0) return i & 32;
```
`i` が `0` のとき、変換後は全ビットが 1、つまり `-1` になります。答えは 32 です。`i` が奇数のとき、変換後は `0` で、答えは 0 です。どちらも `i <= 0` に当てはまり、`i & 32` でまとめて処理しています。`-1 & 32` は `32`、`0 & 32` は `0` です。**分岐を 1 つで 2 つの場合に答えている** わけです。

### 3. 1 の並びの長さを二分探索で測る

```java:line-numbers=1624
        int n = 1;
        if (i > 1 << 16) { n += 16; i >>>= 16; }
        if (i > 1 <<  8) { n +=  8; i >>>=  8; }
        if (i > 1 <<  4) { n +=  4; i >>>=  4; }
        if (i > 1 <<  2) { n +=  2; i >>>=  2; }
        return n + (i >>> 1);
```
ここからは「下位に 1 が何個並んでいるか」を測ります。`n` を `1` から始め、`i > 1 << 16`（17 個以上並んでいるか）なら 16 を足して 16 ビットずらす、を 8・4・2 と続けます。最後に残る `i` は `1`（`1` 個）か `3`（`11`、2 個）なので、`i >>> 1` を足せば 0 か 1 の補正ができます。例の `111` では、`n = 1`、`i > 4` が真で `n = 3`、`i = 0`、最後に `3 + 0 = 3` が答えになります。

## ここがすごい

- **「末尾の 0」を「数えやすい形」に変える**: 末尾の 0 の数を直接数えるのは面倒ですが、`~i & (i - 1)` で「下位から 1 が並んだ数」に変えれば、あとは値の大きさを比べるだけで長さがわかります。問題を解きやすい形に変換する、という発想の好例です。
- **境界ケースを 1 行で**: 0 と奇数という 2 種類の特別な入力を、変換後の値がちょうど `-1` と `0` になることを利用して `i & 32` の 1 式で返しています。
- **定番のビットトリック**: `i & (i - 1)`（いちばん右の 1 を消す）、`i & -i`（いちばん右の 1 だけ残す）と並ぶ、Hacker's Delight に載っている基本パターンです。覚えておくとほかの場面でも使えます。
- **専用命令の予備実装**: `@IntrinsicCandidate` により、多くの CPU では `TZCNT` などの 1 命令に置き換わります。

## まとめ

- `i - 1` は「いちばん右の 1 から右」を反転させる。これを `~i` と組み合わせると末尾の 0 を取り出せる。
- 数えにくいものは、数えやすい形に変換してから数える。
- 特別な入力が特定の値に変換されることを利用すると、分岐をまとめられる。
