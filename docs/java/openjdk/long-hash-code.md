## ひとことで

Java の `hashCode()` は `int`（32 ビット）を返す決まりです。ところが `long` は 64 ビットあります。`Long.hashCode(value)` は、**64 ビットを真ん中で 2 つに折り、上半分と下半分を XOR で重ねて** 32 ビットにします。

たとえば `0x00000001_00000002` なら、`0x00000001 ^ 0x00000002` = `3` がハッシュ値です。

## コード

```java:line-numbers=1232
    public static int hashCode(long value) {
        return (int)(value ^ (value >>> 32));
    }
```

## 前提知識

- **ハッシュ値**: オブジェクトを表す整数です。`HashMap` などは、この値でデータを入れる場所を決めます。**等しい値は必ず同じハッシュ値** になり、違う値はなるべく違うハッシュ値になるのが理想です。
- **`long` と `int`**: `long` は 64 ビット、`int` は 32 ビットの整数です。
- **`(int)` キャスト**: `long` を `int` に変換すると、**下位 32 ビットだけが残り**、上位は捨てられます。
- **`>>>`**: 左に 0 を入れて右へずらす演算です。`value >>> 32` で、上位 32 ビットが下位に降りてきます。
- **`^`（XOR）**: 桁ごとに「違えば 1、同じなら 0」です。

## 何をしているか

### 上半分を下半分に重ねる

```java:line-numbers=1233
        return (int)(value ^ (value >>> 32));
```

`value = 0x12345678_9ABCDEF0` で追います。

1. `value >>> 32` = `0x00000000_12345678`（上半分が下に来る）
2. `value ^ (value >>> 32)` = `0x12345678_88888888`（下位 32 ビットは `0x9ABCDEF0 ^ 0x12345678` = `0x88888888`）
3. `(int)` で下位 32 ビットを取り出し、`0x88888888` がハッシュ値です。

結果の下位 32 ビットは「上半分 XOR 下半分」になっています。

## ここがすごい

- **両方の半分が効く**: もし `(int) value` だけにすると、上位 32 ビットが捨てられ、`1L << 32` や `2L << 32` など「上半分だけが違う数」はすべて同じハッシュ値 0 になります。XOR で重ねれば、上半分でも下半分でも、1 ビット変われば結果も 1 ビット変わります。
- **安く、偏りが少ない**: XOR は足し算と違って繰り上がりがないので、ビットの情報が均等に混ざります。演算もシフト 1 回と XOR 1 回だけです。
- **仕様として決まっている**: この計算方法は `Long.hashCode` の仕様（Javadoc）に明記されています。そのため、どの JVM でも同じハッシュ値になり、プログラムの動きが予測しやすくなります。`Double.hashCode` も、`double` のビット列を `long` として取り出したあと、同じ折りたたみを使います。
- **弱点も知っておく**: 上半分と下半分が同じ値（`0x00000005_00000005` など）だと結果は 0 になります。完璧なハッシュではありませんが、HashMap 側でさらにビットを混ぜる（`HashMap.hash`）ので、実用上は十分です。

## まとめ

- 大きい値から小さいハッシュを作るときは、捨てるのではなく「折りたたんで」混ぜる。
- XOR は繰り上がりがなく、両方の入力のビットを公平に結果へ反映する。
- `(int)` キャストは下位 32 ビットを残す。上位の情報を失いたくなければ、先に混ぜておく。
