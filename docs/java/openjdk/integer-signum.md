## ひとことで

`Integer.signum(i)` は、`i` が正なら `1`、負なら `-1`、ゼロなら `0` を返します。

ふつうに書けば `if (i > 0) return 1; else if (i < 0) return -1; else return 0;` ですが、この実装は **`if` を 1 つも使わず**、シフトと OR の 1 行で 3 通りの答えを作っています。

## コード

::: code-group

```java:line-numbers=1950 [日本語訳]
    public static int signum(int i) {
        // HD（Hacker's Delight）の 2-7 節
        return (i >> 31) | (-i >>> 31);
    }
```

```java:line-numbers=1950 [原文]
    public static int signum(int i) {
        // HD, Section 2-7
        return (i >> 31) | (-i >>> 31);
    }
```

:::

## 前提知識

- **2 の補数**: Java の `int` は 32 ビットで、負の数は「2 の補数」という方式で表します。重要なのは **最上位ビット（31 ビット目）が `1` なら負、`0` なら 0 以上** という点です。`-1` は 32 ビットすべてが `1` です。
- **`>>`（算術右シフト）**: 右にずらしたとき、左端に **元の最上位ビットをコピー** して埋めます。なので負の数を `>> 31` すると全ビットが `1`（= `-1`）、0 以上なら `0` になります。
- **`>>>`（論理右シフト）**: 左端を常に `0` で埋めます。`>>> 31` すると、元の最上位ビットだけが最下位に来て、結果は `0` か `1` になります。
- **`|`（ビットごとの OR）**: どちらかが `1` の桁を `1` にします。
- **`-i`**: 符号を反転した値です。

## 何をしているか

### 式を 2 つの部品に分ける

```java:line-numbers=1952
        return (i >> 31) | (-i >>> 31);
```

式は 2 つの部品からできています。

- **`i >> 31`**: `i` が負なら `-1`（全ビット 1）、それ以外は `0`。
- **`-i >>> 31`**: `-i` が負、つまり `i` が正なら `1`、それ以外は `0`。

### 具体的な値で追う

| `i` | `i >> 31` | `-i` | `-i >>> 31` | OR の結果 |
| --- | --- | --- | --- | --- |
| `5` | `0` | `-5` | `1` | `1` |
| `-5` | `-1` | `5` | `0` | `-1` |
| `0` | `0` | `0` | `0` | `0` |

正のときは右側の部品だけが `1` になり、負のときは左側の部品が `-1`（全ビット 1）になります。`-1` は全部 1 なので、何と OR しても `-1` のままです。ゼロのときはどちらも `0` です。

### 最小値の場合

`int` の最小値 `-2147483648` は、`-i` をしても桁あふれで同じ値（負）に戻ります。このとき右側の部品も `1` になりますが、左側が `-1` なので OR の結果は `-1` で、正しく「負」と判定されます。全ビット 1 の値が他方を吸収する性質のおかげで、この特別なケースでも壊れません。

## ここがすごい

- **分岐がない**: `if` を使うと、CPU は条件の結果を予測して先に処理を進めます。予測が外れると処理をやり直すので遅くなります。この実装は分岐がないため、正負がランダムに混ざるデータでも速度が安定します。
- **2 種類のシフトの使い分け**: Java には `>>` と `>>>` の 2 つの右シフトがあります。この 1 行は「符号を全体に広げる」`>>` と「符号を 1 ビットとして取り出す」`>>>` の違いを、そのまま答えの `-1` と `1` に対応させています。2 つの演算子の違いを学ぶ教材としても優秀です。
- **境界値まで正しい**: 最小値で `-i` があふれても、OR の性質で結果が崩れません。

なお現代の JIT コンパイラ（実行中に機械語へ変換するしくみ）は、素直な `if` 版も分岐なしの命令に変換することがあります。それでも、分岐をビット演算で置き換える考え方は、ほかの言語や場面でも使える重要なテクニックです。

## まとめ

- `x >> 31` は「負なら -1、そうでなければ 0」、`x >>> 31` は「負なら 1、そうでなければ 0」。
- 全ビット 1 の値は OR で他方を吸収するので、場合分けを合成するのに使える。
- 分岐をビット演算に置き換えると、入力によらず一定の速さで動くコードになる。
