## ひとことで

UTF-8 は、1 文字を 1 バイトから 4 バイトで表す文字コードです。`é`（U+00E9）は、2 バイトの `C3 A9` で表されます。

`String` は、UTF-8 のバイト列を読んで文字（`char`）に直すとき、2 バイト文字を `decode2` で処理します。この関数は、2 つのバイトから、その文字の番号を 1 つの式で求めます。

## コード

```java:line-numbers=1207
    private static char decode2(int b1, int b2) {
        return (char)(((b1 << 6) ^ b2) ^
                (((byte) 0xC0 << 6) ^
                        ((byte) 0x80 << 0)));
    }
```

## 前提知識

- **UTF-8 の 2 バイト文字**: 1 バイト目は `110xxxxx`、2 バイト目は `10xxxxxx` の形です。`x` の部分に、文字の番号のビットが入ります。
- **`byte` の符号拡張**: Java の `byte` は符号付きです。`0xC3` は `-61` になり、`int` に変換すると上の桁も 1 で埋められます（`0xFFFFFFC3`）。
- **XOR（`^`）**: 同じビットなら 0、違えば 1 です。同じ値を 2 回 XOR すると、元に戻ります。
- **`<< 6`**: 6 ビット左へずらすと 64 倍になります。2 バイト目の下位 6 ビットを、1 バイト目の上に空けるために使います。

## 何をしているか

### 1. 2 つのバイトを、XOR で 1 つにまとめる

```java:line-numbers=1208
        return (char)(((b1 << 6) ^ b2) ^
                (((byte) 0xC0 << 6) ^
                        ((byte) 0x80 << 0)));
```

`(b1 << 6) ^ b2` は、1 バイト目を 6 ビット左へずらし、2 バイト目と XOR で重ねます。2 バイト目の上の 2 ビット（`10` の部分）は、この後で定数と打ち消し合います。

### 2. 定数の XOR で、マーカーのビットを消す

```java:line-numbers=1208
        return (char)(((b1 << 6) ^ b2) ^
                (((byte) 0xC0 << 6) ^
                        ((byte) 0x80 << 0)));
```

`((byte) 0xC0 << 6) ^ ((byte) 0x80 << 0)` は、定数です。UTF-8 の目印のビット（`110` と `10`）を、符号拡張された 1 の並びまで含めて作っています。この定数を XOR すると、目印のビットが消え、文字の番号だけが残ります。

例として、`é`（`C3 A9`）で確かめます。`b1 = -61`、`b2 = -87` で、`(b1 << 6) ^ b2` は `0x00000F69` になります。定数は `0x00000F80` なので、XOR は `0x000000E9`、つまり `é` の番号 233 です。

## ここがすごい

- **マスクを使わない**: `& 0x1F` や `& 0x3F` のような個別のマスクを書く代わりに、定数 1 つでまとめて目印を消しています。
- **符号拡張が打ち消し合う**: `b1` と `b2` は、どちらも符号拡張されているので、定数の側も同じ符号拡張を持ちます。上の桁が正しく 0 になるのは、この対応のおかげです。
- **定数の作り方が式に見える**: `(byte) 0xC0 << 6` のように、目印の値をそのまま式で書いているので、どのビットを消しているかが読み取れます。
- **速い**: 分岐がなく、シフトと XOR だけなので、1 文字あたりの処理が軽くなります。

## まとめ

- `decode2` は、2 バイトを `(b1 << 6) ^ b2` で重ね、UTF-8 の目印を定数の XOR で消す。
- `byte` の符号拡張を、定数の側でも同じに持つので、上の桁が正しく打ち消される。
- 結果は文字の番号で、`é` は `C3 A9` から `0xE9` になる。
