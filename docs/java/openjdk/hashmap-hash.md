## ひとことで

`HashMap.hash(key)` は、キーの `hashCode()`（オブジェクトごとの整数の目印）をそのまま使わずに、**上位 16 ビットを下位 16 ビットに XOR で混ぜてから** 返す関数です。

HashMap は配列の何番目にデータを入れるかを、ハッシュ値の **下位ビットだけ** で決めます。そのため、上位ビットにしか違いがないキーばかりだと、全部が同じ場所に集まってしまいます。この 1 行は、その偏りを安く打ち消すための工夫です。

## コード

```java:line-numbers=336
    static final int hash(Object key) {
        int h;
        return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
    }
```

## 前提知識

- **`HashMap`**: キーと値のペアを保存し、キーから値をすばやく取り出せるデータ構造です。中には配列（バケット配列）があり、キーのハッシュ値から「何番目の箱に入れるか」を計算します。
- **`hashCode()`**: Java のすべてのオブジェクトが持つメソッドで、そのオブジェクトを表す `int` を返します。等しいオブジェクトは同じ値を返す決まりです。
- **`Object key`**: `Object` は Java のすべてのクラスの親です。どんな種類のキーでも受け取れることを表します。
- **`null`**: 「何も指していない」ことを表す値です。`null` に対して `hashCode()` を呼ぶとエラーになるので、先に確認しています。
- **`(h = key.hashCode()) ^ …`**: Java では代入も値を持つ式です。`h` に代入しつつ、その値を使って計算を続けています。
- **`^`（XOR）と `>>>`**: `^` は桁ごとに「違えば 1」、`>>>` は左に 0 を入れる右シフトです。`h >>> 16` で上位 16 ビットが下位に降りてきます。

## 何をしているか

### 1. null は 0 番へ

```java:line-numbers=338
        return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
```
HashMap は `null` をキーにできます。その場合はハッシュ値を `0` にして、0 番目の箱に入れます。

### 2. 上位を下位に混ぜる

```java:line-numbers=338
        return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
```
HashMap は箱の位置を `(配列の長さ - 1) & hash` で求めます。配列の長さは常に 2 のべき乗で、たとえば 16 なら `& 0b1111`、つまり **下位 4 ビットだけ** が使われます。

ここで、ハッシュ値が次の 3 つのキーを考えます。

```
0x0001_0000
0x0002_0000
0x0003_0000
```

下位 16 ビットはすべて 0 なので、長さ 16 の配列ではどれも 0 番の箱に入ってしまいます。`h ^ (h >>> 16)` を通すと、

```
0x0001_0000 → 0x0001_0001   （箱 1）
0x0002_0000 → 0x0002_0002   （箱 2）
0x0003_0000 → 0x0003_0003   （箱 3）
```

となり、別々の箱に分かれます。上位の情報が下位に「折りたたまれた」わけです。

## ここがすごい

- **コストは最小、効果は十分**: 混ぜ方としてはもっと強力なハッシュ関数もあります。でも HashMap は `get` や `put` のたびにこれを呼ぶので、重い処理は置けません。シフト 1 回と XOR 1 回なら、ほとんどコストがかかりません。
- **2 のべき乗サイズと組み合わせる設計**: 配列の長さを 2 のべき乗にすると、割り算（`%`）の代わりに速い `&` で位置が決まります。その代わり下位ビットしか使われない弱点があり、この関数がそれを補っています。設計上のトレードオフを 1 行で埋めているのです。
- **衝突しても木で守る**: Java 8 以降の HashMap は、1 つの箱に要素が増えすぎると、つながったリストを赤黒木（バランスの取れた二分探索木）に切り替えます。だからハッシュ関数をそこまで凝る必要がなく、「安い混ぜ方 + 木で保険」という組み合わせになっています。
- **`h` への代入を式の中で**: `hashCode()` を 2 回呼ばないように、代入を式の中に埋め込んでいます。短く、無駄のない書き方です。

## まとめ

- ハッシュ表のサイズが 2 のべき乗だと、位置は下位ビットだけで決まる。
- `h ^ (h >>> 16)` で上位ビットを下位に混ぜると、偏ったハッシュ値でも散らばる。
- よく呼ばれる処理では、効果とコストのバランスで「ちょうどよい」強さを選ぶ。
