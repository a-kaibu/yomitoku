## ひとことで

`Integer.bitCount(i)` は、32 ビットの整数 `i` を 2 進数で書いたときに **`1` が何個あるか** を返します。たとえば `bitCount(13)` は、`13` が 2 進数で `1101` なので `3` です。

ループで 32 回調べるのではなく、6 行の式だけで答えを出します。特に最初の式は、多くの解説で見る「足し算」版ではなく **引き算 1 回** で済ませている点がおもしろいところです。

## コード

::: code-group

```java:line-numbers=1642 [日本語訳]
    @IntrinsicCandidate
    public static int bitCount(int i) {
        // HD（Hacker's Delight）の図 5-2
        i = i - ((i >>> 1) & 0x55555555);
        i = (i & 0x33333333) + ((i >>> 2) & 0x33333333);
        i = (i + (i >>> 4)) & 0x0f0f0f0f;
        i = i + (i >>> 8);
        i = i + (i >>> 16);
        return i & 0x3f;
    }
```


## 前提知識

- **`int`**: Java の `int` は 32 ビットの符号付き整数です。値は「`0` と `1` が 32 個並んだもの」として扱えます。
- **`static` メソッド**: `public static int bitCount(int i)` は「クラス `Integer` に属する関数」です。オブジェクトを作らずに `Integer.bitCount(13)` のように呼べます。
- **`>>>`（符号なし右シフト）**: ビット列を右にずらし、左端には必ず `0` を入れます。Java には符号を保つ `>>` もあり、こちらは左端に元の最上位ビット（符号）をコピーします。ビットを「ただの並び」として扱いたいときは `>>>` を使います。
- **`&`（ビットごとの AND）**: 両方が `1` の桁だけ `1` にします。マスクと呼ばれる値と組み合わせて、必要な桁だけを取り出します。
- **16 進数のマスク**: `0x55555555` は 2 進数で `0101…0101`、`0x33333333` は `0011…0011`、`0x0f0f0f0f` は `00001111…` です。
- **`@IntrinsicCandidate`**: JVM（Java を動かす仮想マシン）が、この呼び出しを CPU の専用命令（x86 の `POPCNT` など）に置き換えてよい、という印です。このコードは専用命令が使えないときの実装でもあります。
- **HD**: コメントの `HD` は書籍『Hacker's Delight（ハッカーのたのしみ）』のことで、Figure 5-2 はその図番号です。

## 何をしているか

考え方は「となり同士の個数を足し合わせる」を 2 ビット → 4 ビット → 8 ビット … と広げていくことです。8 ビットの例 `i = 1101 1011`（1 が 6 個）で追ってみます。

### 1. 2 ビットずつ数える

```java:line-numbers=1645
        i = i - ((i >>> 1) & 0x55555555);
```
2 ビットの箱 `ab` に入っている 1 の個数は `a + b` です。一方、箱の値そのものは `2a + b` です。なので **箱の値から `a` を 1 回引けば `a + b` になります**。

`(i >>> 1) & 0x55555555` は、各箱の左側のビット `a` を右側の位置に持ってきたものです。これを `i` から引きます。

```
i              = 11 01 10 11   （箱の値 3, 1, 2, 3）
(i>>>1)&0x55.. = 01 00 01 01   （各箱の a = 1, 0, 1, 1）
引き算          = 10 01 01 10   （2, 1, 1, 2 = 各箱の 1 の個数）
```

箱ごとの引き算は、どの箱でも結果が 0 以上になるので、となりの箱から借りてくること（繰り下がり）が起きません。だから 32 ビットまとめて 1 回の引き算で、16 個の箱を同時に計算できます。

### 2. 4 ビットずつにまとめる

```java:line-numbers=1646
        i = (i & 0x33333333) + ((i >>> 2) & 0x33333333);
```
`0x33333333` で 2 ビットの箱のうち右側を、`>>> 2` してから同じマスクで左側を取り出して足します。`10 01 | 01 10` は `0011 | 0011`（3 と 3）になります。

### 3. 8 ビットずつにまとめる

```java:line-numbers=1647
        i = (i + (i >>> 4)) & 0x0f0f0f0f;
```
`(i + (i >>> 4)) & 0x0f0f0f0f` で 4 ビットの箱どうしを足します。4 ビットの箱の値は最大 4 で、足しても最大 8 です。8 は 4 ビットに収まるので、**先に足してから 1 回だけマスクすれば十分** です。この例ではここで `6` が出ます。

### 4. 残りは足すだけ

```java:line-numbers=1648
        i = i + (i >>> 8);
        i = i + (i >>> 16);
        return i & 0x3f;
```
32 ビットは 4 バイトなので、各バイトの個数を `i + (i >>> 8)`、`i + (i >>> 16)` で下位バイトに集めます。上位にはゴミが残りますが、答えは最大 32 で 6 ビットに収まるので、最後に `& 0x3f`（下位 6 ビット）で取り出して完成です。

## ここがすごい

- **1 段目の引き算**: 素直に書くと `(i & 0x55555555) + ((i >>> 1) & 0x55555555)` で、AND が 2 回と足し算が 1 回です。引き算版は AND 1 回と引き算 1 回で済み、演算が 1 つ減ります。「箱の値 `2a+b` から `a` を引けば `a+b`」という小さな算数の観察から生まれた技です。
- **あふれない範囲を見積もってマスクを省く**: 3 段目以降は、値の最大値を見積もったうえで AND を減らしています。4 段目・5 段目はマスクを 1 つも使いません。
- **分岐もループもない**: どんな入力でも同じ数の命令で終わります。条件分岐がないので、CPU が分岐を予測しそこねて遅くなることもありません。
- **専用命令との二段構え**: `@IntrinsicCandidate` によって、対応 CPU では 1 命令に置き換わります。Java のコードは「どの環境でも正しく、そこそこ速い」予備の実装として、Hacker's Delight の定番アルゴリズムをそのまま採用しています。

## まとめ

- 2 ビットの箱 `ab` の 1 の数は「箱の値 − 上位ビット」で求まる。
- 1 つの整数を小さな箱の集まりとみなすと、たくさんの計算を一度にできる（SWAR と呼ばれる手法）。
- 値の上限を見積もれば、マスクなどの処理を安全に省ける。
- Java でビットを「並び」として扱うときは `>>` ではなく `>>>` を使う。
