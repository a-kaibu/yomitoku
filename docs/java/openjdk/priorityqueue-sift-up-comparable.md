## ひとことで

`PriorityQueue`（優先度付きキュー）は、いつでも **いちばん小さい要素** をすぐに取り出せるデータ構造です。内部では「二分ヒープ」という木を配列で表しています。

`siftUpComparable(k, x, es)` は、新しい要素 `x` を位置 `k`（配列の末尾）に入れたとき、親より小さければ上へ移動させていく関数です。この実装は **要素を入れ替えず**、親を下にずらしながら「穴」を上へ動かし、最後に 1 回だけ書き込みます。

## コード

```java:line-numbers=668
    private static <T> void siftUpComparable(int k, T x, Object[] es) {
        Comparable<? super T> key = (Comparable<? super T>) x;
        while (k > 0) {
            int parent = (k - 1) >>> 1;
            Object e = es[parent];
            if (key.compareTo((T) e) >= 0)
                break;
            es[k] = e;
            k = parent;
        }
        es[k] = key;
    }
```

## 前提知識

- **二分ヒープ**: 各ノードが、自分の子より小さい（または等しい）という規則を持つ木です。根（いちばん上）が最小値になります。
- **配列で木を表す**: 位置 `k` の子は `2k + 1` と `2k + 2`、親は `(k - 1) / 2` です。ポインタを使わず、番号の計算だけで木をたどれます。
- **`<T>`**: ジェネリクスで、要素の型を表します。
- **`Comparable`**: 「大小を比べられる」ことを表すインタフェースです。`a.compareTo(b)` は、`a < b` なら負、等しければ 0、`a > b` なら正を返します。
- **`(Comparable<? super T>) x`**: `x` を「比較できるもの」として扱うための型変換（キャスト）です。
- **`>>> 1`**: 右に 1 ビットずらす、つまり 2 で割ることです。

## 何をしているか

ヒープ `[1, 3, 2, 7, 4]` に `0` を追加します。末尾の位置 `k = 5` に入れる想定です。

```
       1
     /   \
    3     2
   / \   /
  7   4 (0を入れる場所)
```

### 1. 親と比べる（670〜674 行目）

- `k = 5` の親は `(5 - 1) >>> 1 = 2`、値は `2`。`0 < 2` なので上へ。
- 親の `2` を位置 5 に下ろします（675 行目）。`k = 2` になります。
- `k = 2` の親は `0`、値は `1`。`0 < 1` なので上へ。`1` を位置 2 に下ろし、`k = 0`。
- `k = 0` は根なので、ループを抜けます。

### 2. 最後に 1 回だけ書く（678 行目）

空いた位置 0 に `0` を書き込みます。

```
       0
     /   \
    3     1
   / \   /
  7   4 2
```

## ここがすごい

- **入れ替えではなく穴の移動**: 素直に書くと「親と子を入れ替える」を繰り返すので、1 段ごとに 2 回の書き込みが必要です。この実装は、親を 1 回下ろすだけで、新しい要素は最後に 1 回書くだけです。書き込みがほぼ半分になります。挿入ソートで要素をずらしていくのと同じ発想です。
- **計算が少ない木**: 親の位置は `(k - 1) >>> 1` という 1 回の引き算とシフトで求まります。ポインタをたどる木よりもメモリが連続していて、CPU のキャッシュにも乗りやすい構造です。
- **等しいときは止まる**: `compareTo(...) >= 0` で止まるので、同じ値の要素はそれ以上上へ移動しません。無駄な移動を省いています。
- **`Comparable` 版と `Comparator` 版を分けている**: 同じクラスには、比較用のオブジェクトを使う `siftUpUsingComparator` もあります。ループの中で毎回「どちらで比べるか」を判定しないよう、関数ごと分けています。

## まとめ

- 二分ヒープは配列で表せて、親は `(k - 1) / 2`、子は `2k + 1` と `2k + 2` で求まる。
- 要素を上へ移動させるときは、入れ替えより「穴を動かして最後に書く」方が書き込みが少ない。
- 比較の方法ごとに関数を分けると、ループの中の判定を減らせる。
