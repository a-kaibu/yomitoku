## ひとことで

`Integer.rotateLeft(i, distance)` は、`int` の 32 ビットを左に `distance` ビット回転させます。左へ押し出されたビットは、捨てられずに右の端から戻ってきます。ハッシュ関数や暗号、乱数生成など、ビットを失わずに混ぜたいときによく使われます。

たとえば、`0x80000001`（最上位と最下位だけが 1）を 1 ビット左に回すと、`0x00000003` になります。最上位の 1 が右端に戻り、残りは左へ一つずれるからです。

## コード

```java:line-numbers=1673
    public static int rotateLeft(int i, int distance) {
        return (i << distance) | (i >>> -distance);
    }
```

## 前提知識

- **ビットシフト `<<`**: すべてのビットを左へずらします。左端から出たビットは消え、右端には 0 が入ります。
- **符号なし右シフト `>>>`**: すべてのビットを右へずらし、左端には必ず 0 を入れます。`>>` と違い、符号ビットを複製しません。
- **`|`（OR）**: 2 つの値の同じ位置のビットのどちらかが 1 なら 1 にします。ずれた 2 つの結果を重ねるときに使います。
- **`int` は 32 ビット**: Java の `int` は常に 32 ビットです。回転の計算はこの幅を前提にしています。
- **負の数の表現**: `-d` は、`d` のビットを反転して 1 を足した値です。2 の補数表現と呼ばれます。

## 何をしているか

### 1. 左へずらす

```java:line-numbers=1674
        return (i << distance) | (i >>> -distance);
```

まず `i << distance` で、全体を左へ `distance` ビットずらします。左から押し出されたビットは消えます。ここまでだと、消えた分の情報が失われてしまいます。

### 2. 押し出されたビットを右から戻す

同じ式の後半 `i >>> -distance` が、消えた分を補います。`-distance` を使って符号なしに右へずらすと、ちょうど `32 - distance` ビットだけ右へずれます。これは、左へ `distance` ビットずらした分の残りです。Java では、シフト量は下位 5 ビットだけが使われるため、`-distance` は自動的に `32 - distance` として働きます。

### 3. 2 つを OR で合わせる

`|` で 2 つの結果を重ねます。左へずらした部分と、戻ってきたビットは互いに重ならないので、OR で足し算と同じ結果になります。

### 4. 距離が 0 のとき

`distance` が 0 のとき、`i << 0` は `i` そのもので、`i >>> -0` も `i >>> 0` で `i` です。結果は `i | i` となり、`i` のままです。特別な分岐を書かなくても正しく動きます。

## ここがすごい

- **分岐なしで回転できる**: 「押し出されたビットを右へ戻す」という条件分岐を書かず、シフト 2 回と OR だけで表しています。CPU の命令数も少なくて済みます。
- **負の値を使ってシフト量を逆にする**: `-distance` を使うことで、「32 から引く」という計算を省いています。シフト量の下位 5 ビットだけを見るという Java の仕様を生かした書き方です。
- **例外を出さない**: 距離が 32 を超えても、下位 5 ビットで扱われるので、範囲外の値でも安全に回ります。
- **ハッシュの混ぜ方の定番**: 回転は、値のビットを偏りなく動かす基本的な操作です。`Long.rotateLeft` など、他の型でも同じ形で書かれています。

## まとめ

- 左回転は、左シフトと符号なし右シフトの OR で書ける。
- `-distance` は、32 から引いた右シフト量として働く。
- 距離が 0 でも、分岐なしで元の値をそのまま返す。
