## ひとことで

`Integer.numberOfLeadingZeros(i)` は、32 ビットの整数を 2 進数で書いたとき、**左端（上位）から `0` が何個続くか** を返します。

たとえば `i = 1` は `0000…0001` なので `31`、`i = 255` は上位 24 ビットが 0 なので `24` です。この値は「この数は何ビットあれば表せるか」（`32 - 結果`）を求めるのによく使われます。1 ビットずつ数えるのではなく、**探す範囲を半分ずつに絞る二分探索** で、最大 4 回の比較で答えを出します。

## コード

```java:line-numbers=1592
    @IntrinsicCandidate
    public static int numberOfLeadingZeros(int i) {
        // HD, Count leading 0's
        if (i <= 0)
            return i == 0 ? 32 : 0;
        int n = 31;
        if (i >= 1 << 16) { n -= 16; i >>>= 16; }
        if (i >= 1 <<  8) { n -=  8; i >>>=  8; }
        if (i >= 1 <<  4) { n -=  4; i >>>=  4; }
        if (i >= 1 <<  2) { n -=  2; i >>>=  2; }
        return n - (i >>> 1);
    }
```

## 前提知識

- **`int` と符号**: Java の `int` は 32 ビットの符号付き整数です。最上位ビット（いちばん左）が `1` だと負の数になります。
- **`1 << 16`**: `1` を左に 16 ビットずらした値、つまり 2 の 16 乗（65536）です。
- **`>>>=`**: `i >>>= 16` は `i = i >>> 16` の省略形です。`>>>` は左端に `0` を入れる右シフトです。
- **`条件 ? A : B`**: 三項演算子です。条件が真なら `A`、偽なら `B` になります。
- **`{ n -= 16; i >>>= 16; }`**: `if` の本体を 1 行に書いたものです。`n -= 16` は `n = n - 16` です。
- **`@IntrinsicCandidate`**: JVM がこの関数を CPU の専用命令（x86 の `LZCNT` など）に置き換えてよい、という印です。
- **HD**: 書籍『Hacker's Delight』のことです。

## 何をしているか

### 1. 0 以下を先に片づける（1595〜1596 行目）

`i == 0` なら全部 0 なので `32` です。`i < 0` なら最上位ビットが `1` なので、先頭の 0 は `0` 個です。これで以降は「正の数」だけを考えればよくなります。

### 2. 半分ずつ絞り込む（1597〜1601 行目）

`n` は「先頭の 0 の数の候補」で、最初は `31`（1 のビットが最下位にしかない場合）にしておきます。

`i = 0x0000_1234`（2 進数で `0001 0010 0011 0100`、最上位の 1 は 12 ビット目）で追ってみます。

- `i >= 1 << 16`（65536 以上か）? → `0x1234` = 4660 なので **いいえ**。上位 16 ビットは全部 0 だとわかりました。
- `i >= 1 << 8`（256 以上か）? → **はい**。最上位の 1 は 8 ビット目より上にあるので、`n` を 8 減らして `23`、`i` を 8 ビット右にずらして `0x12` にします。
- `i >= 1 << 4`（16 以上か）? → `0x12` = 18 なので **はい**。`n = 19`、`i = 0x1`。
- `i >= 1 << 2`（4 以上か）? → **いいえ**。

各ステップで「上半分に 1 があるか」を確かめ、あれば上半分に移動しています。数当てゲームで「50 より大きい？」と聞いて範囲を半分にするのと同じです。

### 3. 最後の 2 ビットを引き算で（1602 行目）

ここで `i` は `1`〜`3` のどれかです。`i` が `2` か `3`（2 ビット目に 1 がある）ならもう 1 つ減らす必要があり、`1` なら不要です。これを `if` を使わず `n - (i >>> 1)` で書いています。`i >>> 1` は `1 → 0`、`2 → 1`、`3 → 1` になるからです。例では `19 - 0 = 19` が答えです。`0x1234` は 13 ビットの数なので、`32 - 13 = 19` と一致します。

## ここがすごい

- **比較が最大 4 回**: 1 ビットずつ上から調べると最悪 31 回のループですが、二分探索なら 16 → 8 → 4 → 2 の 4 回 + 最後の 1 演算で終わります。
- **最後の段は分岐なし**: 「1 ビットずらした値をそのまま引く」ことで、最後の `if` を消しています。値の範囲が 1〜3 に絞れていることを利用した小技です。
- **負の数を最初に切り分ける**: 符号付き整数で `>=` の比較を使うので、負の数が混ざると比較の意味が崩れます。最初に `i <= 0` を処理することで、後ろのコードを単純に保っています。
- **専用命令の予備**: 対応する CPU では JVM が 1 命令に置き換えます。この Java コードは、そうでない環境でも速く動く移植性のある実装です。

## まとめ

- 「上半分に 1 があるか」を繰り返し聞く二分探索で、ビット位置を高速に見つけられる。
- 値の範囲が小さく絞れたら、`if` の代わりに算術で答えを作れる。
- 符号付き整数でビット操作をするときは、負の数とゼロを最初に分けると後が楽になる。
