## ひとことで

`Integer.reverse(i)` は、32 ビットの並びを **鏡に映したように左右反転** します。最下位ビットが最上位に、最上位ビットが最下位に移ります。たとえば `1`（`000…0001`）は `MIN_VALUE`（`1000…000`）になります。

1 ビットずつ取り出して並べ直すと 32 回のループですが、この実装は **「となり同士の入れ替え」を幅を倍々にして 3 回** 行い、最後に「バイトの並びを逆にする」関数に任せて完成させます。

## コード

::: code-group

```java:line-numbers=1711 [日本語訳]
    @IntrinsicCandidate
    public static int reverse(int i) {
        // HD（Hacker's Delight）の図 7-1
        i = (i & 0x55555555) << 1 | (i >>> 1) & 0x55555555;
        i = (i & 0x33333333) << 2 | (i >>> 2) & 0x33333333;
        i = (i & 0x0f0f0f0f) << 4 | (i >>> 4) & 0x0f0f0f0f;

        return reverseBytes(i);
    }
```


## 前提知識

- **マスク**: `0x55555555` は `0101…`、`0x33333333` は `0011…`、`0x0f0f0f0f` は `00001111…` です。`&` を取ると、決まった位置のビットだけが残ります。
- **`<<` と `>>>`**: ビットを左・右へずらします。`>>>` は左端に `0` を入れます。
- **`|`（OR）**: 2 つの値のビットを重ね合わせます。重ならない位置にあるビットを 1 つの値にまとめるのに使えます。
- **演算子の優先順位**: Java では `<<` や `>>>` が `&` より先に、`&` が `|` より先に計算されます。最初の入れ替えの式は `((i & 0x55555555) << 1) | ((i >>> 1) & 0x55555555)` と読みます。
- **`reverseBytes(i)`**: 同じクラスの関数で、32 ビットを 4 つのバイト（8 ビット）に分け、その順番を逆にします（`AABBCCDD` → `DDCCBBAA`）。

## 何をしているか

8 ビット `abcdefgh`（各文字が 1 ビット）で考えます。目標は `hgfedcba` です。

### 1. となりの 1 ビット同士を入れ替え

```java:line-numbers=1714
        i = (i & 0x55555555) << 1 | (i >>> 1) & 0x55555555;
```
`(i & 0x55…) << 1` は各ペアの右側を左へ、`(i >>> 1) & 0x55…` は左側を右へ動かします。OR で合わせると、

```
ab cd ef gh  →  ba dc fe hg
```

### 2. 2 ビットの組同士を入れ替え

```java:line-numbers=1715
        i = (i & 0x33333333) << 2 | (i >>> 2) & 0x33333333;
```
同じことを `0x33…` と 2 ビットのシフトで行います。

```
badc fehg  →  dcba hgfe
```

### 3. 4 ビットの組同士を入れ替え

```java:line-numbers=1716
        i = (i & 0x0f0f0f0f) << 4 | (i >>> 4) & 0x0f0f0f0f;
```
`0x0f…` と 4 ビットのシフトで、

```
dcbahgfe  →  hgfedcba
```

これで **各バイトの中** は反転できました。

### 4. バイトの順番を逆に

```java:line-numbers=1718
        return reverseBytes(i);
```
32 ビットにはバイトが 4 つあります。各バイトの中身は反転済みなので、あとはバイトの並びを逆にすれば全体の反転が完成します。それを `reverseBytes` に任せています。

## ここがすごい

- **分割統治**: 「全体を反転する」は「左右の半分を入れ替えて、それぞれの半分を反転する」と同じです。これを 1 ビット・2 ビット・4 ビット…と下から積み上げると、32 ビットなら 5 段で終わります。1 段ごとに 32 ビット全部を同時に処理するので、ループに比べて圧倒的に少ない命令で済みます。
- **後半の 2 段をバイト反転に任せる**: 8 ビット・16 ビット単位の入れ替えは、`reverseBytes` とまったく同じ処理です。`reverseBytes` は多くの CPU で `BSWAP` という 1 命令になる（`@IntrinsicCandidate`）ので、それを再利用するのが速くて短い書き方です。
- **マスクとシフトの対称性**: 3 行がまったく同じ形をしていて、変わるのはマスクとシフト量だけです。パターンがそろっているので、読む人が規則性に気づきやすく、検証もしやすくなっています。

## まとめ

- 反転は「小さい単位の入れ替え」を倍々に重ねることで、少ない段数で実現できる（分割統治）。
- マスク・シフト・OR の組み合わせで、ビットの集団を一度に動かせる。
- 既存の高速な部品（ここでは `reverseBytes`）を最後の仕上げに使うと、コードが短くなる。
