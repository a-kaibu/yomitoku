## ひとことで

Java の整数の割り算 `/` は、答えの小数部分を **0 に向かって** 切り捨てます。`7 / 2 = 3`、`-7 / 2 = -3` です。

ところが、カレンダーの計算や、座標をマス目に分ける計算などでは、**常に小さい方へ** 切り捨てたいことがよくあります。`-7 ÷ 2 = -3.5` なら `-4` が欲しいのです。`Math.floorDiv(x, y)` はこれを計算します。中身は、ふつうの割り算に「必要なときだけ 1 引く」補正を加えるだけです。

## コード

::: code-group

```java:line-numbers=1475 [日本語訳]
    public static int floorDiv(int x, int y) {
        final int q = x / y;
        // 符号が異なり、余りが 0 でなければ、下に丸める
        if ((x ^ y) < 0 && (q * y != x)) {
            return q - 1;
        }
        return q;
    }
```

```java:line-numbers=1475 [原文]
    public static int floorDiv(int x, int y) {
        final int q = x / y;
        // if the signs are different and modulo not zero, round down
        if ((x ^ y) < 0 && (q * y != x)) {
            return q - 1;
        }
        return q;
    }
```

:::

## 前提知識

- **`/`（整数の割り算）**: `int` 同士の割り算は整数の結果を返し、小数部分は 0 に向かって捨てられます（正なら切り下げ、負なら切り上げに見えます）。
- **`final int q`**: `final` は「この変数にはもう代入しない」という宣言です。読む人に「`q` は途中で変わらない」と伝えます。
- **`^`（XOR）と `< 0`**: `(x ^ y) < 0` は「`x` と `y` の符号ビットが違う」、つまり **符号が逆** かどうかを調べる定番の書き方です。2 つの数の最上位ビット（符号）が違えば、XOR の最上位が 1 になり、負の値になります。
- **`&&`**: 「かつ」です。左が偽なら右は評価しません。

## 何をしているか

### 1. まずふつうに割る

```java:line-numbers=1476
        final int q = x / y;
```
`q = x / y` を計算します。

### 2. 補正が必要な場合だけ 1 引く

```java:line-numbers=1478
        if ((x ^ y) < 0 && (q * y != x)) {
            return q - 1;
        }
```
0 に向かう切り捨てと、下に向かう切り捨てが **違う結果になるのは、答えが負で、しかも割り切れないとき** だけです。

- 答えが負になるのは、`x` と `y` の符号が逆のとき → `(x ^ y) < 0`
- 割り切れないのは、`q * y` が `x` に戻らないとき → `q * y != x`

### 具体例

| `x` | `y` | `x / y` | 符号が逆? | 割り切れる? | 結果 |
| --- | --- | --- | --- | --- | --- |
| `7` | `2` | `3` | いいえ | — | `3` |
| `-7` | `2` | `-3` | はい | いいえ | `-4` |
| `-8` | `2` | `-4` | はい | はい | `-4` |
| `7` | `-2` | `-3` | はい | いいえ | `-4` |
| `-7` | `-2` | `3` | いいえ | — | `3` |

`-7 / 2` は数学的には `-3.5` です。0 に向かうと `-3`、下に向かうと `-4` なので、1 引いて直しています。

## ここがすごい

- **補正の条件を最小限に絞っている**: 「符号が逆」と「割り切れない」の 2 つが同時に成り立つときだけ 1 引きます。それ以外は `/` の結果がそのまま正解なので、余計な計算をしません。
- **余りの計算を使わない**: `x % y != 0` で割り切れるかを調べる方法もありますが、割り算をもう 1 回することになります。`q * y != x` なら、すでにある `q` を使った掛け算 1 回で済みます。
- **符号比較のイディオム**: `(x ^ y) < 0` は「2 つの数の符号が逆か」を、比較 1 回で判定する定番の書き方です。`(x < 0) != (y < 0)` と同じ意味ですが、より短い命令になります。
- **対になる `floorMod`**: 同じクラスには、下向きの割り算に対応する余り `floorMod` もあります。`floorMod(-7, 2)` は `1` で、「時計の針」のように常に 0 以上の余り（`y` が正のとき）が得られます。配列を循環して使うときなどに便利です。

## まとめ

- Java の `/` は 0 に向かって切り捨てる。負の数を扱うときは結果が直感とずれることがある。
- 下向き切り捨てとの違いは「答えが負で割り切れないとき」だけなので、その場合だけ 1 引けばよい。
- `(x ^ y) < 0` は 2 つの整数の符号が逆かどうかを調べる定番の書き方。
