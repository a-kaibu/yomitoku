## ひとことで

Java のオブジェクト配列のソート（`Arrays.sort(Object[])` など）には **TimSort** というアルゴリズムが使われています。TimSort は、配列を「ラン」と呼ぶ小さなかたまりに分けて、それぞれを挿入ソートで並べ、あとでマージ（合体）していきます。

`minRunLength(n)` は、長さ `n` の配列に対して **ランの最小の長さ** を決める関数です。16〜32 の範囲で、`n` をその長さで割ったときに 2 のべき乗に近く（ただし少し下回るように）なる値を選びます。そうすると、後のマージが左右釣り合った形で進みます。

## コード

```java:line-numbers=400
    private static int minRunLength(int n) {
        assert n >= 0;
        int r = 0;      // Becomes 1 if any 1 bits are shifted off
        while (n >= MIN_MERGE) {
            r |= (n & 1);
            n >>= 1;
        }
        return n + r;
    }
```

`MIN_MERGE` は同じファイルの 80 行目で `32` と定義されています。

## 前提知識

- **ソートの安定性とマージ**: TimSort は、2 つの並んだ列を 1 つに合体させる「マージ」を繰り返します。マージは、2 つの列の長さが近いほど効率がよくなります。
- **ラン**: すでに並んでいる（昇順または降順の）連続した部分のことです。TimSort は、短すぎるランを挿入ソートで伸ばして最低限の長さにそろえます。
- **`assert`**: 「ここでは必ずこの条件が成り立つ」という確認です。テスト時にだけ有効にでき、ふだんの実行では無視されます。
- **`n & 1`**: `n` の最下位ビット、つまり奇数なら 1、偶数なら 0 です。
- **`r |= …`**: `r = r | …` です。一度でも 1 が来たら、`r` は 1 のままになります。
- **`n >>= 1`**: `n` を右に 1 ビットずらす、つまり 2 で割って切り捨てます。

## 何をしているか

### 計算の手順（402〜407 行目）

`n` が 32 未満になるまで 2 で割り続けます。その途中で **切り捨てた 1 ビットが一度でもあったら `r = 1`** にし、最後に `n + r` を返します。

言い換えると、`n` の上位 5 ビット（16〜31 の値）を取り出し、残りの下位ビットが 0 でなければ 1 を足す、という計算です。

### 具体例

- `n = 20`: 32 未満なので、そのまま `20`。小さい配列は挿入ソートだけで済ませます。
- `n = 1024`: 2 で割り続けて `16`。こぼれた 1 はないので `r = 0`、答えは `16`。`1024 / 16 = 64` 個のランになり、64 は 2 のべき乗なので、マージは完全な二分木になります。
- `n = 2112`: 2112 = `100001000000`₂。上位 5 ビットは `10000`₂ = 16、残りに 1 があるので `r = 1`、答えは `17`。`2112 / 17` ≈ 124.2 なので、ランは 125 個で、128 を少し下回ります。

### なぜ「少し下回る」がよいのか

もし長さ 16 でランを作ると、2112 / 16 = 132 個になり、128 個を少しだけ超えます。すると、128 個分をきれいにマージしたあと、**巨大な列と、とても小さな列（4 個分）のマージ** が最後に残ります。長さが極端に違うマージは無駄が多くなります。

長さを 17 にしてランを 128 個以下に収めれば、最後まで釣り合ったマージになります。

## ここがすごい

- **1 ビットの記憶で切り上げ**: 「`n / k` が 2 のべき乗以下になる最小の `k`」は、`n` の上位ビットに、こぼれたビットがあれば 1 を足すだけで求まります。割り算や対数の計算を使わず、シフトと OR だけで済んでいます。
- **マージの形まで見越した設計**: ランの長さという一見細かい値が、後のマージ全体の効率を左右します。TimSort の考案者 Tim Peters 氏が Python のために書いた解説文書（コメントで参照している `listsort.txt`）で、この選び方の理由が説明されています。
- **コメントが仕様を語る**: 直前の Javadoc に「ほぼこういう計算をする」という説明が書かれていて、コードがその実装になっています。

## まとめ

- マージソートは、マージする 2 つの列の長さが近いほど効率がよい。
- ランの数を 2 のべき乗以下に収めると、最後まで釣り合ったマージになる。
- 「上位ビットを取り出し、こぼれたビットがあれば 1 足す」で、ビット演算だけで切り上げが計算できる。
