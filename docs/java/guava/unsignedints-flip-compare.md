## ひとことで

Java の `int` は符号付きなので、`-1` は「とても大きい符号なしの数」として扱いたい場面があります。`UnsignedInts.flip(value)` は、その変換に使われる小さな関数です。やることは **最上位ビット（符号ビット）を反転させる** だけです。

この 1 つの操作で、符号なしの大小の順番が、そのまま符号付きの大小の順番に変わります。

## コード

```java:line-numbers=54
  static int flip(int value) {
    return value ^ Integer.MIN_VALUE;
  }
```

## 前提知識

- **符号付き整数と符号なし整数**: 同じ 32 ビットでも、最上位ビットを「マイナス」と読むか、「2^31 の位」と読むかで値が変わります。`0xFFFFFFFF` は符号付きなら `-1`、符号なしなら `4294967295` です。
- **`Integer.MIN_VALUE`**: `-2147483648` のことで、2 進数では `1000…0000`（最上位ビットだけが 1）です。
- **`^`（XOR）**: 桁ごとに「違えば 1、同じなら 0」です。ある桁を反転させたいとき、その桁だけが 1 の値と XOR を取ります。
- **`static int`**: クラスの中の関数で、オブジェクトを作らずに呼べます。この関数はパッケージの中だけで使われる内部用です。

## 何をしているか

### 1. 最上位ビットだけが 1 の値を作る

```java:line-numbers=55
    return value ^ Integer.MIN_VALUE;
```

`Integer.MIN_VALUE` は、まさに「最上位ビットだけが 1」の値です。これと XOR を取ると、最上位ビットだけが反転し、下位 31 ビットはそのままになります。

### 2. 具体的な値で追う

| 元の値（符号なしとして） | 元のビット | flip 後のビット | flip 後を符号付きで読むと |
| --- | --- | --- | --- |
| `0` | `0000…` | `1000…` | `-2147483648`（最小） |
| `1` | `0000…01` | `1000…01` | `-2147483647` |
| `2147483648` | `1000…` | `0000…` | `0` |
| `4294967295` | `1111…` | `0111…` | `2147483647`（最大） |

符号なしで小さい順だった並び `0, 1, …, 4294967295` が、flip 後には `-2147483648, …, 2147483647` の順になります。大小の順番が保たれているのがわかります。

### 3. 比較への使い方

`UnsignedInts.compare(a, b)` は、両方を `flip` してから `Integer.compare` に渡します。`compare(-1, 1)` は、符号なしでは `-1` の方が大きいので正の値を返すべきです。`flip(-1) = 2147483647`、`flip(1) = -2147483647` を比べると、確かに正になります。

## ここがすごい

- **1 演算で順番を入れ替える**: 符号なしの比較を一から書くと、符号が違う場合の場合分けが必要です。`flip` は最上位ビットを 1 回反転するだけで、その場合分けを不要にしています。
- **既存の比較をそのまま使う**: 新しい比較ロジックを書かず、既存の `Integer.compare` を再利用しています。少ないコードで正しさを保てます。
- **ビットの性質を利用**: 符号なしの世界と符号付きの世界で、最上位ビットの意味だけが違います。その違いを XOR 1 回で埋めるという発想が中心です。
- **注記で後継を示す**: コメントには、Java 8 以降は `Integer.compareUnsigned` を使うべきだと書かれています。古い環境向けの実装として、役割が明確に残されています。

## まとめ

- 符号なしの大小は、最上位ビットを反転すると符号付きの大小として比べられる。
- XOR で 1 ビットだけ反転するのは、ビット演算の基本的な使い方。
- 同じ問題の新しい解決策（`Integer.compareUnsigned`）があるなら、その存在もあわせて知っておく。
