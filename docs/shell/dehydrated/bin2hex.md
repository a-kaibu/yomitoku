## ひとことで

`bin2hex` は、**バイナリのデータを、16 進数の文字列に変換する** 関数です。`hex2bin` の逆の働きをします。

証明書や鍵のデータは、バイナリのままでは表示や比較が難しいです。16 進の表記にすると、目で確かめやすく、テキストとして扱えます。

## コード

```bash:line-numbers=946
bin2hex() {
  hexdump -v -e '/1 "%02x"'
}
```

## 前提知識

- **`hexdump`**: バイナリのデータを、指定した書式で表示するコマンドです。
- **`-v`**: 同じ行の繰り返しを省かず、すべてを表示する指定です。
- **`-e` の書式**: 出力の 1 単位ごとの書き方を指定します。ここでは、1 バイトを `%02x` の 2 桁の 16 進数で表します。
- **標準入力**: 関数の外からパイプで渡されたデータを、そのまま読むための入り口です。

## 何をしているか

### 1. 標準入力を読んで、1 バイトずつ整形する

```bash:line-numbers=947
  hexdump -v -e '/1 "%02x"'
```

`hexdump` は、標準入力のデータを 1 バイトずつ読みます。各バイトを、`%02x` で 2 桁の 16 進数にして出力します。

## ここがすごい

- **1 行で完結する**: 変換の書式を `-e` で指定するだけで、ループを書かずに済みます。
- **省略を防ぐ**: `-v` を付けるので、同じ値が続いても出力が省かれません。元のデータと一対一に対応します。
- **`hex2bin` と対になる**: 2 つの関数で、往復の変換ができます。データを保存と復元の両方に使えます。

## まとめ

- バイナリを確かめるときは、16 進数に直すと扱いやすい。
- 書式の指定を使うと、ループを書かずに整形できる。
- 変換と逆変換を対で用意すると、データの往復が安全になる。
