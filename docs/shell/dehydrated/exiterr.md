## ひとことで

`_exiterr` は、dehydrated が **回復できない誤り** に出会ったときに使う関数です。メッセージを標準エラーに表示し、必要ならフックのスクリプトを呼んでから、終了ステータス 1 でプログラムを止めます。

どこかで失敗したときに、そのまま処理を続けると、証明書の状態が中途半端になるおそれがあります。そこで、ここで必ず止まるようにしています。

## コード

```bash:line-numbers=909
_exiterr() {
  if [ -n "${1:-}" ]; then
    echo "ERROR: ${1}" >&2
  fi
  [[ "${skip_exit_hook:-no}" = "no" ]] && [[ -n "${HOOK:-}" ]] && ("${HOOK}" "exit_hook" "${1:-}" || echo 'exit_hook returned with non-zero exit code!' >&2)
  exit 1
}
```

## 前提知識

- **標準エラー（`>&2`）**: エラーメッセージを出す出力先です。結果の出力と分けておくと、パイプにつないでも結果だけが流れます。
- **`exit 1`**: プログラムを終了ステータス 1（失敗）で止めます。
- **フック（hook）**: 特定の出来事のときに呼ばれる、ユーザーが用意するスクリプトです。ここでは、終了の出来事を知らせるために使われます。
- **`${skip_exit_hook:-no}`**: 変数が無ければ `no` として扱います。
- **`||`**: 左が失敗したときだけ、右を実行します。

## 何をしているか

### 1. メッセージを表示する

```bash:line-numbers=910
  if [ -n "${1:-}" ]; then
    echo "ERROR: ${1}" >&2
  fi
```

引数があれば、`ERROR:` の付いたメッセージを標準エラーに出します。

### 2. フックを呼ぶ

```bash:line-numbers=913
  [[ "${skip_exit_hook:-no}" = "no" ]] && [[ -n "${HOOK:-}" ]] && ("${HOOK}" "exit_hook" "${1:-}" || echo 'exit_hook returned with non-zero exit code!' >&2)
```

`skip_exit_hook` が `no`、かつ `HOOK` が設定されていれば、フックを `exit_hook` という引数付きで呼びます。フックが失敗したら、その旨も標準エラーに出します。

### 3. 終了する

```bash:line-numbers=914
  exit 1
```

最後に `exit 1` で、失敗の終了ステータスを返して止まります。

## ここがすごい

- **止まることを保証する**: どの呼び出し元からでも、この関数を通ると必ず終了します。中途半端な状態で続くことを防ぎます。
- **後始末の機会を作る**: 終了の前にフックを呼べるので、ユーザーは通知や掃除を組み込めます。
- **メッセージと結果を分ける**: 標準エラーに出すので、結果を受け取るパイプの処理が壊れません。

## まとめ

- 回復できないエラーは、その場で必ず止まるようにする。
- エラーは標準エラーに出すと、結果と分けられる。
- 終了の前に後始末の仕組みを呼べると、運用が楽になる。
