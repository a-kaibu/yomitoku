## ひとことで

`json_path` は、JSON の中から値を探すときに使う **検索パターンの文字列** を作る関数です。`json_path "domain"` と呼ぶと `"domain"` を、`json_path -p 'a.b'` と呼ぶと `a.b` の部分をそのまま返します。

dehydrated は JSON を解析する専用の道具を使わず、`sed` で行を探して値を取り出します。そのため、探す文字列を正しく組み立てる部分がとても大切になります。この関数はその入口です。

## コード

```bash:line-numbers=51
json_path() {
  if [ ! "${1}" = "-p" ]; then
    printf '"%s"' "${1}"
  else
    printf '%s' "${2}"
  fi
}
```

## 前提知識

- **`printf '書式' 値`**: C 言語の `printf` と同じく、書式に従って文字列を出力します。`%s` は文字列を入れる場所です。
- **`"${1}"`**: 1 番目の引数を取り出します。ダブルクォートで囲むと、空白があっても 1 つの値として扱われます。
- **`[ ! "${1}" = "-p" ]`**: 1 番目の引数が `-p` **ではない** なら真です。`!` は否定の記号です。
- **JSON のキー**: JSON では `"name": "value"` のように、キーはダブルクォートで囲まれます。そのため通常のキーは `"` で囲んで検索します。

## 何をしているか

### 1. 通常のキーの場合

```bash:line-numbers=53
    printf '"%s"' "${1}"
```

`-p` で始まらない引数は、キーの名前とみなします。`"domain"` のように、前後にダブルクォートを付けて返します。JSON の中で `"domain"` というキーを探すためです。

### 2. `-p` が付いている場合

```bash:line-numbers=55
    printf '%s' "${2}"
```

`-p` のときは、2 番目の引数をそのまま返します。こちらは、ネストした JSON のパス（`a.b` など）のように、ダブルクォートを付けたくない場合に使われます。

`json_path` は、単独で使われるのではなく、`get_json_string_value` などの関数の中で使われます。そこでは `$(json_path ...)` の形で結果を埋め込み、`sed` のパターンを作ります。

## ここがすごい

- **分岐は 1 か所だけ**: 検索パターンの作り方の違いを、この関数 1 つに閉じ込めています。呼ぶ側はキーの種類を指定するだけで済みます。
- **`printf` で安全に組み立てる**: `echo` ではなく `printf` を使うことで、キーに `-` や `\` が含まれていても、意図しない解釈をされにくくしています。
- **シンプルな組み合わせ**: 小さな関数を組み合わせて、大きな処理（JSON の値の取り出し）を作る、という考え方の良い例です。

## まとめ

- 検索パターンのような文字列は、作る関数を分けると読みやすくなる。
- `printf '%s'` は、値をそのまま埋め込むのに向いている。
- 小さな関数を組み合わせると、シェルでも構造化されたデータを扱える。
