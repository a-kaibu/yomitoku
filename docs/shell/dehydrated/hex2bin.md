## ひとことで

`hex2bin` は、**16 進数で書かれた文字列を、元のバイナリのデータに戻す** 関数です。`ab 0f` のような表記を、そのままのバイト列にします。

証明書の鍵などのデータは、16 進の文字列で扱われることがあります。ファイルとして保存するときは、元のバイナリに戻す必要があります。この関数は、その変換の役目です。

## コード

::: code-group

```bash:line-numbers=939 [日本語訳]
hex2bin() {
  # 空白を除き、先頭に 0 を補って、16 進の文字列としてエスケープし、printf で読み取ります。
  # shellcheck の警告を抑える指定です。
  printf "%b" "$(cat | _sed -e 's/[[:space:]]//g' -e 's/^(.(.{2})*)$/0\1/' -e 's/(.{2})/\\x\1/g')"
}
```

```bash:line-numbers=939 [原文]
hex2bin() {
  # Remove spaces, add leading zero, escape as hex string and parse with printf
  # shellcheck disable=SC2059
  printf "%b" "$(cat | _sed -e 's/[[:space:]]//g' -e 's/^(.(.{2})*)$/0\1/' -e 's/(.{2})/\\x\1/g')"
}
```

:::

## 前提知識

- **16 進数**: 0 から 9 と a から f の 16 種類の記号で、1 バイトを 2 桁で表す書き方です。
- **`printf "%b"`**: `\x41` のようなエスケープを解釈して、バイトとして出力します。
- **`cat`**: 標準入力を、そのまま出力するコマンドです。ここでは、関数へ流し込まれた文字列を読むために使われます。
- **`_sed`**: この実装で使われる sed の包みです。環境に合わせて、正しいコマンドを使います。
- **`$(...)`**: コマンドの出力を、文字列として取り出す書き方です。

## 何をしているか

### 1. 空白を除き、桁数をそろえる

```bash:line-numbers=941
  # shellcheck の警告を抑える指定です。
```

空白を取り除き、桁数が奇数なら先頭に 0 を付けて、2 桁ずつに分けられる形にします。

### 2. 2 桁ごとに \x を付ける

```bash:line-numbers=941
  # shellcheck の警告を抑える指定です。
```

2 桁ずつの区切りに `\x` を付けて、printf が読める形のエスケープにします。

### 3. printf でバイトに変換する

```bash:line-numbers=942
  printf "%b" "$(cat | _sed -e 's/[[:space:]]//g' -e 's/^(.(.{2})*)$/0\1/' -e 's/(.{2})/\\x\1/g')"
```

`printf "%b"` で、エスケープをバイトに変換して出力します。出力が、元のバイナリのデータになります。

## ここがすごい

- **標準の道具の組み合わせ**: 専用の変換コマンドが無くても、sed と printf だけで変換できます。移植性が高いです。
- **桁数の揺れに備える**: 桁数が奇数でも、先頭に 0 を補うことで、必ず 2 桁の組になります。
- **変換の段階が見える**: 空白の除去、桁の調整、エスケープの付与、変換、と段階ごとに書かれています。読めば流れが追えます。

## まとめ

- 16 進の変換は、printf の機能を使うと外部の道具が要らない。
- 入力の揺れは、変換の前に整えておくと後の処理が単純になる。
- 段階ごとに分けて書くと、どこで壊れるかを追いやすい。
