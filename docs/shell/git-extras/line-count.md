## ひとことで

`line_count` は、**対象のファイルの全行数を数える** 関数です。1 行ごとに作者を割り当てた一覧を作り、その行数を数えます。

git-summary の概要で、コードの量を示すために使われます。どの作者が何行書いたかの集計とも、同じ材料を使います。

## コード

```bash:line-numbers=196
line_count() {
  lines "$@" | wc -l
}
```

## 前提知識

- **`lines`**: 対象のファイルの各行について、作者を一覧にする関数です。同じファイル内で定義されています。
- **`wc -l`**: 行の数を数えるコマンドです。1 行が 1 件に対応します。
- **引数の受け渡し `"$@"`**: 関数に渡された引数を、そのまま次の関数に渡す書き方です。

## 何をしているか

### 1. 作者の一覧を作る

```bash:line-numbers=197
  lines "$@" | wc -l
```

`lines` に引数をそのまま渡し、各行の作者を一覧にします。引数が無ければ、Git の全ファイルが対象です。

### 2. 行数を数える

```bash:line-numbers=197
  lines "$@" | wc -l
```

一覧の行数を `wc -l` で数えます。1 行 1 件なので、この数が全体の行数になります。

## ここがすごい

- **材料を使い回す**: 作者の集計と行数の計算が、同じ `lines` を使います。処理の重複がありません。
- **引数をそのまま流す**: 対象を絞る仕組みを、ほかの関数に任せています。
- **集計を簡潔に**: 数えるだけなので、一行の中で済みます。

## まとめ

- 同じ材料から複数の集計を作ると、処理の重複を減らせる。
- 引数は、次の関数へそのまま渡すと、対象の指定が一貫する。
- 数える処理は、一覧の行数に置き換えると簡単になる。
