## ひとことで

`namespace_file コンテキスト名` は、そのコンテキストの **名前空間を保存するファイルのパス** を返す関数です。コンテキストの名前に `/` や空白などが含まれていても、ファイル名として壊れないように、先に変換しています。

Kubernetes のコンテキスト名は、クラウドのプロバイダーやクラスタ名によって、さまざまな文字を含みます。そのまま使うとファイルの場所が狂うので、この関数が安全な名前に直します。

## コード

```bash:line-numbers=80
namespace_file() {
  local ctx

  ctx="$(escape_context_name "${1}")"
  echo "${KUBENS_DIR}/${ctx}"
}
```

## 前提知識

- **ファイルパス**: ディレクトリとファイル名を `/` でつないだ文字列です。ファイル名に `/` が入ると、別のディレクトリを指してしまいます。
- **`escape_context_name`**: コンテキストの名前を、ファイル名として安全な形に変える関数です。
- **`KUBENS_DIR`**: 保存先のディレクトリを表す変数です。
- **`"${1}"`**: 1 番目の引数を、空白があっても 1 つの値として扱うための書き方です。

## 何をしているか

### 1. 名前を安全な形にする

```bash:line-numbers=83
  ctx="$(escape_context_name "${1}")"
```

コンテキストの名前を、`escape_context_name` でファイル名に使える形に変換します。

### 2. 保存先のパスを組み立てる

```bash:line-numbers=84
  echo "${KUBENS_DIR}/${ctx}"
```

保存用のディレクトリと、変換した名前を `/` でつないで、パスを作って表示します。

## ここがすごい

- **名前の変換を 1 か所に**: 変換の仕方を、この関数の中の 1 行に閉じ込めています。他の場所で同じ変換を書かずに済みます。
- **外部の値を信用しない**: コンテキストの名前は、利用者が自由に付けられます。ファイルのパスに使う前に、必ず変換しています。
- **パスの組み立てが単純**: ディレクトリとファイル名をつなぐだけなので、読みやすく、誤りが入りにくい作りです。

## まとめ

- 外部から来た名前をファイル名に使うときは、必ず安全な形に変換する。
- 変換の処理は関数にまとめておくと、どこでも同じ規則が使える。
- パスの組み立ては単純に保つと、誤りが少ない。
