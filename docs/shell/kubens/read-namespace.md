## ひとことで

`read_namespace コンテキスト名` は、保存されている **名前空間の名前** を読み出して表示する関数です。保存ファイルが無い場合は、何も表示せずに成功として終わります。

まだ一度も名前空間を保存していないコンテキストは、当然ファイルがありません。その状態を「エラー」ではなく「保存なし」として扱うのが、この関数の役割です。

## コード

```bash:line-numbers=87
read_namespace() {
  local f
  f="$(namespace_file "${1}")"
  [[ -f "${f}" ]] && cat "${f}"
  return 0
}
```

## 前提知識

- **`[[ -f ファイル ]]`**: そのパスが通常のファイルとして存在すれば、真になります。
- **`cat`**: ファイルの中身を表示します。
- **`&&`**: 左が成功したときだけ、右を実行します。
- **`return 0`**: 関数を成功として終わらせます。
- **`namespace_file`**: コンテキスト名から保存先のパスを作る関数です。

## 何をしているか

### 1. 保存先を決める

```bash:line-numbers=89
  f="$(namespace_file "${1}")"
```

コンテキスト名から、保存ファイルのパスを作ります。

### 2. ファイルがあれば中身を表示する

```bash:line-numbers=90
  [[ -f "${f}" ]] && cat "${f}"
```

ファイルが存在すれば、`cat` で中身を表示します。存在しなければ、この行は何もしません。

### 3. 必ず成功で終わる

```bash:line-numbers=91
  return 0
```

最後に `return 0` で、成功として終わります。ファイルが無くても、エラーにはなりません。

## ここがすごい

- **無いことを異常にしない**: 名前空間を一度も保存していない状態は、普通のことです。エラーにすると、呼ぶ側が毎回例外を扱う必要が出てしまいます。
- **`&&` で条件つきの表示**: 1 行で「あれば表示」を書けるので、関数が短くなります。
- **最後に明示的に成功を返す**: 直前の `cat` が失敗しても、結果を成功にそろえます。

## まとめ

- 保存されていないことは、エラーではなく普通の状態として扱うと呼ぶ側が楽になる。
- ファイルの存在を確かめてから読むと、エラーを避けられる。
- 関数の終了の値は、意図して明示すると分かりやすい。
