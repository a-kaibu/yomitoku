## ひとことで

`nvm_is_natural_num` は、引数が **自然数（1 以上の整数）か** を判定する関数です。`5` や `128` なら成功、`0`、`-3`、`abc`、空文字なら失敗です。失敗の理由によって違う番号を返します。

最後に使われている `[ "$1" -eq "$1" ]` は「自分自身と数値として比べる」という古くからある裏技です。この関数は、その裏技の弱点をコメントで説明しながら補っています。

## コード

```sh:line-numbers=4350
nvm_is_natural_num() {
  if [ -z "$1" ]; then
    return 4
  fi
  case "$1" in
    0) return 1 ;;
    -*) return 3 ;; # some BSDs return false positives for double-negated args
    *[!0-9]*) return 2 ;; # `-eq` also accepts signs and whitespace, and in ksh, any arithmetic expression
    *)
      [ "$1" -eq "$1" ] 2>/dev/null # returns 2 if it doesn't match
    ;;
  esac
}
```

## 前提知識

- **`[ A -eq B ]`**: A と B を **数値として** 比べ、等しければ真です。どちらかが数値でないと、エラーになって終了ステータス 2 を返します。
- **`2>/dev/null`**: エラーメッセージを捨てます。
- **`case` のパターン**: `0` はちょうど `0`、`-*` は `-` で始まる文字列、`*[!0-9]*` は「数字以外の文字を 1 つでも含む文字列」です。
- **`return 4`**: 関数を終了ステータス 4 で終わらせます。
- **関数の結果**: 最後のコマンド（ここでは `[ ... ]`）の終了ステータスが、関数の結果になります。

## 何をしているか

### 1. 空なら 4（4351〜4353 行目）

引数が空ならすぐに `4` を返します。

### 2. 0 なら 1（4355 行目）

`0` は整数ですが自然数ではないので `1` を返します。

### 3. マイナスなら 3（4356 行目）

`-` で始まる値は `3` を返します。コメントによると、一部の BSD の `[` は `--5` のような二重の負号を数値として受け付けてしまうため、先に弾いています。

### 4. 数字以外を含めば 2（4357 行目）

`12a`、` 5`（空白付き）、`1+1` などは `2` を返します。コメントのとおり、`-eq` は符号や前後の空白を受け付け、ksh では `1+1` のような **算術式まで計算してしまう** ためです。

### 5. 最後の確認（4359 行目）

ここまで来た値は数字だけでできています。`[ "$1" -eq "$1" ]` で、本当に数値として扱えるかを確かめます。数値として扱えないとエラー（2）になります。

## ここがすごい

- **裏技の仕組み**: 「同じ値どうしを `-eq` で比べる」と、数値なら必ず等しいので真、数値でなければエラーで偽になります。外部コマンドなしで数値判定ができる、シェルらしい技です。
- **裏技の弱点を知って補う**: ただし、この技だけだと `" 5"` や `+5`、ksh の `1+1` も数値と判定されます。そこで `case` で先に「数字以外を含む値」を弾き、裏技は最後の確認にだけ使っています。コメントにその理由がはっきり書かれているので、後から読む人も安心して触れます。
- **失敗の種類を番号で返す**: 空・ゼロ・負数・数字以外と、理由ごとに終了ステータスを変えているので、テストやデバッグで原因を特定しやすくなっています。

## まとめ

- `[ "$x" -eq "$x" ]` は数値判定の古典的な技だが、シェルによって判定がゆるい。
- 文字の種類のチェックは `case` の `*[!0-9]*` で確実にできる。
- 裏技を使うときは、弱点と対策をコメントに残す。
