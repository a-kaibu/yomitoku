## ひとことで

`nvm_sanitize_url` は、URL に含まれる **ユーザー名とパスワードを `***` に置き換える** 関数です。

```
入力: https://alice:s3cret@mirror.example.com/dist/
出力: https://***@mirror.example.com/dist/
```

nvm はエラーメッセージなどで URL を表示することがあります。そのときに認証情報が画面やログに残らないよう、表示の前にこの関数を通します。

## コード

```sh:line-numbers=4346
nvm_sanitize_url() {
  nvm_echo "${1-}" | command sed -e 's#://[^/[:space:]]*@#://***@#g'
}
```

## 前提知識

- **URL の userinfo**: URL の `://` の後、ホスト名の前に `ユーザー:パスワード@` を書くと、認証情報を含められます。便利ですが、URL を表示するとパスワードも見えてしまいます。
- **`sed -e 's#A#B#g'`**: A に一致する部分を B に置き換えます。区切りに `/` ではなく `#` を使っているのは、URL に `/` がたくさん含まれるからです。`g` は 1 行の中のすべての一致を置き換える指定です。
- **`[^/[:space:]]*`**: 正規表現で「`/` でも空白でもない文字の 0 回以上の繰り返し」です。`[^...]` は「〜以外」、`[:space:]` は空白類の文字です。
- **`*` の最長一致**: 正規表現の `*` は、できるだけ長く一致しようとします。

## 何をしているか

この関数は 1 行だけです。

置換のパターンは `://[^/[:space:]]*@` です。これは次の意味になります。

1. `://` から始まり、
2. `/` も空白も含まない文字が続き、
3. `@` で終わる部分

`https://alice:s3cret@mirror.example.com/dist/` では、`://alice:s3cret@` が一致します。これを `://***@` に置き換えるので、ホスト名とパスはそのまま残ります。

パスワードに `@` が含まれる場合（`https://alice:p@ss@host/`）も、`*` が最長一致なので最後の `@` まで含めて `://alice:p@ss@` が一致し、正しく隠せます。コメント「curl や wget と同じく、パスより前の最後の `@` までが userinfo」はこのことです。

一方、`/` を含まないという条件があるので、パスの中の `@`（`https://host/pkg/@scope/name`）は対象になりません。`://` の後、最初の `/` より前までしか見ないからです。

`g` が付いているので、1 行に URL が複数あっても全部隠せます。

## ここがすごい

- **パターン 1 つで境界を正確に表している**: 「`://` の直後から、パスの始まり（`/`）より前の、最後の `@` まで」という条件を、文字クラスと最長一致の組み合わせだけで表現しています。
- **空白も止まる条件に入れる**: 空白を除外しているので、メッセージの文中に URL があっても、後ろに続く文章（`at` を含む英文など）を巻き込みません。
- **表示の直前にかける**: URL そのものは変えず、画面に出す文字列だけを加工します。ダウンロードには元の URL を使えるので、機能を損ないません。

## まとめ

- ログや画面に出す URL からは、認証情報を取り除く。
- 文字クラス `[^...]` で「ここを越えない」という境界を表せる。
- `*` の最長一致を理解すると、正規表現の結果を正確に予想できる。
