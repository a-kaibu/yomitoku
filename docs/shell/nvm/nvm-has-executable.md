## ひとことで

`nvm_has_executable curl` のように呼ぶと、**`curl` という実行可能なコマンドが本当にあるか** を調べ、あれば成功（終了ステータス 0）、なければ失敗を返します。

ポイントは「同じ名前のエイリアスや関数があっても、それには騙されない」ことです。そのために、**使い捨てのサブシェルの中で** エイリアスと関数を一時的に消してから調べています。

## コード

::: code-group

```sh:line-numbers=71 [日本語訳]
nvm_has_executable() {
  (
    # `|| true` を付けるのは、errexit 系のオプション（zsh の ERR_RETURN など）を使うシェルで
    # 名前がエイリアスでも関数でもないときにサブシェルが中断されないようにするため
    unalias "${1-}" 2>/dev/null || true
    unset -f "${1-}" 2>/dev/null || true
    command -v "${1-}" >/dev/null 2>&1
  )
}
```

```sh:line-numbers=71 [原文]
nvm_has_executable() {
  (
    # `|| true` so that shells with errexit-style options (eg, zsh's ERR_RETURN)
    # do not abort the subshell when the name is not an alias or a function
    unalias "${1-}" 2>/dev/null || true
    unset -f "${1-}" 2>/dev/null || true
    command -v "${1-}" >/dev/null 2>&1
  )
}
```

:::

## 前提知識

- **終了ステータス**: シェルのコマンドは終わるときに数値を返します。`0` が成功、それ以外が失敗です。関数の場合は最後に実行したコマンドの終了ステータスが、その関数の結果になります。`if` や `&&` はこの値を見て動きます。
- **`( ... )` サブシェル**: 丸かっこで囲んだ部分は、シェルのコピー（子プロセス）の中で実行されます。中で変数を変えたり関数を消したりしても、**かっこの外には一切影響しません**。
- **`command -v 名前`**: 名前がコマンドとして見つかれば、その場所や種類を表示して成功を返します。見つからなければ失敗します。エイリアスや関数も「見つかった」扱いになるのが注意点です。
- **`unalias 名前`**: エイリアスを削除します。存在しないとエラーになります。
- **`unset -f 名前`**: 関数を削除します。
- **`${1-}`**: 1 番目の引数です。`-` を付けると、引数が無いときに「未定義の変数を使った」というエラー（`set -u` を使っている場合）にならず空文字になります。
- **`>/dev/null 2>&1`**: 通常の出力もエラー出力もすべて捨てる書き方です。
- **`|| true`**: 左側が失敗しても、全体としては成功にする書き方です。

## 何をしているか

### 1. サブシェルに入る

関数全体を `( ... )` で囲んでいます。これで、この中で何を消しても、呼び出し元のシェルのエイリアスや関数はそのまま残ります。

### 2. エイリアスと関数を消す

```sh:line-numbers=75
    unalias "${1-}" 2>/dev/null || true
```


たとえばユーザーが `alias curl='curl --silent'` と定義していたとします。`unalias curl` でこのエイリアスを消します。同じく `unset -f curl` で、もし `curl` という名前の関数があれば消します。

どちらも、該当するエイリアスや関数が無ければエラーになります。エラーメッセージは `2>/dev/null` で捨て、`|| true` で失敗をなかったことにしています。コメントにあるとおり、zsh の `ERR_RETURN` のように「失敗したら即座に抜ける」設定が有効だと、ここで処理が止まってしまうからです。

### 3. 本物のコマンドを探す

エイリアスと関数を取り除いた状態で `command -v curl` を実行します。残っているのは組み込みコマンドか、`PATH` 上の実行ファイルだけなので、これが成功すれば「本当に使える curl がある」とわかります。この終了ステータスがサブシェルの結果になり、さらに関数の結果になります。

## ここがすごい

- **`command -v` の弱点を補っている**: `command -v` だけだと、`curl` という名前の関数がユーザーの設定にあるだけで「ある」と答えてしまいます。nvm はこの後で `command curl ...` を実行するので、本物のコマンドが無いと困ります。消してから調べることで、この誤判定を防いでいます。
- **サブシェルで「やり直し可能な破壊」をする**: 調べるためにエイリアスを消すのは本来乱暴ですが、サブシェルの中なら終わった瞬間に元通りです。後片付けのコードを書く必要がありません。
- **シェルの厳格モードまで想定**: `|| true` の一言で、`set -e` や zsh の `ERR_RETURN` といった設定をしているユーザーでも途中で止まらないようにしています。

一方で、サブシェルはプロセスを 1 つ作るので、呼び出すたびに少しコストがかかります。nvm ではコマンドの有無を調べる回数は多くないので、正確さを優先した選択といえます。

## まとめ

- `( ... )` のサブシェルは、副作用を外に漏らさない「使い捨ての実験場」として使える。
- `command -v` はエイリアスや関数も見つけてしまうので、実行ファイルの有無を知りたいときは工夫が必要。
- `|| true` で、失敗してもかまわない処理をエラー扱いから外せる。
