## ひとことで

`nvm_has_colors` は、**今の出力先でカラー表示をしてよいか** を判定する関数です。色を使ってよければ成功（0）、だめなら失敗を返します。

たとえば `nvm ls` は、インストール済みのバージョンを色分けして表示します。でも結果をファイルに保存したり、色が使えない古い端末で見たりするときは、色を付けるとかえって読みにくくなります。そこで、この関数で事前にチェックしています。

## コード

```sh:line-numbers=110
nvm_has_colors() {
  local NVM_NUM_COLORS
  if nvm_has tput; then
    NVM_NUM_COLORS="$(command tput -T "${TERM:-vt100}" colors)"
  fi
  [ -t 1 ] && [ "${NVM_NUM_COLORS:--1}" -ge 8 ] && [ "${NVM_NO_COLORS-}" != '--no-colors' ]
}
```

## 前提知識

- **`local 変数名`**: その関数の中だけで使える変数を宣言します。関数の外の同名変数を上書きしません（POSIX の規格には無いものの、ほとんどのシェルで使えます）。
- **`tput colors`**: 端末の情報データベース（terminfo）を調べて、その端末が出せる色の数を表示するコマンドです。多くの端末では `8` や `256` が返ります。
- **`-T 端末名`**: `tput` に「どの種類の端末として調べるか」を指定するオプションです。
- **`${TERM:-vt100}`**: 変数 `TERM` が未定義か空なら `vt100` を使う、という書き方です。`TERM` は端末の種類を表す環境変数です。
- **`$( ... )`**: コマンド置換。中のコマンドの出力を文字列として取り込みます。
- **`[ -t 1 ]`**: ファイル記述子 1（標準出力）が端末につながっていれば真です。パイプやファイルにリダイレクトされているときは偽になります。
- **`[ 数 -ge 8 ]`**: 数値の比較で「8 以上」です。`-ge` は greater or equal の略です。
- **`&&`**: 左が成功したときだけ右を実行します。並べると「全部成功したら成功」になります。

## 何をしているか

### 1. 色数を調べる（112〜114 行目）

`nvm_has tput` で `tput` コマンドがあるか確認し、あれば `tput -T "${TERM:-vt100}" colors` の結果を `NVM_NUM_COLORS` に入れます。`TERM=xterm-256color` の環境なら `256` が入ります。`tput` が無ければ変数は空のままです。

### 2. 3 つの条件をまとめて判定する（115 行目）

最後の 1 行は、3 つのテストを `&&` でつないでいます。

1. `[ -t 1 ]` — 標準出力が端末か。`nvm ls > list.txt` のようにファイルへ書き出すときは偽になり、色を付けません。
2. `[ "${NVM_NUM_COLORS:--1}" -ge 8 ]` — 色数が 8 以上か。`tput` が無くて変数が空のときは `:-` によって `-1` に置き換わるので、比較がエラーにならずに確実に偽になります。
3. `[ "${NVM_NO_COLORS-}" != '--no-colors' ]` — ユーザーが `--no-colors` オプションで色を無効にしていないか。

関数の最後のコマンドの結果がそのまま関数の結果になるので、3 つ全部が真のときだけ成功を返します。

## ここがすごい

- **空の値を `-1` にする小技**: `[ "" -ge 8 ]` と書くと、多くのシェルで「数値が必要です」というエラーが出ます。`${VAR:--1}` で「わからないときは -1」と決めておけば、エラーを出さずに自然に「色なし」と判定できます。`:-` の後ろの `-1` がそのまま既定値なので、`:--1` とハイフンが 2 つ並ぶ見た目になっています。
- **`TERM` が無い環境にも備える**: cron や一部の CI では `TERM` が設定されていません。`-T "${TERM:-vt100}"` とすることで、`tput` がエラーを出さずに答えを返せます。
- **「色が出せるか」と「色を出すべきか」を両方見ている**: 端末の能力（色数）だけでなく、出力先（端末かファイルか）とユーザーの意思（`--no-colors`）も考慮しています。これは、よくできた CLI ツールが共通して守っている作法です。
- **if を使わずに書ける**: 判定関数は「最後のテストの結果を返す」だけでよいので、`if ...; then return 0; else return 1; fi` と書く必要がありません。

## まとめ

- `[ -t 1 ]` で「出力が端末かどうか」を判定し、ファイルやパイプには色を付けない。
- `${VAR:-既定値}` で、空の変数による比較エラーを防げる。
- 条件を `&&` で並べると、判定関数を短く書ける。
