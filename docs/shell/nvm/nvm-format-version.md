## ひとことで

`nvm_format_version` は、バージョン番号を **必ず `vX.Y.Z` の 3 要素の形にそろえる** 関数です。

- `20` → `v20.0.0`
- `20.1` → `v20.1.0`
- `v20.1.3.4` → `v20.1.3`

足りない要素を補うのに、**自分自身を呼び出す（再帰）** という方法を使っています。

## コード

```sh:line-numbers=1496
nvm_format_version() {
  local VERSION
  VERSION="$(nvm_ensure_version_prefix "${1-}")"
  local NUM_GROUPS
  NUM_GROUPS="$(nvm_num_version_groups "${VERSION}")"
  if [ "${NUM_GROUPS}" -lt 3 ]; then
    nvm_format_version "${VERSION%.}.0"
  else
    nvm_echo "${VERSION}" | command cut -f1-3 -d.
  fi
}
```

## 前提知識

- **再帰**: 関数が自分自身を呼び出すことです。「問題を少しだけ簡単にして、残りを自分に任せる」と考えます。必ずどこかで止まる条件（終了条件）が必要です。
- **`nvm_ensure_version_prefix`**: 先頭が数字なら `v` を付ける nvm の関数です（`20` → `v20`）。
- **`nvm_num_version_groups`**: ドット区切りの要素数を返す nvm の関数です（`v20.1` → `2`）。
- **`[ A -lt 3 ]`**: A が 3 より小さければ真です。
- **`${VERSION%.}`**: 末尾にドットがあれば 1 つ取り除きます。
- **`cut -f1-3 -d.`**: ドットで区切った 1〜3 番目の部分だけを取り出します。

## 何をしているか

`20` を例に、呼び出しの流れを追います。

### 1 回目: `nvm_format_version 20`

- `nvm_ensure_version_prefix` で `v` を付けて `v20` にします。
- `nvm_num_version_groups` で要素数を数えると `1` です。
- 3 より少ないので、 `v20` に `.0` を足した `v20.0` で自分を呼びます。

### 2 回目: `nvm_format_version v20.0`

- すでに `v` があるので `v20.0` のままです。
- 要素数は `2`。まだ足りないので `v20.0.0` で自分を呼びます。

### 3 回目: `nvm_format_version v20.0.0`

- 要素数は `3` になりました。`cut` を通し、`v20.0.0` を出力します。

この出力が 2 回目、1 回目の呼び出しの出力としてそのまま外に出てきます。

### `.0` を足す前に末尾のドットを取る

`${VERSION%.}` によって、`20.` のように末尾がドットの値でも `20..0` にならず `20.0` になります。

### 4 要素以上の場合

`v20.1.3.4` のように多すぎる場合は、`cut -f1-3 -d.` で最初の 3 つだけを残して `v20.1.3` にします。

## ここがすごい

- **足りない数を数えなくてよい**: ループで書くと「あといくつ足りないか」を計算して、その回数だけ `.0` を足す必要があります。再帰なら「1 つ足して、あとは自分に任せる」だけで、何個足りなくても同じコードで済みます。
- **終了条件がはっきりしている**: 1 回呼ぶごとに要素が必ず 1 つ増えるので、最大でも 3 回で必ず止まります。再帰を使うときに大切な「必ず終わる」ことが明らかです。
- **増やす・減らすの両方に対応**: 少なければ再帰で足し、多ければ `cut` で削るので、どんな入力でも 3 要素にそろいます。

なお、シェルの関数は呼び出しのたびにコマンド置換（サブシェル）を作るので、深い再帰には向きません。ここは最大 3 回なので問題ありません。

## まとめ

- 再帰は「少しだけ問題を簡単にして、残りを自分に任せる」書き方。
- 再帰には必ず止まる条件を用意する。毎回確実に終わりへ近づく形にするとよい。
- 足りないときは補い、多すぎるときは削ると、入力を一定の形にそろえられる。
