## ひとことで

`nvm_version_path VERSION` は、Node.js のバージョン名から **そのバージョンがインストールされているディレクトリのパス** を返す関数です。`nvm_version_path v20.1.0` なら `~/.nvm/versions/node/v20.1.0` のようなパスになります。

最初に `..` を含む怪しいバージョン名を弾いているのがポイントです。`../../etc` のような値を渡されて、nvm のディレクトリの外を操作してしまうのを防いでいます。

## コード

```sh:line-numbers=1083
nvm_version_path() {
  local VERSION
  VERSION="${1-}"
  case "/${VERSION}/" in
    */../*)
      nvm_err "invalid version: ${VERSION}"
      return 3
    ;;
  esac
  if [ -z "${VERSION}" ]; then
    nvm_err 'version is required'
    return 3
  elif nvm_is_iojs_version "${VERSION}"; then
    nvm_echo "$(nvm_version_dir iojs)/$(nvm_strip_iojs_prefix "${VERSION}")"
  elif nvm_version_greater 0.12.0 "${VERSION}"; then
    nvm_echo "$(nvm_version_dir old)/${VERSION}"
  else
    nvm_echo "$(nvm_version_dir new)/${VERSION}"
  fi
}
```

## 前提知識

- **`..`**: パスの中で「1 つ上のディレクトリ」を意味します。`/a/b/../c` は `/a/c` と同じ場所です。これを悪用して、本来の場所の外へ出ることを **ディレクトリトラバーサル** と呼びます。
- **`case 値 in パターン) ... ;; esac`**: 値をパターンと照合して分岐します。パターンでは `*` が「任意の文字列（空も含む）」を表します。
- **`[ -z 文字列 ]`**: 文字列が空なら真です。
- **`elif`**: 「そうでなく、もし〜なら」という追加の条件です。
- **`$( ... )`**: コマンドの出力を文字列として埋め込みます。ここでは別の関数の出力をパスの一部として使っています。
- **終了ステータス `return 3`**: 関数を失敗として終わらせます。

## 何をしているか

### 1. `..` を弾く（1086〜1091 行目）

`"/${VERSION}/"` と、値の **前後に `/` を足してから** `*/../*` というパターンと照合しています。これは「`/../` という部分を含むか」という意味です。

前後に `/` を足す理由は、`..` がどこにあっても同じパターンで見つけるためです。

| VERSION | 照合する文字列 | 結果 |
| --- | --- | --- |
| `..` | `/../` | 一致 → 弾く |
| `../etc` | `/../etc/` | 一致 → 弾く |
| `v20/..` | `/v20/../` | 一致 → 弾く |
| `a/../b` | `/a/../b/` | 一致 → 弾く |
| `v20.1.0` | `/v20.1.0/` | 一致しない |
| `v1..2` | `/v1..2/` | 一致しない（`..` がパスの 1 要素ではない） |

もし `/` を足さずに `*..*` で調べると、`v1..2` のように `..` を含むだけの無害な文字列まで弾いてしまいます。逆に `*/../*` だけだと、先頭の `../x` や末尾の `x/..` を見逃します。前後に `/` を足すことで、ちょうど「パスの要素としての `..`」だけを正確に見つけられます。

### 2. 空チェック（1092〜1094 行目）

バージョンが空ならエラーにします。

### 3. 種類ごとに置き場所を変える（1095〜1101 行目）

- io.js のバージョン（`iojs-v3.0.0` など）なら io.js 用のディレクトリの下。
- `0.12.0` より古いバージョンなら、昔の nvm が使っていた古い配置（`$NVM_DIR` 直下）。
- それ以外は新しい配置 `$NVM_DIR/versions/node` の下。

古い nvm の配置との互換性を保ったまま、新しい配置に移行していることがわかります。

## ここがすごい

- **番兵（センチネル）を足して場合分けを消す**: 「先頭にある場合」「途中にある場合」「末尾にある場合」「`..` だけの場合」と 4 通りを別々に調べる代わりに、前後に `/` を足すだけで 1 つのパターンにまとめています。データの両端に印を足して境界の特別扱いをなくすのは、プログラミング全般でよく使われる考え方です。
- **入口で弾く**: このパスは後でディレクトリの削除（`nvm uninstall`）などにも使われます。パスを作る関数の入口でチェックしておけば、使う側すべてが守られます。
- **外部コマンド不要**: `grep` や正規表現を使わず、シェル組み込みの `case` だけで判定しているので速く、どのシェルでも動きます。

## まとめ

- パスを外部入力から組み立てるときは、`..` によるディレクトリ脱出に注意する。
- 値の前後に区切り文字を足すと、「先頭・途中・末尾」の場合分けを 1 つのパターンにまとめられる。
- チェックはパスを作る関数の入口に置くと、使う側すべてが安全になる。
