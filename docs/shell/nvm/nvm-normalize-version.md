## ひとことで

`nvm_normalize_version v20.1.3` は `20000001000003` を出力します。バージョン番号を **1 つの大きな整数に変換** する関数です。

`1.9.0` と `1.10.0` を文字列として比べると、`"9"` と `"1"` の比較で `1.9.0` のほうが大きいと誤判定されます。整数に直せば、`1000009000000 < 1000010000000` と普通の数の比較で正しく大小が決まります。

## コード

```sh:line-numbers=1439
nvm_normalize_version() {
  command awk 'BEGIN {
    split(ARGV[1], a, /\./);
    printf "%d%06d%06d\n", a[1], a[2], a[3];
    exit;
  }' "${1#v}"
}
```

## 前提知識

- **`awk 'BEGIN { ... }'`**: awk は本来テキストを 1 行ずつ処理する言語ですが、`BEGIN` ブロックだけを書くと、入力を読まずにその中の処理だけを実行します。ちょっとした計算機として使えます。
- **`ARGV[1]`**: awk に渡したコマンドライン引数です。ここではシェルから渡したバージョン文字列が入ります。
- **`split(文字列, 配列, /区切り/)`**: 文字列を区切りで分けて配列に入れます。awk の配列は 1 から始まります。
- **`printf "%d%06d%06d\n"`**: 書式付きで出力します。`%d` は整数、`%06d` は「6 桁になるよう左を 0 で埋めた整数」です。
- **`exit`**: awk をそこで終わらせます。`BEGIN` の後に入力を待ってしまうのを防ぎます。
- **`${1#v}`**: 引数の先頭の `v` を取り除きます。

## 何をしているか

`v20.1.3` を例に追います。

### 1. `v` を取る

シェル側で `${1#v}` を使い、`20.1.3` を awk に渡します。

### 2. ドットで分ける

`split` で `a[1]=20`、`a[2]=1`、`a[3]=3` に分けます。

### 3. ゼロ埋めしてつなげる

`%d%06d%06d` に当てはめると、`20` + `000001` + `000003` で `20000001000003` になります。

もう 1 つ例を見ます。`1.10.0` は `1` + `000010` + `000000` = `1000010000000`。`1.9.0` は `1000009000000`。整数として比べれば、`1.10.0` のほうが大きいと正しく判定できます。

`v20` のように要素が足りないときは、`a[2]` や `a[3]` が空になり、`%06d` では `000000` として扱われます。つまり `v20` は `20.0.0` と同じ値になります。

## ここがすごい

- **比較の問題を「並べ方」の問題に変える**: バージョン比較を自分で書くと、要素ごとに比べるループが必要です。桁をそろえて 1 つの数にしてしまえば、あとは `[ A -gt B ]` や `sort -n` に任せられます。
- **固定幅にする発想**: 日付を `20261101` と書くと数値順と日付順が一致するのと同じ考え方です。各要素を 6 桁に決め打ちすることで、要素の境目がずれません。
- **シェルの弱点を awk で補う**: POSIX シェルの `printf` でもゼロ埋めはできますが、文字列の分割と組み合わせると長くなります。awk なら分割・数値化・整形が 1 行で済みます。

ただし、各要素は 6 桁（999999）までという前提があります。Node.js のバージョンではまず超えない値なので、実用上の問題はありません。

## まとめ

- 複数の数字からなるキーは、各要素をゼロ埋めして連結すると 1 つの数として比較できる。
- `awk 'BEGIN{...}' 引数` は、シェルから使える小さな計算機になる。
- 固定幅の表現は、文字列順と数値順を一致させる手軽な方法。
