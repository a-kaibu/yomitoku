## ひとことで

`_json_decode` は、JSON から受け取った文字列の中の **`\/` を `/` に戻す** 関数です。`http:\/\/example.com` のような文字列を、`http://example.com` に直します。

JSON では、スラッシュ `/` を `\/` と書いてもよい決まりがあります。そのため、サーバーの応答を読むときに、URL の中にこの形が混ざることがあります。この関数は、その形を普通の書き方に戻すための、最小限の変換です。

## コード

```bash:line-numbers=914
_json_decode() {
  _j_str="$(sed 's#\\/#/#g')"
  _debug3 "_json_decode"
  _debug3 "_j_str" "$_j_str"
  echo "$_j_str"
}
```

## 前提知識

- **JSON のエスケープ**: JSON では、`\"` や `\\` のように、バックスラッシュで始まる書き方で特別な文字を表します。`\/` もその 1 つで、単に `/` と同じ意味です。
- **`sed 's#\\/#/#g'`**: `#` を区切りに使った置換です。区切りを `#` にしているのは、パターンに `/` が含まれていて、普通の区切りだと読みにくくなるためです。
- **`\\/`**: sed のパターンの中で、バックスラッシュとスラッシュの 2 文字に一致します。
- **`g`**: 1 行の中で一致したものを、すべて置き換える指定です。

## 何をしているか

### 1. 入力を読んで置換する

```bash:line-numbers=915
  _j_str="$(sed 's#\\/#/#g')"
```

標準入力を読んで、`\/` を `/` に置き換えます。`#` を区切りにしているので、パターンの中の `/` をそのまま書けます。

### 2. 結果を出力する

```bash:line-numbers=916
  _debug3 "_json_decode"
  _debug3 "_j_str" "$_j_str"
  echo "$_j_str"
```

デバッグの出力を経て、変換後の文字列を表示します。`_debug3` は、詳しい情報を出すときだけ表示されるログです。

## ここがすごい

- **区切りを変えて読みやすく**: 置換のパターンに `/` が含まれるときは、区切りに `#` を使うのが定番の書き方です。
- **最小限の変換**: JSON 全体を解析するのではなく、必要な 1 つの変換だけを行います。単純なので、間違いが起きにくいです。
- **ログで確認できる**: 変換の前後の値をログに出せるので、問題が起きたときに原因を追いやすくなっています。

## まとめ

- 置換の区切り文字は、パターンに合わせて変えると読みやすい。
- JSON のエスケープは、必要な部分だけを戻せば足りることがある。
- デバッグの出力を用意しておくと、通信の問題を調べやすい。
