## ひとことで

`_json_encode` は、シェルの文字列を **JSON の文字列の中に安全に入れられる形** に変える関数です。ダブルクォートは `\"` に、CR は `\r` に変えます。改行は、そのまま扱うと JSON が壊れるので、特別に処理しています。

acme.sh は、証明書を発行するための通信で、JSON の形のデータを送ります。文字列の中に引用符や改行が混ざると、JSON として読めなくなります。この関数は、その事故を防ぐための変換を行います。

## コード

```bash:line-numbers=906
_json_encode() {
  _j_str="$(sed 's/"/\\"/g' | sed "s/\r/\\r/g")"
  _debug3 "_json_encode"
  _debug3 "_j_str" "$_j_str"
  echo "$_j_str" | _hex_dump | _lower_case | sed 's/0a/5c 6e/g' | tr -d ' ' | _h2b | tr -d "\r\n"
}
```

## 前提知識

- **JSON の文字列**: ダブルクォートで囲まれ、中の引用符は `\"`、改行は `\n` と書く決まりがあります。
- **エスケープ**: 特別な意味を持つ文字を、別の書き方に置き換えることです。
- **`sed 's/"/\\"/g'`**: 引用符を、バックスラッシュ付きの引用符に置き換えます。
- **`_hex_dump`**: 入力を 16 進数のバイト列にする acme.sh の関数です。
- **`_h2b`**: 16 進数のバイト列を、実際のバイトに戻す関数です。
- **`tr -d "\r\n"`**: 改行と CR を取り除きます。

## 何をしているか

### 1. 引用符と CR をエスケープする

```bash:line-numbers=907
  _j_str="$(sed 's/"/\\"/g' | sed "s/\r/\\r/g")"
```

まず、ダブルクォートを `\"` に、CR を `\r` に置き換えます。

### 2. 改行を 16 進数で作り直す

```bash:line-numbers=910
  echo "$_j_str" | _hex_dump | _lower_case | sed 's/0a/5c 6e/g' | tr -d ' ' | _h2b | tr -d "\r\n"
```

文字列を 16 進数のバイト列にしてから、改行の `0a` を `5c 6e`（バックスラッシュと n）に置き換えます。そのあとで、バイト列を元の文字に戻します。

この流れによって、改行は `\n` という 2 文字の書き方になります。JSON の中で改行を表す正しい形です。

## ここがすごい

- **改行を 16 進数の段階で置き換える**: 改行を直接文字として扱うと、sed の行単位の処理で壊れやすくなります。そこで、いったんバイト列にしてから置き換えています。
- **変換の順番が大事**: 引用符を先に処理してから、改行を処理しています。逆にすると、作ったエスケープを二重に変えてしまうおそれがあります。
- **外部ツールを組み合わせる**: sed、16 進数の変換、tr など、既存の部品を組み合わせています。

## まとめ

- 文字列を JSON に入れるには、引用符と改行をエスケープする。
- 改行のような扱いにくい文字は、バイト列の段階で置き換えると安全。
- 変換は、順番を誤ると二重にエスケープしてしまうので注意する。
