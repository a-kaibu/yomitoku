## ひとことで

`early_death` は、**回復できないエラーを表示して、すぐにスクリプトを終了させる** 関数です。どのスクリプトでも、同じ形でエラーを出せるようにまとめています。

tfenv の多くの場所が、この関数を使ってエラーを報告します。エラーの形を統一することで、利用者が問題を見分けやすくなります。

## コード

```bash:line-numbers=9
function early_death() {
  echo "[FATAL] ${0}: ${1}" >&2;
  exit 1;
};
```

## 前提知識

- **`$0`**: 実行されているスクリプトの名前です。エラーメッセージに、どこで起きたかを付けるために使います。
- **`$1`**: 関数に渡された最初の引数です。ここでは、エラーの内容として使われます。
- **`>&2`**: 標準エラー出力へ書き出す指定です。
- **`exit 1`**: エラーを示す終了コードで、スクリプトを止めます。

## 何をしているか

### 1. エラーの内容を標準エラーに出す

```bash:line-numbers=10
  echo "[FATAL] ${0}: ${1}" >&2;
```

`[FATAL]` の印、スクリプト名、エラーの内容を並べて、標準エラーに出力します。

### 2. スクリプトを終了させる

```bash:line-numbers=11
  exit 1;
```

`exit 1` で、エラーを示す終了コードを返して止めます。後続の処理は実行されません。

## ここがすごい

- **表示の形をそろえる**: どの場所から出ても、同じ `[FATAL]` の形で表示されます。原因の探しやすさにつながります。
- **止まるかどうかを明確にする**: 回復できないエラーは、ここで必ず止めます。途中で壊れた状態が続くのを防ぎます。
- **標準エラーを使う**: 通常の出力と分けるので、パイプでの処理にも影響しません。

## まとめ

- 致命的なエラーは、形をそろえた関数にまとめると扱いやすい。
- エラーは標準エラーに出し、終了コードで伝える。
- 出力にスクリプト名を入れると、どこで起きたか分かる。
