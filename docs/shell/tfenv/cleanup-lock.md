## ひとことで

`cleanup_lock` は、**インストールの途中で作ったロック用のディレクトリを削除する** 関数です。インストールの終わりや、途中で止まったときに呼ばれます。

ロックは、同じバージョンを同時にインストールしないための印です。使い終わったら確実に消して、次のインストールを妨げないようにします。

## コード

```bash:line-numbers=152
cleanup_lock() {
  rmdir "${lockdir}" 2>/dev/null || true;
};
```

## 前提知識

- **ロック**: 同じ処理を同時に行わないための目印です。ここでは、ディレクトリがあるかどうかで判断します。
- **`rmdir`**: 空のディレクトリだけを削除するコマンドです。中身があれば失敗します。
- **`2>/dev/null`**: 標準エラーを捨てて、失敗のメッセージを表示しない指定です。
- **`|| true`**: 直前のコマンドが失敗しても、全体を成功として扱う書き方です。

## 何をしているか

### 1. ロック用のディレクトリを削除する

```bash:line-numbers=153
  rmdir "${lockdir}" 2>/dev/null || true;
```

`rmdir` で、ロック用のディレクトリを削除します。空のときだけ成功します。

### 2. 失敗を無視して終える

```bash:line-numbers=153
  rmdir "${lockdir}" 2>/dev/null || true;
```

削除に失敗しても、エラーを表示せず、正常終了として扱います。すでに無い場合でも、後片付けは終わったと考えられるためです。

## ここがすごい

- **空のときだけ消す**: `rmdir` は、中身のあるディレクトリを消しません。誤って他のファイルを消すのを防げます。
- **後片付けを確実にする**: 失敗しても止まらないので、終了の処理が必ず最後まで進みます。
- **エラーを隠す範囲を狭く**: 1 行の中だけで失敗を捨てているので、ほかの問題は見逃しません。

## まとめ

- 後片付けは、中身を消さない安全な命令を使う。
- 失敗を無視してよい場面では、その範囲を最小にする。
- ロックは、使い終わったら必ず解放する。
