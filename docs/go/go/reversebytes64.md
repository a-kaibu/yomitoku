## ひとことで

`ReverseBytes64` は、64 ビット整数を 8 個のバイト（8 ビットの塊）の並びと見て、**その順番を逆にした値** を返します。
16 進数で書くと、`0x0102030405060708` が `0x0807060504030201` になります。

この操作は、データの「バイトの並べ方（エンディアン）」が違うコンピュータ同士でやりとりするときに必要になります。

## コード

```go:line-numbers=292
func ReverseBytes64(x uint64) uint64 {
	const m = 1<<64 - 1
	x = x>>8&(m3&m) | x&(m3&m)<<8
	x = x>>16&(m4&m) | x&(m4&m)<<16
	return x>>32 | x<<32
}
```

`m3 = 0x00ff00ff00ff00ff`、`m4 = 0x0000ffff0000ffff` は同じファイルの 113〜114 行目で定義されているマスクです。

## 前提知識

- **バイト**: 8 ビットのまとまりです。16 進数の 2 桁がちょうど 1 バイトです（`0xff` = 1 バイト分すべて 1）。
- **エンディアン**: 複数バイトの数をメモリに置くとき、上位バイトから置くか（ビッグエンディアン）、下位バイトから置くか（リトルエンディアン）の違いです。ネットワークやファイル形式ではビッグエンディアンが多く、多くの PC はリトルエンディアンなので変換が必要になります。
- **`&`、`|`、`<<`、`>>`**: AND、OR、左シフト、右シフトです。Go ではシフトと `&` が `|` より先に計算されます。
- **`const m = 1<<64 - 1`**: 全ビット 1 の定数。64 ビット版では実質何もしませんが、他の幅の関数と形をそろえています。

## 何をしているか

`x = 0x0102030405060708` で追ってみます（読みやすさのため 2 桁ずつ区切ります）。

### 1. 隣り合うバイトを入れ替える（294 行目）

`m3` は 1 バイトおきに `ff` が並ぶマスクです。`x>>8 & m3` で偶数番目のバイトを右へ、`x & m3 << 8` で奇数番目のバイトを左へ移し、`|` で合わせます。

```
01 02 03 04 05 06 07 08  →  02 01 04 03 06 05 08 07
```

### 2. 2 バイトの組を入れ替える（295 行目）

今度は `m4`（2 バイトおき）と 16 ビットのシフトです。

```
02 01 04 03 | 06 05 08 07  →  04 03 02 01 08 07 06 05
```

### 3. 前半と後半を入れ替える（296 行目）

最後は 32 ビットの左右を入れ替えるだけなので、マスクは不要です。`x>>32 | x<<32` で、はみ出した部分は自然に消えます。

```
04 03 02 01 08 07 06 05  →  08 07 06 05 04 03 02 01
```

## ここがすごい

- **3 段で 8 バイトを並べ替える**: 1 バイトずつ取り出して組み立てると 8 回の取り出しとシフトが必要です。入れ替えの幅を倍々にすることで log2(8) = 3 段になります。
- **最後の段はマスクが要らない**: 32 ビットずらすと、はみ出した半分は 64 ビットの外に出て自然に消えます。「ずらせば勝手に消える」ことを見切って演算を減らしています。
- **コンパイラが 1 命令にする**: Go のコンパイラはこの関数を認識して、多くの CPU で専用命令（x86 の `BSWAP` など）に置き換えます。Go のコードは、専用命令がない環境でも正しく速く動くための「仕様書」兼「予備の実装」です。
- **`Reverse64` から再利用される**: ビットの左右反転のうち、後半はバイトの反転と同じなので、`Reverse64` はこの関数を呼んでいます。

## まとめ

- バイト順の反転は「隣同士の入れ替え」を幅を倍にしながら 3 回行えばよい。
- シフトではみ出したビットは消えるので、最後の段はマスクを省ける。
- エンディアン変換は、ネットワークやファイル形式を扱うときの基本操作。
