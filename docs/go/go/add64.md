## ひとことで

`Add64` は `x + y + carry` を計算し、**64 ビットに収まった部分（`sum`）と、あふれた繰り上がり（`carryOut`、0 か 1）** を返します。
これを並べて使うと、128 ビットや 256 ビットといった **64 ビットより大きな数の足し算** を作れます。暗号や多倍長整数（巨大な数）の計算で使われる部品です。

## コード

```go:line-numbers=386
func Add64(x, y, carry uint64) (sum, carryOut uint64) {
	sum = x + y + carry
	// The sum will overflow if both top bits are set (x & y) or if one of them
	// is (x | y), and a carry from the lower place happened. If such a carry
	// happens, the top bit will be 1 + 0 + 1 = 0 (&^ sum).
	carryOut = ((x & y) | ((x | y) &^ sum)) >> 63
	return
}
```

## 前提知識

- **複数の戻り値**: Go の関数は複数の値を返せます。`(sum, carryOut uint64)` は 2 つの `uint64` を名前付きで返すという意味で、最後の `return` だけでその 2 つが返されます。
- **符号なし整数のあふれ**: `uint64` の足し算で 2 の 64 乗以上になると、上の桁は捨てられて 0 から数え直します（ラップアラウンド）。たとえば最大値に 1 を足すと 0 になります。
- **`&^`（AND NOT）**: Go 独特の演算子で、`a &^ b` は「`a` のうち、`b` が 1 の桁を 0 にしたもの」です。`a & (^b)` と同じ意味です。
- **`>> 63`**: 64 ビットの最上位ビット（63 番目）を一番下へ降ろします。結果は 0 か 1 になります。

## 何をしているか

### 1. とりあえず足す（387 行目）

`sum = x + y + carry` を計算します。あふれた分は消えますが、それで構いません。消えた分は次の行で繰り上がりとして復元します。

### 2. 最上位ビットだけで繰り上がりを判断する（391 行目）

繰り上がりが起きるのは、最上位ビット（63 番目）の足し算があふれたときです。そこで最上位ビットの組み合わせだけを考えます。

- `x` と `y` の最上位が **両方 1** なら、下からの繰り上がりに関係なく必ずあふれます → `x & y`
- **片方だけ 1** の場合（`x | y` が 1）、下の桁から繰り上がりが来たときだけあふれます。繰り上がりが来ると、最上位は 1 + 0 + 1 = 10 で、`sum` の最上位は **0** になります → `(x | y) &^ sum`

この 2 つを `|` でまとめ、`>> 63` で最上位ビットだけを取り出すと、繰り上がりが 0 か 1 で得られます。

### 具体例（8 ビットで考える）

`x = 1100 0000`、`y = 0100 0000`、`carry = 0` とします。

- `sum = 1 0000 0000` → 8 ビットに収めると `0000 0000`
- 最上位: `x & y` は 0。`x | y` は 1 で、`sum` の最上位は 0 なので `(x | y) &^ sum` の最上位は 1
- よって `carryOut = 1`。実際 192 + 64 = 256 なので、あふれています。

## ここがすごい

- **分岐なし**: 素直に書くと `if sum < x { carryOut = 1 }` のような比較と分岐になります（`carry` も足すと条件はさらに複雑になります）。この書き方は **ビット演算だけ** なので、暗号処理のように「入力によって処理時間が変わってはいけない」場面（定数時間処理）でも安心して使えます。
- **論理回路そのもの**: 388〜390 行目のコメントで説明されている式は、ハードウェアの「全加算器」の繰り上がり出力と同じ考え方です。1 ビットの回路の式を、64 ビット整数の最上位ビットにだけ適用しています。
- **コンパイラが専用命令にする**: Go のコンパイラはこの関数を、多くの CPU で「繰り上がり付き足し算」命令（x86 の `ADC` など）に置き換えます。Go 言語には繰り上がりフラグを直接扱う手段がないので、関数として用意しておき、コンパイラに任せる設計になっています。

## まとめ

- 符号なし整数はあふれると黙って折り返すので、繰り上がりは自分で計算する必要がある。
- 繰り上がりは最上位ビットの組み合わせだけで判定でき、ビット演算 1 行で書ける。
- 分岐を使わないコードは、速さだけでなく暗号での安全性（定数時間）にもつながる。
