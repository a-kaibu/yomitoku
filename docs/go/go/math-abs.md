## ひとことで

`math.Abs(x)` は、浮動小数点数 `x` の絶対値を返します。`math.Abs(-3.5)` は `3.5` です。

素直に書くと `if x < 0 { return -x }` ですが、この関数は **数のビット表現の最上位ビット（符号ビット）を 0 にするだけ** で答えを出します。

## コード

```go:line-numbers=13
func Abs(x float64) float64 {
	return Float64frombits(Float64bits(x) &^ signMask)
}
```

`signMask` は同じパッケージで `signMask = 1 << 63` と定義されています。最上位ビットだけが 1 の値です。

## 前提知識

- **IEEE 754 の浮動小数点数**: `float64` は 64 ビットで、最上位の 1 ビットが **符号**（0 なら正、1 なら負）、続く 11 ビットが **指数**、残り 52 ビットが **仮数**（有効数字）です。正の数と負の数は、符号ビットだけが違います。
- **`Float64bits(x)`**: `float64` のビットの並びを、そのまま `uint64` の整数として取り出す関数です。値を変換するのではなく、同じビットを別の型として見るだけです。
- **`Float64frombits(b)`**: その逆で、`uint64` のビットを `float64` として見ます。
- **`&^`**: Go の AND NOT 演算子です。`b &^ signMask` は「`b` から符号ビットを消したもの」です。
- **-0（マイナスゼロ）**: IEEE 754 には `+0` と `-0` があります。比較すると等しいですが、符号ビットが違います。
- **NaN**: 「数ではない」を表す特別な値です（0 ÷ 0 など）。

## 何をしているか

```go:line-numbers=14
	return Float64frombits(Float64bits(x) &^ signMask)
```

`x = -3.5` で追います。

### 1. ビットとして取り出す

`-3.5` のビットは、16 進数で `0xC00C000000000000` です。最上位の `C`（`1100`）の先頭 1 ビットが符号です。

### 2. 符号ビットを消す

`0xC00C000000000000 &^ 0x8000000000000000 = 0x400C000000000000`

### 3. float64 に戻す

`0x400C000000000000` は `3.5` です。符号以外のビットは一切変わっていません。

## ここがすごい

- **分岐なし**: `if x < 0` を使わないので、CPU の分岐予測を外すことがありません。実際、Go のコンパイラはこの関数を、多くの CPU でビット演算の 1〜2 命令に置き換えます。
- **-0 を正しく扱える**: `if x < 0 { return -x }` だと、`-0 < 0` は偽なので `-0` がそのまま返ってしまいます。符号ビットを消す方法なら `+0` になります。
- **NaN にも素直**: NaN との比較は常に偽なので、比較を使う書き方では NaN の符号ビットが残ります。ビット演算なら NaN でも符号ビットだけが消えます（IEEE 754 でも abs は符号ビットだけを操作する演算と定められています）。
- **浮動小数点のハードウェアを使わない**: 整数のビット演算だけなので、浮動小数点の例外や丸めの心配がありません。

## まとめ

- `float64` は符号・指数・仮数のビットでできていて、正負は最上位ビットだけで決まる。
- 絶対値は、符号ビットを消すだけで求まる。
- 比較による書き方は `-0` や NaN でつまずくが、ビット演算なら素直に扱える。
