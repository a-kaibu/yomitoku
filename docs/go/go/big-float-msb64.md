## ひとことで

`msb64(x)` は、大きな仮数 `x` の、一番上にある 64 ビットを返します。`msb` は most significant bits、つまり「最上位のビット」を意味します。

浮動小数点数の計算では、仮数の上の部分だけを見て、丸めや比較を行うことがよくあります。この関数は、その上の 64 ビットをすばやく取り出す役目です。

## コード

```go:line-numbers=715
func msb64(x nat) uint64 {
	i := len(x) - 1
	if i < 0 {
		return 0
	}
	if debugFloat && x[i]&(1<<(_W-1)) == 0 {
		panic("x not normalized")
	}
	switch _W {
	case 32:
		v := uint64(x[i]) << 32
		if i > 0 {
			v |= uint64(x[i-1])
		}
		return v
	case 64:
		return uint64(x[i])
	}
	panic("unreachable")
}
```

## 前提知識

- **仮数（mant）**: 浮動小数点数の有効数字の部分です。`math/big` では、ワードを並べた配列で表されます。
- **最上位ワード**: 配列の末尾側にあるワードです。大きな数の上の桁を担当します。
- **ワードの大きさ（`_W`）**: 1 ワードのビット数です。64 ビットの機械では 64、32 ビットの機械では 32 です。
- **`panic("unreachable")`**: 絶対に通らないはずの場所を示す印です。`switch` で 32 か 64 のどちらかが必ず選ばれるので、ここには届きません。

## 何をしているか

### 1. 空なら 0 を返す

```go:line-numbers=716
	i := len(x) - 1
	if i < 0 {
		return 0
	}
```

`i` は最上位ワードの位置です。配列が空なら、取り出す値がないので 0 を返します。

### 2. 32 ビットの機械では 2 つのワードをまとめる

```go:line-numbers=725
		v := uint64(x[i]) << 32
		if i > 0 {
			v |= uint64(x[i-1])
		}
```

1 ワードが 32 ビットしかないときは、上位の 32 ビットと、その下の 32 ビットを合わせて、64 ビットの値を作ります。上のワードを 32 ビット左にずらし、下のワードを `|` で入れます。

### 3. 64 ビットの機械では 1 ワードで足りる

```go:line-numbers=731
		return uint64(x[i])
```

1 ワードが 64 ビットなら、最上位のワードをそのまま返せば、上の 64 ビットが揃います。

## ここがすごい

- **環境で作り方を変える**: `switch _W` により、32 ビットと 64 ビットの機械のどちらでも、同じ意味の 64 ビットの値が得られます。
- **必要な分だけを取り出す**: 仮数全体を見ず、上の部分だけを使います。浮動小数点数の比較や丸めに、必要な情報は大体ここにあります。
- **デバッグで矛盾を検出**: `debugFloat` のときは、最上位ワードの最上位ビットが 1 かを確かめます。正規化されていなければ、すぐ止まります。

## まとめ

- `msb64` は、仮数の上の 64 ビットを取り出します。
- 空の仮数は 0 を返します。
- 32 ビットの機械では 2 つのワードを、64 ビットの形にまとめます。
