## ひとことで

`down` は、二分ヒープの位置 `i0` にある要素を、**子のうち小さいほうより大きい間、入れ替えて下へ沈める** 関数です。
`heap.Pop`（最小値を取り出す）で末尾の要素を根に移したときや、`heap.Init` でヒープを作るときに使われます。
戻り値は「要素が少しでも動いたか」です。

## コード

::: code-group

```go:line-numbers=100 [日本語訳]
func down(h Interface, i0, n int) bool {
	i := i0
	for {
		j1 := 2*i + 1
		if j1 >= n || j1 < 0 { // 整数オーバーフローのあと j1 < 0 になる
			break
		}
		j := j1 // 左の子
		if j2 := j1 + 1; j2 < n && h.Less(j2, j1) {
			j = j2 // = 2*i + 2  // 右の子
		}
		if !h.Less(j, i) {
			break
		}
		h.Swap(i, j)
		i = j
	}
	return i > i0
}
```

```go:line-numbers=100 [原文]
func down(h Interface, i0, n int) bool {
	i := i0
	for {
		j1 := 2*i + 1
		if j1 >= n || j1 < 0 { // j1 < 0 after int overflow
			break
		}
		j := j1 // left child
		if j2 := j1 + 1; j2 < n && h.Less(j2, j1) {
			j = j2 // = 2*i + 2  // right child
		}
		if !h.Less(j, i) {
			break
		}
		h.Swap(i, j)
		i = j
	}
	return i > i0
}
```

## 前提知識

- **二分ヒープ**: 「どの親も自分の子以下」という性質を持つ木で、配列で表します。位置 `i` の子は `2i+1`（左）と `2i+2`（右）です。
- **`h.Less(a, b)`**: 利用者が定義する「a 番目は b 番目より小さいか」の比較です。
- **`if j2 := j1 + 1; j2 < n && ...`**: Go の `if` は、条件の前に短い文（ここでは変数 `j2` の宣言）を置けます。`j2` はこの `if` の中だけで使えます。
- **整数のオーバーフロー**: `int` の最大値を超える計算をすると、値が負の数に折り返します。

## 何をしているか

```go:line-numbers=111
		if !h.Less(j, i) {
```

ヒープ `[9, 3, 2, 7, 5]` の根の `9` を沈めます（`i0 = 0`, `n = 5`）。

### 1 回目（i = 0）

左の子 `j1 = 1`（値 3）、右の子 `j2 = 2`（値 2）。右のほうが小さいので `j = 2`。
`9` は `2` より小さくないので入れ替え → `[2, 3, 9, 7, 5]`。`i = 2`。

### 2 回目（i = 2）

左の子は `2*2+1 = 5`。`n = 5` 以上なので子がいません。ループを抜けます。

### 戻り値

`i = 2 > i0 = 0` なので `true`（動いた）を返します。

### 小さいほうの子を選ぶ理由

大きいほうの子と入れ替えると、新しい親（大きいほうの子）がもう片方の子より大きくなり、ヒープ条件が崩れてしまいます。小さいほうを上げれば、もう片方の子よりも必ず小さいので安全です。

## ここがすごい

- **オーバーフローまで想定**: `j1 < 0` は、`2*i + 1` が `int` の範囲をあふれて負の数になった場合への備えです（コメントにも `after int overflow` とあります）。現実のメモリでは起きにくい状況ですが、標準ライブラリとして「ありえない入力でも壊れない」ことを重視しています。
- **右の子の存在チェックをまとめた**: `j2 < n && h.Less(j2, j1)` で、「右の子がいて、しかも左より小さい」を 1 行で判定しています。`&&` は左が偽なら右を評価しないので、存在しない位置を比較することはありません。
- **「動いたか」を返す**: この戻り値のおかげで、`heap.Fix` は「下に動かなかったときだけ上を試す」という書き方ができます。小さな情報を返すだけで、呼び出し側の無駄な処理を省けます。

## まとめ

- ヒープで要素を沈めるときは、子のうち小さいほうと入れ替える。
- 子の位置の計算はオーバーフローしうるので、標準ライブラリでは負の数もチェックしている。
- 処理の結果（動いたかどうか）を返すと、呼び出し側が賢く分岐できる。
