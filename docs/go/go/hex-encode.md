## ひとことで

`hex.Encode(dst, src)` は、バイト列 `src` を **16 進数の文字** に変換して `dst` に書き込みます。
`[]byte{0x1f, 0xa0}` は `"1fa0"` になります。ハッシュ値や暗号鍵などのバイナリデータを、人が読める文字で表示するときによく使われます。

1 バイトは必ず 2 文字になるので、`dst` には `src` の 2 倍の長さが必要です。

## コード

```go:line-numbers=45
func Encode(dst, src []byte) int {
	j := 0
	for _, v := range src {
		dst[j] = hextable[v>>4]
		dst[j+1] = hextable[v&0x0f]
		j += 2
	}
	return len(src) * 2
}
```

`hextable` は同じファイルで `const hextable = "0123456789abcdef"` と定義されています。

## 前提知識

- **16 進数**: 0〜9 と a〜f の 16 文字で数を表す方法です。16 進数の 1 桁は、2 進数のちょうど 4 桁（4 ビット）に対応します。だから 1 バイト（8 ビット）は 16 進数 2 桁で表せます。
- **`v >> 4`**: バイトを右に 4 ビットずらし、上位 4 ビットを取り出します。`0x1f >> 4 = 0x1`。
- **`v & 0x0f`**: 下位 4 ビットだけを取り出します。`0x1f & 0x0f = 0xf`。
- **文字列の添字**: Go では文字列も `hextable[3]` のように添字でアクセスでき、その位置のバイト（ここでは `'3'`）が得られます。
- **`for _, v := range src`**: `src` のバイトを先頭から 1 つずつ `v` に取り出して繰り返します。

## 何をしているか

```go:line-numbers=48
		dst[j] = hextable[v>>4]
```

`src = [0x1f, 0xa0]` で追います。

### 1 バイト目（`v = 0x1f`）

- 上位 4 ビット: `0x1f >> 4 = 1` → `hextable[1] = '1'`
- 下位 4 ビット: `0x1f & 0x0f = 15` → `hextable[15] = 'f'`

`dst[0] = '1'`、`dst[1] = 'f'`、`j = 2`。

### 2 バイト目（`v = 0xa0`）

- 上位: `10` → `'a'`
- 下位: `0` → `'0'`

`dst[2] = 'a'`、`dst[3] = '0'`。

### 戻り値

書き込んだ文字数 `len(src) * 2 = 4` を返します。

## ここがすごい

- **計算ではなく表引き**: 数値を文字に変えるには「10 未満なら `'0'` を足し、それ以上なら `'a' - 10` を足す」という分岐が必要ですが、16 文字の表を引けば分岐なしで済みます。表は 16 バイトしかないので、メモリの負担もありません。
- **文字列定数を表として使う**: `"0123456789abcdef"` という文字列そのものが表になっています。配列を別に宣言するより短く、読む人にも意味が一目でわかります。
- **書き込み先を呼び出し側が用意する**: 関数の中でメモリを確保せず、呼び出し側が渡した `dst` に書き込みます。同じバッファを何度も使い回せるので、大量のデータを変換するときにメモリ確保が起きません。文字列が欲しいだけなら `hex.EncodeToString` という便利関数があります。

## まとめ

- 16 進数の 1 桁は 4 ビットなので、1 バイトは上位と下位の 4 ビットに分けて 2 文字にできる。
- 小さな範囲の値を文字に変えるときは、文字列定数を表として引くと分岐がいらない。
- 書き込み先を受け取る API は、バッファの再利用がしやすい。
