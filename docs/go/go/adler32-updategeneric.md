## ひとことで

Adler-32 は、データの整合性を確かめるための、簡単なチェックサムです。2 つの和 `s1`（バイトの合計）と `s2`（`s1` の合計）から作られ、結果は 32 ビットの値になります。`updateGeneric` は、その和を、データを読みながら計算していきます。

ここでの工夫は、和を毎回割るのではなく、**溢れない範囲でまとめて割る** ことです。

## コード

```go:line-numbers=97
func updateGeneric(d digest, p []byte) digest {
	s1, s2 := uint32(d&0xffff), uint32(d>>16)
	for len(p) > 0 {
		var q []byte
		if len(p) > nmax {
			p, q = p[:nmax], p[nmax:]
		}
		for len(p) >= 4 {
			s1 += uint32(p[0])
			s2 += s1
			s1 += uint32(p[1])
			s2 += s1
			s1 += uint32(p[2])
			s2 += s1
			s1 += uint32(p[3])
			s2 += s1
			p = p[4:]
		}
		for _, x := range p {
			s1 += uint32(x)
			s2 += s1
		}
		s1 %= mod
		s2 %= mod
		p = q
	}
	return digest(s2<<16 | s1)
}
```

## 前提知識

- **チェックサム**: データの値から作る小さな値で、データが変わっていないかを確かめるのに使います。
- **Adler-32 の定義**: `s1` は、1 から始めて各バイトを足した値です。`s2` は、その `s1` を毎回足した値です。最後に、`s2<<16 | s1` が結果になります。
- **`mod`（65521）**: 素数で、Adler-32 の和を割る値です。`nmax` は、割る前に和を大きくしてもよい最大のバイト数です。
- **`uint32` の溢れ**: 32 ビットを超えると値が戻ってしまいます。和が溢れないように、割るタイミングを決めています。

## 何をしているか

### 1. 大きすぎるときは区切って処理する

```go:line-numbers=101
			if len(p) > nmax {
				p, q = p[:nmax], p[nmax:]
			}
```

データが `nmax` より長ければ、先頭の `nmax` バイトだけをこの回の処理にします。残りは `q` に分けて、次のループで処理します。`nmax` は、割る前に和が溢れないバイト数の上限です。

### 2. 4 バイトずつまとめて足す

```go:line-numbers=104
			for len(p) >= 4 {
				s1 += uint32(p[0])
				s2 += s1
				s1 += uint32(p[1])
				s2 += s1
				s1 += uint32(p[2])
				s2 += s1
				s1 += uint32(p[3])
				s2 += s1
				p = p[4:]
			}
```

4 バイトずつ、`s1` と `s2` を更新します。同じ形の処理を 4 回並べることで、ループの回数と条件判定を減らしています。

### 3. 残りを 1 バイトずつ、そして割る

```go:line-numbers=119
			s1 %= mod
			s2 %= mod
			p = q
```

区切られた部分の処理が終わったら、`s1` と `s2` を `mod` で割った余りにします。これで、次の区切りの処理を始める前に、値が十分小さくなります。`p = q` で、残りを次の回の入力にします。

## ここがすごい

- **割り算の回数を減らす**: 1 バイトごとに割ると、割り算が大量に発生します。大きな和のまま、`nmax` ごとにまとめて割るので、割り算が少なくて済みます。
- **溢れを防ぐ上限が決まっている**: `nmax` は、32 ビットの和が溢れない最大の長さから決められています。安全と速さを、両立させています。
- **4 バイトの展開**: ループを展開すると、条件判定と添字の計算が減ります。速さを重視したコードの典型です。

## まとめ

- Adler-32 は、`s1` と `s2` という 2 つの和から作られるチェックサムです。
- 和は、溢れないように `nmax` バイトごとに、`mod` で割った余りに直します。
- 4 バイトずつ展開して、ループの回数を減らしています。
- 割り算を減らすことが、この関数の速さの鍵です。
