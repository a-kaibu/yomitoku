## ひとことで

`heap.Init(h)` は、すでにデータが入っている `h` を、ヒープの形に並べ直します。ヒープは「親は子より小さい」という性質を持つ木で、先頭（根）に最小値が来ます。

ヒープを作る方法は 2 つあります。1 つは要素を 1 つずつ `heap.Push` すること、もう 1 つは `Init` で一度にまとめて並べ直すことです。`Init` のほうが速く、要素数に比例する時間で終わります。

## コード

::: code-group

```go:line-numbers=41 [日本語訳]
func Init(h Interface) {
	// ヒープ化する（配列を並べてヒープにする）。
	n := h.Len()
	for i := n/2 - 1; i >= 0; i-- {
		down(h, i, n)
	}
}
```

```go:line-numbers=41 [原文]
func Init(h Interface) {
	// heapify
	n := h.Len()
	for i := n/2 - 1; i >= 0; i-- {
		down(h, i, n)
	}
}
```

:::

## 前提知識

- **二分ヒープ**: 親が子より小さい（最小ヒープの場合）木です。配列で表すと、位置 `i` の子は `2i+1` と `2i+2` にあります。
- **`down(h, i, n)`**: 位置 `i` の要素を、子と比べながら下へ沈める関数です。`n` は有効な要素数です。
- **`n/2 - 1`**: 葉でない最後の親の位置です。`n` 個の要素では、位置 `n/2` より後ろは葉（子のない要素）になります。
- **`Interface`**: `Len`、`Less`、`Swap` などを持つ型です。ヒープはこの型を使って操作します。

## 何をしているか

`h = [3, 1, 2]`（`n = 3`）で追います。

### 1. 最後の親から始める

```go:line-numbers=43
	n := h.Len()
	for i := n/2 - 1; i >= 0; i-- {
		down(h, i, n)
	}
```

`n/2 - 1 = 0` なので、ループは位置 0 だけを処理します。位置 0 の `3` は、子の `1` と `2` のうち小さい `1` と比べられ、`3 > 1` なので入れ替わります。結果は `[1, 3, 2]` です。

### 2. 子がいない要素は何もしない

位置 1 と 2 は葉なので、`down` を呼ぶ必要がありません。`n/2 - 1` より後ろを飛ばしているのは、この無駄を省くためです。

## ここがすごい

- **後ろから順に沈める**: 子の部分木が先にヒープになっているので、親を沈めるときにはもう下の部分がヒープの形になっています。根に向かって処理を進めることで、全体がヒープになります。
- **1 つずつ追加するより速い**: `Push` を `n` 回すると、1 回ごとに高さ分の比較が必要になり、合計は n log n です。`Init` は、葉の多くが沈める必要がないことを使って、全体を O(n) で済ませます。
- **葉を数えずに飛ばす**: 葉の半分以上は、子を持たないので処理が要りません。`n/2 - 1` という式だけで、その範囲を正確に決めています。

## まとめ

- ばらばらのデータからヒープを作るなら、1 つずつ追加するより `Init` で一括に並べるほうが速い。
- 後ろの親から順に沈めると、下の部分が先に整った状態で上に進める。
- 葉は沈める必要がないので、処理の範囲を親だけに絞れる。
