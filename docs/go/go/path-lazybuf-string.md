## ひとことで

`b.string()` は、パスを整理した結果の文字列を返します。元のパスの文字を書き換えていなければ、元の文字列の先頭の一部をそのまま返します。書き換えていれば、バッファの内容から新しい文字列を作ります。

パスの整理（`path.Clean` など）は、多くの場合、元の文字列をほとんど変えません。その場合にコピーを作らないことで、無駄なメモリを節約します。

## コード

```go:line-numbers=46
func (b *lazybuf) string() string {
	if b.buf == nil {
		return b.s[:b.w]
	}
	return string(b.buf[:b.w])
}
```

## 前提知識

- **遅延バッファ（lazybuf）**: 書き換えが必要になるまで、新しいバッファを作らずに、元の文字列を読むだけの仕組みです。
- **`b.buf`**: 書き換えが起きたときだけ作られる、新しいバイト列です。`nil` なら、まだ書き換えは起きていません。
- **`b.w`**: 結果の長さです。整理の途中で、どこまで有効な文字が書けたかを表します。
- **文字列とバイト列の変換**: `string(b.buf[:b.w])` は、バイト列の一部を新しい文字列にします。コピーが発生します。

## 何をしているか

### 1. 書き換えがなければ元の文字列を切り出す

```go:line-numbers=47
	if b.buf == nil {
		return b.s[:b.w]
	}
```

`buf` が作られていなければ、文字は一つも書き換えられていません。元の文字列 `s` の先頭から `w` 文字までを切り出して返します。切り出しはコピーを作らず、元の文字列の一部を指すだけです。

### 2. 書き換えがあればバッファから作る

```go:line-numbers=50
	return string(b.buf[:b.w])
```

書き換えが起きていれば、`buf` の先頭から `w` 文字を、新しい文字列にして返します。この時点で、コピーが一度だけ行われます。

## ここがすごい

- **コピーを先送りする**: 書き換えが起きなければ、一度もコピーしません。多くのパスで、この速い道が使われます。
- **書き換えと切り出しを分ける**: 書き換えの有無を `buf` の有無で判断するので、どちらの場合も同じ `string` 呼び出しで済みます。
- **結果の長さで切る**: `w` を使って、有効な部分だけを返します。余った領域は、結果に含まれません。

## まとめ

- `lazybuf.string` は、パスの整理の結果を文字列で返します。
- 書き換えがなければ、元の文字列の一部を切り出します。
- 書き換えがあったときだけ、バッファから新しい文字列を作ります。
