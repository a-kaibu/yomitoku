## ひとことで

`binary.AppendUvarint(buf, x)` は、符号なし整数 `x` を **varint（可変長整数）** という形式でバイト列 `buf` の末尾に追加します。
varint では、小さい数は少ないバイト数で表せます。`1` なら 1 バイト、`300` なら 2 バイト、64 ビットの最大値でも 10 バイトです。

ふつう 64 ビット整数は常に 8 バイト使いますが、実際のデータには小さい数が多いので、varint にするとデータがずっと小さくなります。

## コード

```go:line-numbers=41
func AppendUvarint(buf []byte, x uint64) []byte {
	for x >= 0x80 {
		buf = append(buf, byte(x)|0x80)
		x >>= 7
	}
	return append(buf, byte(x))
}
```

## 前提知識

- **`append(buf, v)`**: スライス `buf` の末尾に `v` を追加した新しいスライスを返す組み込み関数です。容量が足りなければ自動で広げます。だから結果を `buf =` で受け取り直す必要があります。
- **`byte(x)`**: 整数を下位 8 ビットだけの値（0〜255）に変換します。上の桁は捨てられます。
- **`0x80`**: 2 進数で `1000 0000`、最上位ビットだけが 1 の値です。`| 0x80` で最上位ビットを立てます。
- **`x >>= 7`**: `x` を 7 ビット右にずらして代入します。下位 7 ビットが消え、上の桁が降りてきます。

## 何をしているか

varint は、数を **7 ビットずつ** に分けて、下位から順に 1 バイトずつ書きます。各バイトの最上位ビット（8 ビット目）は「**まだ続きがある**」という印です。

`x = 300` で追います。300 は 2 進数で `1 0010 1100`（9 ビット）です。

### 1 回目（42〜45 行目）

`300 >= 128` なので、下位 7 ビット `010 1100`（0x2C）に続きの印を付けて `1010 1100`（0xAC）を追加します。`x >>= 7` で `x = 2` になります。

`byte(x)|0x80` は、`byte(300)` = `0010 1100`（上位が捨てられた値）に 0x80 を OR しています。最上位ビットは印で上書きされるので、7 ビットだけが残ります。

### 2 回目

`2 < 128` なのでループを抜けます。

### 最後のバイト（46 行目）

`2`（`0000 0010`）を印なしで追加します。結果は `[0xAC, 0x02]` の 2 バイトです。

読むときは、最上位ビットが 0 のバイトが来るまで読み、7 ビットずつを下位から積み上げれば元の数に戻ります（`Uvarint` 関数）。

## ここがすごい

- **小さい数ほど短い**: 0〜127 は 1 バイト、128〜16383 は 2 バイトです。個数や長さ、ID の差分など、現実のデータは小さい数が多いので、効果が大きい方式です。Google の Protocol Buffers や Go のバイナリ形式（gob）などでも同じ考え方が使われています。
- **区切りの情報をデータに埋め込む**: 各バイトの最上位ビットが「続く／終わり」を表すので、長さを別に書く必要がありません。
- **コードがとても短い**: `byte(x)|0x80` で「下位 7 ビットの取り出し」と「印を付ける」を一度に済ませています。`byte(x & 0x7f) | 0x80` と書くこともできますが、どうせ最上位は 1 で上書きするので `& 0x7f` は不要です。
- **`append` 形式の API**: 書き込み先を受け取って伸ばしたものを返す形なので、呼び出し側は既存のバッファを再利用でき、メモリ確保を減らせます。

## まとめ

- varint は 7 ビットずつに区切り、最上位ビットを「続きがある」の印にする可変長の整数表現。
- 小さい数が多いデータでは、固定長よりずっと小さくなる。
- 上書きされるビットのマスクは省ける。
- `append` で書き足して返す API は、バッファを使い回しやすい。
