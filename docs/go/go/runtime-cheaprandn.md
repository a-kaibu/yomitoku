## ひとことで

`cheaprandn(n)` は、**0 以上 `n` 未満** の乱数を返します。たとえば `cheaprandn(6)` はサイコロのように 0〜5 のどれかを返します。

ふつうは `rand() % n`（割った余り）と書きますが、割り算は CPU にとって重い計算です。この関数は **掛け算 1 回とシフト 1 回** で同じことをしています。

## コード

::: code-group

```go:line-numbers=319 [日本語訳]
func cheaprandn(n uint32) uint32 {
	// Lemire の手法を参照: https://lemire.me/blog/2016/06/27/a-fast-alternative-to-the-modulo-reduction/
	return uint32((uint64(cheaprand()) * uint64(n)) >> 32)
}
```

```go:line-numbers=319 [原文]
func cheaprandn(n uint32) uint32 {
	// See https://lemire.me/blog/2016/06/27/a-fast-alternative-to-the-modulo-reduction/
	return uint32((uint64(cheaprand()) * uint64(n)) >> 32)
}
```

:::

## 前提知識

- **`cheaprand()`**: 0 以上 2^32 未満の 32 ビットの乱数を返す関数です。
- **`uint64(...)`**: 32 ビットの値を 64 ビットに広げます。32 ビット同士の掛け算は最大 64 ビットになるので、あふれないように先に広げています。
- **`>> 32`**: 右に 32 ビットずらす、つまり 2^32 で割って小数点以下を切り捨てることです。
- **割り算のコスト**: 多くの CPU で、割り算（余りを含む）は掛け算の数倍〜数十倍の時間がかかります。

## 何をしているか

```go:line-numbers=321
	return uint32((uint64(cheaprand()) * uint64(n)) >> 32)
```

32 ビットの乱数 `x` を、0 以上 1 未満の小数 `x / 2^32` だとみなします。それに `n` を掛ければ 0 以上 `n` 未満の値になり、小数点以下を切り捨てれば 0〜n-1 の整数になります。

```
(x / 2^32) × n  を切り捨て  =  (x × n) >> 32
```

右辺は整数の掛け算とシフトだけで計算できます。

### 具体例（n = 6）

- `x = 0` → `0 × 6 >> 32 = 0`
- `x = 2^31`（ちょうど真ん中）→ `2^31 × 6 >> 32 = 3`
- `x = 2^32 - 1`（最大）→ `(2^32 - 1) × 6 >> 32 = 5`

0〜2^32-1 の範囲が、6 つの区間に分けられて 0〜5 に対応します。

## ここがすごい

- **割り算ゼロ**: 掛け算とシフトだけなので、`%` を使うよりかなり速くなります。コメントにある Daniel Lemire 氏のブログ記事で紹介された手法です。
- **上位ビットを使う**: `% n` は乱数の **下位** ビットに強く影響されますが、この方法は **上位** ビットで値が決まります。多くの簡易な乱数は下位ビットの質が悪いので、上位を使うほうが安全です。
- **割り切れない偏りは「安い乱数」として許容**: 2^32 が `n` で割り切れないとき、どちらの方法でもわずかな偏りが出ます。厳密に偏りをなくしたい `math/rand/v2` では、この方法に「ごく稀に引き直す」処理を加えています。ランタイム内部では、そこまでの厳密さより速さを優先しています。

## まとめ

- 乱数を 0〜n-1 に収めるのは、`% n` の代わりに「n を掛けて上位を取る」でもできる。
- 掛け算とシフトは割り算よりずっと速い。
- 乱数の上位ビットを使うほうが、品質の面でも有利なことが多い。
- 偏りをどこまで気にするかは用途で決める。
