## ひとことで

`Len64` は、ある整数を 2 進数で表すのに **最低何ビット必要か** を返します。
たとえば `5` は `101` なので `3`、`255` は `11111111` なので `8`、`256` は `100000000` なので `9` です。`0` のときは `0` です。

言い換えると「いちばん左にある 1 が何桁目か」を求める関数で、`log2` の整数版としてもよく使われます。

## コード

```go:line-numbers=337
func Len64(x uint64) (n int) {
	if x >= 1<<32 {
		x >>= 32
		n = 32
	}
	if x >= 1<<16 {
		x >>= 16
		n += 16
	}
	if x >= 1<<8 {
		x >>= 8
		n += 8
	}
	return n + int(len8tab[uint8(x)])
}
```

`len8tab` は同じパッケージ（`bits_tables.go`）にある 256 要素の表で、`len8tab[i]` に「`i` を表すのに必要なビット数」が入っています。

## 前提知識

- **`(n int)` という戻り値**: Go では戻り値に名前を付けられます。`n` は関数の最初で `0` に初期化された変数として使え、最後の `return` で返されます。
- **`1<<32`**: 1 を 32 ビット左にずらした値、つまり 2 の 32 乗です。`x >= 1<<32` は「上位 32 ビットのどこかに 1 があるか」を調べています。
- **`x >>= 32`**: `x = x >> 32` の省略形です。上位 32 ビットを下に降ろします。
- **`n += 16`**: `n = n + 16` の省略形です。
- **`uint8(x)`**: `x` の下位 8 ビットだけを取り出して 0〜255 の値にする型変換です。

## 何をしているか

`x = 0x1234`（2 進数で `1 0010 0011 0100`、13 ビット）で追います。

### 1. 上位 32 ビットにあるか（338〜341 行目）

`0x1234 < 2^32` なので何もしません。もし大きければ、`x` を 32 ビット右に降ろして `n` に 32 を足します。「上の半分に 1 があるなら、少なくとも 32 ビットは必要。残りは上の半分だけ調べればよい」という考え方です。

### 2. 16 ビットで同じことをする（342〜345 行目）

`0x1234 < 2^16` なので何もしません。

### 3. 8 ビットで同じことをする（346〜349 行目）

`0x1234 >= 256` なので、`x >>= 8` で `x = 0x12`、`n = 8` になります。

### 4. 最後の 8 ビットは表で（350 行目）

`0x12 = 18`（`10010`、5 ビット）なので `len8tab[18] = 5` です。答えは `8 + 5 = 13` になります。

## ここがすごい

- **二分探索になっている**: 「上半分にあるか？」を 32 → 16 → 8 と幅を半分にしながら調べるので、64 ビットでもたった 3 回の比較で範囲が 8 ビットまで絞れます。1 ビットずつ調べると最大 64 回かかります。
- **最後は表引きで打ち切る**: 4・2・1 ビットと続けることもできますが、256 要素（256 バイト）の表なら CPU のキャッシュに収まるほど小さく、比較 3 回分を 1 回の読み出しで済ませられます。**計算と表のバランス** をうまく取っています。
- **`0` の特別扱いがいらない**: `len8tab[0] = 0` なので、`x = 0` でもどの `if` にも入らずに `0` が返ります。
- **専用命令の予備**: 多くの CPU には「先頭の 0 を数える」命令（x86 の `LZCNT` など）があり、Go のコンパイラはこの関数をそれに置き換えます。この実装はそうした命令がないときのためのものです。

## まとめ

- 必要なビット数は「範囲を半分ずつ狭める」二分探索で少ない比較回数で求まる。
- 細かいところは小さな表に任せると、比較の回数をさらに減らせる。
- Go の名前付き戻り値は、初期値 0 の変数として使える。
