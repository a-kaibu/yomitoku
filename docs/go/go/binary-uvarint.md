## ひとことで

`binary.Uvarint(buf)` は、varint（7 ビットずつに区切った可変長整数）で書かれたバイト列から **整数を 1 つ読み取り、その値と使ったバイト数** を返します。
`[]byte{0xAC, 0x02}` なら `(300, 2)` です。

この関数は、壊れたデータや悪意あるデータを受け取っても正しく失敗するように作られています。2 つ目の戻り値 `n` の **符号** で、成功・データ不足・桁あふれを区別します。

## コード

```go:line-numbers=68
func Uvarint(buf []byte) (uint64, int) {
	var x uint64
	var s uint
	for i, b := range buf {
		if i == MaxVarintLen64 {
			// Catch byte reads past MaxVarintLen64.
			// See issue https://golang.org/issues/41185
			return 0, -(i + 1) // overflow
		}
		if b < 0x80 {
			if i == MaxVarintLen64-1 && b > 1 {
				return 0, -(i + 1) // overflow
			}
			return x | uint64(b)<<s, i + 1
		}
		x |= uint64(b&0x7f) << s
		s += 7
	}
	return 0, 0
}
```

`MaxVarintLen64` は 10 です。64 ビットの整数は varint で最大 10 バイトになるからです。

## 前提知識

- **varint**: 整数を下位から 7 ビットずつに分け、1 バイトずつ書く形式です。各バイトの最上位ビットが 1 なら「まだ続く」、0 なら「これで終わり」です。
- **`b & 0x7f`**: バイトの下位 7 ビットを取り出します（`0x7f` = `0111 1111`）。
- **`x |= v << s`**: `v` を `s` ビット左にずらして `x` に OR します。7 ビットずつの断片を、正しい位置に積み上げています。
- **`for i, b := range buf`**: `buf` の位置 `i` と値 `b` を先頭から順に取り出して繰り返します。
- **複数の戻り値**: Go では `(uint64, int)` のように複数の値を返せます。エラーを例外ではなく戻り値で表すのが Go の流儀です。

## 何をしているか

`buf = [0xAC, 0x02]` で追います。

### 1 バイト目（i = 0、b = 0xAC）

`0xAC >= 0x80` なので続きがあります。下位 7 ビット `0x2C`（44）を `s = 0` の位置に置いて `x = 44`。`s = 7`。

### 2 バイト目（i = 1、b = 0x02）

`0x02 < 0x80` なので終わりです（77 行目）。`x | 2 << 7 = 44 + 256 = 300` と、使ったバイト数 `2` を返します。

### 戻り値の意味

- `n > 0`: 成功。`n` は読んだバイト数
- `n == 0`: バイト列が途中で終わった（データ不足、86 行目）
- `n < 0`: 桁あふれ。`-n` は問題が見つかった位置まで読んだバイト数

### 桁あふれの検出（72〜80 行目）

64 ビットは 7 ビット × 9 = 63 ビットに、最後の 1 ビットを足した長さです。だから

- 10 バイト目でも終わらない（11 バイト目に進もうとする）なら、あふれ確定（72〜76 行目）
- 10 バイト目（`i == 9`）が来たとき、その値が 1 より大きいと 64 ビットに収まらない（78〜80 行目）

のどちらかでエラーにします。

## ここがすごい

- **3 つの状態を 1 つの整数で**: 「成功・不足・あふれ」を `n` の正・ゼロ・負で表すので、戻り値を増やさずに済みます。負の値の大きさから、どこまで読んだかもわかります。
- **悪意あるデータへの備え**: 72〜76 行目は、コメントにある issue 41185 で追加されたチェックです。続きの印が付いたバイトが延々と続くデータを渡されても、10 バイト以上は読み進めません。シフト量 `s` が大きくなりすぎて結果がおかしくなることも防いでいます。
- **最後のバイトの精密なチェック**: 10 バイト目は 1 ビットしか使えないことを正確に計算し、`b > 1` で判定しています。「だいたい大丈夫」ではなく、ビット単位で正しい境界を守っています。

## まとめ

- 外部から来るデータを読むときは、長すぎる・短すぎる入力に備えて、上限を決めて読む。
- 戻り値の符号で複数の状態を表すと、API を小さく保てる。
- 7 ビット × 9 + 1 ビット = 64 ビット、のようにビット数を正確に数えて境界を決める。
