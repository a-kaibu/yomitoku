## ひとことで

`heap.Fix(h, i)` は、ヒープの `i` 番目の要素の値を書き換えた後に呼ぶと、**その要素を正しい位置に移してヒープを元どおりにする** 関数です。
たとえばタスクの優先度を途中で変えたいとき、要素を一度取り除いて入れ直すより安く済みます。

中身はたった 3 行ですが、「値が大きくなったのか小さくなったのか」を呼び出し側に聞かずに正しく直す工夫があります。

## コード

```go:line-numbers=83
func Fix(h Interface, i int) {
	if !down(h, i, h.Len()) {
		up(h, i)
	}
}
```

## 前提知識

- **二分ヒープ**: 「どの親も、自分の子以下」という性質を持つ木構造です。根が常に最小になります。
- **`down(h, i, n)`**: 要素を子と比べて下へ沈める関数です。少しでも動いたら `true` を返します。
- **`up(h, j)`**: 要素を親と比べて上へ浮かせる関数です。
- **`!`**: 真偽値の否定です。`!down(...)` は「`down` が `false` を返したら（動かなかったら）」という意味です。
- **`h.Len()`**: ヒープの要素数です。利用者が定義したメソッドを呼んでいます。

## 何をしているか

```go:line-numbers=84
	if !down(h, i, h.Len()) {
```

ヒープ `[1, 3, 2, 7, 5]` で考えます。

### 値を大きくした場合

位置 1 の `3` を `8` に変えると `[1, 8, 2, 7, 5]`。子（`7` と `5`）より大きいのでヒープ条件が崩れています。
`down` を呼ぶと、小さいほうの子 `5` と入れ替わって `[1, 5, 2, 7, 8]` になり、`true` が返ります。`up` は呼ばれません。

### 値を小さくした場合

位置 3 の `7` を `0` に変えると `[1, 3, 2, 0, 5]`。親（`3`）より小さいので崩れています。
`down` を呼んでも、位置 3 には子がいないので動かず、`false` が返ります。そこで `up` を呼ぶと、`3`、`1` と順に入れ替わって `[0, 1, 2, 3, 5]` になります。

### 値が変わらなかった（または位置が正しい）場合

`down` も `up` も、比較 1〜2 回で何もせずに終わります。

## ここがすごい

- **場合分けを呼び出し側に押しつけない**: 値が増えたなら下へ、減ったなら上へ動かせばよいのですが、Fix は「どちらに変わったか」を受け取りません。代わりに **まず下を試し、動かなかったら上を試す** ことで、両方の場合を正しく扱います。
- **両方動くことはない**: 下に動いた要素は「子より大きかった」ので、親との関係はもともと正しく（親 ≤ 元の値 ≤ ... の関係は崩れていない）、上へ動かす必要はありません。だから `down` が成功したら `up` を省けます。
- **取り除いて入れ直すより速い**: `Remove` してから `Push` すると、それぞれ log n の操作が 2 回ずつ必要です。Fix なら最大でも片方向に 1 回です。

## まとめ

- ヒープの要素の値が変わったら、上か下のどちらか一方へ動かせば直る。
- 「先に片方を試し、だめならもう片方」と書けば、呼び出し側に場合分けを求めずに済む。
- 小さな関数の戻り値（動いたかどうか）が、こうした組み合わせを可能にしている。
