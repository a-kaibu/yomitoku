## ひとことで

`subtle.ConstantTimeCompare(x, y)` は、2 つのバイト列が等しければ `1`、違えば `0` を返します（`crypto/subtle` パッケージの公開関数の実体です）。
やっていることは `bytes.Equal` と同じですが、**違いが見つかってもすぐには止まらず、必ず最後まで調べます**。

パスワードのハッシュや、通信の改ざん検出コード（MAC）を比べるときに使います。

## コード

```go:line-numbers=17
func ConstantTimeCompare(x, y []byte) int {
	if len(x) != len(y) {
		return 0
	}

	var v byte

	for i := 0; i < len(x); i++ {
		v |= x[i] ^ y[i]
	}

	return constanttime.ByteEq(v, 0)
}
```

## 前提知識

- **タイミング攻撃**: 処理にかかる時間の差から秘密を推測する攻撃です。ふつうの比較は「最初に違うバイトが見つかった時点で終わる」ので、先頭の何バイトが合っているかで時間がわずかに変わります。攻撃者はこれを何度も測り、1 バイトずつ正解を当てていけます。
- **`^`（XOR）**: 桁ごとに「違えば 1、同じなら 0」にする演算です。`x[i] ^ y[i]` は、2 つのバイトが同じなら 0、違えばどこかのビットが 1 になります。
- **`|=`**: OR して代入します。一度 1 になったビットは、その後何を OR しても 1 のままです。
- **`var v byte`**: 型 `byte` の変数 `v` を宣言します。Go では宣言した変数は自動で 0 に初期化されます。

## 何をしているか

### 1. 長さが違えば 0

```go:line-numbers=18
	if len(x) != len(y) {
		return 0
	}
```

長さは秘密ではない（たとえばハッシュの長さは決まっている）という前提で、長さが違えばすぐに 0 を返します。

### 2. 全バイトの違いを集める

```go:line-numbers=22
	var v byte

	for i := 0; i < len(x); i++ {
		v |= x[i] ^ y[i]
	}
```

`x = [0x61, 0x62, 0x63]`、`y = [0x61, 0x78, 0x63]` で追います。

| i | `x[i] ^ y[i]` | `v` |
| --- | --- | --- |
| 0 | `0x00` | `0x00` |
| 1 | `0x62 ^ 0x78 = 0x1A` | `0x1A` |
| 2 | `0x00` | `0x1A` |

2 バイト目で違いが見つかっても、ループは止まりません。どこで違っても、違っていなくても、**ループの回数は同じ** です。

### 3. 最後に 1 回だけ判定

```go:line-numbers=28
	return constanttime.ByteEq(v, 0)
```

`v` が 0 なら全バイトが一致していたということです。`constanttime.ByteEq(v, 0)` で、0 なら 1、そうでなければ 0 を返します。この判定も分岐を使わない関数で行われます。

## ここがすごい

- **時間が中身に依存しない**: どの位置で違っていても、ループは同じ回数だけ回り、毎回同じ演算（XOR と OR）をします。だから計測された時間から「何バイト目まで合っていたか」を知ることができません。
- **OR で「一度でも違ったか」を覚える**: `if` で「違ったらフラグを立てる」と書くと、分岐によって時間が変わるおそれがあります。`v |= ...` なら分岐なしで同じことができます。
- **シンプルさが安全性の根拠**: 13 行しかないので、時間が変わる要素がないことを人間が目で確認できます。暗号のコードでは、この「確認しやすさ」がとても大切です。

ふつうの用途では `bytes.Equal` のほうが速い（違いがあればすぐ止まる）ので、**秘密の値を比べるときだけ** この関数を使い分けます。

## まとめ

- 秘密の値を比べるときは、途中で止まる比較を使うと時間差から情報が漏れる。
- XOR で違いを取り出し、OR で集めると、分岐なしに「すべて一致したか」がわかる。
- 暗号のコードでは、速さより「処理時間が一定であること」を優先する場面がある。
