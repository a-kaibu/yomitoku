## ひとことで

`xorshift` は、George Marsaglia が考案した **とても軽い疑似乱数生成器** です。
内部の値を「左に 13 ずらして XOR」「右に 7 ずらして XOR」「左に 17 ずらして XOR」するだけで、次の乱数ができます。
Go の `slices` パッケージでは、ソートの最悪ケースを避けるためにデータを少しかき混ぜる用途（`breakPatterns`）で使われています。

## コード

```go:line-numbers=186
func (r *xorshift) Next() uint64 {
	*r ^= *r << 13
	*r ^= *r >> 7
	*r ^= *r << 17
	return uint64(*r)
}
```

型は 184 行目で `type xorshift uint64` と定義されています。64 ビット整数に名前を付けただけの型です。

## 前提知識

- **型定義 `type xorshift uint64`**: 既存の型をもとに新しい型を作ります。`xorshift` は中身は `uint64` ですが、独自のメソッド（ここでは `Next`）を持てます。
- **ポインタレシーバ `(r *xorshift)`**: メソッドが値そのものを書き換えられるように、ポインタで受け取っています。`*r` は「`r` が指している値」です。
- **`^=`**: XOR（排他的論理和）して代入します。XOR は、桁ごとに「違えば 1、同じなら 0」にする演算です。
- **疑似乱数**: 計算で作る、乱数のように見える数の列です。同じ初期値（種）からは同じ列が出ます。

## 何をしているか

### 1. 状態を 3 回かき混ぜる（187〜189 行目）

8 ビットで雰囲気をつかむため、`x = 0000 0001` に「左 1 ずらして XOR」を考えると、

```
x      = 0000 0001
x << 1 = 0000 0010
XOR    = 0000 0011
```

ビットが隣に「にじむ」ように広がります。左シフトで上位へ、右シフトで下位へにじませることを繰り返すと、1 つのビットの変化が全体に広がっていきます。
13、7、17 という量は、Marsaglia の論文で「64 ビットの状態で、0 以外のすべての値を一巡する（周期が 2^64 - 1 になる）」ことが確かめられた組み合わせの 1 つです。

### 2. 値を返す（190 行目）

かき混ぜた後の状態をそのまま乱数として返します。状態は `*r` に書き戻されているので、次の呼び出しではここから続きます。

### 種が 0 だと

状態が 0 だと、何度ずらして XOR しても 0 のままです。`breakPatterns` では種に配列の長さ（8 以上）を使うので、0 になることはありません。

## ここがすごい

- **極端に軽い**: 掛け算も割り算もなく、シフトと XOR が 3 回ずつだけです。乱数の質より速さが大事な場面にぴったりです。
- **目的に合った道具選び**: 暗号用の乱数や高品質な乱数（`math/rand/v2` の PCG や ChaCha8）は、ソートのパターン崩しには重すぎます。「ほどほどにばらければよい」用途に、最小限の道具を使っています。
- **型にメソッドを付けるだけ**: `uint64` に名前を付けてメソッドを 1 つ足すだけで、乱数生成器という「オブジェクト」になります。構造体すら要りません。Go の型定義の手軽さがよくわかる例です。

## まとめ

- xorshift は、シフトと XOR を 3 回繰り返すだけで作れる高速な疑似乱数。
- シフト量の組み合わせには数学的な裏付けがあり、適当に選ぶと周期が短くなる。
- 種が 0 だと動かないので注意する。
- 用途に合わせて、乱数の質とコストのバランスを選ぶ。
