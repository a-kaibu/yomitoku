## ひとことで

CRC の表は、256 個の数値からなります。それが正しく作られたかを、1 つの値で確かめたいことがあります。`tableSum(t)` は、表の全部の値を並べたバイト列の CRC-32 を計算して、表全体の「指紋」にします。

表を手で書き換えたり、作り方を変えたりしたとき、指紋が変わったことで、誤りに気づけます。

## コード

```go:line-numbers=249
func tableSum(t *Table) uint32 {
	var a [1024]byte
	b := a[:0]
	if t != nil {
		for _, x := range t {
			b = byteorder.BEAppendUint32(b, x)
		}
	}
	return ChecksumIEEE(b)
}
```

## 前提知識

- **指紋（チェックサム）**: 大きなデータを、短い値にまとめたものです。元のデータが少しでも違えば、指紋も違う可能性が高くなります。
- **ビッグエンディアン**: 数値のバイトを、上位から並べる書き方です。`BEAppendUint32` は、32 ビットの値を、上位のバイトから追加します。
- **`nil` の表**: 表がない場合は、指紋を計算しません。`if t != nil` で、そのときは空のバイト列の指紋になります。
- **`ChecksumIEEE`**: バイト列の IEEE の CRC-32 を求める関数です。

## 何をしているか

### 1. 作業用のバッファを用意する

```go:line-numbers=250
	var a [1024]byte
	b := a[:0]
```

表の 256 個の値を 4 バイトずつ並べると、1024 バイトになります。そこで、1024 バイトの配列を用意して、その空のスライスを `b` とします。配列はスタックに置かれるので、ヒープを使いません。

### 2. 表の値を並べる

```go:line-numbers=253
		for _, x := range t {
			b = byteorder.BEAppendUint32(b, x)
		}
```

表の値を 1 つずつ取り出して、ビッグエンディアンの 4 バイトとして `b` の後ろに追加します。表の並びが、そのままバイト列の並びになります。

### 3. バイト列の CRC を返す

```go:line-numbers=257
	return ChecksumIEEE(b)
```

並べたバイト列の IEEE の CRC-32 を計算して返します。これが表全体の指紋です。

## ここがすごい

- **スタックのバッファで完結する**: 作業用のバイト列を配列で用意するので、表の指紋を取るたびに、ヒープを確保しません。
- **表全体を 1 つの値で比べられる**: 256 個の数値を、1 つの 32 ビットの値にまとめるので、テストでの比較が 1 行で書けます。
- **値の順番も指紋に含まれる**: 並べる順番が変わると、指紋も変わります。値が正しい場所にあるかも確かめられます。

## まとめ

- `tableSum` は、CRC の表の値を並べて、その CRC-32 を指紋として返します。
- 作業用のバイト列は、スタックの配列で用意します。
- 表の値はビッグエンディアンで並べられます。
- 指紋を比べることで、表の作り方の誤りを確かめられます。
