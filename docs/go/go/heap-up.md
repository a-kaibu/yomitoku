## ひとことで

`up` は、二分ヒープ（いちばん小さい値をすぐ取り出せるデータ構造）の要素を **親と比べて、親より小さければ入れ替える** ことを繰り返し、正しい位置まで浮かび上がらせる関数です。
`heap.Push` で末尾に追加した値を、正しい位置に移すために使われます。

## コード

::: code-group

```go:line-numbers=89 [日本語訳]
func up(h Interface, j int) {
	for {
		i := (j - 1) / 2 // 親
		if i == j || !h.Less(j, i) {
			break
		}
		h.Swap(i, j)
		j = i
	}
}
```

```go:line-numbers=89 [原文]
func up(h Interface, j int) {
	for {
		i := (j - 1) / 2 // parent
		if i == j || !h.Less(j, i) {
			break
		}
		h.Swap(i, j)
		j = i
	}
}
```

:::

## 前提知識

- **二分ヒープ**: 木の形をしたデータ構造で、「どの親も、自分の子以下の値」という性質（ヒープ条件）を持ちます。だから根（いちばん上）は常に最小値です。
- **配列で表す木**: ヒープは配列 1 本で表せます。位置 `i` の要素の子は `2i+1` と `2i+2`、親は `(i-1)/2` です。ポインタを使わずに木を表現できます。
- **インターフェース `Interface`**: `container/heap` は具体的な型を知りません。利用者が `Len`・`Less`・`Swap`（と `Push`・`Pop`）というメソッドを持つ型を用意し、ヒープはそのメソッドだけを使って操作します。`h.Less(j, i)` は「j 番目は i 番目より小さいか」です。
- **`for { ... }`**: 条件のない無限ループです。`break` で抜けます。
- **整数の割り算**: Go の整数同士の `/` は小数点以下を切り捨てます（0 に向かって）。`(0-1)/2` は `0` になります。

## 何をしているか

```go:line-numbers=92
		if i == j || !h.Less(j, i) {
```

ヒープ `[1, 3, 2, 7, 5]` の末尾に `0` を追加して `[1, 3, 2, 7, 5, 0]` になったとします。`j = 5` で `up` を呼びます。

### 1 回目

親は `(5-1)/2 = 2`（値 `2`）。`0 < 2` なので入れ替え → `[1, 3, 0, 7, 5, 2]`。`j = 2`。

### 2 回目

親は `(2-1)/2 = 0`（値 `1`）。`0 < 1` なので入れ替え → `[0, 3, 1, 7, 5, 2]`。`j = 0`。

### 3 回目

親は `(0-1)/2 = 0`。Go の整数の割り算は 0 に向かって切り捨てるので、`-1/2` は `0` です。`i == j` になったので終了します。

根に `0` が来て、ヒープ条件が回復しました。

## ここがすごい

- **根の判定に特別な条件がいらない**: `j = 0` のとき親の計算結果も `0` になる性質を使い、`i == j` という 1 つの条件で「根に着いた」を表しています。`if j == 0 { break }` を別に書く必要がありません。
- **比較と交換だけに頼る**: ヒープは要素の型を知らず、`Less` と `Swap` だけで動きます。数値でも、優先度付きのタスクでも、同じコードで扱えます。
- **速い**: 木の高さは要素数の log2 程度なので、100 万要素でも 20 回ほどの比較で終わります。

素直な方法（追加のたびに全体を並べ替える）だと、毎回 n log n の時間がかかります。ヒープなら追加 1 回あたり log n です。

## まとめ

- 二分ヒープは配列で表せ、親は `(i-1)/2`、子は `2i+1` と `2i+2`。
- 値を追加したら、親と比べて入れ替えながら上へ移すだけでヒープ条件が保たれる。
- インターフェースを使うと、データの型を知らずにアルゴリズムを書ける。
