## ひとことで

`Reverse64` は、64 ビット整数のビットの並びを **左右反転** した値を返します。
8 ビットで例えると `1100 0001` が `1000 0011` になります。いちばん左のビットがいちばん右へ、右から 2 番目が左から 2 番目へ…と移ります。

1 ビットずつ取り出して逆側に積み直すと 64 回のループが必要ですが、この関数は **「隣同士を入れ替える」を 6 段** 行うだけで終わります（最後の 3 段は `ReverseBytes64` に任せています）。

## コード

```go:line-numbers=253
func Reverse64(x uint64) uint64 {
	const m = 1<<64 - 1
	x = x>>1&(m0&m) | x&(m0&m)<<1
	x = x>>2&(m1&m) | x&(m1&m)<<2
	x = x>>4&(m2&m) | x&(m2&m)<<4
	return ReverseBytes64(x)
}
```

`m0`〜`m2` は同じファイルで定義されたマスク定数です。`m0 = 0x5555…`（`0101…`）、`m1 = 0x3333…`（`0011…`）、`m2 = 0x0f0f…`（`00001111…`）です。

## 前提知識

- **ビット演算子**: `&` は両方 1 の桁だけ 1、`|` はどちらかが 1 の桁を 1 にします。`<<`・`>>` はビット列を左右にずらします。
- **マスク**: `0101…` のような模様の値と `&` を取ると、その模様の 1 の位置にあるビットだけを取り出せます。
- **Go の演算子の優先順位**: Go では `<<`、`>>`、`&` は `*` と同じグループで、`|` や `+` より先に計算されます。`x>>1&(m0&m) | x&(m0&m)<<1` は `((x>>1)&m0) | ((x&m0)<<1)` と読みます。C 言語とは順位が違うので注意が必要です。
- **`const m = 1<<64 - 1`**: 64 ビットすべてが 1 の定数です。Go の定数は計算中に桁あふれしないので、このように書けます。64 ビット版では `&m` は何も変えませんが、32 ビット版などと形をそろえるために置かれています。

## 何をしているか

8 ビットの `x = abcd efgh`（各文字が 1 ビット）で考えます。

### 1. 1 ビットずつ隣と入れ替える

```go:line-numbers=255
	x = x>>1&(m0&m) | x&(m0&m)<<1
```

`x>>1 & m0` は各ペアの左ビットを右へ、`x & m0 << 1` は各ペアの右ビットを左へ移します。`|` で合わせると、

```
ab cd ef gh  →  ba dc fe hg
```

### 2. 2 ビットの組を入れ替える

```go:line-numbers=256
	x = x>>2&(m1&m) | x&(m1&m)<<2
```

同じことを `m1`（`0011…`）と 2 ビットのシフトで行います。

```
ba dc | fe hg  →  dcba | hgfe
```

### 3. 4 ビットの組を入れ替える

```go:line-numbers=257
	x = x>>4&(m2&m) | x&(m2&m)<<4
```

`m2` と 4 ビットのシフトで、

```
dcba hgfe  →  hgfe dcba
```

8 ビットならここで完全に反転しました。

### 4. 残りはバイトの並べ替え

```go:line-numbers=258
	return ReverseBytes64(x)
```

64 ビットでは、さらに 8・16・32 ビット単位の入れ替えが必要です。それは「バイトの順番を逆にする」のと同じなので、`ReverseBytes64` を呼んで任せます。

## ここがすごい

- **分割統治をビットでやっている**: 「全体を反転 = 前半と後半を入れ替えて、それぞれを反転」という再帰的な考え方を、すべての組で **同時に** 実行しています。64 ビットなら log2(64) = 6 段で終わります。
- **部品の再利用**: 後半 3 段は「バイト順の反転」と完全に同じなので、自分で書かずに `ReverseBytes64` を呼んでいます。`ReverseBytes64` は多くの CPU で 1 命令（x86 の `BSWAP`）に置き換えられるので、速さの面でも得です。
- **兄弟関数と同じ形**: `Reverse8`、`Reverse16`、`Reverse32` も同じ構造で書かれていて、定数 `m` の幅だけが違います。一度理解すれば全部読めます。

素直なループとの比較では、ループ版は 64 回の「取り出す・ずらす・入れる」が必要で、分岐も入ります。この方法は分岐が無いので、入力によって速さが変わりません。

## まとめ

- 「隣と入れ替える」を幅を倍にしながら繰り返すと、ビット列全体が反転する。
- マスクとシフトを組み合わせると、多数の小さな操作を 1 回の演算で同時にできる。
- 共通部分は既存の関数（ここでは `ReverseBytes64`）に任せると、短く速くなる。
