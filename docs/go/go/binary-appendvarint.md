## ひとことで

`binary.AppendVarint(buf, x)` は、**符号付き**整数 `x`（マイナスもありうる数）を varint 形式でバイト列に追加します。
varint は小さい数ほど少ないバイト数で表せる形式ですが、そのままでは負の数がとても大きく見えてしまいます。そこで、この関数は **ジグザグ符号化** という変換を先に行います。

```
 0 → 0
-1 → 1
 1 → 2
-2 → 3
 2 → 4
```

絶対値が小さい数は、プラスでもマイナスでも小さな値になります。

## コード

```go:line-numbers=91
func AppendVarint(buf []byte, x int64) []byte {
	ux := uint64(x) << 1
	if x < 0 {
		ux = ^ux
	}
	return AppendUvarint(buf, ux)
}
```

## 前提知識

- **2 の補数**: コンピュータは負の数を「全ビットを反転して 1 を足した値」で表します。-1 は 64 ビットすべてが 1 です。符号なし整数として見ると、-1 は約 1800 京という巨大な数になります。
- **`uint64(x)`**: 符号付きの `x` を、ビットの並びはそのままに符号なし整数として扱います。
- **`<< 1`**: 1 ビット左にずらします（2 倍）。最上位ビット（符号）は押し出されて消え、最下位には 0 が入ります。
- **`^ux`**: 全ビットを反転します。
- **varint**: 7 ビットずつに分けて書く可変長整数で、小さい数ほど短くなります（`AppendUvarint`）。

## 何をしているか

### 1. 左に 1 ずらす（92 行目）

`ux := uint64(x) << 1` で、数を 2 倍にします。これで最下位ビットが空きます。

### 2. 負なら全ビットを反転（93〜95 行目）

負の数なら `^ux` で全ビットを反転します。

### 具体例

| x | `uint64(x) << 1` | 反転後 | 結果 |
| --- | --- | --- | --- |
| 2 | `...0100`（4） | ─ | 4 |
| -2 | `...1111 1100` | `...0000 0011` | 3 |
| -1 | `...1111 1110` | `...0000 0001` | 1 |

負の数 `x` では、2 の補数の性質から `^(x << 1)` は `-2x - 1` になります。-1 → 1、-2 → 3、-3 → 5 と、奇数に並びます。正の数は `2x` で偶数に並びます。こうして正と負が交互（ジグザグ）に並ぶのです。

### 3. 符号なし varint として書く（96 行目）

変換後の値は小さな正の数なので、`AppendUvarint` で書けば短いバイト列になります。-1 は 1 バイトで済みます（変換しないと 10 バイトになります）。

## ここがすごい

- **負の数でも短くなる**: 変換なしで -1 を varint にすると、全ビットが 1 なので 10 バイトかかります。ジグザグ符号化なら 1 バイトです。温度や座標の差分など、小さな負の数が多いデータで大きな差が出ます。
- **最下位ビットが符号になる**: 結果の最下位ビットが 0 なら正、1 なら負です。符号の情報を「最も短く書ける場所」に移動させた、と考えることもできます。
- **分岐なしでも書ける形**: ここでは `if` を使っていますが、同じ変換は `(x << 1) ^ (x >> 63)` と分岐なしでも書けます（算術右シフトで全 0 か全 1 のマスクを作る）。Protocol Buffers の `sint64` 型も同じ符号化を使っています。
- **既存の部品の再利用**: 変換さえすれば、あとは符号なし版の `AppendUvarint` に任せるだけです。

## まとめ

- 2 の補数の負の数は、符号なしとして見ると巨大なので、varint にそのまま書くと長くなる。
- ジグザグ符号化は 0, -1, 1, -2, 2 … を 0, 1, 2, 3, 4 … に対応させ、負の数も短く書けるようにする。
- 変換はシフトとビット反転だけでできる。
