## ひとことで

`utf8.RuneStart(b)` は、バイト `b` が文字の **先頭** のバイトかを返します。`'a'`（0x61）は先頭なので `true` です。`0x81` のような続きのバイトは `false` です。

文字列の途中から読み始めたときに、どこが文字の境界かを探すために使われます。

## コード

```go:line-numbers=457
func RuneStart(b byte) bool { return b&0xC0 != 0x80 }
```

## 前提知識

- **UTF-8 の続きのバイト**: 2 バイト目以降は、必ず `10xxxxxx` の形です。上位 2 ビットが `10` になります。
- **先頭のバイト**: ASCII は `0xxxxxxx`、先頭のバイトは `11xxxxxx`、または ASCII の `0xxxxxxx` です。上位 2 ビットが `10` 以外なら、先頭です。
- **`&` とマスク**: `b & 0xC0` は、上位 2 ビットだけを取り出します。`0xC0` は `11000000` です。
- **`!=`**: 比べて違うなら `true` です。

## 何をしているか

```go:line-numbers=457
func RuneStart(b byte) bool { return b&0xC0 != 0x80 }
```

`b = 0x81`（「あ」の続きのバイトの 1 つ）で追います。

### 1. 上位 2 ビットを取り出す

`0x81` は `10000001` です。`b & 0xC0`（`11000000`）を取ると、`10000000`（0x80）になります。

### 2. 続きの印と比べる

`0x80 != 0x80` は偽なので、`RuneStart(0x81)` は `false` です。

`b = 'a'`（0x61、`01100001`）では、`b & 0xC0` は `01000000`（0x40）になります。`0x40 != 0x80` なので `true` です。

## ここがすごい

- **判定が 1 行で済む**: 上位 2 ビットを見るだけなので、文字の長さや、範囲の表を調べる必要がありません。
- **UTF-8 の設計を利用**: 続きのバイトの形を `10` に決めたのは、UTF-8 の大きな工夫です。途中から読んでも、先頭を簡単に見つけられます。
- **再同期が速い**: 壊れたデータの途中から読み直すとき、続きのバイトを飛ばして先頭を探せます。どこから読んでも、近い文字の境界が見つかります。

## まとめ

- UTF-8 の続きのバイトは、上位 2 ビットが `10` と決まっている。
- その 2 ビットを見れば、先頭かどうかは 1 回の比較で分かる。
- 途中から読んでも文字の境界を探せるのは、UTF-8 の設計のおかげ。
