## ひとことで

`grow` は、`strings.Builder` の内部バッファ（書き込んだバイトをためておく場所）に、**あと `n` バイト以上書き込めるようにする** メソッドです。`Builder.Grow(n)` から、容量が足りないときだけ呼ばれます。

新しい容量は「今の容量の 2 倍 + `n`」です。少しずつ広げるのではなく大きく広げることで、何度も書き足したときのコピー回数を減らしています。

## コード

```go:line-numbers=66
func (b *Builder) grow(n int) {
	buf := bytealg.MakeNoZero(2*cap(b.buf) + n)[:len(b.buf)]
	copy(buf, b.buf)
	b.buf = buf
}
```

## 前提知識

- **スライスの長さと容量**: Go のスライスには「長さ（`len`、今入っている要素数）」と「容量（`cap`、確保済みの場所の大きさ）」があります。容量を超えて追加するには、より大きな場所を確保して中身を移す必要があります。
- **`copy(dst, src)`**: `src` の中身を `dst` にコピーする組み込み関数です。
- **`[:len(b.buf)]`**: 新しく確保したスライスの長さを、今の中身の長さにそろえています。容量は大きいまま、長さだけ短くした状態です。
- **ゼロ値初期化**: Go では `make([]byte, n)` で確保したメモリは必ず 0 で埋められます。安全ですが、そのぶん時間がかかります。
- **`bytealg.MakeNoZero`**: 標準ライブラリ内部専用の関数で、**0 で埋めずに** バイトスライスを確保します。ふつうのプログラムからは使えません。

## 何をしているか

今の中身が 10 バイト、容量 16、さらに 20 バイト書きたい（`n = 20`）とします。

### 1. 新しい場所を確保する

```go:line-numbers=67
	buf := bytealg.MakeNoZero(2*cap(b.buf) + n)[:len(b.buf)]
```

`2*cap(b.buf) + n = 2*16 + 20 = 52` バイトを確保します。0 埋めはしません。
そして `[:len(b.buf)]` で長さを 10 にします。容量は 52 のままです。

### 2. 中身を移す

```go:line-numbers=68
	copy(buf, b.buf)
```

古いバッファの 10 バイトを、新しいバッファの先頭にコピーします。

### 3. 差し替える

```go:line-numbers=69
	b.buf = buf
```

`b.buf` を新しいバッファにします。古いバッファは、もう誰からも使われなくなればガベージコレクタ（不要なメモリを自動で回収する仕組み）が回収します。ただし `String()` で返した文字列が古いバッファを指している場合は、その文字列が生きている間は残ります。古いバッファを書き換えないので、その文字列は壊れません。

## ここがすごい

- **倍々に広げる**: 1 バイトずつ書き足すたびに「必要なぶんだけ」広げると、毎回全体をコピーすることになり、合計で長さの 2 乗に比例する時間がかかります。容量を倍にすれば、コピーの合計は長さに比例する程度で済みます（償却計算量 O(1)）。
- **`+ n` で一度に足りるようにする**: 2 倍だけでは足りない大きな `n` が来ても、1 回の拡張で必ず収まります。
- **ゼロ埋めを省く**: 新しいバッファの中身は、先頭は直後にコピーで上書きされ、残りは「長さの外」なので読まれる前に必ず書き込まれます。だから 0 で埋めておく意味がありません。`MakeNoZero` でその無駄を省いています。安全性を保てる範囲を見極めた、標準ライブラリならではの最適化です。

## まとめ

- 可変長のバッファは、容量を倍々に増やすとコピーの総量を抑えられる。
- 「直後に必ず上書きする場所」の初期化は省ける。
- 古いバッファを書き換えずに新しい場所へ移ることが、コピーなしで返した文字列の安全性を支えている。
