## ひとことで

`OnesCount64` は、64 ビットの整数を 2 進数で書いたときに **`1` が何個あるか**（ポピュレーションカウント、略して popcount）を返す関数です。
たとえば `13` は 2 進数で `1101` なので、答えは `3` です。

素直に書けば「64 回ループして 1 ビットずつ調べる」ところを、この関数は **ループを 1 回も回さず**、数回の足し算とシフトだけで答えを出します。

## コード

```go:line-numbers=140
func OnesCount64(x uint64) int {
	// Implementation: Parallel summing of adjacent bits.
	// See "Hacker's Delight", Chap. 5: Counting Bits.
	// The following pattern shows the general approach:
	//
	//   x = x>>1&(m0&m) + x&(m0&m)
	//   x = x>>2&(m1&m) + x&(m1&m)
	//   x = x>>4&(m2&m) + x&(m2&m)
	//   x = x>>8&(m3&m) + x&(m3&m)
	//   x = x>>16&(m4&m) + x&(m4&m)
	//   x = x>>32&(m5&m) + x&(m5&m)
	//   return int(x)
	//
	// Masking (& operations) can be left away when there's no
	// danger that a field's sum will carry over into the next
	// field: Since the result cannot be > 64, 8 bits is enough
	// and we can ignore the masks for the shifts by 8 and up.
	// Per "Hacker's Delight", the first line can be simplified
	// more, but it saves at best one instruction, so we leave
	// it alone for clarity.
	const m = 1<<64 - 1
	x = x>>1&(m0&m) + x&(m0&m)
	x = x>>2&(m1&m) + x&(m1&m)
	x = (x>>4 + x) & (m2 & m)
	x += x >> 8
	x += x >> 16
	x += x >> 32
	return int(x) & (1<<7 - 1)
}
```

ここで使われている `m0`〜`m2` は、同じファイルの少し上（110〜112 行目）で次のように定義されている定数です。

```go
const m0 = 0x5555555555555555 // 01010101 ...
const m1 = 0x3333333333333333 // 00110011 ...
const m2 = 0x0f0f0f0f0f0f0f0f // 00001111 ...
```

## 前提知識

- **ビットと 2 進数**: コンピュータの整数は `0` と `1` の並び（ビット）で表されています。`uint64` は「符号なし 64 ビット整数」、つまり 64 個のビットが並んだ値です。
- **`>>`（右シフト）**: `x >> 1` はビット列全体を右に 1 つずらします。はみ出した右端のビットは消え、左端には `0` が入ります。
- **`&`（ビットごとの AND）**: 2 つの値を桁ごとに比べ、両方 `1` の桁だけ `1` にします。「マスク」と呼ばれる値と `&` を取ると、**必要な桁だけを取り出す**ことができます。
- **`0x`**: 16 進数の書き方です。16 進数の 1 桁はちょうど 2 進数の 4 桁に対応します。`0x5` は `0101`、`0x3` は `0011`、`0x0f` は `00001111` です。
- **Go の演算子の優先順位**: Go では `>>` と `&` は `*` と同じ強さで、`+` より先に計算されます。なので `x>>1&(m0&m) + x&(m0&m)` は `((x>>1) & m0) + (x & m0)` と読みます。**C 言語とは優先順位が違う**ので、C に慣れた人ほど注意が必要です。
- **`const m = 1<<64 - 1`**: Go の定数は計算中に桁あふれしないので、`2^64 - 1`（64 ビットすべてが `1`）をそのまま書けます。64 ビット版では `m` と `&` しても値は変わりませんが、32 ビット版など同じファイルの兄弟関数と形をそろえるために書かれています。

## 何をしているか

アイデアは **「となり同士を足す」を、範囲を倍々に広げながら繰り返す** ことです。トーナメント表を下から上へ集計していくイメージです。

わかりやすく 8 ビットの例 `x = 1101 1011`（1 は 6 個）で追ってみます。

### 1. 2 ビットずつのペアで数える（161 行目）

```
x        = 11 01 10 11
x & m0   = 01 01 00 01   ← 各ペアの右側のビット
x>>1 & m0= 01 00 01 01   ← 各ペアの左側のビット
足し算    = 10 01 01 10   ← 各ペアの 1 の個数（2, 1, 1, 2）
```

`m0` は `0101…` という模様なので、2 ビットごとの「右側」だけを取り出せます。右に 1 つずらしてから同じマスクを掛ければ「左側」が取れます。2 つを足すと、**各 2 ビットの枠の中に「その枠の 1 の個数」が入ります**。最大でも 2（`10`）なので、2 ビットの枠からあふれません。

### 2. 4 ビットずつにまとめる（162 行目）

`m1 = 0011…` で、今度は 2 ビットの枠どうしを足します。

```
10 01 | 01 10  →  0011 | 0011   （2+1=3, 1+2=3）
```

### 3. 8 ビットずつにまとめる（163 行目）

`(x>>4 + x) & m2` で 4 ビットの枠どうしを足し、8 ビット（1 バイト）ごとの個数にします。
ここでは **先に足してから 1 回だけマスク** しています。4 ビット枠の値は最大 4 で、2 つ足しても最大 8。8 は 4 ビット（最大 15）に収まるので、となりの枠に繰り上がりが漏れる心配がありません。だからマスクを 1 回省けるのです。

8 ビットの例ではここで `0000 0110`、つまり **6** が求まりました。

### 4. 残りはマスクなしで足すだけ（164〜166 行目）

64 ビットでは、8 バイトぶんの個数を合計する必要があります。`x += x >> 8`、`x += x >> 16`、`x += x >> 32` と足していくと、**いちばん下のバイトに全体の合計が集まります**。

上のほうのバイトにはゴミの値が残りますが、答えは最大でも 64 なので 7 ビットあれば足ります。最後の `& (1<<7 - 1)`（= `& 0b1111111`）で下位 7 ビットだけを取り出して完成です（167 行目）。

## ここがすごい

- **ループも if も無い**: 64 回の繰り返しが、わずか十数個の演算になります。分岐が無いので CPU の分岐予測を外すこともなく、どんな入力でも同じ速さで動きます。
- **1 つのレジスタを「たくさんの小さな箱」として使う**: 64 ビットの整数を 32 個・16 個・8 個の小さなカウンタの集まりとみなし、**1 回の足し算で全部の箱を同時に計算** しています。こうした手法は SWAR（SIMD Within A Register）と呼ばれます。
- **「あふれない」ことを見切ってマスクを省く**: どの段階で値が最大いくつになるかを計算し、不要なマスクを削っています。コメントにある通り、これは名著『ハッカーのたのしみ（Hacker's Delight）』の第 5 章に載っている手法です。
- **コメントが教科書になっている**: 141〜159 行目のコメントは、省略前の「素直な形」を示したうえで、どこをなぜ省いたかまで説明しています。読みやすさのために「さらに 1 命令減らせるがあえてやらない」と書いている点もよい判断です。

なお、Go のコンパイラは多くの CPU で `bits.OnesCount64` の呼び出しを CPU 専用の popcount 命令に置き換えます。この Go のコードは、そうした命令が使えないときにも速く動くための実装です。

## まとめ

- 「となり同士を足す」を倍々に広げると、ループなしで合計が求まる。
- 1 つの整数を小さな箱の集まりとして扱えば、複数の計算を一度にできる（SWAR）。
- 値の最大値を見積もれば、安全に処理を省ける。
- Go の演算子の優先順位は C と違うので、ビット演算の式は読むときに注意する。
