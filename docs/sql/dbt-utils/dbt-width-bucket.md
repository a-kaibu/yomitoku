## ひとことで

`width_bucket` は、数値を等間隔の区間（バケット）に振り分けて、その番号を返す関数です。データベースによっては組み込みの関数がありますが、この版は標準の関数だけで同じ働きを作っています。区間の境界ぴったりの値の扱いと、範囲外の値の扱いに工夫があります。

## コード

```sql:line-numbers=8
    {% set bin_size -%}
    (( {{ max_value }} - {{ min_value }} ) / {{ num_buckets }} )
    {%- endset %}
```

## 前提知識

- **バケット（区間）**: 値の範囲を等しい幅で切ったもの。ここでは、最小値から最大値までを区間の数で割る。
- **`mod(a, b)`**: `a` を `b` で割ったときの余り。余りが `0` なら、ちょうど割り切れる。
- **`ceil()`**: 小数点以下を切り上げる関数。
- **`least(a, b)`**: 2 つの値の小さい方を返す関数。
- **`dbt.safe_cast`**: 値を数値の型に変換する dbt のマクロ。

## 何をしているか

### 1. 区間の幅を求める

区間の幅は「（最大値 − 最小値）÷ 区間の数」です。`{% set %}` で、その式を変数に保存しておきます。

```sql:line-numbers=8
    {% set bin_size -%}
    (( {{ max_value }} - {{ min_value }} ) / {{ num_buckets }} )
    {%- endset %}
```

### 2. 境界ちょうどの値に 1 を足す

値が区間の幅でちょうど割り切れる（余りが 0 になる）と、その値は区間の境界に乗ります。そのとき `case` は `1` を返し、ほかは `0` を返します。

```sql:line-numbers=13
        case
            when
                mod(
                    {{ dbt.safe_cast(expr, dbt.type_numeric() ) }},
                    {{ dbt.safe_cast(bin_size, dbt.type_numeric() ) }}
                ) = 0
            then 1
            else 0
        end
```

この 1 が、境界の値を次の区間へ送る調整になります。境界を左右どちらの区間に入れるかを、1 か所で決めているのです。

### 3. 切り上げで区間番号を求め、範囲外を最後にまとめる

区間の番号は、`ceil()` で切り上げた値として求めます。

```sql:line-numbers=24
    least(
        ceil(
            ({{ expr }} - {{ min_value }})/{{ bin_size }}
        ),
        {{ num_buckets }} + 1
    )
```

`least(…, 区間の数 + 1)` によって、最大値を超えた値は、どれも「最後の番号 + 1」の区間にまとめられます。

## ここがすごい

- **境界の扱いを数式で表している**: 境界の値だけを特別に分ける分岐を書かず、余りの判定を 1 つの足し算にしています。
- **範囲外の値を捨てずに残す**: 最大値を超えた値を、専用の区間に入れるので、数え落としがありません。
- **データベースごとの差を、マクロの上書きで吸収している**: Snowflake には組み込みの関数があるため、そちらを使う別のマクロが用意されています。
- **トレードオフ**: 割り算と余りの計算は、浮動小数点の誤差に影響されます。値が境界ちょうどかどうかの判定は、精度に注意が必要です。

## まとめ

- 境界の値の扱いは、余りの判定で数式として表せる。
- 範囲外の値は、専用の番号にまとめると数え落としがなくなる。
- 組み込みの関数が無いデータベースでは、基本の式を組み合わせて同じ働きを作れる。
