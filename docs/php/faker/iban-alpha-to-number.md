## ひとことで

`alphaToNumber` は、1 文字の英字を、IBAN の検査で使う数字に変換する関数です。`A` は 10、`B` は 11、……`Z` は 35 になります。文字のコード（ASCII 番号）から 55 を引くだけで、この対応を作ります。

## コード

```php:line-numbers=37
    public static function alphaToNumber(string $char)
    {
        return ord($char) - 55;
    }
```

## 前提知識

- **ASCII と文字コード**: コンピュータは、文字を番号で扱います。`A` は 65、`B` は 66、……`Z` は 90 です。数字の `0` は 48 です。
- **`ord`**: 1 文字の文字コード（0〜255 の番号）を返す PHP の関数です。`ord('A')` は `65` です。
- **IBAN の検査**: IBAN では、英字を 10 から 35 の数字として扱ってから、全体の計算をします。英字をそのまま数字にする規則があります。
- **`static function`**: インスタンスを作らずに呼べる関数です。`Iban::alphaToNumber('A')` のように呼びます。
- **`string $char`**: 引数は文字列（ここでは 1 文字）という型の宣言です。

## 何をしているか

### 1. 文字コードを取り出す

```php:line-numbers=39
        return ord($char) - 55;
```

`ord($char)` は、`$char` の文字コードを返します。`'A'` なら `65`、`'C'` なら `67` です。

### 2. 55 を引いて 10 から始める

`A` の文字コードは `65` です。ここから `55` を引くと `10` になります。`B` は `66 - 55 = 11`、`C` は `67 - 55 = 12` と続きます。`Z` は `90 - 55 = 35` です。

なぜ 55 なのかは、IBAN の規則から決まります。規則では `A` を 10 と決めています。`A` の文字コードの `65` から `10` を引き出すと `55` なので、この定数になります。

### 3. 数字の並びに使う

この関数の結果は、IBAN の検査の計算で、そのまま数字として使われます。たとえば `GB` の国コードは、`G` が 16、`B` が 11 になるので、`1611` という数字の並びになります。その並びを、前の記事の `mod97` で 97 で割った余りにして検査します。

## ここがすごい

- **文字コードの連続性を使う**: 英字の `A` から `Z` までの文字コードは、1 つずつ連続して並んでいます。だから 1 回の引き算で全部の英字を変換できます。
- **表を持たない**: 26 文字の対応表を作ると、コードが長くなります。引き算 1 回のほうが短く、間違えにくい書き方です。
- **大文字だけを扱う前提**: IBAN の国コードや検査の文字は大文字です。大文字専用の変換にすることで、式が単純になっています。
- **関数名が規則を説明する**: `alphaToNumber` という名前で、英字から数字への変換だと分かります。

## まとめ

- 英字を数字に変えるには、ASCII の文字コードから規則の定数を引くと簡単。
- 大文字の `A` から `Z` は、10 から 35 の数字に連続して対応する。
- 文字コードの連続性を使うと、対応表を作らずに済む。
- 規則の定数（ここでは 55）の由来を知っておくと、コードの意味が追いやすくなる。
