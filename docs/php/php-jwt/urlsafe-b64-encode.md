## ひとことで

`urlsafeB64Encode` は、バイト列を Base64 という文字の並びに変換したあと、URL や ファイル名に入れても壊れない形に整える関数です。JWT（JSON Web Token）というログイン情報の形式で、ヘッダやペイロードを表すときに使われます。

## コード

```php:line-numbers=466
    public static function urlsafeB64Encode(string $input): string
    {
        return \str_replace('=', '', \strtr(\base64_encode($input), '+/', '-_'));
    }
```

## 前提知識

- **Base64**: 0 から 255 のバイト列を、`A`〜`Z`、`a`〜`z`、`0`〜`9`、`+`、`/` の 64 種類の文字だけで表す方法です。3 バイトが 4 文字になります。
- **パディング `=`**: 3 バイトで割り切れないとき、末尾を `=` で埋めて 4 文字の倍数にする決まりです。
- **`static` メソッド**: `JWT::urlsafeB64Encode(...)` のように、インスタンスを作らずにクラス名から直接呼べるメソッドです。
- **`\str_replace` の `\`**: 名前空間の中で、グローバルな PHP 組み込み関数を明示して呼ぶための印です。
- **`strtr`**: 文字列の中の文字を、対応する別の文字へ一度に置き換える関数です。`strtr($s, '+/', '-_')` は `+` を `-` に、`/` を `_` に置き換えます。

## 何をしているか

### 1. 標準の Base64 に変換する

```php:line-numbers=468
        return \str_replace('=', '', \strtr(\base64_encode($input), '+/', '-_'));
```

処理は内側から順に動きます。まず `\base64_encode($input)` で、バイト列を標準の Base64 文字列にします。たとえば `"\xFB\xFF"`（2 バイト）は `+/8=` になります。

### 2. `+` と `/` を URL で安全な文字に置き換える

`strtr` の 3 つ目の引数 `'-_'` は、2 つ目の引数 `'+/'` の 1 文字目を `-`、2 文字目を `_` に置き換えます。`+/8=` は `-_8=` になります。

標準の Base64 では `+` と `/` が URL の中で特別な意味を持ちます。`+` は空白として、`/` はパスの区切りとして解釈されることがあるためです。`-` と `_` はどちらも URL の中で意味を持たない文字です。

### 3. 末尾の `=` を取り除く

```php:line-numbers=468
        return \str_replace('=', '', \strtr(\base64_encode($input), '+/', '-_'));
```

`str_replace('=', '', ...)` は、すべての `=` を空文字に置き換えます。`-_8=` は `-_8` になります。`=` は URL の中でクエリ文字列の区切りに使われるため、取り除くと扱いやすくなります。

長さは、元が 1 バイト増えるたびに 4 文字の単位で変わるので、パディングを取った長さから元の長さを割り出せます。その計算は、戻す側の `convertBase64UrlToBase64` が行います。

### 4. 使う側の例

JWT のヘッダは `{"alg":"HS256","typ":"JWT"}` のような JSON をエンコードしたものです。この関数を通すと、`.` で区切られた 3 つの部分のどこにも `+`、`/`、`=` が現れなくなります。そのため、そのままリンクのパラメータやヘッダに入れられます。

## ここがすごい

- **置き換えを 1 回の `strtr` でまとめている**: 「`+` を `-` に、`/` を `_` に」を、`str_replace` を 2 回呼ぶ書き方もできます。`strtr` に配列を渡す方法もあります。どれも結果は同じですが、この書き方は「どの文字が何に変わるか」を 1 行で読めます。
- **戻す処理と対になっている**: エンコードでは `=` を捨て、デコードでは長さを見て `=` を付け直します。片方だけでは元に戻りません。
- **名前が仕様を説明している**: `urlsafe` という名前で、目的（URL で安全に使う）と、標準の Base64 と違う点が伝わります。
- **仕様に合わせた省略**: JWT の仕様（RFC 7515）では、この形式の Base64 を `base64url` と呼び、パディングを付けない決まりです。関数はその決まりに従っています。

## まとめ

- Base64 は 64 種類の文字で表すので、そのままでは URL の中で意味を持つ文字が混ざる。
- `strtr` で 2 文字だけを置き換え、`str_replace` で `=` を取り除くと、URL で使える文字列になる。
- エンコードとデコードは対になっている。デコード側は、長さから `=` を補ってから元の Base64 に戻す。
- 関数名に「何のための処理か」を入れると、読む人が仕様を推測しやすくなる。
