## ひとことで

`convertBase64UrlToBase64` は、URL 用の Base64（`-` と `_` を使い、末尾の `=` を取り除いたもの）を、標準の Base64 に戻す関数です。取り除かれた `=` の数を、文字列の長さから計算して付け直します。

## コード

```php:line-numbers=449
    public static function convertBase64UrlToBase64(string $input): string
    {
        $remainder = \strlen($input) % 4;
        if ($remainder) {
            $padlen = 4 - $remainder;
            $input .= \str_repeat('=', $padlen);
        }
        return \strtr($input, '-_', '+/');
    }
```

## 前提知識

- **Base64 の決まり**: 文字は 4 つずつ 1 組で扱われ、全体の長さは必ず 4 の倍数になります。足りない分は `=` で埋められます。
- **`%`（剰余）**: `10 % 4` は `2` のように、割った余りを返します。
- **`if ($remainder)`**: PHP では `0` は偽として扱われます。つまり「余りがあるときだけ」という意味になります。
- **`.=`**: 文字列の末尾に別の文字列を連結して、同じ変数に入れ直す代入です。
- **`\str_repeat`**: 同じ文字列を指定回数だけ繰り返して返す関数です。`str_repeat('=', 2)` は `==` を返します。

## 何をしているか

### 1. 文字数を 4 で割った余りを求める

```php:line-numbers=451
        $remainder = \strlen($input) % 4;
```

`strlen($input)` は文字列の長さです。Base64 では、長さが 4 の倍数なら完全な組になっています。余りが 1、2、3 のときは、末尾の組が欠けています。

たとえば `-_8`（3 文字）の余りは `3` です。`-_8=` の 4 文字であれば余りは `0` で、補う必要はありません。

### 2. 足りない `=` の数を決める

```php:line-numbers=452
        if ($remainder) {
            $padlen = 4 - $remainder;
```

余りが 0 でなければ、`4 - $remainder` 個の `=` が必要です。余りが 3 なら `4 - 3 = 1` 個、余りが 2 なら 2 個です。余りが 1 のケースは、Base64 としては本来ありえない長さで、この式では `=` を 3 個付けます。

### 3. `=` を補い、記号を戻す

```php:line-numbers=454
            $input .= \str_repeat('=', $padlen);
        }
        return \strtr($input, '-_', '+/');
```

`str_repeat('=', $padlen)` で必要な数の `=` を作り、末尾に連結します。`-_8` は `-_8=` になります。

最後の `strtr($input, '-_', '+/')` は、ちょうど逆向きの置き換えです。`-` を `+`、`_` を `/` に戻します。`-_8=` は `+/8=` になり、これは `"\xFB\xFF"` を表す標準の Base64 です。

### 4. 順番が大事な理由

パディングを補うのは、記号を戻す前です。`strtr` が先だと、`+` や `/` の文字は変わっても長さは変わりません。どちらが先でも結果は同じになりそうに見えますが、読む側としては「長さの計算は URL 形式の文字列に対して行う」と考えると理解しやすくなります。

## ここがすごい

- **長さの情報だけで足りる**: JWT では `=` を捨てても、欠けた数は文字数の余りから一意に決まります。だから、パディングを保存しなくても元に戻せます。
- **分岐を最小限にしている**: 余りが 0 のときは何もしません。`if` が 1 つだけなので、正常なケースでは処理がほとんど増えません。
- **エンコード側と対になっている**: 送る側の `urlsafeB64Encode` は `=` を捨てるだけです。受け取る側がこの関数で復元することで、JWT のどちらの側でも同じ仕組みを使えます。
- **ライブラリ内の共通関数**: デコードするたびにこの変換を通すので、呼び出し側は URL 形式を意識しなくて済みます。

## まとめ

- 取り除かれたパディングは、文字数の余りから計算できる。
- 余りが 0 なら補う必要はなく、余りが 1〜3 なら `4 - 余り` 個の `=` を付ける。
- `strtr` で `-_` を `+/` に戻すと、標準の Base64 として読める。
- エンコードとデコードは対になっていて、片方だけでは正しく復元できない。
