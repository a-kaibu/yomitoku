## ひとことで

`sign_extend` は、`get_int` のように **任意のバイト数（1 から 8 バイト）の符号付き整数** を読むときに、その値を正しい `i64` にする関数です。読んだバイト列は、まず `u64` の下位にそのまま入っています。そのままでは、負の数が正しい符号を持ちません。

この関数は、足りない上位ビットを、符号ビットの値で埋めるように、左右のシフトを使って広げます。これを **符号拡張（sign extension）** と呼びます。

## コード

::: code-group

```rust:line-numbers=88 [日本語訳]
fn sign_extend(val: u64, nbytes: usize) -> i64 {
    if nbytes == 0 {
        // `val << 64` でパニックしないように
        0
    } else {
        let shift = (8 - nbytes) * 8;
        (val << shift) as i64 >> shift
    }
}
```

```rust:line-numbers=88 [原文]
fn sign_extend(val: u64, nbytes: usize) -> i64 {
    if nbytes == 0 {
        // avoid `val << 64` panic
        0
    } else {
        let shift = (8 - nbytes) * 8;
        (val << shift) as i64 >> shift
    }
}
```

:::

`nbytes` が 0 のときは、値が 0 なので、そのまま 0 を返します。0 のときにシフトを行うと、`val << 64` となり、パニックするので別扱いにしています。

## 前提知識

- **符号付き整数の表し方**: 2 の補数では、最上位ビットが 1 なら負の数です。たとえば 8 ビットの `0xFF` は、`-1` です。
- **符号拡張**: 短い整数を長い整数に変えるとき、上位ビットを最上位の符号ビットの値で埋めることです。
- **論理右シフトと算術右シフト**: 左側に 0 を入れるシフトと、符号を保って入れるシフトがあります。Rust では、`i64` への `>>` は算術右シフトになります。
- **`as i64`**: `u64` のビットを、`i64` の値として読み替えます。
- **`val << 64` の問題**: 64 ビット以上のシフトはパニックになるので、特別に扱います。

## 何をしているか

### 1. 0 バイトは特別扱いする

```rust:line-numbers=89
    if nbytes == 0 {
        // avoid `val << 64` panic
        0
```

読むバイト数が 0 なら、値は 0 です。シフトを避けるために、ここで 0 を返します。

### 2. 空いているビットの数を求める

```rust:line-numbers=93
        let shift = (8 - nbytes) * 8;
```

8 バイトの中で、使われていない上位の部分の量をビット数で求めます。たとえば 3 バイトなら、5 バイト分、つまり 40 ビットを空けます。

### 3. 左に寄せてから、算術的に右へ戻す

```rust:line-numbers=94
        (val << shift) as i64 >> shift
```

値を左へ寄せて、符号ビットを最上位に置きます。それを `i64` として読み、算術右シフトで元の位置に戻します。その過程で、上位には符号ビットがコピーされ、正しい符号拡張になります。

## ここがすごい

- **シフトだけで完結する**: 符号を判定する `if` は要りません。左に寄せて、算術右シフトで戻すだけで、符号が自動的に広がります。
- **任意の長さに対応**: 1 から 8 バイトまで、同じ式で処理できます。長さごとに関数を分ける必要がありません。
- **境界の値を明示**: 0 バイトのように、シフト量が 64 になる場合を、コメントとともに避けています。

## まとめ

- 上位ビットを符号ビットで埋めるのが符号拡張であり、左右のシフトで実現できる。
- 符号判定の分岐なしに、左へ寄せて算術右シフトで戻す。
- シフト量が 64 になる境界（0 バイト）は、別扱いにして安全を保つ。
