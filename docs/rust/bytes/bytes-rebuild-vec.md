## ひとことで

`rebuild_vec` は、`Vec<u8>` のポインタ（先頭の位置）と長さ、容量を受け取って、**元の確保領域の先頭から始まる Vec を組み直す** 関数です。`bytes` の内部で、先頭を後ろにずらして切り出された領域を、もう一度 `Vec` として返すために使われます。
`off` は「先頭から何バイト後ろにずれているか」を表す値です。ポインタを `off` だけ戻し、長さと容量を `off` だけ増やせば、元の `Vec` と同じ状態になります。

## コード

```rust:line-numbers=1888
unsafe fn rebuild_vec(ptr: *mut u8, mut len: usize, mut cap: usize, off: usize) -> Vec<u8> {
    let ptr = ptr.sub(off);
    len += off;
    cap += off;

    Vec::from_raw_parts(ptr, len, cap)
}
```

この関数は `unsafe` です。渡すポインタ・長さ・容量が、実際に確保された `Vec` のものと一致していることを呼び出し側が保証します。

## 前提知識

- **`Vec<T>`**: 可変長の配列です。内部では、確保された領域の先頭ポインタ、長さ（今の要素数）、容量（確保済みの大きさ）を持っています。
- **`Vec::from_raw_parts`**: ポインタ、長さ、容量の 3 つを受け取って、`Vec` を作り直す関数です。渡した領域は、以後その `Vec` が所有します。
- **`ptr.sub(off)`**: ポインタを `off` 個分、後ろから前へ戻します。`u8` なので、`off` はバイト数です。
- **`unsafe`**: コンパイラが安全性を検査できないことを、プログラマが保証する宣言です。この関数では、ポインタの指す先が正しい領域であることが、呼び出し側の約束になっています。
- **所有権**: 1 つの領域を所有できるのは 1 つの `Vec` だけです。二重に解放しないように、組み直しの後は古いものを使わないことが重要です。

## 何をしているか

### 1. ポインタを元の先頭まで戻す

```rust:line-numbers=1889
    let ptr = ptr.sub(off);
```

`off` は、もともとの確保領域の先頭から、今の先頭までのずれです。`ptr.sub(off)` で、そのずれを戻すと、確保領域の本当の先頭を指すポインタになります。

### 2. 長さと容量にずれ分を足す

```rust:line-numbers=1890
    len += off;
    cap += off;
```

先頭を戻した分だけ、有効な範囲も広がっています。たとえば先頭から 3 バイトを切った `Vec` は、長さが 3 つ減っています。これを `off` だけ足し戻すと、元の長さと容量に揃います。

### 3. 3 つの値から `Vec` を作る

```rust:line-numbers=1893
    Vec::from_raw_parts(ptr, len, cap)
```

`Vec::from_raw_parts` に、戻したポインタ、増やした長さ、増やした容量を渡します。これで、元と同じ領域を指す `Vec` が返ります。

## ここがすごい

- **切り出しの情報を失わない**: 先頭をずらすと、ポインタ・長さ・容量のどれも変わるので、`off` を別に覚えておけば、いつでも元に戻せます。
- **計算が 2 行で済む**: ずらす量を足し引きするだけなので、コピーや再確保がありません。大きなデータでも、コストは定数時間です。
- **`unsafe` の範囲が狭い**: 関数全体が `unsafe` ですが、中身は 3 行の計算と 1 回の呼び出しだけです。確認すべき条件がはっきりしています。
- **`bytes` の型設計と合っている**: `bytes` は、同じ領域を複数の `Bytes` が共有し、先頭の位置だけを変えて見せます。その状態から `Vec` に戻すときも、この関数で元の情報を取り戻せます。
- **所有権の移動が一度だけ**: 組み直した `Vec` が、その後の解放を担当します。古いポインタを捨てる約束を守れば、二重解放は起きません。

## まとめ

- 先頭を後ろにずらした領域は、ポインタを `off` だけ戻し、長さと容量を `off` だけ増やせば元に戻る。
- 戻した 3 つの値を `Vec::from_raw_parts` に渡すと、元の領域を所有する `Vec` が作れる。
- `unsafe` の約束（ポインタ・長さ・容量が正しいこと）を、呼び出し側で守る必要がある。
