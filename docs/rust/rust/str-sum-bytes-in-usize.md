## ひとことで

`sum_bytes_in_usize` は、`usize`（64 ビット環境では 8 バイト）の値を 8 個のバイトの並びとみなし、**その 8 個の合計** を返す関数です。
たとえば各バイトが `1, 2, 3, 4, 5, 6, 7, 8` なら `36` を返します。

コメントにある通り、意味は `values.to_ne_bytes().into_iter().sum()`（バイト配列に分解して合計する）と同じですが、**ループを使わず、掛け算 1 回** で合計を出します。

## コード

```rust:line-numbers=120
// Morally equivalent to `values.to_ne_bytes().into_iter().sum::<usize>()`, but
// more efficient.
#[inline]
fn sum_bytes_in_usize(values: usize) -> usize {
    const LSB_SHORTS: usize = usize::repeat_u16(0x0001);
    const SKIP_BYTES: usize = usize::repeat_u16(0x00ff);

    let pair_sum: usize = (values & SKIP_BYTES) + ((values >> 8) & SKIP_BYTES);
    pair_sum.wrapping_mul(LSB_SHORTS) >> ((USIZE_SIZE - 2) * 8)
}
```

## 前提知識

- **`usize::repeat_u16(0x0001)`**: 2 バイトの値 `0x0001` を `usize` 全体に繰り返し並べた定数です。64 ビットなら `0x0001_0001_0001_0001` になります。同様に `repeat_u16(0x00ff)` は `0x00ff_00ff_00ff_00ff` です。
- **`wrapping_mul`**: 掛け算をして、型の範囲を超えた上位の桁は捨てる（折り返す）メソッドです。Rust の通常の `*` はデバッグ時にオーバーフローを検出するとパニックするので、あふれる前提の計算では `wrapping_` 系を使います。
- **`>>`**: 右シフトです。`>> 48` で上位 16 ビットだけを下に持ってきます。
- **`USIZE_SIZE`**: このファイルで定義されている `size_of::<usize>()`、つまり 8 です。

## 何をしているか

前提として、呼び出し元では各バイトの値は 192 以下になっています。

### 1. 隣り合うバイトを足して 16 ビットの枠にする（127 行目）

```
values & SKIP_BYTES        → 各 16 ビット枠の下位バイト
(values >> 8) & SKIP_BYTES → 各 16 ビット枠の上位バイト
```

この 2 つを足すと、4 個の 16 ビット枠それぞれに「2 バイトの合計」が入ります。192 + 192 = 384 なので 16 ビットに余裕で収まります。

8 バイト `[1, 2, 3, 4, 5, 6, 7, 8]` なら、16 ビット枠は `[3, 7, 11, 15]` になります。

### 2. 掛け算で 4 個の枠を合計する（128 行目）

ここが一番の工夫です。`x × 0x0001_0001_0001_0001` は、筆算で考えると

```
x
+ x を 16 ビット左にずらしたもの
+ x を 32 ビット左にずらしたもの
+ x を 48 ビット左にずらしたもの
```

と同じです。すると **最上位の 16 ビット枠には、4 個の枠すべてが重なって足し込まれます**。上の例なら `3 + 7 + 11 + 15 = 36` です。

最上位からはみ出した分は `wrapping_mul` で捨てられるので問題ありません。最後に `>> ((8 - 2) * 8)`、つまり 48 ビット右にずらすと、最上位の 16 ビットに集まった合計 `36` が取り出せます。

合計は最大でも 192 × 8 = 1536 なので、16 ビット枠からあふれて答えが壊れることもありません。

## ここがすごい

- **掛け算を「ずらして足す」として使う**: `0x0001` が並んだ定数を掛けると、すべての枠を 1 か所に集めて合計できます。掛け算は現代の CPU では数サイクルで終わるので、ループで 8 回足すより速くなります。
- **先に 16 ビットにまとめる理由**: いきなり 8 ビット枠のまま掛け算すると、合計が 255 を超えたときにあふれてしまいます。まず隣どうしを足して枠を 16 ビットに広げることで、合計 1536 まで安全に扱えます。
- **ビット幅に依存しない書き方**: 定数を `repeat_u16` で作り、シフト量を `USIZE_SIZE` から計算しているので、32 ビット環境でも同じコードで動きます。
- **使う回数を減らしてある**: この関数は 192 ワードに 1 回しか呼ばれません。重い処理をまとめて後回しにする設計と組み合わさっています。

## まとめ

- `0x0001_0001_...` を掛けると、複数の枠の値を最上位の枠に集めて合計できる。
- あふれないように、まず枠を広げて（隣どうしを足して）から合計する。
- 定数とシフト量は型の大きさから計算すると、移植性が上がる。
