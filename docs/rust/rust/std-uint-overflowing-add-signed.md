## ひとことで

`overflowing_add_signed` は、符号なしの整数 `self` に、**符号付きの整数 `rhs`** を足します。結果は `(値, 溢れたか)` の組で返します。
符号なしの整数は負にできないので、`rhs` が負のときは「引き算」になります。この関数は、その場合の溢れの判定を、**1 回の排他的論理和** で正しく直しています。

## コード

```rust:line-numbers=3084
        pub const fn overflowing_add_signed(self, rhs: $SignedT) -> (Self, bool) {
            let (res, overflowed) = self.overflowing_add(rhs as Self);
            (res, overflowed ^ (rhs < 0))
        }
```

`rhs as Self` は、符号付きの値を同じビット幅の符号なしの値として読み直します。負の数は、大きな正の数に見えるようになります。

## 前提知識

- **符号なし整数と符号付き整数**: 符号なしは 0 以上の値だけを表せます。符号付きは負の値も表せ、同じビット幅で表す値の範囲が違います。
- **2 の補数**: 負の数を、同じビット列で大きな正の数として読み直す方法です。たとえば 8 ビットでは `-1` は `255` と同じビット列です。
- **`overflowing_add`**: 足し算をして、結果と溢れたかどうかの組を返す操作です。溢れても止まりません。
- **排他的論理和（`^`）**: 2 つの真偽値が違うときだけ真になります。`a ^ b` は、`a` と `b` が反対のときに真です。
- **`rhs < 0`**: 符号付きの値が負かどうかを表します。

## 何をしているか

### 1. 負の数を大きな正の数として足す

```rust:line-numbers=3085
            let (res, overflowed) = self.overflowing_add(rhs as Self);
```

`rhs as Self` で、符号付きの `rhs` を同じビットの符号なしの値に読み直し、`overflowing_add` で足します。`rhs` が負なら、この読み直した値は非常に大きな数になっています。
この足し算の結果は、「本当の答え」を 2^N だけずらした値です（N はビット数）。そのため、溢れの判定も、そのずれの分だけ裏返っています。

### 2. 負のときは溢れの判定を反転する

```rust:line-numbers=3086
            (res, overflowed ^ (rhs < 0))
```

`overflowed ^ (rhs < 0)` で、`rhs` が負のときだけ溢れの判定を反対にします。負の数の足し算は、符号なしとして見ると、溢れの有無が逆に見えるからです。
結果の値 `res` は、そのまま本当の答えになっています。

## ここがすごい

- **1 回の足し算で、符号を扱う**: 符号付きと符号なしの型を変換せず、同じビットのまま足せます。負の数の引き算も、足し算だけで済みます。
- **判定の反転が 1 行で書ける**: 「負なら反転」という条件を、`^` で表しています。`if` を使わず、真偽値の演算だけで意味を表します。
- **結果の値と溢れを両方返す**: 呼び出し側が、値と溢れの有無を両方使えます。`checked_add_signed` などは、この 2 つを使って作られています。
- **2 の補数の性質を利用**: 負の数を大きな正の数として読み直しても、足し算の結果のビットは正しい答えになります。その仕組みを前提に、溢れの判定だけを直しています。
- **型の変換の意味が明確**: `as Self` は、ビットの読み直しだけです。値を変えないことを前提に、コードが書かれています。

## まとめ

- 符号付きの値は、同じビット幅の符号なしとして読み直し、`overflowing_add` で足す。
- 負の数のときは、溢れの判定が逆になるので、`^` で反転する。
- 結果の値は正しいまま、溢れの有無だけを正しく返せる。
