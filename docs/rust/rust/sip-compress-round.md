## ひとことで

`compress!` は、標準ライブラリのハッシュ関数 **SipHash** の中で、4 つの 64 ビット値（状態）を **1 ラウンド** 混ぜ合わせるマクロです。
この 1 ラウンドを何回か繰り返すことで、入力の小さな違いが出力全体に広がるようになります。マクロにしてあるので、関数の呼び出しを挟まずに、その場で展開されます。

## コード

```rust:line-numbers=77
    ($v0:expr, $v1:expr, $v2:expr, $v3:expr) => {{
        $v0 = $v0.wrapping_add($v1);
        $v2 = $v2.wrapping_add($v3);
        $v1 = $v1.rotate_left(13);
        $v1 ^= $v0;
        $v3 = $v3.rotate_left(16);
        $v3 ^= $v2;
        $v0 = $v0.rotate_left(32);

        $v2 = $v2.wrapping_add($v1);
        $v0 = $v0.wrapping_add($v3);
        $v1 = $v1.rotate_left(17);
        $v1 ^= $v2;
        $v3 = $v3.rotate_left(21);
        $v3 ^= $v0;
        $v2 = $v2.rotate_left(32);
    }};
```

このマクロは `$v0`、`$v1`、`$v2`、`$v3` の 4 つの式を受け取ります。1 つの状態 `state` を渡す形（最初の規則）からも、この形に展開されます。

## 前提知識

- **ハッシュ関数**: 任意の大きさの入力から、固定長の値（ハッシュ値）を作る関数です。同じ入力からは必ず同じ値が出ます。
- **SipHash**: 小さな入力でも、ハッシュ値が予測しにくいように設計されたハッシュ関数です。`HashMap` のような場面で、攻撃から守るために使われています。
- **`wrapping_add`**: 64 ビットの足し算で、溢れたら 2^64 で割った余りになります。
- **`rotate_left(k)`**: ビットを左に `k` 個回転させる操作です。左端から出たビットが右端に戻ってきます。
- **マクロ（`macro_rules!`）**: 書いたコードの形をもとに、そのまま展開されるしくみです。関数と違い、呼び出しの手間がありません。

## 何をしているか

### 1. 足し算と回転で、2 組の値を混ぜる

```rust:line-numbers=78
        $v0 = $v0.wrapping_add($v1);
        $v2 = $v2.wrapping_add($v3);
        $v1 = $v1.rotate_left(13);
        $v1 ^= $v0;
        $v3 = $v3.rotate_left(16);
        $v3 ^= $v2;
        $v0 = $v0.rotate_left(32);
```

`v0` と `v1`、`v2` と `v3` をそれぞれ足します。そのあと `v1` と `v3` を回転させて、排他的論理和で元の値と混ぜます。最後に `v0` を 32 ビット回転させます。

### 2. 2 組目の混ぜ合わせ

```rust:line-numbers=86
        $v2 = $v2.wrapping_add($v1);
        $v0 = $v0.wrapping_add($v3);
        $v1 = $v1.rotate_left(17);
        $v1 ^= $v2;
        $v3 = $v3.rotate_left(21);
        $v3 ^= $v0;
        $v2 = $v2.rotate_left(32);
```

同じ形の混ぜ合わせを、今度は別の組み合わせで行います。足し算、回転、排他的論理和の順番を変えることで、4 つの値の間で情報が行き来します。
回転の量（13, 16, 32, 17, 21, 32）は、混ぜ方を広げるために選ばれた定数です。

### 3. 戻り値なしで状態を直接書き換える

ここまでの処理はすべて、`$v0` から `$v3` の値を書き換えるだけです。関数の戻り値はなく、呼び出し側の状態を直接更新します。

## ここがすごい

- **足し算、回転、排他的論理和だけ**: これは ARX（Add, Rotate, XOR）と呼ばれる設計です。どれも CPU で速く計算でき、テーブルを引かないので、キャッシュの攻撃の影響を受けにくくなっています。
- **少ない命令で大きく混ぜる**: 1 回の SipRound は、14 行ほどの小さな代入の並びです。この短い列を繰り返すことで、1 ビットの違いが、ほぼすべてのビットに広がります。
- **マクロで展開して速くする**: 関数にすると、呼び出しの手間や引数のやり取りが増えます。マクロで直接書けば、コンパイラが状態を CPU のレジスタに置いたまま計算できます。
- **引数の形を 2 通り用意**: `compress!(state)` と `compress!(v0, v1, v2, v3)` の両方を使えるようにしています。構造体の中の値を直接渡せるので、書き方が簡単です。
- **安全性の検証が容易**: 中身は足し算、回転、排他的論理和だけなので、どの部分が何をしているかを数えられます。暗号の設計の検証でも、この単純さが役立ちます。

## まとめ

- SipHash の 1 ラウンドは、足し算、回転、排他的論理和を 4 つの値に順に行う。
- ARX という単純な演算だけで、入力の違いを広く混ぜられる。
- マクロで展開すると、関数呼び出しの手間を省いて速く動く。
