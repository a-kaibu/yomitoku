## ひとことで

`contains_non_continuation_byte` は、`usize`（64 ビット環境では 8 バイト）の値 `w` を 8 個のバイトの並びとみなし、**それぞれのバイトが UTF-8 の文字の先頭か（継続バイトでないか）** を調べる関数です。

結果は、先頭のバイトの位置に `0x01`、継続バイトの位置に `0x00` が入った値です。たとえばバイトが `E3 81 82 61 ...` なら、`01 00 00 01 ...` になります。文字数を高速に数える `do_count_chars` の部品です。

## コード

::: code-group

```rust:line-numbers=110 [日本語訳]
// `w` の各バイトが UTF-8 の文字の先頭バイトかどうかを調べる。
// 継続バイトなら `0x00`（false）、先頭バイトなら `0x01`（true）を残す。
// （ここでは false/true は値の意味を表す）
//
#[inline]
fn contains_non_continuation_byte(w: usize) -> usize {
    const LSB: usize = usize::repeat_u8(0x01);
    ((!w >> 7) | (w >> 6)) & LSB
}
```

```rust:line-numbers=110 [原文]
// Checks each byte of `w` to see if it contains the first byte in a UTF-8
// sequence. Bytes in `w` which are continuation bytes are left as `0x00` (e.g.
// false), and bytes which are non-continuation bytes are left as `0x01` (e.g.
// true)
#[inline]
fn contains_non_continuation_byte(w: usize) -> usize {
    const LSB: usize = usize::repeat_u8(0x01);
    ((!w >> 7) | (w >> 6)) & LSB
}
```

:::

## 前提知識

- **UTF-8 の継続バイト**: UTF-8 で 2 バイト以上になる文字は、先頭バイトのあとに `10xxxxxx`（最上位ビットが 1、次が 0）という形のバイトが続きます。これを継続バイトと呼びます。ASCII（`0xxxxxxx`）や先頭バイト（`11xxxxxx`）はそれ以外の形です。
- **`usize::repeat_u8(0x01)`**: 1 バイトの値 `0x01` を `usize` のすべてのバイトに並べた定数を作ります。64 ビットなら `0x0101010101010101` です。
- **`!w`**: 整数に対する `!` はビット反転（0 と 1 を入れ替える）です。
- **`>>`、`|`、`&`**: 右シフト、ビットごとの OR、ビットごとの AND です。
- **最後の式が戻り値**: 関数本体の最後の式には `;` がないので、その値が返ります。

## 何をしているか

1 バイト分だけを取り出して考えます。バイトのビットを上から `b7 b6 ... b0` とすると、継続バイトは `b7 = 1` かつ `b6 = 0` のときです。
逆に言えば、**「`b7` が 0」または「`b6` が 1」なら継続バイトではない** ので、`(!b7) | b6` を計算すればよいことになります。

### 1. `!w >> 7`

```rust:line-numbers=117
    ((!w >> 7) | (w >> 6)) & LSB
```


`w` を反転してから 7 ビット右にずらすと、各バイトの `b7` の反転が、そのバイトの最下位ビット（`b0` の位置）に来ます。

### 2. `w >> 6`

6 ビット右にずらすと、各バイトの `b6` が最下位ビットの位置に来ます。

### 3. OR して、最下位ビットだけ残す

2 つを OR すると、各バイトの最下位ビットが `(!b7) | b6` になります。シフトによって隣のバイトのビットが上の方に入り込んでいますが、最後に `& LSB`（各バイトの最下位ビットだけが 1 のマスク）を取るので、それらはすべて消えます。

具体例として、バイト `0x81`（`1000 0001`、継続バイト）と `0x61`（`0110 0001`、ASCII の `a`）を見ます。

```
0x81: b7=1, b6=0 → !b7=0, b6=0 → 0
0x61: b7=0, b6=1 → !b7=1, b6=1 → 1
```

これが 8 バイト同時に、わずか 4 回の演算で計算されます。

## ここがすごい

- **条件をビットの論理式に直す**: 「`10` で始まるか」という判定を、`(!b7) | b6` という 1 ビットの式に変換しています。比較も分岐もいりません。
- **シフトで「調べたいビット」を同じ位置にそろえる**: 7 ビットと 6 ビットのシフトで、別々の位置にあったビットを最下位にそろえ、あとはまとめて OR できるようにしています。
- **はみ出しはマスクで捨てる**: 整数全体をシフトすると隣のバイトのビットが混ざりますが、必要なのは各バイトの最下位ビットだけなので、最後の AND で一掃できます。「余計なものが混ざっても最後に捨てればよい」という SWAR の典型的な考え方です。
- **結果が足し算できる形**: `0x01` か `0x00` を並べた値なので、呼び出し側はこれを足すだけで 8 個のカウンタを同時に進められます。

## まとめ

- 「特定のビットパターンか」は、ビットの論理式に直すと分岐なしで判定できる。
- シフトで調べたいビットをそろえ、マスクで不要なビットを捨てる。
- 判定結果を `0`/`1` の並びにしておくと、そのまま足してカウントできる。
