## ひとことで

`less_than_5` は、0 より大きく 100000 より小さい整数 `val` について、**10 進数で何桁か（から 1 を引いた値）** を返す関数です。
数学でいう `floor(log10(val))` で、`7` なら `0`、`345` なら `2`、`99999` なら `4` になります。

素直に書くなら `if val < 10 { 0 } else if val < 100 { 1 } ...` と比較を 4 回並べるところですが、この関数は **if を 1 つも使わず**、定数を足して AND と XOR を取るだけで答えを出します。
Rust 標準ライブラリの `u32::ilog10()` などの中身として使われています。

## コード

```rust:line-numbers=27
// 0 < val < 100_000
#[inline]
const fn less_than_5(val: u32) -> u32 {
    // Similar to u8, when adding one of these constants to val,
    // we get two possible bit patterns above the low 17 bits,
    // depending on whether val is below or above the threshold.
    const C1: u32 = 0b011_00000000000000000 - 10; // 393206
    const C2: u32 = 0b100_00000000000000000 - 100; // 524188
    const C3: u32 = 0b111_00000000000000000 - 1000; // 916504
    const C4: u32 = 0b100_00000000000000000 - 10000; // 514288

    // Value of top bits:
    //                +c1  +c2  1&2  +c3  +c4  3&4   ^
    //         0..=9  010  011  010  110  011  010  000 = 0
    //       10..=99  011  011  011  110  011  010  001 = 1
    //     100..=999  011  100  000  110  011  010  010 = 2
    //   1000..=9999  011  100  000  111  011  011  011 = 3
    // 10000..=99999  011  100  000  111  100  100  100 = 4
    (((val + C1) & (val + C2)) ^ ((val + C3) & (val + C4))) >> 17
}
```

## 前提知識

- **`const fn`**: Rust の `fn` は関数の定義です。前に `const` が付くと、コンパイル時（プログラムを作る段階）にも実行できる関数になります。
- **`u32`**: 符号なし（0 以上）の 32 ビット整数の型です。`val: u32` は「引数 `val` の型は `u32`」、`-> u32` は「戻り値の型は `u32`」という意味です。
- **最後の式が戻り値**: Rust では関数本体の最後に書いた式（末尾に `;` がないもの）がそのまま戻り値になります。`return` を書かなくてもよいのです。
- **`0b011_00000000000000000`**: `0b` は 2 進数の書き方、`_` は読みやすさのための区切りで値には影響しません。これは「下に 0 が 17 個並び、その上に `011` がある数」です。
- **`&`・`^`・`>>`**: それぞれビットごとの AND（両方 1 なら 1）、XOR（違うときだけ 1）、右シフト（ビットを右へずらす）です。`>> 17` で下位 17 ビットを捨て、その上のビットだけを取り出せます。

## 何をしているか

### 1. 「しきい値を超えたら繰り上がる」定数を作る（33〜36 行目）

`2^17 = 131072` は 100000 より大きいので、`val` は必ず下位 17 ビットに収まります。
そこで `C2 = 0b100 << 17 - 100` のような定数を用意します。`val + C2` を計算すると、

- `val < 100` なら、`0b100 << 17` に届かず、上位ビットは `011`
- `val >= 100` なら、ちょうど `0b100 << 17` を超えて、上位ビットは `100`

になります。つまり **足し算の繰り上がりを「比較」の代わりに使っている** のです。`C1`（10）、`C3`（1000）、`C4`（10000）も同じ考え方で、それぞれ別の上位ビットのパターンに変わるよう調整されています。

### 2. 4 つの結果を AND と XOR で合成する（45 行目）

コメントの表（38〜44 行目）が、各しきい値で上位 3 ビットがどう変わるかを示しています。`val = 345` で追ってみます。

```
val + C1 = 393551 → 上位 011
val + C2 = 524533 → 上位 100
           AND      → 000
val + C3 = 916849 → 上位 110
val + C4 = 514633 → 上位 011
           AND      → 010
XOR                 → 010 = 2
```

答えは `2`、つまり 345 は 3 桁です。定数の上位ビットは、AND と XOR を取ったときにちょうど `0`〜`4` が出てくるよう **逆算して** 決められています。
下位 17 ビットには `val` の値が混ざって残っていますが、最後に `>> 17` で捨てるので影響しません。

## ここがすごい

- **分岐がない**: if の連鎖は、CPU が「どちらに進むか」の予測を外すと遅くなります。この関数は入力によらず同じ命令列を実行するので、予測ミスが起きません。
- **比較を足し算に置き換える発想**: 「`val` がしきい値以上か」を、「足したら特定のビットまで繰り上がるか」に言い換えています。比較の結果を 1 ビットとして取り出せるので、複数の比較結果をビット演算でまとめて計算できます。
- **定数の設計が緻密**: 4 つの比較結果から 0〜4 の 5 通りの答えを作るため、各定数の上位ビットを表に書いて設計しています。コメントにその表がそのまま残っていて、読み手が検算できるのもよい点です。
- **組み合わせて大きな型にも使う**: 同じファイルの `u32_impl` や `u64_impl` は、先に 100000 や 10^10 で割ってからこの関数を呼びます。小さな高速部品を作り、それを組み立てて全体を作る構成になっています。

## まとめ

- 「x がしきい値以上か」は「x に定数を足したら繰り上がるか」で表せる。
- 複数の比較結果をビットに並べれば、AND や XOR で一度に組み合わせられる。
- 分岐をなくすと、入力によらず速度が安定する。
- トリッキーな定数には、検算できる表をコメントで残すと読み手が助かる。
