## ひとことで

`partition_point` は、スライスの前半が「条件を満たす要素」、後半が「満たさない要素」に分かれているとき、**その境目の位置** を返す関数です。

たとえば `[1, 2, 3, 4, 5, 6]` に「4 より小さい」という条件を渡すと、`1, 2, 3` が条件を満たし `4` 以降が満たさないので、境目の `3` が返ります。
C++ の `std::partition_point` や `lower_bound` にあたる機能を、たった 2 行で既存の二分探索から作っています。

## コード

```rust:line-numbers=4871
    pub const fn partition_point<P>(&self, mut pred: P) -> usize
    where
        P: [const] FnMut(&T) -> bool + [const] Destruct,
    {
        self.binary_search_by(const |x| if pred(x) { Less } else { Greater })
            .unwrap_or_else(const |i| i)
    }
```

## 前提知識

- **ジェネリクスとトレイト境界**: `P: FnMut(&T) -> bool` は「`pred` は要素の参照を受け取って `true`/`false` を返す関数（クロージャ）」という意味です。`where` 以降にその条件を書きます。`[const]` や `Destruct` は、コンパイル時にも使えるようにするための指定で、読むときは無視して構いません。
- **クロージャ `|x| ...`**: その場で作る無名関数です。`const |x| ...` はコンパイル時にも使えるクロージャです。
- **`Ordering`**: 比較結果を表す型で、`Less`・`Equal`・`Greater` の 3 つの値があります。
- **`binary_search_by`**: 比較関数を受け取る二分探索です。要素が目的より小さければ `Less`、大きければ `Greater`、等しければ `Equal` を返す関数を渡すと、見つかれば `Ok(位置)`、なければ挿入すべき位置を `Err(位置)` で返します。
- **`unwrap_or_else`**: `Result` が `Ok(v)` なら `v` を、`Err(e)` ならクロージャに `e` を渡した結果を返します。

## 何をしているか

### 1. 条件を比較結果に読み替える（4875 行目）

`pred(x)` が `true` なら `Less`、`false` なら `Greater` を返すクロージャを作ります。
二分探索から見ると、「条件を満たす要素はすべて目的より小さく、満たさない要素はすべて目的より大きい」ように見えます。目的の値は、ちょうど境目にある「どこにも存在しない値」です。

### 2. 必ず `Err` になる

比較関数が `Equal` を一度も返さないので、`binary_search_by` は必ず「見つからなかった」と判断し、`Err(挿入位置)` を返します。その挿入位置こそが境目です。

`[1, 2, 3, 4, 5, 6]` で「4 より小さい」なら、比較結果は `[Less, Less, Less, Greater, Greater, Greater]` に見え、挿入位置は `3` です。

### 3. 位置を取り出す（4876 行目）

`unwrap_or_else(|i| i)` で `Err(3)` から `3` を取り出します。`Ok` になることは実際にはありませんが、型の上では両方を扱う必要があるので、`Ok` のときもその値を返す形にしています。

## ここがすごい

- **既存の部品の再利用**: 境界探索のために新しい二分探索を書かず、`binary_search_by` の「見つからなければ挿入位置を返す」性質をそのまま利用しています。二分探索の最適化（分岐なし・回数固定）もそのまま受け継げます。
- **「存在しない値を探す」という発想**: `Equal` を返さない比較関数を渡すのは、境目にだけ存在する架空の値を探すことに相当します。二分探索のバグの多くは境界の扱いで起きますが、この方法なら境界の計算は一か所にまとまります。
- **使う側にやさしい API**: 利用者は「条件」を書くだけでよく、`Ordering` を自分で組み立てる必要がありません。たとえば「スコアが 80 以上の人がどこから始まるか」を、`partition_point(|s| s < &80)` のように書けます。
- **前提条件は利用者の責任**: スライスが「前半は条件を満たし、後半は満たさない」形でないと結果は意味を持ちませんが、パニックや未定義動作にはなりません。安全性を保ったまま、速さを優先した設計です。

## まとめ

- 二分探索は「値を探す」だけでなく「条件の境目を探す」のにも使える。
- 比較関数が `Equal` を返さなければ、二分探索は必ず挿入位置（境目）を返す。
- 既存の関数の性質をうまく使えば、新しい機能を数行で作れる。
