## ひとことで

`divmod100` は、0 以上 9999 以下の整数 `value` を **100 で割ったときの商と余り** を、1 回の掛け算と 1 回のシフトだけで求める関数です。
たとえば `divmod100(1234)` は `(12, 34)` を返します。

Rust で `value / 100` と書けば、コンパイラが同じ結果を出す命令を選んでくれます。それでもこの関数が割り算を使わないのは、整数の割り算が掛け算やシフトより遅いことが多いからです。10 進数の文字列を作るライブラリでは、この計算が何度も呼ばれるので、そこを速くしています。

## コード

::: code-group

```rust:line-numbers=230 [日本語訳]
// 4 桁までの値について正しく、{value / 100, value % 100} を返す。
fn divmod100(value: u32) -> (u32, u32) {
    debug_assert!(value < 10_000);
    const EXP: u32 = 19; // 3 桁でも 12 と同じかそれより速いので、19 を選んでいる。
    const SIG: u32 = (1 << EXP) / 100 + 1;
    let div = (value * SIG) >> EXP; // value / 100 にあたる商
    (div, value - div * 100)
}
```

```rust:line-numbers=230 [原文]
// Returns {value / 100, value % 100} correct for values of up to 4 digits.
fn divmod100(value: u32) -> (u32, u32) {

    (div, value - div * 100)
}
```

## 前提知識

- **`u32`**: 0 から約 42 億までの値を持つ符号なし 32 ビット整数です。
- **`fn divmod100(value: u32) -> (u32, u32)`**: 引数は `u32` で、戻り値は商と余りの 2 つの値を入れたタプル（`(u32, u32)`）です。
- **`const`**: 値がコンパイル時に決まる定数です。`const EXP: u32 = 19;` は `EXP` が常に 19 であることを表します。
- **`<<` と `>>`**: 左シフトと右シフトです。`x >> n` は、2 の n 乗で割って小数点以下を切り捨てることと同じです。
- **`debug_assert!`**: デバッグビルドのときだけ条件を確かめる文です。リリースビルドでは消えます。
- **`(a, b)` のタプルの返し方**: 最後の行の式がそのまま戻り値になります。`return` は不要です。

## 何をしているか

### 1. 2 の 19 乗を 100 で割った値を作る

```rust:line-numbers=233
    const EXP: u32 = 19; // 19 is faster or equal to 12 even for 3 digits.
    const SIG: u32 = (1 << EXP) / 100 + 1;
```

`1 << 19` は 524288 です。これを 100 で割ると 5242.88 なので、切り上げた 5243 を `SIG` とします。`+ 1` は、切り捨てによる誤差が出ないよう値を少し大きくするための調整です。

### 2. 掛けてから 19 ビット右にずらす

```rust:line-numbers=235
    let div = (value * SIG) >> EXP; // value / 100
```

`value * 5243` を 2 の 19 乗（524288）で割ると、おおむね `value / 100` になります。`value = 1234` で確かめます。

```
1234 * 5243 = 6469862
6469862 >> 19 = 6469862 / 524288 = 12.34…  → 12
```

切り捨てると 12 になり、1234 を 100 で割った商と一致します。

### 3. 余りは引き算で求める

```rust:line-numbers=236
    (div, value - div * 100)
```

余りは、もとの値から「商 × 100」を引けば求まります。`1234 - 12 * 100 = 34` です。割り算をもう一度せず、掛け算と引き算だけで余りが出せるのがポイントです。

## ここがすごい

- **割り算の代わりに掛け算とシフト**: 掛け算とシフトは CPU で 1 命令か、ごく少ない命令で終わります。割り算命令はそれより時間がかかることが多いため、10 進文字列への変換のように頻繁に呼ばれる処理で効きます。
- **定数を自分で選んでいる**: `EXP = 19` は「3 桁でも 12 と同じかそれより速い」という測定に基づく選択だと、コメントに書かれています。数字の意味を読み手に伝えています。
- **範囲を限定している**: 関数の先頭のコメントが「4 桁まで」と明記しています。対象を絞ったからこそ、小さな定数とシフトで正確な答えが出せます。何でも扱える汎用の割り算ではありません。
- **`debug_assert!` で前提を確認**: 4 桁以外の値が来るとデバッグビルドでは止まり、誤った使い方を早く見つけられます。リリースビルドでは余計な確認が消えます。

## まとめ

- 割る数が決まっているなら、掛け算とシフトで商を近似できる。
- 余りは、商を使って引き算で求めると速い。
- 近似が正しく動く範囲を、コメントと `debug_assert!` で明示する。
- 定数の選び方は、測定結果をコメントに残すと読み手が理解しやすい。
