## ひとことで

`u64_to_hi64_2` は、2 つの 64 ビット整数 `r0` と `r1` を **1 つの 128 ビットの数とみなして、その上位 64 ビットを取り出す** 関数です。上位の桁が 0 のままだと精度が落ちるので、先頭のゼロを左に詰めてから取り出します。

戻り値の 1 つ目は、詰めた上位 64 ビットです。2 つ目は、下位のビットに 0 でない部分があるかどうかの情報です。この値は、浮動小数点の丸めを正しく決めるために使われます。

## コード

```rust:line-numbers=117
fn u64_to_hi64_2(r0: u64, r1: u64) -> (u64, bool) {
    debug_assert!(r0 != 0);
    let ls = r0.leading_zeros();
    let rs = 64 - ls;
    let v = match ls {
        0 => r0,
        _ => (r0 << ls) | (r1 >> rs),
    };
    let n = r1 << ls != 0;
    (v, n)
}
```

この関数は、`hi64_2` などのトレイトメソッドから呼ばれます。浮動小数点の文字列を数値に変換するとき、大きな整数の掛け算の結果を、扱いやすい形に整えるために使われます。

## 前提知識

- **上位ビット（hi）**: 2 進数の左側の桁です。128 ビットの数の左半分、つまり上位 64 ビットを指します。
- **`leading_zeros`**: 先頭の 0 の個数です。`r0` の先頭の 0 を数えると、左へどれだけ詰めればよいか分かります。
- **左シフト（`<<`）**: ビットを左へ動かします。値が 2 倍ずつ大きくなります。
- **右シフト（`>>`）**: ビットを右へ動かします。`rs` 個分だけ、`r1` の上位ビットを下へ落とします。
- **論理和（`|`）**: 2 つの値の同じ位置のビットを合わせます。詰めた `r0` と、`r1` から来たビットを 1 つにまとめます。

## 何をしているか

### 1. 先頭の 0 の数を数える

```rust:line-numbers=118
    debug_assert!(r0 != 0);
    let ls = r0.leading_zeros();
```

`r0` の先頭にある 0 の個数を `ls` とします。`rs` は、残りの有効なビットの数です。`r0` が 0 でないことは、呼び出し側が保証しています。

### 2. 上位 64 ビットを詰め直す

```rust:line-numbers=121
    let v = match ls {
        0 => r0,
        _ => (r0 << ls) | (r1 >> rs),
    };
```

`ls` が 0 なら、`r0` はすでに上位にあるので、そのまま使います。そうでなければ、`r0` を `ls` 個左にずらし、空いた下位ビットに `r1` の上位ビットを入れます。

### 3. 下位の情報を残す

```rust:line-numbers=125
    let n = r1 << ls != 0;
    (v, n)
```

`r1 << ls` が 0 でないなら、`r1` のうち上位に取り込まれなかった残りのビットに 1 が含まれています。その情報を `n` として返すので、呼び出し側は丸めの判断ができます。

## ここがすごい

- **128 ビットの整数を作らずに済む**: 2 つの 64 ビットをそのまま扱い、ビットを組み合わせるだけで、必要な上位部分を得ています。
- **捨てた情報を忘れない**: 上位を取り出すと、下位のビットは消えてしまいます。`n` で「消えた部分に 1 があったか」を覚えておくことで、丸めを誤りなく判断できます。
- **分岐が 1 回だけ**: `ls` が 0 かどうかで、一度だけ分岐します。それ以外は、シフトと論理和だけで計算します。

## まとめ

- 2 つの 64 ビット整数から、上位 64 ビットを先頭の 0 を詰めて取り出す。
- 捨てられる下位の情報は、戻り値の真偽値に残す。
- 128 ビットの整数を使わず、シフトと論理和だけで同じ結果を得る。
