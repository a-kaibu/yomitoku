## ひとことで

`match_full` は、SIMD で読み込んだ 16 個の目印（タグ）のうち、**値が入っているバケット** を表すビットの一覧（`BitMask`）を返す関数です。値が入っているとは、空（EMPTY）でも削除済み（DELETED）でもないことです。
この関数は、「空か削除済みか」を表すビットの一覧を作り、その全ビットを反転しています。そのため、新しい比較は要らず、ビットを 1 つ反転するだけで済みます。

## コード

```rust:line-numbers=112
    #[inline]
    pub(crate) fn match_full(&self) -> BitMask {
        BitMask(!self.match_empty_or_deleted().0)
    }
```

`self.match_empty_or_deleted()` は、同じファイルにある関数で、空または削除済みのタグがどこにあるかを一覧にします。`match_full` はその結果を使います。

## 前提知識

- **SIMD（同時に複数の値を扱う命令）**: SSE2 では、128 ビットのレジスタに 16 個のバイトを載せて、一度に比べられます。hashbrown は、16 個のタグを 1 回の命令で処理しています。
- **`BitMask`**: 1 ビットずつが、バケットの 1 つに対応する整数です。立っているビットが、条件を満たすバケットを表します。
- **タグの値**: 空は `0b1111_1111`、削除済みは `0b1000_0000` です。どちらも最上位ビットが 1 で、値の入っているタグは最上位ビットが 0 です。
- **`!`（ビット反転）**: すべてのビットを反転します。`BitMask` の中の 0 と 1 が入れ替わります。
- **`movemask`**: 16 個のバイトのそれぞれについて、最上位ビットを集めて 1 つの整数にする命令です。

## 何をしているか

### 1. 空か削除済みかの一覧を作る

```rust:line-numbers=107
            BitMask(x86::_mm_movemask_epi8(self.0) as u16)
```

`match_empty_or_deleted` は、各バイトの最上位ビットを `movemask` で集めます。空も削除済みも、最上位ビットは 1 なので、その位置のビットが 1 になります。

### 2. その一覧を反転する

```rust:line-numbers=113
    pub(crate) fn match_full(&self) -> BitMask {
        BitMask(!self.match_empty_or_deleted().0)
    }
```

`match_full` は、この一覧の 0 と 1 を反転します。空でも削除済みでもない位置、つまり値が入っている位置のビットが 1 になります。
`match_full` は `&self` を取り、グループの内容を変えずに一覧だけを返します。

## ここがすごい

- **比較を 1 回で全部判定する**: 16 個のタグを、SIMD の命令で同時に判定します。バケットを 1 つずつ調べるより、ずっと速く終わります。
- **反転だけで別の意味が得られる**: 「空か削除済み」と「値がある」は、互いに逆の集合です。すでにある一覧を反転するだけで求められるので、同じ処理を 2 回書く必要がありません。
- **最上位ビットの設計が効いている**: タグの設計で、値があるかどうかが最上位ビットで決まっています。だから、`movemask` 1 回で、空・削除済みの一覧が作れます。
- **結果が BitMask なので、そのまま走査できる**: 値があるバケットを、ビットを 1 つずつ取り出して順に見ていけます。
- **処理がすべてビット演算**: ループや分岐がほとんどなく、CPU の命令が続けて流れるように書かれています。

## まとめ

- 値が入っているバケットは、「空か削除済み」の一覧を反転すると得られる。
- SIMD で 16 個のタグを 1 回の命令で判定し、結果をビットの一覧にする。
- タグの最上位ビットを「値の有無」にしてあるので、この反転と `movemask` だけで済む。
