## ひとことで

`roll` は、**文字列の中で検索している窓（ウィンドウ）を 1 バイト右にずらしたときの、ハッシュ値の更新** を行う関数です。窓の先頭のバイトを外し、末尾に新しいバイトを加えます。
ハッシュ値を毎回ゼロから計算し直すのではなく、前の値から **足し引き** で求めるので、窓がどんなに長くても、ずらすたびの作業は一定です。この考え方を **ローリングハッシュ** と呼び、Rabin-Karp 法という文字列検索の土台になっています。

## コード

```rust:line-numbers=330
    fn roll(&mut self, finder: &Finder, old: u8, new: u8) {
        self.del(finder, old);
        self.add(new);
    }
```

`roll` は、`del` で古いバイトを取り除き、`add` で新しいバイトを加える、という 2 つの操作をまとめたものです。

## 前提知識

- **文字列検索**: 長い文字列（ヘイスタック）の中に、短い文字列（ニードル）が現れる場所を探す問題です。
- **ハッシュ値の比較**: 窓のハッシュとニードルのハッシュを比べて、等しければ念のため中身を確かめます。ハッシュが違えば、その窓は一致しないと分かります。
- **`wrapping_shl` と `wrapping_add`**: 溢れても止まらないビットのずらしと足し算です。`u32` の範囲で計算されます。
- **多項式ハッシュ**: バイトを「各位置の重み付きの和」として扱うハッシュです。ここでは、重みが 2 の冪になっています。
- **`u32::from(byte)`**: 1 バイトを `u32` に広げます。

## 何をしているか

### 1. 古いバイトの寄与を取り除く

```rust:line-numbers=344
    fn del(&mut self, finder: &Finder, byte: u8) {
        let factor = finder.hash_2pow;
        self.0 = self.0.wrapping_sub(u32::from(byte).wrapping_mul(factor));
    }
```

`del` は、窓の先頭にあったバイトの寄与を、ハッシュから引きます。寄与は、バイトの値に、その位置の重みを掛けたものです。重みは `finder.hash_2pow` で、事前に計算されています。

### 2. 新しいバイトを加える

```rust:line-numbers=337
    fn add(&mut self, byte: u8) {
        self.0 = self.0.wrapping_shl(1).wrapping_add(u32::from(byte));
    }
```

`add` は、今のハッシュを 1 ビット左にずらしてから、新しいバイトを足します。左にずらすことで、既存のバイトの重みが 2 倍になり、新しいバイトが一番小さい重みで入ります。

### 3. 2 つを組み合わせる

```rust:line-numbers=331
        self.del(finder, old);
        self.add(new);
```

`roll` は、先に古いバイトを外し、そのあとで新しいバイトを加えます。これで、窓が 1 バイト分右に動いたときのハッシュ値になります。

## ここがすごい

- **窓の長さによらず一定の作業**: 窓が 1000 バイトでも、ずらすたびの計算は、引き算 1 回と、ずらし 1 回、足し算 1 回だけです。窓の中身を全部読み直す必要がありません。
- **ずらしで重みを表す**: 左にずらすだけで、古いバイトは重みが倍になっていきます。窓の先頭の重みを事前に計算しておけば、`del` で正確に取り除けます。
- **`wrapping` で溢れを気にしない**: 窓が長くなると、ハッシュは `u32` の範囲を超えます。溢れを wrapping で受け入れて、剰余のような別の計算をせずに済みます。
- **ハッシュが一致したら確かめる**: ローリングハッシュは衝突することがあります。そのため、一致したときは、実際にバイトを比べて確かめます。
- **順番の工夫**: 先に取り除き、あとで加えるので、窓の大きさを一時的に超えません。単純な順序が、正しい重みを保つ鍵になっています。

## まとめ

- ローリングハッシュは、窓を 1 バイトずらすとき、古いバイトを引き、新しいバイトを足して更新する。
- 窓の長さに関係なく、更新は一定の計算で済む。
- ハッシュの一致は確かめのきっかけで、最後は実際のバイトを比べる。
