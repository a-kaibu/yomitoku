## ひとことで

`random` は、`futures` の内部で **偶然の値（64 ビットの整数）を 1 つ返す** 関数です。`async` の処理で、実行の順番をランダムに決めたい場面などで使われます。

乱数の作り方は **xorshift\*** という方法です。3 回のシフトと排他的論理和で状態を変え、最後に大きな奇数を掛けて、ビットを散らします。外部のライブラリに頼らず、とても小さなコードで済んでいます。

## コード

```rust:line-numbers=45
    RNG.with(|rng| {
        let mut x = rng.get();
        debug_assert_ne!(x.0, 0);
        x ^= x >> 12;
        x ^= x << 25;
        x ^= x >> 27;
        rng.set(x);
        x.0.wrapping_mul(0x2545_f491_4f6c_dd1d)
    })
```

状態は `thread_local!` で、スレッドごとに 1 つずつ持ちます。ロックを使わないので、スレッドが増えても待ちが発生しません。

## 前提知識

- **xorshift**: 整数を右と左へ、ビット単位でずらしながら排他的論理和を取る乱数の作り方です。とても軽く、乱数の質も実用的です。
- **`thread_local!`**: 変数を、スレッドごとに別々に持つ仕組みです。各スレッドが自分の状態を書き換えるので、ロックが要りません。
- **`Cell`**: 中の値を、共有された参照からでも書き換えられる箱です。`get` と `set` で値を読み書きします。
- **`wrapping_mul`**: 溢れても止まらずに、2^64 で折り返す掛け算です。乱数の定番の書き方です。
- **`debug_assert_ne!`**: デバッグのときだけ、2 つの値が違うことを確かめる確認です。状態が 0 になると、xorshift は 0 のままになってしまいます。

## 何をしているか

### 1. 状態を読み、0 でないことを確かめる

```rust:line-numbers=46
        let mut x = rng.get();
        debug_assert_ne!(x.0, 0);
```

スレッドの状態 `x` を読みます。xorshift は 0 から先に進めないので、0 でないことを前提にしています。この前提は、種を作る処理（`prng_seed`）で保たれています。

### 2. 3 回のシフトと排他的論理和で状態を変える

```rust:line-numbers=48
        x ^= x >> 12;
        x ^= x << 25;
        x ^= x >> 27;
```

右に 12 ビット、左に 25 ビット、右に 27 ビットずらし、そのたびに自分自身と排他的論理和を取ります。ビットが少しずつ混ざり、同じ値が続きにくくなります。

### 3. 状態を保存し、大きな奇数を掛けて返す

```rust:line-numbers=51
        rng.set(x);
        x.0.wrapping_mul(0x2545_f491_4f6c_dd1d)
```

新しい状態を `set` で保存します。返す値は、状態に定数を掛けたものです。掛ける定数は奇数なので、下位のビットが偏りにくくなります。

## ここがすごい

- **状態は 1 つの整数**: 必要な記憶は 64 ビットだけです。スレッドごとに持っても、負担になりません。
- **ロックが要らない**: 状態はスレッドごとに分かれているので、他のスレッドと競合しません。乱数を取るたびに、待つことがありません。
- **掛け算で仕上げる**: シフトと排他的論理和だけだと、下位のビットに偏りが残ることがあります。最後の掛け算で、ビットを上位へ散らしています。

## まとめ

- 乱数の状態をスレッドごとに持つと、ロックなしで乱数を取り出せる。
- xorshift のシフトと排他的論理和で状態を変え、掛け算で仕上げる。
- 状態が 0 になると進まないので、種は必ず 0 でない値にする。
