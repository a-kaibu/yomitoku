## ひとことで

`slot_for` は、**ある期限（ミリ秒）が、階層 `level` のどの区画（スロット）に入るか** を求める関数です。タイミングホイールは、時計の針のように区画が円になっていて、時間が近いものは細かい階層に、遠いものは粗い階層に入れます。

計算はとても短く、期限を `level * 6` ビット右にずらしてから、区画の数で割った余りを取るだけです。

## コード

```rust:line-numbers=183
fn slot_for(duration: u64, level: usize) -> usize {
    ((duration >> (level * 6)) % LEVEL_MULT as u64) as usize
}
```

## 前提知識

- **タイミングホイール**: 時間の予約を、区画の並んだ円盤に入れて管理するデータ構造です。タイマーを 1 つずつ比べる代わりに、どの区画に入るかで扱います。
- **階層**: 区画を何段にも重ねたものです。下の段は細かく、上の段は粗い単位になります。
- **右シフト（`>>`）**: 2 進数の桁を右に動かします。`>> 6` は、64 で割った商を取り出すことと同じです。
- **剰余（`%`）**: 割り算の余りです。区画の数で割ると、円のどの位置かが分かります。
- **`LEVEL_MULT`**: 1 つの階層にある区画の数を表す定数です。この関数では、`level * 6` ビットの右シフトと組み合わせて使われます。

## 何をしているか

### 1. 階層に応じてビットを下ろす

```rust:line-numbers=184
    ((duration >> (level * 6)) % LEVEL_MULT as u64) as usize
```

`duration >> (level * 6)` は、期限を階層ごとの単位に換算します。階層が 1 つ上がるたびに、6 ビット分だけ右にずれるので、単位は区画の数ずつ大きくなります。

### 2. 区画の数で割った余りを取る

```rust:line-numbers=184
    ((duration >> (level * 6)) % LEVEL_MULT as u64) as usize
```

`% LEVEL_MULT` で、その階層の中の区画番号に変換します。余りなので、結果は必ず `0` 以上 `LEVEL_MULT` 未満になります。最後に `as usize` で配列の添字に使える型へ変えます。

## ここがすごい

- **割り算を使わない**: 区画の数が 2 の冪なら、剰余は下位ビットの取り出しと同じです。階層を 1 つ上げるたびに、`>> 6` で単位を 64 倍にできます。
- **計算が一定**: 期限がいくら遠くても、階層を選ぶのに必要な計算は同じです。ループや比較の回数が増えません。
- **階層の境界が自然に決まる**: 上位の階層の区画は、下位の階層の何個分かに対応します。その対応が、ビットをずらす量の 6 ビット刻みで表現されています。

## まとめ

- 期限を、階層ごとに 6 ビットずつ右にずらし、区画の数で割った余りが区画番号になる。
- 割り算の代わりにビットの操作を使うので、計算は短く速い。
- 階層が増えても、同じ式で区画を求められる。
