## ひとことで

`ord2` は、コードポイント（文字の番号）を、2 バイトの UTF-8 に変換する関数です。`'é'`（U+00E9）のような、2 バイトで表せる文字を扱います。

名前の `ord` は「序数」（文字の番号）を意味し、`2` は「2 バイトで表す」ことを表します。変換の中身は、ビットを切り出すことだけです。

## コード

```haskell:line-numbers=107
ord2 c =
#if defined(ASSERTS)
    assert (n >= 0x80 && n <= 0x07ff)
#endif
    (x1,x2)
    where
      n  = ord c
      x1 = intToWord8 $ (n `shiftR` 6) + 0xC0
      x2 = intToWord8 $ (n .&. 0x3F)   + 0x80
```

## 前提知識

- **UTF-8 の 2 バイト形式**: 先頭のバイトは `110xxxxx`、続きのバイトは `10xxxxxx` です。`x` の部分に、コードポイントのビットを入れます。
- **ビット演算**: `shiftR`（右シフト）と `.&.`（かつ）を使います。`shiftR n 6` は、下から 6 ビットを捨てて、上の部分を取り出します。`.&. 0x3F` は、下位 6 ビットだけを残します。
- **`where`**: 関数の中で、補助の値 `n` や `x1` などに名前を付けています。
- **`intToWord8`**: 整数を 1 バイトに変換する関数です。
- **`#if defined(ASSERTS)`**: コンパイル時の指示です。デバッグ用の確認（`assert`）は、特定の設定でだけ有効になります。

## 何をしているか

### 1. コードポイントを取り出す

```haskell:line-numbers=113
      n  = ord c
```

`ord c` は、文字 `c` の番号（コードポイント）を整数として取り出します。

### 2. 先頭のバイトを作る

```haskell:line-numbers=114
      x1 = intToWord8 $ (n `shiftR` 6) + 0xC0
```

`n shiftR 6` で、下位 6 ビットを捨てて、上位のビットを取り出します。そこに `0xC0`（`11000000`）を足すと、先頭バイトの `110xxxxx` の形になります。

### 3. 続きのバイトを作る

```haskell:line-numbers=115
      x2 = intToWord8 $ (n .&. 0x3F)   + 0x80
```

`n .&. 0x3F` は、下位 6 ビットを取り出します。そこに `0x80`（`10000000`）を足すと、`10xxxxxx` の形の続きのバイトになります。

具体的に見てみます。`'é'` のコードポイントは `0xE9` です。上位の部分は `0x3`（`11`）、下位は `0x29`（`101001`）です。先頭バイトは `11000011` で `0xC3`、続きは `10101001` で `0xA9` になります。

## ここがすごい

この変換は、コードポイントのビットを 6 ビットずつ切り分けているだけです。UTF-8 の規則が、ビットの切り分けそのものとして決まっているので、計算は単純な足し算とシフトで済みます。

また、「2 バイトだと分かっている」ときにしか呼べないように、名前と説明で前提を明示しています。範囲を確かめるのは `assert` の役目で、デバッグ時だけ有効になる仕組みが用意されています。速さを保ちながら、安全を確かめる方法を分けています。

## まとめ

- UTF-8 は、コードポイントのビットを 6 ビットずつ切り分けて作る。
- 先頭の目印（`110`、`10`）は、足し算で付けられる。
- 前提の確認を、デバッグ時だけの仕組みに分けると、本番の速さを保てる。
