## ひとことで

`mask` は、ハッシュ値と段の深さから、その段で使う枝の番号に対応する **1 ビットだけが立った整数** を作ります。この整数を「ビットマップ」と呼ばれる枝の一覧と照らし合わせると、その枝があるかどうかを一瞬で確かめられます。

たとえば番号が 2 なら、`0b0100`（2 番目のビットだけが 1）になります。

## コード

```haskell:line-numbers=2939
mask :: Hash -> Shift -> Bitmap
mask w s = 1 `unsafeShiftL` index w s
```

## 前提知識

- **`Bitmap`**: 枝の有無を、1 ビットずつ表す整数です。ビットが 1 なら、その番号の枝がある、という意味です。
- **`index`**: 前の記事で見た、枝の番号（0 から 31）を返す関数です。
- **`1 `unsafeShiftL` n`**: 1 を左へ `n` ビットずらす演算です。結果は、ビットの位置 `n` だけが 1 の値になります。
- **`mask` の型**: `Hash -> Shift -> Bitmap` は、ハッシュ値と段の深さを受け取り、ビットマップを返す関数です。

## 何をしているか

### 1. 枝の番号を取り出す

```haskell:line-numbers=2940
mask w s = 1 `unsafeShiftL` index w s
```

`index w s` で、その段の枝の番号を求めます。次に、`1` をその番号の分だけ左にずらします。たとえば番号が 2 なら、`1 << 2` は `0b0100` になります。

### 2. ビットマップと照らし合わせる

枝の一覧（ビットマップ）を持つノードでは、`mask` の結果と、ビットマップの「かつ」を取ります。結果が 0 なら、その枝は存在しません。0 でなければ、その枝があります。

さらに、ビットマップの中で、その枝より下位に何本の枝が立っているかを数えると、配列の中の位置が分かります。こうして、配列には実際にある枝だけを詰めて入れられます。

## ここがすごい

32 本の枝のうち、どれがあるかを、32 ビットの 1 つの整数で表せます。配列の中に空の枝を入れておく必要がないので、メモリを節約できます。

また、存在の判定は「かつ」の 1 回の演算で済みます。ループや比較を使わないので、木をたどる処理が速くなります。`index` と `mask` を分けておくことで、番号を求める処理と、ビットに変える処理を別々に読めるのも利点です。

## まとめ

- 枝の有無は、ビットの 0 と 1 で表すと、少ないメモリで判定できる。
- 1 を番号の分だけずらすと、その番号に対応するビットが得られる。
- 空の枝を置かずに、実際にある枝だけを詰めて持てる。
