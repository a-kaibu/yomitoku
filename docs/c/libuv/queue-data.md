## ひとことで

libuv は、ハンドルやリクエストをつなぐ双方向リストを自前で持っています。リストのノード `struct uv__queue` は、つなぎたい構造体の **中に埋め込まれて** います。
`uv__queue_data` は、リストをたどって手に入れた「ノードのアドレス」から、**そのノードを中に持っている構造体のアドレス** を計算するマクロです。
あわせて定義されている `uv__queue_foreach` は、リストを 1 周するための `for` 文の決まり文句です。

## コード

```c:line-numbers=21
#define uv__queue_data(pointer, type, field)                                  \
  ((type*) ((char*) (pointer) - offsetof(type, field)))

#define uv__queue_foreach(q, h)                                               \
  for ((q) = (h)->next; (q) != (h); (q) = (q)->next)
```

## 前提知識

- **`#define`（マクロ）**: コンパイル前に文字列を置き換える仕組みです。引数を取るマクロは関数のように書けますが、実際には呼び出しではなく、その場にコードが展開されます。行末の `\` は「次の行に続く」という印です。
- **ポインタ**: メモリ上のアドレスを持つ値です。`type*` は「`type` 型の値がある場所」を表します。
- **キャスト `(type*)`**: 値を別の型として扱うよう指示します。ここではアドレスの数値はそのままに「何を指しているか」の解釈だけを変えます。
- **`char*` でのポインタ演算**: ポインタに整数を足し引きすると、「指している型の大きさ × その数」だけ動きます。`char` は 1 バイトなので、`(char*) p - 8` はちょうど 8 バイト手前を指します。
- **`offsetof(type, field)`**: `<stddef.h>` にある標準マクロで、構造体 `type` の先頭からメンバ `field` までが何バイト離れているかを返します。
- **双方向循環リスト**: 各ノードが `next`（次）と `prev`（前）を持ち、最後のノードの `next` が先頭の「見張り役（ヘッド）」に戻ってくるリストです。

## 何をしているか

### 1. 持ち主を逆算する

```c:line-numbers=21
#define uv__queue_data(pointer, type, field)                                  \
  ((type*) ((char*) (pointer) - offsetof(type, field)))
```

たとえば、次のような構造体を考えます（説明用）。

```c
struct job {
  int id;                  /* 先頭から 0 バイト目 */
  int prio;                /* 4 バイト目 */
  struct uv__queue link;   /* 8 バイト目 */
};
```

リストをたどると、手元には `link` のアドレス（たとえば `0x1008`）だけがあります。欲しいのは `struct job` の先頭（`0x1000`）です。
`offsetof(struct job, link)` は 8 なので、`(char*) 0x1008 - 8` で `0x1000` が求まり、それを `(struct job*)` にキャストすれば完成です。
`uv__queue_data(q, struct job, link)` は、この計算をそのまま 1 行にしたものです。

### 2. 1 周する決まり文句

```c:line-numbers=24
#define uv__queue_foreach(q, h)                                               \
  for ((q) = (h)->next; (q) != (h); (q) = (q)->next)
```

`uv__queue_foreach(q, h)` は `for ((q) = (h)->next; (q) != (h); (q) = (q)->next)` に展開されます。
ヘッド `h` の次から始めて、ヘッドに戻ってきたら終わり、という循環リストの典型的な走査です。ヘッド自身はデータを持たない見張り役なので、ループの中には現れません。

## ここがすごい

- **リストが中身の型を知らなくてよい**: リストの関数はすべて `struct uv__queue` だけを扱います。タイマーでも TCP ハンドルでも、同じリスト操作を使い回せます。C にはジェネリクス（型を引数にする仕組み）がありませんが、このマクロで似た効果を得ています。
- **メモリ確保が要らない**: 「ノードの中にデータへのポインタを入れる」方式だと、つなぐたびにノードを `malloc` する必要があります。埋め込み方式なら構造体を用意した時点でノードも存在するので、リストへの追加が失敗しません。
- **1 つの構造体が複数のリストに入れる**: ノードを 2 つ埋め込めば、同時に 2 本のリストに属せます。どちらのノードから来ても、`field` を変えて同じマクロで持ち主に戻れます。
- **カッコの付け方**: マクロ本体で `(pointer)` や `(q)` のように引数を毎回カッコで囲んでいます。`p + 1` のような式を渡されても、展開後に演算の優先順位が崩れないようにするための、マクロを書くときの基本の作法です。
- Linux カーネルの `container_of` と同じ考え方で、C の世界では定番の技法です。libuv 自身も `uv-common.h` に同じ計算の `container_of` を持っています。

## まとめ

- 構造体にリストのノードを埋め込み、ノードのアドレスから `offsetof` を引けば持ち主の構造体に戻れる。
- `char*` にしてから引き算するのは、バイト単位でアドレスを動かすため。
- 循環リストは「ヘッドの次から、ヘッドに戻るまで」で 1 周できる。
- マクロの引数は必ずカッコで囲む。
