## ひとことで

`uv__get_surrogate_value` は、UTF-16 の文字列の先頭から **1 文字ぶんのコードポイント** を取り出す関数です。
先頭が上位サロゲート、次が下位サロゲートなら、2 つを合体させて U+10000 以上の 1 つの番号にします。そうでなければ、先頭の 16 ビット値をそのまま返します。
対になっていないサロゲートもエラーにしない点が、Windows のファイル名を扱う libuv らしいところです。

## コード

```c:line-numbers=414
static int32_t uv__get_surrogate_value(const uint16_t* w_source_ptr,
                                       ssize_t w_source_len) {
  uint16_t u;
  uint16_t next;

  u = w_source_ptr[0];
  if (u >= 0xD800 && u <= 0xDBFF && w_source_len != 1) {
    next = w_source_ptr[1];
    if (next >= 0xDC00 && next <= 0xDFFF)
      return 0x10000 + ((u - 0xD800) << 10) + (next - 0xDC00);
  }
  return u;
}
```

## 前提知識

- **UTF-16 とサロゲートペア**: UTF-16 は文字を 16 ビット単位で表します。U+10000 以上の文字は、上位サロゲート（0xD800〜0xDBFF）と下位サロゲート（0xDC00〜0xDFFF）の 2 単位で表します。
- **はぐれサロゲート（lone surrogate）**: 相方のいないサロゲートです。正しい UTF-16 にはありませんが、Windows のファイル名には実際に含まれることがあります。
- **`const uint16_t* w_source_ptr`**: 16 ビット整数の並びを指すポインタです。`w_source_ptr[0]` が先頭、`w_source_ptr[1]` がその次の値です。`const` は「この関数は書き換えない」という約束です。
- **`ssize_t w_source_len`**: 残りの長さです。符号付きなので負の値も入ります。libuv では **負の長さは「0 で終わる文字列なので長さは不明」** という意味に使っています。
- **`static`**: このファイルの中だけで使う関数という意味です。

## 何をしているか

### 1. 先頭を読む

```c:line-numbers=419
  u = w_source_ptr[0];
```

`u` に先頭の 16 ビット値を入れます。

### 2. 上位サロゲートで、次がありそうなら次を見る

```c:line-numbers=420
  if (u >= 0xD800 && u <= 0xDBFF && w_source_len != 1) {
    next = w_source_ptr[1];
```

`u` が 0xD800〜0xDBFF（上位サロゲート）であり、かつ `w_source_len != 1` なら、次の値 `next` を読みます。
長さが 1 ちょうどなら次の値は存在しないので、読みません。長さが負（0 終端の文字列）なら、次の値は少なくとも終端の 0 として存在するので、読んでも安全です。

### 3. 下位サロゲートなら合体

```c:line-numbers=422
    if (next >= 0xDC00 && next <= 0xDFFF)
      return 0x10000 + ((u - 0xD800) << 10) + (next - 0xDC00);
```

`next` が 0xDC00〜0xDFFF なら、`0x10000 + ((u - 0xD800) << 10) + (next - 0xDC00)` で合体させます。
`D83D DE00` なら、`(0xD83D - 0xD800) << 10 = 0x3D << 10 = 0xF400`、`0xDE00 - 0xDC00 = 0x200`、合計 `0x10000 + 0xF400 + 0x200 = 0x1F600`（😀）です。

### 4. それ以外はそのまま

```c:line-numbers=425
  return u;
```

普通の文字も、はぐれサロゲートも、`u` をそのまま返します。たとえば `D83D 0041`（上位サロゲートの直後に `A`）なら、`0xD83D` が返ります。

## ここがすごい

- **`!= 1` の 1 つの比較で 2 種類の長さを扱う**: 「長さがわかっていて残り 2 以上」と「0 終端で長さ不明」の両方で次を読んでよく、「残り 1」のときだけ読んではいけません。`w_source_len != 1` はちょうどその条件です。長さ 0 はこの関数を呼ぶ前に呼び出し側のループで止まります。負の長さを特別な意味に使う設計が、ここで 1 つの比較にきれいに収まっています。
- **壊れたデータを捨てない**: 厳密な変換なら、はぐれサロゲートはエラーか置換文字（U+FFFD）にします。しかしファイル名でそれをすると、変換後の名前で元のファイルを開けなくなります。libuv は WTF-8 という「はぐれサロゲートも表せる UTF-8」を使い、値をそのまま運ぶことで往復できるようにしています。この関数はその最初の入口です。
- **呼び出し側が進め方を決める**: この関数は位置を進めません。返り値が 0x10000 以上なら 2 単位、そうでなければ 1 単位進めればよいと、呼び出し側（`uv_utf16_length_as_wtf8` など）が値から判断します。

## まとめ

- 上位サロゲートの次に下位サロゲートがあれば、`0x10000 + (上位 - 0xD800) << 10 + (下位 - 0xDC00)` で 1 文字に戻る。
- 次の値を読む前に、それが存在するかを長さで確かめる。
- 負の長さを「0 終端」の意味に使うと、1 つの関数で両方の文字列を扱える。
- ファイル名のように壊れていても失えないデータは、エラーにせずそのまま運ぶ。
