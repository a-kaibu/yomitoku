## ひとことで

`uv__queue_add(h, n)` は、リスト `n` に入っている要素を **すべて**、リスト `h` の末尾にまとめてつなげる関数です。
要素が 3 個でも 3 万個でも、ポインタを 4 回書き換えるだけで終わります。
ヘッド（見張り役のノード）付きの双方向循環リストならではの、短くてきれいな操作です。

## コード

```c:line-numbers=44
static inline void uv__queue_add(struct uv__queue* h, struct uv__queue* n) {
  h->prev->next = n->next;
  n->next->prev = h->prev;
  h->prev = n->prev;
  h->prev->next = h;
}
```

## 前提知識

- **`struct uv__queue`**: `next`（次のノード）と `prev`（前のノード）の 2 つのポインタだけを持つ構造体です。データは持たず、データ側の構造体に埋め込んで使います。
- **ヘッド付き循環リスト**: リストの入口に、データを持たない特別なノード「ヘッド」を置きます。最後の要素の `next` はヘッドに、ヘッドの `prev` は最後の要素に戻ってきます。空のリストは、ヘッドの `next` も `prev` も自分自身を指している状態です。
- **`->`**: ポインタが指す構造体のメンバにアクセスします。`h->prev->next` は「`h` の前のノードの、次のポインタ」です。
- **`static inline`**: ヘッダファイルに書く小さな関数によく付けます。`inline` は「呼び出し部分に本体を埋め込んでよい」という最適化のヒント、`static` は「このファイルの中だけの関数」という意味です。

## 何をしているか

リスト `h` が `[H] ⇄ A ⇄ B ⇄ (H に戻る)`、リスト `n` が `[N] ⇄ X ⇄ Y ⇄ (N に戻る)` だとします。結果として `[H] ⇄ A ⇄ B ⇄ X ⇄ Y` にしたいわけです。

### 1. B → X をつなぐ

```c:line-numbers=45
  h->prev->next = n->next;
```

`h->prev` は `h` の最後の要素 B です。その `next` を、`n` の最初の要素 X（`n->next`）にします。これで B → X がつながります。

### 2. X → B を戻す

```c:line-numbers=46
  n->next->prev = h->prev;
```

X の `prev` を B にします。これで B ⇄ X の双方向のリンクが完成します。

### 3. ヘッドの末尾を Y にする

```c:line-numbers=47
  h->prev = n->prev;
```

ヘッド H の `prev`（＝最後の要素）を、`n` の最後の要素 Y にします。

### 4. 輪を閉じる

```c:line-numbers=48
  h->prev->next = h;
```

新しい最後の要素 Y の `next` を、H に戻します。これで円が閉じます。

この 4 行で `[H] ⇄ A ⇄ B ⇄ X ⇄ Y ⇄ (H)` ができあがります。ヘッド N は誰からも指されなくなりますが、N 自身の `next`・`prev` は古い値のままです。そのため、`n` をもう一度使うなら呼び出し側で初期化し直す必要があります。

## ここがすごい

- **長さに関係なく一定時間**: 配列なら全要素のコピーが、ヘッドなしの片方向リストなら末尾を探すループが必要です。双方向循環リストは「最後の要素」がヘッドの `prev` ですぐわかるので、連結は `O(1)` です。
- **場合分けがない**: ヘッドがあるおかげで、「`h` が空のとき」も特別扱いがいりません。`h` が空なら `h->prev` は `h` 自身なので、最初の行は `h->next = X`、つまり先頭を X にする操作に自然になります。ヘッドを使う最大の利点が、この「空のリストも普通のリストと同じコードで扱える」点です。
- **ただし前提がある**: `n` が空だと、`n->next` も `n->prev` も N 自身なので、H と N がつながってリストが壊れます。このため、空かもしれないリストを移すときは、`uv__queue_move` のように先に `uv__queue_empty` で確かめてから別の関数を使います。短い関数ほど、前提条件を呼び出し側が守る設計になっています。

## まとめ

- 双方向循環リストでは、末尾はヘッドの `prev` で即座にわかる。
- ヘッド付きにすると、空リストへの操作を特別扱いせずに書ける。
- 2 つのリストの連結はポインタ 4 本の付け替えだけで、要素数に関係ない。
- 速い関数は前提条件（ここでは `n` が空でないこと）を呼び出し側に任せていることが多い。
