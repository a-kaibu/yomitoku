## ひとことで

`uv__queue_split(h, q, n)` は、ヘッド `h` のリストを、要素 `q` の **手前** で 2 つに切ります。
前半はそのまま `h` に残り、`q` から最後までの後半は、新しいヘッド `n` のリストになります。
要素の数に関係なく、決まった回数のポインタ書き換えだけで終わります。

## コード

```c:line-numbers=51
static inline void uv__queue_split(struct uv__queue* h,
                                   struct uv__queue* q,
                                   struct uv__queue* n) {
  n->prev = h->prev;
  n->prev->next = n;
  n->next = q;
  h->prev = q->prev;
  h->prev->next = h;
  q->prev = n;
}
```

## 前提知識

- **`struct uv__queue`**: `next`（次）と `prev`（前）の 2 つのポインタだけを持つリストのノードです。
- **ヘッド付き双方向循環リスト**: 入口にデータを持たないノード（ヘッド）を置き、最後の要素の `next` がヘッドに、ヘッドの `prev` が最後の要素に戻る、輪になったリストです。
- **`->`**: ポインタが指す構造体のメンバを読み書きします。`n->prev->next` は「`n` の前のノードの `next`」です。
- **代入の順番**: 前の行で書き換えた値を、次の行で読むことがあります。ポインタの付け替えは順番がすべてなので、上から 1 行ずつ追う必要があります。

## 何をしているか

元のリストを `[H] ⇄ A ⇄ B ⇄ C ⇄ D ⇄ (H)`、`q = C` とします。結果は `[H] ⇄ A ⇄ B` と `[N] ⇄ C ⇄ D` です。

### 後半を新しいヘッドにぶら下げる

```c:line-numbers=54
  n->prev = h->prev;
  n->prev->next = n;
  n->next = q;
```

- `n->prev = h->prev;` … N の `prev` を元の最後の要素 D にします。後半の最後は D なので正しい値です。
- `n->prev->next = n;` … D の `next` を N にします。D から見た「次」が H から N に変わり、後半の輪が N で閉じます。
- `n->next = q;` … N の次（後半の先頭）を C にします。

### 前半の輪を閉じる

```c:line-numbers=57
  h->prev = q->prev;
  h->prev->next = h;
```

- `h->prev = q->prev;` … H の `prev`（前半の最後）を、C の手前にいる B にします。
- `h->prev->next = h;` … B の `next` を H にします。前半の輪が H で閉じます。

### 最後のつなぎ

```c:line-numbers=59
  q->prev = n;
```

- `q->prev = n;` … C の `prev` を N にします。これで後半の `N ⇄ C` が双方向になります。

ここで `h->prev = q->prev` が `q->prev`（B）を読むのは、最後の `q->prev = n` で書き換える **前** でなければなりません。行の順番がそのまま正しさになっている例です。

## ここがすごい

- **「全部移す」を特別扱いしない**: 同じファイルの `uv__queue_move` は、`uv__queue_split(h, h->next, n)` として「先頭の手前で切る」＝全要素を `n` に移す操作を実現しています。`q = A` のとき、`h->prev = q->prev` で `h->prev = A->prev`、つまり H 自身になり、前半は空のリスト（自分自身を指すヘッド）として正しく残ります。1 つの関数で、部分の切り出しと全体の移動の両方をまかなっています。
- **安全な処理のための土台**: libuv のイベントループは、処理中に新しい要素が追加されうるキューを扱います。キューの中身を先に別のヘッドへ移し替えておけば、処理中に元のキューへ追加された要素と混ざりません（`uv__run_pending` がこの使い方をしています）。その移し替えが一定時間でできるのは、この関数のおかげです。
- **6 回の代入だけ**: 配列なら後半のコピーが必要ですが、輪になったリストは「切れ目の 2 か所」をつなぎ直すだけで済みます。

## まとめ

- 循環リストを切るには、切れ目の前後とヘッド 2 つのリンクを直せばよい。
- ポインタの付け替えは、読む値が書き換えられる前に読むよう順番を考える。
- 「先頭の手前で切る」と全体の移動になるので、1 つの関数で 2 つの用途をまかなえる。
- キューを別のヘッドに移してから処理すると、処理中の追加と混ざらない。
