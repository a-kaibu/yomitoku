## ひとことで

`uv__queue_remove(q)` は、双方向循環リストからノード `q` を取り外す関数です。
前のノードと次のノードを直接つなぎ直して `q` を飛ばし、最後に `q` 自身を「自分だけの空のリスト」の状態に戻します。
たった 4 行ですが、最後の 2 行に libuv らしい安全への配慮があります。

## コード

```c:line-numbers=85
static inline void uv__queue_remove(struct uv__queue* q) {
  q->prev->next = q->next;
  q->next->prev = q->prev;
  q->next = q;
  q->prev = q;
}
```

## 前提知識

- **ポインタ**: メモリ上の場所を指す値です。`struct uv__queue* q` は「リストのノードがある場所」です。
- **`->`**: ポインタが指す構造体のメンバにアクセスします。`q->prev->next` は「`q` の前のノードの `next`」です。
- **`struct uv__queue`**: `next` と `prev` の 2 つのポインタだけを持つ、リストのノードです。データを持つ構造体の中に埋め込んで使います。
- **双方向循環リスト**: 各ノードが前後を知っていて、最後の要素の `next` は先頭のヘッドに戻る、輪になったリストです。空のリストは「`next` も `prev` も自分を指している」ノードで表します。
- **`static inline`**: ヘッダに書く小さな関数に付けるおまじないです。呼び出し元に本体を埋め込む最適化を許し、他のファイルと名前がぶつからないようにします。

## 何をしているか

リスト `[H] ⇄ A ⇄ B ⇄ C` から `B` を外す場合で追います。

### 1. 前から飛ばす

```c:line-numbers=86
  q->prev->next = q->next;
```

B の前（A）の `next` を、B の次（C）にします。A → C が直接つながり、前向きにたどると B は飛ばされます。

### 2. 後ろから飛ばす

```c:line-numbers=87
  q->next->prev = q->prev;
```

B の次（C）の `prev` を、B の前（A）にします。後ろ向きにたどっても B は飛ばされます。これでリストは `[H] ⇄ A ⇄ C` です。

### 3. 自分を指す状態に戻す

```c:line-numbers=88
  q->next = q;
  q->prev = q;
```

B 自身の `next` と `prev` を、B 自身に向けます。B は「中身のない 1 個だけの輪」、つまり空のリストのヘッドと同じ形になります。

## ここがすごい

- **どこにあっても 1 ステップ**: 双方向リストはノード自身が前後を知っているので、外すために先頭からたどる必要がありません。片方向リストだと「1 つ前のノード」を探すループが必要です。
- **ヘッドのおかげで場合分けがない**: 先頭の要素を外すときも、最後の要素を外すときも、前後には必ず何かのノード（少なくともヘッド）がいます。だから `NULL` チェックがまったくありません。
- **外したあとに自分を指す理由**: 外したノードの `next`・`prev` を古い値のまま残すと、うっかりもう一度 `uv__queue_remove` を呼んだとき、すでに別の並びになっている A や C のリンクを壊してしまいます。自分を指すようにしておけば、2 回目の取り外しは「自分の前後（＝自分）を自分につなぐ」だけになり、何も壊れません。
  さらに、「`q->next == q` ならどのリストにも入っていない」と判定できます。libuv の `uv__io_start` は、`uv__queue_empty(&w->watcher_queue)` で「まだ監視キューに入っていないか」を確かめていますが、それが成り立つのは取り外しのたびに自分を指す状態へ戻しているからです。
- たった 2 回の代入で、二重解除の事故を防ぎ、「所属しているか」というフラグの代わりにもなる、効率のよい防御です。

## まとめ

- 双方向リストからの削除は、前後のノードを直接つなぎ直すだけで済む。
- ヘッド付き循環リストでは、端の要素でも `NULL` の場合分けが要らない。
- 外したノードを「自分を指す」状態に戻すと、二重削除が安全になり、所属の判定にも使える。
