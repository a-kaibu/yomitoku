## ひとことで

`reciprocal_value(d)` は、「これから何度も `d` で割る」ときのための下ごしらえをする関数です。
割り算命令は遅いので、`d` の逆数 `1/d` に相当する整数 `m` と、シフト量 `sh1`、`sh2` を前もって計算しておきます。
すると `a / d` は、ヘッダにある `reciprocal_divide` で **掛け算 1 回・引き算・足し算・シフト** だけで求まります。
ヘッダのコメントによると、Granlund と Montgomery の論文「Division by Invariant Integers Using Multiplication」の方法に基づいています。

## コード

```c:line-numbers=17
struct reciprocal_value reciprocal_value(u32 d)
{
	struct reciprocal_value R;
	u64 m;
	int l;

	l = fls(d - 1);
	m = ((1ULL << 32) * ((1ULL << l) - d));
	do_div(m, d);
	++m;
	R.m = (u32)m;
	R.sh1 = min(l, 1);
	R.sh2 = max(l - 1, 0);

	return R;
}
```

実際の割り算は `include/linux/reciprocal_div.h` にあります。

	u32 m;

<!-- source: include/linux/reciprocal_div.h -->
```c:line-numbers=33
static inline u32 reciprocal_divide(u32 a, struct reciprocal_value R)
{
	u32 t = (u32)(((u64)a * R.m) >> 32);
	return (t + ((a - t) >> R.sh1)) >> R.sh2;
}
```

## 前提知識

- **`u32` / `u64` / `u8`**: カーネルの「32 / 64 / 8 ビットの符号なし整数」の型名です。
- **`struct`**: 複数の値をまとめた型です。この関数は `m`、`sh1`、`sh2` をまとめた構造体を**値として**返します。
- **`1ULL << 32`**: 64 ビットの 1 を 32 ビット左にずらした値、つまり 2 の 32 乗です。
- **`fls(x)`**: `x` のいちばん上に立っている 1 が何ビット目か（1 から数える。0 なら 0）を返す関数です。`fls(d - 1)` は「`2^l >= d` となる最小の `l`」、つまり log2(d) の切り上げになります。
- **`do_div(m, d)`**: 64 ビットの `m` を `d` で割り、**商を `m` に書き戻す**カーネルのマクロです。32 ビット CPU でも 64 ビットの割り算ができます。
- **固定小数点**: 小数を「2 の 32 乗倍した整数」として扱う方法です。`x * m >> 32` は、`x` に `m / 2^32` を掛けるのと同じ意味になります。
- **`min` / `max`**: 小さいほう・大きいほうを返すマクロです。

## 何をしているか

### 考え方

`a / d` は `a × (1/d)` です。`1/d` を `M / 2^(32+l)` の形の分数で十分正確に表せれば、`a × M` を右に `32 + l` ビットずらすだけで割り算になります。
ただし必要な `M` は 33 ビットになるので、`M = 2^32 + m` と分けて、32 ビットに収まる `m` だけを保存します。

### `l` を求める

```c:line-numbers=23
	l = fls(d - 1);
```

`l = fls(d - 1)` で、`d` 以上の最小の 2 のべき乗の指数を求めます。`d = 7` なら `fls(6) = 3`（`2^3 = 8 >= 7`）です。

### 掛ける数 `m`

```c:line-numbers=24
	m = ((1ULL << 32) * ((1ULL << l) - d));
	do_div(m, d);
	++m;
```

`m = 2^32 × (2^l − d) / d + 1` を計算します。`d = 7` なら `2^32 × 1 / 7 = 613566756.57…` を切り捨てて `613566756`、1 を足して `613566757` です。最後の `+1` は、切り捨てで小さくなりすぎないための切り上げです。

### シフト量

```c:line-numbers=27
	R.m = (u32)m;
	R.sh1 = min(l, 1);
	R.sh2 = max(l - 1, 0);
```

`sh1 = min(l, 1)`、`sh2 = max(l - 1, 0)` です。`d = 7` なら `sh1 = 1`、`sh2 = 2` です。

### 割り算を確かめる: `100 / 7`

`reciprocal_divide` では、まず `t = 100 × 613566757 >> 32 = 14` です。
`(100 − 14) >> 1 = 43`、`14 + 43 = 57`、`57 >> 2 = 14`。`100 / 7 = 14` と一致します。

## ここがすごい

- **33 ビットの掛け算を 32 ビットで**: 本当は `a × (2^32 + m) >> (32 + l)` を計算したいのですが、`a × 2^32` の部分は `a` そのものです。つまり答えは `(a + t) >> l` です。ところが `a + t` は 32 ビットからあふれることがあります。そこで `(t + (a − t) / 2) >> (l − 1)` と変形し、あふれずに同じ値を得ています。`sh1` と `sh2` に分かれている理由がこれです。
- **`d = 1` などの端もそのまま動く**: `d = 1` なら `l = 0`、`m = 1`、`sh1 = sh2 = 0` になり、`reciprocal_divide` は `a` をそのまま返します。`min` と `max` で場合分けなしに正しい値にしています。
- **遅い計算は 1 回だけ**: 前計算の中では `do_div` という重い割り算を使いますが、これは `d` ごとに 1 回だけです。ネットワークのパケット振り分けなど、同じ数で何百万回も割る場面で効果を発揮します。
- **トレードオフ**: 前計算の結果を構造体として持ち歩く必要があり、割る数が毎回変わる場面では逆に遅くなります。ヘッダのコメントにも、割る数がほぼ変わらないときに役立つと書かれています。

## まとめ

- 同じ数で何度も割るなら、逆数を固定小数点の整数として前計算すると、掛け算とシフトだけで割り算できる。
- `fls(d - 1)` は「log2(d) の切り上げ」を 1 命令で求める定番の式。
- あふれそうな `(a + t) >> l` は、`(t + (a − t) >> 1) >> (l − 1)` と変形すると安全に計算できる。
- 重い処理を前計算に追い出し、くり返す処理を軽くするのは最適化の基本。
