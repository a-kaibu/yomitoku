## ひとことで

`lcm(a, b)` は、`a` と `b` の最小公倍数（両方で割り切れる最小の正の数）を返す関数です。`lcm(4, 6)` は `12` です。
最小公倍数は「`a × b ÷ 最大公約数`」で求まるという有名な公式があります。この関数は、その公式を**割り算を先にする順番**で計算しているのがポイントです。

## コード

::: code-group

```c:line-numbers=7 [日本語訳]
/* 最小公倍数 */
unsigned long lcm(unsigned long a, unsigned long b)
{
	if (a && b)
		return (a / gcd(a, b)) * b;
	else
		return 0;
}
```

```c:line-numbers=7 [原文]
/* Lowest common multiple */
unsigned long lcm(unsigned long a, unsigned long b)
{
	if (a && b)
		return (a / gcd(a, b)) * b;
	else
		return 0;
}
```

:::

## 前提知識

- **`unsigned long`**: 0 以上の整数の型です。64 ビット環境なら、約 1800 京（2 の 64 乗 − 1）までの数を表せます。
- **オーバーフロー（あふれ）**: 計算結果が型の最大値を超えると、上の桁が捨てられて、まったく違う小さな値になります。C の符号なし整数ではエラーにならず、静かに起きます。
- **`gcd(a, b)`**: 最大公約数（両方を割り切る最大の数）を返すカーネルの関数です。
- **`if (a && b)`**: `&&` は「かつ」です。C では 0 が偽、0 以外が真なので、「`a` も `b` も 0 でない」という意味になります。
- **整数の割り算 `/`**: 切り捨ての割り算です。ただし `a / gcd(a, b)` は必ず割り切れるので、ここでは切り捨ては起きません。

## 何をしているか

### 0 を除く

```c:line-numbers=10
	if (a && b)
```

どちらかが 0 だと最大公約数がもう片方になり、公式がそのまま使えません。また、0 の倍数を考えても意味がないので、`return 0;`で 0 を返します。

### 割ってから掛ける

```c:line-numbers=11
		return (a / gcd(a, b)) * b;
```

`(a / gcd(a, b)) * b` を計算します。

`a = 4, b = 6` なら、`gcd = 2` なので `(4 / 2) * 6 = 12` です。

公式を書いたとおりの `a * b / gcd(a, b)` でも、数学的には同じ答えです。違いは**途中の値の大きさ**です。

### 具体例: あふれる場合とあふれない場合

`a = b = 2^40`（約 1.1 兆）の場合を考えます。答えは `2^40` そのものです。

- `a * b` を先に計算すると `2^80` になり、64 ビットに入りません。上の桁が捨てられて 0 になり、`0 / 2^40 = 0` という間違った答えが出ます。
- `a / gcd = 2^40 / 2^40 = 1` を先に計算すれば、`1 * 2^40 = 2^40` で正しく求まります。

## ここがすごい

- **計算の順番だけで安全性が上がる**: 数学では同じ式でも、コンピュータの整数は桁数が限られているので、計算の順番で結果が変わります。先に割り算をすれば、途中の値は最終的な答え以下に収まります。答えが型に入る限り、途中であふれることはありません。
- **割り切れることが保証されている**: 割り算を先にすると、ふつうは切り捨てで誤差が出ます。しかし `gcd(a, b)` は定義から `a` を割り切るので、ここでは誤差がまったく出ません。「どの割り算なら先にしても安全か」を見極めた書き方です。
- **0 を丁寧に扱う**: 0 を渡されたときは割り算に進まないので、0 割りの危険もありません。同じファイルの `lcm_not_zero` は、この関数が 0 を返したときに 0 でないほうの値を返す、という使い分けも用意しています。
- **トレードオフ**: 答えそのものが 64 ビットに入らない場合は、この方法でもあふれます。この関数はそれを検出しないので、呼び出し側が値の範囲を知っている前提です。

## まとめ

- 最小公倍数は `a / gcd(a, b) * b` の順に計算すると、途中の値があふれにくい。
- 整数の計算では、数学的に同じ式でも計算の順番で結果が変わることがある。
- 割り算を先にしてよいのは、割り切れることが保証されているとき。
- 0 のような特別な入力は、公式に入る前に分けて扱う。
