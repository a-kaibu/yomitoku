## ひとことで

`binary_gcd` は、2 つの正の整数の最大公約数（両方を割り切る最大の数。GCD）を求める関数です。
有名なユークリッドの互除法は「割った余り」をくり返し求めますが、この関数は**割り算を一度も使わず**、ビットのシフトと引き算だけで計算します。
ファイル冒頭のコメントによると、割り算が速い x86 でも、こちらのほうが速いそうです。

## コード

```c:line-numbers=20
static unsigned long binary_gcd(unsigned long a, unsigned long b)
{
	unsigned long r = a | b;

	b >>= __ffs(b);
	if (b == 1)
		return r & -r;

	for (;;) {
		a >>= __ffs(a);
		if (a == 1)
			return r & -r;
		if (a == b)
			return a << __ffs(r);

		if (a < b)
			swap(a, b);
		a -= b;
	}
}
```

## 前提知識

- **`unsigned long`**: 符号なし（0 以上）の整数型です。64 ビット環境では 64 ビットです。
- **`>>` と `<<`**: ビットを右・左にずらす演算です。`x >> k` は「`x` を 2 の `k` 乗で割って切り捨て」、`x << k` は「2 の `k` 乗を掛ける」と同じです。
- **`|` と `&`**: ビットごとの OR と AND です。
- **`r & -r`**: 符号なし整数の `-r` は「ビットを反転して 1 を足した値」になり、`r & -r` は `r` の**いちばん下に立っている 1 のビットだけ**を取り出します。`12`（`1100`）なら `4`（`0100`）です。
- **`__ffs(x)`**: カーネルの関数で、`x` のいちばん下に立っている 1 が何ビット目か（0 から数える）を返します。`__ffs(12)` は `2` です。多くの CPU は 1 命令で計算できます。`x` が 0 のときは使えません。
- **`swap(a, b)`**: 2 つの変数の中身を入れ替えるカーネルのマクロです。
- **`for (;;)`**: 終了条件のない無限ループです。中の `return` で抜けます。

## 何をしているか

この関数は `gcd()` から、`a` も `b` も 0 でないときだけ呼ばれます。

### 共通の「2 のべき乗」を先に覚える

```c:line-numbers=22
	unsigned long r = a | b;
```

最大公約数には、両方に共通する 2 の因数が含まれます。それは「`a` と `b` の末尾の 0 の数の少ないほう」の分だけです。
`a | b` の最下位の 1 は、ちょうどその位置に来ます。そこで `r = a | b` を保存しておき、最後に `r & -r`（その 2 のべき乗）や `__ffs(r)`（その指数）として使います。

### `b` を奇数にする

```c:line-numbers=24
	b >>= __ffs(b);
	if (b == 1)
		return r & -r;
```

`b >>= __ffs(b)` で、末尾の 0 を一気に削って `b` を奇数にします。もし `b` が 1 になったら、奇数部分の公約数は 1 なので、答えは共通の 2 のべき乗だけです。

### 奇数どうしで引き算をくり返す

```c:line-numbers=28
	for (;;) {
		a >>= __ffs(a);
		if (a == 1)
			return r & -r;
		if (a == b)
			return a << __ffs(r);

		if (a < b)
			swap(a, b);
		a -= b;
	}
```

1. `a >>= __ffs(a);`: `a` の末尾の 0 を削って奇数にします。最大公約数の奇数部分は、2 の因数を取り除いても変わりません。
2. 2 つの `if`: `a` が 1 なら奇数部分は 1、`a == b` ならそれが奇数部分の答えです。後者は共通の 2 のべき乗を掛け戻して返します。
3. `swap(a, b);` と `a -= b;`: 大きいほうを `a` にして `a -= b` とします。`gcd(a, b) = gcd(a - b, b)` が成り立つからです。奇数どうしの差は必ず偶数なので、次の周の `a >>= __ffs(a);`で必ず 1 ビット以上削れます。

### 具体例: `gcd(48, 18)`

- `r = 48 | 18 = 50`（`110010`）。共通の 2 のべき乗は `2`。
- `b = 18 >> 1 = 9`。
- 1 周目: `a = 48 >> 4 = 3`。`3 < 9` なので入れ替えて `a = 9, b = 3`、`a = 6`。
- 2 周目: `a = 6 >> 1 = 3`。`a == b` なので `3 << __ffs(50) = 3 << 1 = 6` を返します。

## ここがすごい

- **割り算がいらない**: 割り算命令は、足し算や引き算に比べて何倍も時間がかかります。引き算とシフトだけで済むので、割り算命令を持たない CPU でもそのまま速く動きます。
- **末尾の 0 を 1 命令で削る**: 古典的なバイナリ GCD は「偶数なら 2 で割る」を 1 ビットずつくり返します。`__ffs` を使えば何ビットでも一度に削れます。関数の直前のコメントは、`__ffs` が使えるなら、1 ビットずつのやり方（`gcd()` の後半）よりこちらが速かったと述べています。
- **2 の因数の扱いがうまい**: 共通の 2 のべき乗を数えるループを書かず、`a | b` の最下位ビットという 1 回の OR で求めています。
- **CPU ごとに切り替える**: `__ffs` が遅い CPU のために、`#if !defined(CONFIG_CPU_NO_EFFICIENT_FFS)`の `#if` で丸ごと外せるようになっており、その場合は `gcd()` の中の別のやり方が使われます。

## まとめ

- 最大公約数は `gcd(a, b) = gcd(a - b, b)` と、2 の因数の取り除きだけで計算できる。
- 共通の 2 のべき乗は `(a | b) & -(a | b)` で一発で求まる。
- 末尾の 0 の数を数える命令（`__ffs`）は、ビット単位のループを 1 命令にしてくれる。
- 速さはハードウェア次第なので、ビルド設定で実装を選べるようにしている。
