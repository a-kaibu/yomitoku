## ひとことで

`OPENSSL_strlcpy(dst, src, size)` は、文字列 `src` を大きさ `size` のバッファ `dst` にコピーします。入りきらない場合は切り詰めますが、**必ず最後に終端の 0（ヌル文字）を書きます**。
戻り値は `src` の長さです。たとえば `size = 4` のバッファに `"hello"` をコピーすると、`dst` は `"hel"` になり、戻り値は `5` です。戻り値が `size` 以上なら「切り詰めが起きた」とわかります。

## コード

```c:line-numbers=78
size_t OPENSSL_strlcpy(char *dst, const char *src, size_t size)
{
    size_t l = 0;
    for (; size > 1 && *src; size--) {
        *dst++ = *src++;
        l++;
    }
    if (size)
        *dst = CH_ZERO;
    return l + strlen(src);
}
```

85 行目の `CH_ZERO` は同じファイルの 20 行目で `'\0'` と定義されています。

```c
#define CH_ZERO '\0'
```

## 前提知識

- **C の文字列**: 文字（`char`）がメモリ上に並び、最後に値 0 のバイト（`'\0'`）が置かれたものです。`"hi"` は `h i \0` の 3 バイトです。
- **ポインタ**: メモリ上の場所を指す値です。`*dst` はその場所の 1 文字、`dst++` は次の場所へ進むことを表します。
- **`*dst++ = *src++;`**: 「`src` が指す文字を `dst` が指す場所に書き、両方を 1 つ進める」という C の定番の書き方です。`++` を後ろに書くと、値を使ったあとで増やします。
- **`size_t`**: 長さを表す符号なし整数型です。
- **`for (; 条件; 更新)`**: 初期化部分を空にした `for` 文です。
- **`strlen(s)`**: 文字列 `s` の長さ（終端の 0 の手前までの文字数）を返す標準関数です。
- **バッファオーバーフロー**: 確保した領域より後ろに書き込んでしまうバグです。ほかの変数や戻りアドレスを壊し、重大なセキュリティ問題になります。標準の `strcpy` は長さを確認しないので、この危険があります。

## 何をしているか

### 1. 入る分だけコピーする（81〜84 行目）

ループの条件は `size > 1 && *src` です。

- `size > 1`: 終端の 0 を書く 1 バイトを残すため、「残りが 2 バイト以上ある間」だけコピーします。
- `*src`: `src` の終端（0）に来たら止まります。

1 文字コピーするごとに `size` を 1 減らし、コピーした文字数を `l` に数えます。

`dst` の大きさが 4、`src = "hello"` で追うと、`size` は 4 → 3 → 2 → 1 と減り、`h`, `e`, `l` の 3 文字をコピーした時点で `size > 1` が偽になって止まります。`l = 3` です。

### 2. 終端の 0 を書く（85〜86 行目）

`size` が 0 でなければ、今の位置に `'\0'` を書きます。上の例では `dst` は `"hel"` になります。`size` が最初から 0 の場合（大きさ 0 のバッファ）は、1 バイトも書きません。

### 3. 本来の長さを返す（87 行目）

`l + strlen(src)` を返します。`src` はコピーした分だけ進んでいるので、`strlen(src)` は「コピーしきれなかった残りの長さ」です。上の例では `3 + strlen("lo") = 5` で、元の `"hello"` の長さになります。

## ここがすごい

- **必ず 0 で終わる**: 標準の `strncpy` は、入りきらないときに終端の 0 を付けません。その結果、あとで `strlen` などを呼ぶとバッファの外まで読んでしまいます。`strlcpy` は `size > 0` なら必ず終端を付けるので、結果は常に正しい C の文字列です。
- **切り詰めを検出できる戻り値**: 戻り値が「コピーしようとした長さ」なので、呼び出し側は `if (OPENSSL_strlcpy(buf, s, sizeof(buf)) >= sizeof(buf))` と書くだけで、切り詰めが起きたかを判定できます。必要な大きさがわかるので、確保し直すこともできます。
- **無駄な 0 埋めをしない**: `strncpy` は、短い文字列をコピーしたとき残りを全部 0 で埋めるので、大きなバッファでは遅くなります。この関数は必要な分しか書きません。
- **移植性のため自前で持つ**: `strlcpy` は BSD 系 OS 由来の関数で、長いあいだ標準 C にも glibc にもありませんでした。OpenSSL はどの環境でも同じ動きにするため、11 行の自前実装を持っています。
- 直後の `OPENSSL_strlcat`（90〜96 行目）は、`dst` の終端を探してから残りの大きさでこの関数を呼ぶだけの作りで、うまく再利用されています。

## まとめ

- `strlcpy` は「入る分だけコピーし、必ず 0 で終わらせる」安全な文字列コピー。
- 終端用に 1 バイトを残すため、ループ条件は `size > 1` になる。
- 戻り値が元の文字列の長さなので、`>= size` で切り詰めを検出できる。
- 標準にない便利関数は、自前で小さく実装して移植性を確保する。
