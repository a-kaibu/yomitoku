## ひとことで

`CRYPTO_memcmp(a, b, len)` は、`a` と `b` の先頭 `len` バイトが **すべて等しければ 0、どこか違えば 0 以外** を返します。
標準の `memcmp` と似ていますが、違うバイトを見つけても **途中でやめません**。必ず `len` バイト全部を調べてから答えます。
暗号の検証（受け取ったメッセージ認証コードが正しいか、など）で使うための比較です。

## コード

```c:line-numbers=202
int CRYPTO_memcmp(const void *in_a, const void *in_b, size_t len)
{
    size_t i;
    const volatile unsigned char *a = in_a;
    const volatile unsigned char *b = in_b;
    unsigned char x = 0;

    for (i = 0; i < len; i++)
        x |= a[i] ^ b[i];

    return x;
}
```

## 前提知識

- **`const void *`**: 型を決めていないポインタ（メモリ上の場所）で、`const` は「中身を書き換えない」という約束です。どんな型のデータでも渡せるように、引数をこの型にしています。
- **`const volatile unsigned char *a = in_a;`**: `void *` を「1 バイト単位で読めるポインタ」に変換しています。`volatile` は「この場所の値は勝手に変わるかもしれないので、読み出しを省略しないこと」とコンパイラに伝える修飾子です。
- **`a[i]`**: ポインタ `a` から `i` バイト目の値です。
- **`size_t`**: 長さや個数を表す符号なし整数型です。
- **`^`（XOR）と `|=`**: XOR は 2 つの値が同じなら 0、違えば 0 以外になります。`x |= y` は `x = x | y` で、一度立ったビットは消えずに残ります。
- **`#undef CRYPTO_memcmp`**（201 行目）: ヘッダで `CRYPTO_memcmp` が同名のマクロとして定義されている場合に、それを取り消して、ここで本物の関数を定義できるようにしています。
- **タイミング攻撃**: 処理時間の差から秘密を推測する攻撃です。

## 何をしているか

### 1. 結果をためる変数（207 行目）

`x` は 0 から始まる 1 バイトの変数です。違いが見つかるたびに、ここにビットが立っていきます。

### 2. 全バイトの差を OR で集める（209〜210 行目）

各 `i` について `a[i] ^ b[i]` を計算します。同じバイトなら 0、違えば 0 以外です。それを `x |= ...` で `x` に合流させます。

`a = "abcd"`、`b = "abXd"` で追うと、

- `i = 0`: `'a' ^ 'a' = 0` → `x = 0`
- `i = 1`: `'b' ^ 'b' = 0` → `x = 0`
- `i = 2`: `'c' ^ 'X'` は 0 以外 → `x` に何ビットか立つ
- `i = 3`: `'d' ^ 'd' = 0` → `x` は変わらない（一度立ったビットは消えない）

最後に `x` は 0 以外なので、「違う」と判定されます。

### 3. 結果を返す（212 行目）

全部一致したときだけ `x` は 0 です。標準の `memcmp` と違い、「どちらが大きいか」はわかりません。等しいかどうかだけを答えます。

## ここがすごい

- **早期リターンをしない理由**: 標準の `memcmp` は、最初に違うバイトを見つけた時点で返ります。速いのですが、「先頭何バイトが合っていたか」によって処理時間が変わります。攻撃者が正しい MAC（メッセージ認証コード）を 1 バイトずつ当てずっぽうで試し、時間がわずかに長くなったものを選んでいけば、全体を総当たりするよりはるかに少ない回数で正解にたどり着けてしまいます。この関数は常に `len` バイトを調べるので、その手がかりを与えません。
- **分岐がループ条件だけ**: ループの中に `if` がありません。ループの回数は `len` で決まり、`len` は秘密ではないので、データの中身が処理の流れに影響しません。
- **`volatile` でコンパイラの近道を封じる**: コメント（189〜193 行目）によると、`volatile` は「配列のすべての値を読み、最適化で省略しないコード」を生成させるためのものです。賢いコンパイラが「`x` が 0 以外になったらもう結果は変わらない」と見抜いてループを打ち切るのを防ぐ狙いです。コメントは、規格上は保証されないが実際のコンパイラではそう振る舞う、と正直に書いています。
- **検証済み**: 同じコメントに、この C 版と各アーキテクチャ向けのアセンブリ版が、Valgrind を使った定数時間検証（`enable-ct-validation`）で確認されていると書かれています。

## まとめ

- 秘密の比較では、違いを見つけても途中で抜けてはいけない。
- 各バイトの XOR を OR で 1 つの変数に集めれば、「どこかが違ったか」だけを最後に判定できる。
- 標準の `memcmp` と違い、大小関係ではなく等しいかどうかだけを返す。
- `volatile` は、コンパイラが最適化で処理を省くのを防ぐために使われる。
