## ひとことで

`expand` は、OpenSSL のハッシュ表 **LHASH** に要素が増えてきたとき、表を広げる関数です。
ふつうのハッシュ表は、いっぱいになると表の大きさを 2 倍にして **全要素を一度に入れ直します**。LHASH は **線形ハッシュ法**（Linear hashing）という方法で、1 回の呼び出しで **バケツを 1 つだけ** 2 つに分けます。拡張の手間が少しずつに分散されるので、1 回の挿入が急に遅くなることがありません。

## コード

```c:line-numbers=242
static int expand(OPENSSL_LHASH *lh)
{
    OPENSSL_LH_NODE **n, **n1, **n2, *np;
    unsigned int p, pmax, nni, j;
    unsigned long hash;

    nni = lh->num_alloc_nodes;
    p = lh->p;
    pmax = lh->pmax;
    if (p + 1 >= pmax) {
        j = nni * 2;
        n = OPENSSL_realloc_array(lh->b, j, sizeof(OPENSSL_LH_NODE *));
        if (n == NULL) {
            lh->error++;
            return 0;
        }
        lh->b = n;
        memset(n + nni, 0, sizeof(*n) * (j - nni));
        lh->pmax = nni;
        lh->num_alloc_nodes = j;
        lh->p = 0;
    } else {
        lh->p++;
    }

    lh->num_nodes++;
    n1 = &(lh->b[p]);
    n2 = &(lh->b[p + pmax]);
    *n2 = NULL;

    for (np = *n1; np != NULL;) {
        hash = np->hash;
        if ((hash % nni) != p) { /* move it */
            *n1 = (*n1)->next;
            np->next = *n2;
            *n2 = np;
        } else
            n1 = &((*n1)->next);
        np = *n1;
    }

    return 1;
}
```

## 前提知識

- **ハッシュ表**: キーからハッシュ値（数値）を計算し、`ハッシュ値 % バケツ数` 番目のバケツに要素を入れるデータ構造です。同じバケツに入った要素は、連結リストでつなぎます。
- **連結リスト**: 各要素が「次の要素へのポインタ（`next`）」を持ち、数珠つなぎになった構造です。最後の要素の `next` は NULL です。
- **構造体と `->`**: `lh->p` は「ポインタ `lh` が指す構造体の `p` という項目」です。LHASH では `b` がバケツの配列、`pmax` が今の基本のバケツ数、`p` が次に分割するバケツの番号、`num_alloc_nodes` が確保済みの配列の大きさ（`pmax` の 2 倍）です。
- **ポインタのポインタ（`OPENSSL_LH_NODE **`）**: 「ポインタが入っている場所」を指すポインタです。`*n1 = 値` と書くと、その場所に入っているポインタ自体を書き換えられます。
- **`&(lh->b[p])`**: `&` はアドレスを取る演算子で、これは「配列の `p` 番目の要素が置かれている場所」です。
- **`OPENSSL_realloc_array`**: 確保済みのメモリを新しい大きさに確保し直す関数（標準の `realloc` に、掛け算のオーバーフロー検査を付けたもの）です。失敗すると NULL を返します。

## 何をしているか

### 1. 必要なら配列を 2 倍にする（248〜265 行目）

`p` が `pmax` の手前まで来ていたら（`p + 1 >= pmax`）、この回で分割を一巡するので、配列を `nni * 2` の大きさに広げ、新しい部分を `memset` で 0（空のバケツ）にします。そして `pmax` を 2 倍に、`p` を 0 に戻します。それ以外なら `p` を 1 進めるだけです。

注意したいのは、この後の処理ではローカル変数の **古い `p` と `pmax`** を使うことです。

### 2. 分割元と分割先を決める（267〜270 行目）

分割するのはバケツ `p`、新しく使い始めるのはバケツ `p + pmax` です。最初は `pmax = 8`、`num_alloc_nodes = 16` なので、1 回目の `expand` ではバケツ 0 を、バケツ 0 と 8 に分けます。

### 3. 要素を振り分ける（272〜281 行目）

バケツ `p` のリストを先頭からたどり、各要素について `hash % nni`（`nni` は `pmax` の 2 倍）を計算します。

- 結果が `p` なら、そのまま残します（`n1` を次の要素の `next` の場所へ進める）。
- 結果が `p + pmax` なら、リストから外し（`*n1 = (*n1)->next`）、分割先のリストの先頭につなぎます。

たとえばハッシュ値が 3, 11, 19 の要素がバケツ 3 にあり、`nni = 16` なら、`3 % 16 = 3` と `19 % 16 = 3` は残り、`11 % 16 = 11` はバケツ 11 へ移ります。

### 4. 検索側との約束

検索の `getrn`（318 行目〜）は、まず `hash % pmax` を計算し、それが `p` より小さい（もう分割済みのバケツ）なら `hash % num_alloc_nodes` を使います。分割済みかどうかで割る数を変えることで、途中まで分割された表でも正しいバケツを見つけられます。

## ここがすごい

- **拡張の手間を平らにならす**: 全体を作り直す方式では、たまに起きる拡張のとき、要素数に比例した時間が一度にかかります。線形ハッシュ法では、1 回の拡張で触るのは 1 つのバケツの要素だけです。挿入のたびに少しずつ広がるので、処理時間が安定します。
- **ハッシュ値を保存して再計算しない**: 各ノードは `hash` を持っているので（273 行目の `np->hash`）、振り分けのたびにキーからハッシュ値を計算し直す必要がありません。文字列のキーなら大きな節約です。
- **ポインタのポインタで分岐を減らす**: `n1` は「今見ている要素を指しているポインタの場所」です。先頭の要素を外すときも途中の要素を外すときも、`*n1 = (*n1)->next` の 1 行で済みます。「先頭なら配列を書き換え、途中なら前の要素の `next` を書き換え」という場合分けが不要になります。
- **割る数が 2 倍になるだけ**: `hash % 8 == 3` だった要素は、`hash % 16` では 3 か 11 のどちらかにしかなりません。分割は「同じバケツの中だけ」で完結し、ほかのバケツに影響しないのが、この方法の美しい性質です。

## まとめ

- 線形ハッシュ法は、バケツを 1 つずつ分割して表を少しずつ大きくする。
- `hash % n` で入っていた要素は、`hash % 2n` では 2 つのバケツのどちらかに必ず分かれる。
- 「どこまで分割したか」を表す `p` を見て、検索側は割る数を切り替える。
- ポインタのポインタを使うと、リストから要素を外す処理を場合分けなしで書ける。
