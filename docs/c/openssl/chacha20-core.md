## ひとことで

`chacha20_core` は、暗号 **ChaCha20** の中心となる関数です。鍵・カウンタ・ノンス（使い捨ての番号）から成る 16 個の 32 ビット整数を受け取り、それを徹底的にかき混ぜて **64 バイトの出力**（鍵ストリーム）を作ります。
この出力を平文と XOR すれば暗号文になり、もう一度 XOR すれば平文に戻ります。使う操作は **足し算・ビット回転・XOR** の 3 つだけです。

## コード

```c:line-numbers=55
/* QUARTERROUND updates a, b, c, d with a ChaCha "quarter" round. */
#define QUARTERROUND(a, b, c, d) (                  \
    x[a] += x[b], x[d] = ROTATE((x[d] ^ x[a]), 16), \
    x[c] += x[d], x[b] = ROTATE((x[b] ^ x[c]), 12), \
    x[a] += x[b], x[d] = ROTATE((x[d] ^ x[a]), 8),  \
    x[c] += x[d], x[b] = ROTATE((x[b] ^ x[c]), 7))

/* chacha_core performs 20 rounds of ChaCha on the input words in
 * |input| and writes the 64 output bytes to |output|. */
static void chacha20_core(chacha_buf *output, const uint32_t input[16])
{
    uint32_t x[16];
    int i;
    DECLARE_IS_ENDIAN;

    memcpy(x, input, sizeof(x));

    for (i = 20; i > 0; i -= 2) {
        QUARTERROUND(0, 4, 8, 12);
        QUARTERROUND(1, 5, 9, 13);
        QUARTERROUND(2, 6, 10, 14);
        QUARTERROUND(3, 7, 11, 15);
        QUARTERROUND(0, 5, 10, 15);
        QUARTERROUND(1, 6, 11, 12);
        QUARTERROUND(2, 7, 8, 13);
        QUARTERROUND(3, 4, 9, 14);
    }

    if (IS_LITTLE_ENDIAN) {
        for (i = 0; i < 16; ++i)
            output->u[i] = x[i] + input[i];
    } else {
        for (i = 0; i < 16; ++i)
            U32TO8_LITTLE(output->c + 4 * i, (x[i] + input[i]));
    }
}
```

`ROTATE` は同じファイルの 24 行目で定義された、32 ビットの左回転のマクロです（環境によってはアセンブリ版に置き換えられます）。`chacha_buf` は 19〜22 行目の共用体です。

```c
typedef union {
    uint32_t u[16];
    uint8_t c[64];
} chacha_buf;

#define ROTATE(v, n) (((v) << (n)) | ((v) >> (32 - (n))))
```

## 前提知識

- **`uint32_t`**: ちょうど 32 ビットの符号なし整数です。足し算は 2³² を超えると回り込みます。
- **ビット回転（ROTATE）**: 左シフトで押し出されたビットを、右端に戻す操作です。`ROTATE(0x80000001, 1)` は `0x00000003` です。情報を失わずに並びだけを変えます。
- **マクロ**: `#define` で定義した文字の置き換えです。`QUARTERROUND(0, 4, 8, 12)` と書くと、56〜60 行目の式の `a` に 0、`b` に 4… が入った形に展開されます。
- **カンマ演算子**: `(式1, 式2, 式3)` は左から順に評価し、最後の値を全体の値にする演算子です。56〜60 行目では、複数の代入を 1 つの式にまとめるために使っています。
- **`x[a] += x[b]`**: `x[a] = x[a] + x[b]` の短縮形です。
- **共用体（`union`）**: 同じメモリを複数の型として見る仕組みです。`chacha_buf` は 64 バイトの領域を、「32 ビット整数 16 個」としても「バイト 64 個」としても読み書きできます。
- **エンディアン**: 複数バイトの整数をメモリに並べる順番です。下位のバイトから置く方式をリトルエンディアンと呼びます。`DECLARE_IS_ENDIAN` と `IS_LITTLE_ENDIAN` は、今の CPU がどちらかを調べる OpenSSL のマクロです。

## 何をしているか

### 1. クォーターラウンド（55〜60 行目）

`QUARTERROUND(a, b, c, d)` は、4 つの整数を次の 4 段でかき混ぜます。

1. `x[a] += x[b]` して、`x[d]` に `x[a]` を XOR し、16 ビット回転
2. `x[c] += x[d]` して、`x[b]` に `x[c]` を XOR し、12 ビット回転
3. もう一度 `x[a] += x[b]`、`x[d]` に XOR して 8 ビット回転
4. もう一度 `x[c] += x[d]`、`x[b]` に XOR して 7 ビット回転

足し算は桁上がりで下のビットを上へ伝え、回転はビットの位置を動かし、XOR は値を混ぜます。この 3 つを組み合わせると、1 ビットの変化があっという間に全体へ広がります。

### 2. 入力をコピーする（70 行目）

`memcpy` で入力 16 個を作業用の配列 `x` にコピーします。入力そのものは最後に使うので壊しません。

### 3. 列と対角線を交互に混ぜる（72〜81 行目）

16 個を 4×4 の表として並べると、73〜76 行目の 4 回は **縦の列**（0,4,8,12 など）、77〜80 行目の 4 回は **対角線**（0,5,10,15 など）を混ぜています。この 2 段を 1 組として、`i` を 20 から 2 ずつ減らしながら 10 回、合計 20 ラウンド行います。

### 4. 入力を足し戻して出力する（83〜89 行目）

最後に、かき混ぜた `x[i]` に元の `input[i]` を足して出力します。リトルエンディアンの CPU なら整数のまま `output->u[i]` に書けばバイトの順番も規格どおりになります。それ以外の CPU では、`U32TO8_LITTLE` で 1 バイトずつ下位から書き出します。

## ここがすごい

- **表を使わないので定数時間**: AES のような暗号は表引き（S-box）を使う実装が多く、どの場所を読んだかがキャッシュの状態から漏れる危険があります。ChaCha20 は足し算・回転・XOR だけで、どの命令も入力の値によって処理時間が変わりません。専用命令のない CPU でも、素直な C で安全に速く書けます。
- **最後の足し戻し**: ラウンドの操作はすべて逆算できるので、出力が `x` だけだと、出力から入力（鍵を含む）を逆算できてしまいます。最後に入力を足すことで、逆算できない一方向の関数になります。
- **マクロで規則性を表現**: 8 行の `QUARTERROUND` の並びを見るだけで、「列 4 本、対角線 4 本」という構造が読み取れます。関数ではなくマクロにしているので、配列の添字がコンパイル時に定数になり、`x` をレジスタに置く最適化がしやすくなります。
- **エンディアンを 1 か所で吸収**: 本体の計算は整数だけで行い、バイトへの変換は最後の出力だけに閉じ込めています。共用体を使うことで、リトルエンディアンの CPU ではコピーの手間も省けます。

## まとめ

- ChaCha20 は、足し算・回転・XOR（ARX と呼ばれる）だけで作られた暗号。
- クォーターラウンドを「列」と「対角線」に交互にかけ、20 ラウンドで全体を混ぜる。
- 最後に入力を足し戻すことで、出力から入力を逆算できなくしている。
- 表引きを使わないので、処理時間から秘密が漏れにくい。
