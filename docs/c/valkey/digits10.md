## ひとことで

`digits10` は、整数を 10 進数の文字列にしたとき **何文字（何桁）になるか** を返す関数です。
たとえば `digits10(7)` は `1`、`digits10(12345)` は `5`、`digits10(1000000)` は `7` を返します。
Valkey は数値を文字列に変換する前にこの関数で必要な長さを調べ、書き込む位置を後ろから決めています。

## コード

```c:line-numbers=324
/* Return the number of digits of 'v' when converted to string in radix 10.
 * See ll2string() for more information. */
uint32_t digits10(uint64_t v) {
    if (v < 10) return 1;
    if (v < 100) return 2;
    if (v < 1000) return 3;
    if (v < 1000000000000UL) {
        if (v < 100000000UL) {
            if (v < 1000000) {
                if (v < 10000) return 4;
                return 5 + (v >= 100000);
            }
            return 7 + (v >= 10000000UL);
        }
        if (v < 10000000000UL) {
            return 9 + (v >= 1000000000UL);
        }
        return 11 + (v >= 100000000000UL);
    }
    return 12 + digits10(v / 1000000000000UL);
}
```

## 前提知識

- **`uint64_t`**: 符号なし（マイナスがない）64 ビット整数の型です。0 から約 1844 京（`18446744073709551615`、20 桁）までを表せます。`<stdint.h>` で定義されています。
- **`uint32_t`**: 同じく符号なしの 32 ビット整数です。桁数は最大 20 なので、戻り値はこれで十分です。
- **整数リテラルの `UL`**: `1000000000000UL` の末尾の `UL` は「この数は `unsigned long` 型として扱ってね」という印です。大きな数を書くときに、型が小さすぎて値があふれないようにするために付けます。
- **比較式は 0 か 1 になる**: C では `(v >= 100000)` のような比較の結果は整数で、真なら `1`、偽なら `0` です。だから `5 + (v >= 100000)` は「`v` が 100000 以上なら 6、そうでなければ 5」という意味になります。
- **再帰**: 関数が自分自身を呼び出すことです。343 行目では `digits10` の中で `digits10` を呼んでいます。

## 何をしているか

### 1. 小さい数はすぐ返す（327〜329 行目）

実際のプログラムで扱う数は小さいことが多いので、まず 1〜3 桁を順にチェックします。`v = 42` なら 2 回目の比較 `v < 100` で `2` が返り、それ以上何もしません。

### 2. 12 桁未満を二分探索のように絞る（330〜342 行目）

4 桁から 12 桁までは、1 つずつ比べるのではなく「真ん中」で区切ります。

- 330 行目: `v < 10^12` か？（12 桁以下か）
- 331 行目: `v < 10^8` か？（8 桁以下か）
- 332 行目: `v < 10^6` か？（6 桁以下か）

`v = 12345` を追ってみます。`10^12` 未満、`10^8` 未満、`10^6` 未満と進み、333 行目の `v < 10000` は偽、334 行目で `5 + (12345 >= 100000)` = `5 + 0` = `5` が返ります。合計 6 回の比較で答えが出ました。

`v = 3000000000`（30 億、10 桁）なら、330 行目は真、331 行目は偽で 338 行目へ。`v < 10^10` は真なので、339 行目で `9 + (v >= 10^9)` = `9 + 1` = `10` です。

### 3. 12 桁以上は 10^12 で割って再帰（343 行目）

`v` が `10^12` 以上なら、`10^12` で割って 12 桁ぶん落とし、残りの桁数に 12 を足します。`uint64_t` の最大値は 20 桁なので、割ったあとの値は最大 8 桁です。再帰は 1 回で終わります。

## ここがすごい

**素直な書き方との比較**: 桁数を数えるいちばん簡単な方法は、`while (v >= 10) { v /= 10; n++; }` のように 10 で割り続けることです。でも整数の割り算は、CPU にとって足し算や比較よりずっと重い命令です。20 桁の数なら 19 回も割り算することになります。
この関数は、12 桁未満なら **割り算を 1 回もせず** 比較だけで答えを出します。

**よく出る値を先に**: 最初の 3 行で 1〜3 桁を直接チェックしているのは、「小さい数がよく使われる」という前提で、よくある場合を最短で終わらせるためです。一方、4 桁以上は二分探索の形にして比較の回数を抑えています。均等に分布している前提の最適と、現実の分布に合わせた最適を組み合わせたつくりです。

**比較結果を数として足す**: `5 + (v >= 100000)` のように、比較の 0/1 をそのまま足し算に使うことで、`if` を 1 段減らしています。コンパイラはこれを分岐なしの命令（条件によって 0 か 1 を作る命令）に変換しやすくなります。

**呼び出し側との関係**: 同じファイルの `ull2string` は、この関数で先に桁数を求め、文字列の **末尾から** 数字を埋めていきます。長さが先にわかるので、後から文字列を反転する手間がいりません。

## まとめ

- 整数の割り算は重いので、比較で済むなら比較を使う。
- 「よくある小さな値は先にチェック」「残りは二分探索」の組み合わせで平均の手数を減らせる。
- C の比較式は 0 か 1 の整数なので、そのまま足し算に使える。
- 範囲が広すぎる値は、大きな単位で一度割ってから再帰すると表を小さく保てる。
