## ひとことで

`sdstrim(s, cset)` は、文字列 `s` の **先頭と末尾から**、`cset` に含まれる文字を取り除きます。
コメントの例では、`"AA...AA.a.aa.aHelloWorld     :::"` に `cset = "Aa. :"` を指定すると、`"HelloWorld"` だけが残ります。
新しい文字列は作らず、元の文字列を **その場で** 書き換えます。

## コード

```c:line-numbers=771
sds sdstrim(sds s, const char *cset) {
    char *end, *sp, *ep;
    size_t len;

    sp = s;
    ep = end = s + sdslen(s) - 1;
    while (sp <= end && strchr(cset, *sp)) sp++;
    while (ep > sp && strchr(cset, *ep)) ep--;
    len = (ep - sp) + 1;
    if (s != sp) memmove(s, sp, len);
    s[len] = '\0';
    sdssetlen(s, len);
    return s;
}
```

## 前提知識

- **ポインタ**: メモリ上の位置を指す値です。`char *sp` は文字を指すポインタで、`*sp` でその文字を読めます。`sp++` で次の文字、`ep--` で前の文字へ移ります。
- **ポインタの比較と引き算**: 同じ文字列の中を指すポインタどうしは、`sp <= end` のように位置の前後を比べられます。`ep - sp` は 2 つの位置の間の文字数です。
- **`strchr(cset, c)`**: 文字列 `cset` の中から文字 `c` を探し、見つかればその位置を、なければ `NULL`（偽として扱われる）を返す標準関数です。「`c` が集合に含まれるか」の判定に使っています。
- **`memmove(dst, src, n)`**: `n` バイトをコピーします。コピー元と先が重なっていても正しく動くのが `memcpy` との違いです。
- **`sdslen` / `sdssetlen`**: SDS 文字列の長さを読む / 書き換える関数です。SDS は長さをヘッダに持っているので、中身を変えたら長さも更新します。

## 何をしているか

`s = "xxHixx"`、`cset = "x"` で追ってみます。長さは 6 です。

### 1. 2 本のポインタを置く（775〜776 行目）

`sp` は先頭（`'x'`、0 番目）、`ep` と `end` は最後の文字（`'x'`、5 番目）を指します。

### 2. 先頭側を進める（777 行目）

`sp` が指す文字が `cset` に含まれる間、`sp` を進めます。0 番目と 1 番目は `'x'` なので進み、2 番目の `'H'` で止まります。`sp <= end` の条件で、文字列の外へ出ないようにしています。

### 3. 末尾側を戻す（778 行目）

`ep` が指す文字が `cset` に含まれる間、`ep` を戻します。5 番目、4 番目は `'x'` なので戻り、3 番目の `'i'` で止まります。`ep > sp` の条件で、`sp` を追い越さないようにしています。

### 4. 残りを先頭に寄せる（779〜783 行目）

残る長さは `(ep - sp) + 1` = `(3 - 2) + 1` = 2 です。`sp` が先頭でなければ、`memmove` で `"Hi"` を先頭へ移します。
最後に `s[2] = '\0'` で終端を書き、長さを 2 に更新します。結果は `"Hi"` です。

### 5. 全部が取り除かれる場合

`s = "xxx"` なら、777 行目で `sp` は `end` を越えて 3 番目（終端の位置）まで進みます。778 行目は `ep > sp` が偽なのですぐ終わり、`ep` は 2 番目のままです。`len = (2 - 3) + 1 = 0` となり、空文字列になります。

## ここがすごい

**メモリを確保しない**: 結果は必ず元より短いか同じなので、新しい文字列を作る必要はありません。残す部分を先頭に寄せて長さを書き換えるだけです。確保に失敗する心配もありません。

**`memmove` を選ぶ理由**: 残す部分（コピー元）と先頭（コピー先）は、多くの場合重なっています。`"xxHixx"` なら、コピー元は 2〜3 番目、コピー先は 0〜1 番目ですが、残す部分が長ければ範囲が重なります。重なりを正しく扱える `memmove` が必要なのです。さらに `s != sp`（先頭に削る文字がなかった場合）はコピー自体を省いています。

**集合の判定を `strchr` に任せる**: 「この文字は削除対象か」を `strchr` で調べるので、`cset` には好きな文字を好きなだけ並べられます。`cset` が数文字なら、表を作るより単純で十分速い方法です。

**SDS ならではの更新**: C の文字列なら `'\0'` を書くだけで長さが決まりますが、SDS はヘッダに長さを持っています。だから `s[len] = '\0'` と `sdssetlen` の **両方** が必要です。終端を書くのは、SDS を C の文字列として `printf` などに渡しても正しく動くようにするためです。

**空き容量は残る**: 長さは縮みますが、確保したメモリの大きさはそのままです。不要なら `sdsRemoveFreeSpace` で切り詰められます。

## まとめ

- 両端から 2 本のポインタを内側へ進めると、trim は 1 回ずつの走査で書ける。
- 結果が元より短い処理は、その場で書き換えれば新しいメモリがいらない。
- コピー元と先が重なる可能性があるなら `memmove` を使う。
- 長さを別に持つ文字列では、終端の `'\0'` と長さの両方を更新する。
