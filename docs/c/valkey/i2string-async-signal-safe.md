## ひとことで

`i2string_async_signal_safe` は、符号付き 64 ビット整数を 10 進または 16 進の文字列にする関数です。
Valkey がクラッシュしたときにログを書く処理など、**シグナルハンドラの中** から呼べるように、標準の `snprintf` を使わずに自前で書かれています。
`-1` を 16 進で書くと `"ffffffffffffffff"` になるように、負の数の 16 進表記を桁の置き換えで作っているのが面白いところです。

## コード

```c:line-numbers=1514
static char *i2string_async_signal_safe(int base, int64_t val, char *buf) {
    char *orig_buf = buf;
    const int32_t is_neg = (val < 0);
    *buf-- = 0;

    if (is_neg) {
        val = -val;
    }
    if (is_neg && base == 16) {
        int ix;
        val -= 1;
        for (ix = 0; ix < 16; ++ix) buf[-ix] = '0';
    }

    do {
        *buf-- = HEX[val % base];
    } while ((val /= base) != 0);

    if (is_neg && base == 10) {
        *buf-- = '-';
    }

    if (is_neg && base == 16) {
        int ix;
        buf = orig_buf - 1;
        for (ix = 0; ix < 16; ++ix, --buf) {
            switch (*buf) {
            case '0': *buf = 'f'; break;
            case '1': *buf = 'e'; break;
            case '2': *buf = 'd'; break;
            case '3': *buf = 'c'; break;
            case '4': *buf = 'b'; break;
            case '5': *buf = 'a'; break;
            case '6': *buf = '9'; break;
            case '7': *buf = '8'; break;
            case '8': *buf = '7'; break;
            case '9': *buf = '6'; break;
            case 'a': *buf = '5'; break;
            case 'b': *buf = '4'; break;
            case 'c': *buf = '3'; break;
            case 'd': *buf = '2'; break;
            case 'e': *buf = '1'; break;
            case 'f': *buf = '0'; break;
            }
        }
    }
    return buf + 1;
}
```

## 前提知識

- **シグナルとシグナルハンドラ**: シグナルは、OS がプロセスに送る「割り込みの知らせ」です（例: 不正なメモリアクセスで送られる SIGSEGV）。受け取ると、実行中の処理を中断して「シグナルハンドラ」という関数が呼ばれます。
- **async-signal-safe**: シグナルハンドラの中から安全に呼べる関数のことです。`printf` や `malloc` は内部でロックを使うことがあり、中断された処理がそのロックを握っていると固まる恐れがあるので、安全ではありません。
- **`char *buf` を後ろから書く**: この関数は、バッファの **末尾を指すポインタ** を受け取り、`*buf-- = 文字` で「書いてから 1 つ前へ戻る」を繰り返します。下の桁から順に求まる数字を、反転なしで並べるためです。
- **`HEX[val % base]`**: `HEX` は `"0123456789abcdef"` という文字列（1503 行目）です。`val % base` が 11 なら `HEX[11]` は `'b'` です。
- **2 の補数**: 負の数の表し方で、64 ビットの `-x` は `2^64 - x` と同じビット並びになります。`-1` は全ビット 1、16 進で `ffffffffffffffff` です。
- **`buf[-ix]`**: ポインタから `ix` 個 **前** の要素です。

## 何をしているか

### 1. 終端と符号（1515〜1521 行目）

終端の `'\0'` を書いて 1 つ戻ります。負の数なら `val = -val` で絶対値にします。

### 2. 10 進数の場合（1528〜1534 行目）

`val = -42`、`base = 10` で追います。絶対値 42 を、`42 % 10 = 2` → `'2'`、`4 % 10 = 4` → `'4'` と後ろから書きます。最後に `'-'` を書き、`buf + 1`（最後に書いた文字の位置）を返します。結果は `"-42"` です。

### 3. 16 進数の負の数（1522〜1526、1536〜1559 行目）

`val = -1`、`base = 16` で追います。

1. 絶対値は `1`。さらに 1525 行目までで `val -= 1` して `0` にし、終端の前の 16 文字を `'0'` で埋めます。
2. 1528 行目からのループで `0` を書きます（もともと `'0'` なので見た目は変わりません）。この時点で 16 文字は `"0000000000000000"` です。
3. 1536 行目から、16 文字すべてを「15 から引いた桁」に置き換えます。`'0'` は `'f'`、`'1'` は `'e'`、…、`'f'` は `'0'` です。結果は `"ffffffffffffffff"` になります。

なぜこれで正しいのでしょうか。2 の補数では `-x` = `2^64 - x` = `(2^64 - 1) - (x - 1)` です。`2^64 - 1` は 16 進で `f` が 16 個なので、`x - 1` の各桁を **15 から引く** と、繰り下がりなしで答えが得られます。だから先に 1 を引き、16 桁ぶん 0 で埋めておいたのです。

`val = -255` なら、`255 - 1 = 254` = `0xfe`。16 桁は `"00000000000000fe"`、各桁を置き換えて `"ffffffffffffff01"` となり、これは確かに `-255` の 2 の補数表記です。

## ここがすごい

**ライブラリに頼れない場所の工夫**: クラッシュ時の記録は、まさにメモリが壊れているかもしれない状況で動きます。そこで `snprintf` の代わりに、ロックもメモリ確保もしない小さな変換関数を自前で用意しています。後ろから書く方式なので、作業用のバッファも反転処理もいりません。

**ビット演算を使わずに補数を作る**: 負の数を 16 進で表示するには、ふつうは符号なし整数にキャストしてそのまま変換します。この関数は、絶対値から `1` を引いて桁ごとに「15 - 桁」に置き換える、という算数で同じ結果を出しています。`switch` で 16 通りの置き換えを並べているので、何をしているかが一目でわかります。

**注意点**: 1520 行目の `val = -val` は、`val` が `INT64_MIN` のとき符号付きのオーバーフローになります。ログ出力用の補助関数なので、その極端な値までは考慮していない書き方だと読めます。

## まとめ

- シグナルハンドラの中では、ロックやメモリ確保をする標準関数を使えない。
- 数字は下の桁から求まるので、バッファの後ろから書けば反転がいらない。
- 2 の補数の `-x` は、`x - 1` の各桁を「基数 - 1」から引くことで作れる。
- 絶対値をとる `-val` は、最小の負の数で溢れることに注意する。
