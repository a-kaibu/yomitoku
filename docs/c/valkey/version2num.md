## ひとことで

`version2num` は、`"7.2.4"` のようなバージョン文字列を `0x070204` という 1 つの整数に変換します。
各部分（メジャー・マイナー・パッチ）を 1 バイト（0〜255）ずつ並べるので、**整数の大小がそのままバージョンの新旧** になります。
形式が正しくなければ `-1` を返します。

## コード

```c:line-numbers=1073
/* Parses a version string on the form "major.minor.patch" and returns an
 * integer on the form 0xMMmmpp. Returns -1 on parse error. */
int version2num(const char *version) {
    int v = 0, part = 0, numdots = 0;
    const char *p = version;
    do {
        if (*p >= '0' && *p <= '9') {
            part = part * 10 + (unsigned)(*p - '0');
            if (part > 255) return -1;
        } else if (*p == '.') {
            if (++numdots > 2) return -1;
            v = (v << 8) | part;
            part = 0;
        } else {
            return -1;
        }
        p++;
    } while (*p);
    if (numdots != 2) return -1;
    v = (v << 8) | part;
    return v;
}
```

## 前提知識

- **16 進数の `0x`**: `0x070204` は 16 進数で、2 桁が 1 バイトに当たります。`07`、`02`、`04` がそれぞれメジャー、マイナー、パッチです。
- **左シフト `<<`**: `v << 8` は `v` のビットを 8 個左にずらし、右に 0 を 8 個入れます。1 バイトぶん左へ寄せて、空いた右の 1 バイトに次の値を入れる準備になります。`0x07 << 8` は `0x0700` です。
- **ビット OR `|`**: 桁ごとに「どちらかが 1 なら 1」を計算します。`0x0700 | 0x02` は `0x0702` です。空いた場所に値を入れる操作として使われます。
- **`do { ... } while (条件);`**: まず本体を 1 回実行し、そのあと条件が真の間くり返すループです。
- **`*p`**: ポインタ `p` が指す 1 文字です。文字列の終端 `'\0'` は値 0 なので、`while (*p)` は「文字列の終わりまで」という意味になります。
- **`++numdots > 2`**: `numdots` を先に 1 増やしてから 2 と比べます（前置インクリメント）。

## 何をしているか

### 1. 1 文字ずつ見る（1078〜1090 行目）

`"7.2.4"` を追ってみます。最初は `v = 0`、`part = 0` です。

| 文字 | 処理 | `v` | `part` |
| --- | --- | --- | --- |
| `7` | `part = 0*10 + 7` | `0x00` | 7 |
| `.` | `v = (0 << 8) \| 7` | `0x07` | 0 |
| `2` | `part = 2` | `0x07` | 2 |
| `.` | `v = (0x07 << 8) \| 2` | `0x0702` | 0 |
| `4` | `part = 4` | `0x0702` | 4 |

数字なら `part` に 10 進数として積み上げ、`.` が来たら `part` を `v` の右端の 1 バイトに押し込みます。

### 2. 不正な形式を弾く

- 1081 行目: 1 つの部分が 255 を超えたら失敗（1 バイトに入らないため）。`"7.300.1"` は失敗します。
- 1083 行目: ドットが 3 つ以上なら失敗。`"1.2.3.4"` は失敗します。
- 1087 行目: 数字とドット以外の文字があれば失敗。`"7.2.4-rc1"` は失敗します。

### 3. 最後の部分を押し込む（1091〜1093 行目）

ドットがちょうど 2 つでなければ失敗です（`"7.2"` は失敗）。最後の `part`（パッチの 4）はドットの後に来ないので、ループの外で `v = (0x0702 << 8) | 4 = 0x070204` として仕上げます。

## ここがすごい

**比較が楽になる**: バージョンを文字列のまま比べると、`"10.0.0"` と `"9.0.0"` では先頭の文字 `'1'` と `'9'` を比べてしまい、`"10.0.0"` のほうが小さいと判定されてしまいます。整数にしておけば `0x0A0000 > 0x090000` で正しく比較できます。Valkey 自身のバージョン番号も同じ形式の整数として扱われます。

**1 バイトずつ詰める理由**: 各部分に 8 ビット（0〜255）を割り当てると、上位の部分ほど大きな桁に来るので、整数の大小関係が「メジャー → マイナー → パッチ」の優先順位と一致します。辞書の並び順と同じ考え方です。16 進数で書けば `07` `02` `04` と人間にも読みやすいのもよい点です。

**小さく厳格なパーサ**: 正規表現も `sscanf` も使わず、1 文字ずつの状態を `part` と `numdots` の 2 つだけで管理しています。範囲外の値や余計な文字を見逃さないので、不正な入力から変な数が作られることがありません。

**`do-while` の選択**: 本体を先に 1 回実行するので、空文字列 `""` を渡すと最初の文字 `'\0'` が「数字でもドットでもない」として 1087 行目で弾かれます。ふつうの `while` で書いた場合は、ループに入らずに `numdots != 2` で弾かれることになります。どちらでも失敗にはなりますが、`do-while` だと「1 文字目から形式を検査する」流れが素直に書けています。

## まとめ

- 複数の小さな数は、シフトと OR で 1 つの整数に詰め込める。
- 上位の要素を上位のビットに置けば、整数の比較がそのまま優先順位つきの比較になる。
- バージョンを文字列のまま比べると `10` と `9` の順序を間違える。
- 小さなパーサは、少数の状態変数と早めの `return -1` で厳格に書ける。
