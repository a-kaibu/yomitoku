## ひとことで

`ngx_strnstr` は、文字列 `s1` の **先頭 `len` バイトの中から**、文字列 `s2` が現れる場所を探す関数です。見つかればその開始位置を、見つからなければ `NULL` を返します。
たとえば `s1 = "error: upstream timed out"`、`s2 = "timed"` なら、`"timed"` が始まる位置を返します。nginx では FastCGI のエラーメッセージから決まった文字列を探す場面などで使われています。

## コード

```c:line-numbers=690
u_char *
ngx_strnstr(u_char *s1, char *s2, size_t len)
{
    u_char  c1, c2;
    size_t  n;

    c2 = *(u_char *) s2++;

    n = ngx_strlen(s2);

    do {
        do {
            if (len-- == 0) {
                return NULL;
            }

            c1 = *s1++;

            if (c1 == 0) {
                return NULL;
            }

        } while (c1 != c2);

        if (n > len) {
            return NULL;
        }

    } while (ngx_strncmp(s1, (u_char *) s2, n) != 0);

    return --s1;
}
```

## 前提知識

- **C の文字列とポインタ**: 文字列は「バイトの並び＋終端の 0」です。`u_char *s1` はその先頭を指すポインタで、`*s1++` は「今の 1 文字を読んで次へ進む」です。
- **`NULL`**: 「どこも指していない」ことを表す特別なポインタの値です。「見つからなかった」の意味でよく返されます。
- **キャスト `(u_char *) s2`**: 値の型を一時的に別の型として扱う書き方です。`s2` は `char *` ですが、`u_char *`（符号なしのバイト）として読み出しています。
- **`do { ... } while (条件);`**: 本体を最低 1 回実行し、そのあと条件が真のあいだ繰り返すループです。
- **`len--` と `--s1`**: `len--` は「今の値を使ってから 1 減らす」、`--s1` は「1 つ戻してからその値を使う」です。
- **`ngx_strlen` / `ngx_strncmp`**: 標準の `strlen`（長さ）と `strncmp`（先頭 n バイトの比較、等しければ 0）を呼ぶマクロです。

## 何をしているか

### 1. 探す文字列を「先頭 1 文字」と「残り」に分ける

```c:line-numbers=696
    c2 = *(u_char *) s2++;

    n = ngx_strlen(s2);
```

`c2` に `s2` の 1 文字目を入れ、`s2` を 1 つ進めます。`n` は **残りの部分の長さ** です。`s2 = "timed"` なら、`c2 = 't'`、残りは `"imed"`、`n = 4` です。

### 2. 先頭の文字が見つかるまで進む

```c:line-numbers=701
        do {
            if (len-- == 0) {
                return NULL;
            }

            c1 = *s1++;

            if (c1 == 0) {
                return NULL;
            }

        } while (c1 != c2);
```

内側のループは `s1` を 1 文字ずつ読み、`c2` と同じ文字が出るまで進みます。途中で 2 つの止まる理由があります。

- `if (len-- == 0)`: 検索してよい長さ `len` を使い切った。
- `if (c1 == 0)`: `s1` の文字列が終わった（0 を読んだ）。

どちらでも「見つからない」として `NULL` を返します。

### 3. 残りが範囲に収まるか確かめる

```c:line-numbers=714
        if (n > len) {
            return NULL;
        }
```

先頭の文字が見つかった時点で、残り `len` が `n` より短ければ、もう収まりきらないので `NULL` を返します。範囲外のバイトを比べてしまうのを防ぐ確認です。

### 4. 残りを比べる

```c:line-numbers=718
    } while (ngx_strncmp(s1, (u_char *) s2, n) != 0);
```

`s1` はすでに一致した文字の **次** を指しています。そこから `n` バイトを `"imed"` と比べ、等しければループを抜けます。違えば外側のループに戻り、次の `'t'` を探します。

### 5. 1 つ戻して返す

```c:line-numbers=720
    return --s1;
```

`s1` は一致した先頭文字の次を指しているので、`--s1` で 1 つ戻して、一致の開始位置を返します。

## ここがすごい

- **2 段構えで比較回数を減らす**: すべての位置で `strncmp` を呼ぶと、そのたびに関数呼び出しが起きます。この関数はまず「先頭 1 文字が一致するか」だけを安いループで調べ、一致したときだけ本格的な比較をします。ふつうの文章では先頭文字の一致はそれほど多くないので、多くの位置は 1 回の比較で読み飛ばせます。
- **長さと終端の両方で守る**: nginx が扱うデータは、必ずしも 0 で終わっていません。受信したバッファの一部などは「長さつき」で扱われます。この関数は `len` で範囲を制限しつつ、0 が来たら止まるので、どちらの形のデータに使っても範囲外を読みにくくなっています。標準 C には `strnstr` がない環境も多く、自前で用意している理由の 1 つです。
- **`if (n > len)` の早期打ち切り**: 残りの長さが足りなければ、それ以上探しても見つかりません。ここで止めることで、ムダな探索と、範囲の外を比べる危険を同時に避けています。
- **ポインタが常に「次」を指す前提でまとめる**: 読みながら進める `*s1++` の流儀を通し、最後に `--s1` で 1 回だけ戻すことで、ループ内の添字計算をなくしています。

## まとめ

- 部分文字列検索は「先頭文字で候補を絞る → 残りを比べる」の 2 段にすると安く書ける。
- 長さつきのデータを扱うなら、0 での終わりと長さの上限の両方で止める。
- 残りの長さが足りないと分かった時点で打ち切ると、速さと安全の両方に効く。
