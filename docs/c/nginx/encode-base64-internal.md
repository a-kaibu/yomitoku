## ひとことで

`ngx_encode_base64_internal` は、任意のバイト列を **Base64**（64 種類の文字だけで表したテキスト）に変換する関数です。たとえば `"Man"` の 3 バイトは `"TWFu"` の 4 文字になります。
使う 64 文字の表 `basis` と、末尾に `=` を付けるか（`padding`）を引数で受け取るので、通常の Base64 と URL 用の Base64（`+/` の代わりに `-_` を使い、`=` を付けない）の両方を同じコードで作れます。

## コード

```c:line-numbers=1206
static void
ngx_encode_base64_internal(ngx_str_t *dst, ngx_str_t *src, const u_char *basis,
    ngx_uint_t padding)
{
    u_char         *d, *s;
    size_t          len;

    len = src->len;
    s = src->data;
    d = dst->data;

    while (len > 2) {
        *d++ = basis[(s[0] >> 2) & 0x3f];
        *d++ = basis[((s[0] & 3) << 4) | (s[1] >> 4)];
        *d++ = basis[((s[1] & 0x0f) << 2) | (s[2] >> 6)];
        *d++ = basis[s[2] & 0x3f];

        s += 3;
        len -= 3;
    }

    if (len) {
        *d++ = basis[(s[0] >> 2) & 0x3f];

        if (len == 1) {
            *d++ = basis[(s[0] & 3) << 4];
            if (padding) {
                *d++ = '=';
            }

        } else {
            *d++ = basis[((s[0] & 3) << 4) | (s[1] >> 4)];
            *d++ = basis[(s[1] & 0x0f) << 2];
        }

        if (padding) {
            *d++ = '=';
        }
    }

    dst->len = d - dst->data;
}
```

## 前提知識

- **Base64**: バイナリデータを、英大文字・小文字・数字・記号 2 つの計 64 文字で表す方式です。64 = 2 の 6 乗なので、1 文字で 6 ビットを表します。3 バイト（24 ビット）が 4 文字（6 ビット × 4）にちょうど対応します。
- **`ngx_str_t`**: nginx の文字列型で、長さ `len` と先頭のポインタ `data` を持つ構造体です。`src->len` は「`src` が指す構造体の `len`」という意味です（`->` はポインタ経由でメンバを読む記号）。
- **`s[0]`、`s[1]`**: ポインタ `s` から 0 番目、1 番目のバイトです。
- **シフトと AND**: `x >> 2` はビットを右に 2 つずらし、`x << 4` は左に 4 つずらします。`x & 0x3f` は下位 6 ビットだけを残します（0x3f は 2 進数で `111111`）。`|` は 2 つの値のビットを重ね合わせます。
- **`static`**: このファイルの中だけで使う関数であることを表します。

## 何をしているか

### 1. 3 バイトずつ 4 文字に変える

```c:line-numbers=1217
    while (len > 2) {
        *d++ = basis[(s[0] >> 2) & 0x3f];
        *d++ = basis[((s[0] & 3) << 4) | (s[1] >> 4)];
        *d++ = basis[((s[1] & 0x0f) << 2) | (s[2] >> 6)];
        *d++ = basis[s[2] & 0x3f];

        s += 3;
        len -= 3;
    }
```

3 バイト `s[0] s[1] s[2]` の 24 ビットを、6 ビットずつ 4 つに切ります。`"Man"` で追うと、

- `M` = `010011 01`、`a` = `0110 0001`、`n` = `01 101110`
- 1 文字目（`*d++ = basis[(s[0] >> 2) & 0x3f];`）: `s[0] >> 2` で `M` の上位 6 ビット `010011`（19）→ `'T'`
- 2 文字目（`*d++ = basis[((s[0] & 3) << 4) | (s[1] >> 4)];`）: `M` の下位 2 ビット `01` を 4 つ左へずらし、`a` の上位 4 ビット `0110` と重ねて `010110`（22）→ `'W'`
- 3 文字目（`*d++ = basis[((s[1] & 0x0f) << 2) | (s[2] >> 6)];`）: `a` の下位 4 ビット `0001` を 2 つ左へずらし、`n` の上位 2 ビット `01` と重ねて `000101`（5）→ `'F'`
- 4 文字目（`*d++ = basis[s[2] & 0x3f];`）: `n` の下位 6 ビット `101110`（46）→ `'u'`

得られた 0〜63 の数を添字にして、`basis` から文字を取り出します。

### 2. 余った 1〜2 バイトを処理する

```c:line-numbers=1227
    if (len) {
        *d++ = basis[(s[0] >> 2) & 0x3f];

        if (len == 1) {
            *d++ = basis[(s[0] & 3) << 4];
            if (padding) {
                *d++ = '=';
            }

        } else {
            *d++ = basis[((s[0] & 3) << 4) | (s[1] >> 4)];
            *d++ = basis[(s[1] & 0x0f) << 2];
        }

        if (padding) {
            *d++ = '=';
        }
    }
```

長さが 3 で割り切れないとき、最後に 1 バイトか 2 バイトが残ります。

- 1 バイト残り: 2 文字を作り、`padding` が真なら `=` を 2 つ付けます（`if (len == 1)` の中の `=` と、最後の `if (padding)` の `=`）。足りないビットは 0 で埋まります。
- 2 バイト残り: 3 文字を作り、`=` を 1 つ付けます（最後の `if (padding)`）。

`"Ma"` なら `"TWE="`、`"M"` なら `"TQ=="` です。

### 3. 長さを記録する

```c:line-numbers=1246
    dst->len = d - dst->data;
```

書き終えた位置 `d` から先頭を引いて、出力の長さを `dst->len` に入れます。

## ここがすごい

- **表を差し替えるだけで別の方式になる**: 通常版の `ngx_encode_base64` は `"...+/"` の表と `padding = 1` を、URL 版の `ngx_encode_base64url` は `"...-_"` の表と `padding = 0` を渡して、この関数を呼ぶだけです。違いを「データ（表と旗）」として外に出すことで、ビット操作の本体は 1 か所にまとまっています。
- **`=` を付ける処理の共有**: 1 バイト残りなら `=` が 2 つ、2 バイト残りなら 1 つ必要です。最後の `if (padding)` で書く `=` を両方の場合で共通にし、1 バイト残りのときだけ `if (len == 1)` の中でもう 1 つ足しています。場合分けを最小にした書き方です。
- **出力先の大きさは呼び出し側が確保**: この関数は書き込み先のメモリを自分で確保しません。必要な大きさは `ngx_base64_encoded_length(len)`（`((len + 2) / 3) * 4`）で事前に計算できるので、呼び出し側が確保して渡します。メモリ確保の方法（nginx のメモリプールなど）を呼び出し側が選べます。
- **1 文字ごとの分岐がない**: メインのループは、シフト、AND、OR、表引きだけでできています。

## まとめ

- Base64 は「3 バイト＝24 ビットを 6 ビット × 4 に切る」だけの変換。シフトと AND で切り出せる。
- 方式ごとの違いを表やフラグとして引数に出すと、本体のコードを共有できる。
- 出力の大きさが計算で分かる処理は、確保を呼び出し側に任せると柔軟になる。
