## ひとことで

`ngx_decode_base64_internal` は、Base64 の文字列を元のバイト列に戻す関数です。`"TWFu"` を渡すと `"Man"` の 3 バイトになります。
文字を 6 ビットの値に変える表 `basis` を引数で受け取るので、通常の Base64 と URL 用の Base64 の両方を 1 つのコードで扱えます。不正な文字や、ありえない長さを見つけたら `NGX_ERROR` を返します。

## コード

```c:line-numbers=1304
static ngx_int_t
ngx_decode_base64_internal(ngx_str_t *dst, ngx_str_t *src, const u_char *basis)
{
    size_t          len;
    u_char         *d, *s;

    for (len = 0; len < src->len; len++) {
        if (src->data[len] == '=') {
            break;
        }

        if (basis[src->data[len]] == 77) {
            return NGX_ERROR;
        }
    }

    if (len % 4 == 1) {
        return NGX_ERROR;
    }

    s = src->data;
    d = dst->data;

    while (len > 3) {
        *d++ = (u_char) (basis[s[0]] << 2 | basis[s[1]] >> 4);
        *d++ = (u_char) (basis[s[1]] << 4 | basis[s[2]] >> 2);
        *d++ = (u_char) (basis[s[2]] << 6 | basis[s[3]]);

        s += 4;
        len -= 4;
    }

    if (len > 1) {
        *d++ = (u_char) (basis[s[0]] << 2 | basis[s[1]] >> 4);
    }

    if (len > 2) {
        *d++ = (u_char) (basis[s[1]] << 4 | basis[s[2]] >> 2);
    }

    dst->len = d - dst->data;

    return NGX_OK;
}
```

表は呼び出し側の `ngx_decode_base64` の中で `static u_char basis64[]` として定義されています。256 個の要素があり、添字が文字の番号です。たとえば次の 3 行では、`'+'`（43 番）に 62、`'/'`（47 番）に 63、`'0'`（48 番）以降に 52〜、`'A'`（65 番）以降に 0〜 が入っています。Base64 で使わない文字の位置はすべて 77 です。

## 前提知識

- **Base64**: 64 種類の文字で、1 文字あたり 6 ビットを表す方式です。4 文字（24 ビット）が元の 3 バイトに対応します。末尾が足りないときは `=` で埋めます。
- **`ngx_str_t`**: 長さ `len` と先頭のポインタ `data` を持つ nginx の文字列型です。`src->data[len]` は、`src` の文字列の `len` 番目のバイトです。
- **表引き**: `basis[c]` のように、文字の番号 `c` を添字にして配列から値を取り出すことです。`u_char` は 0〜255 なので、256 要素の表ならどんなバイトでも範囲外になりません。
- **シフトと OR**: `x << 2` は左へ 2 ビットずらし、`x >> 4` は右へ 4 ビットずらします。`|` でビットを重ねます。
- **`(u_char)` のキャスト**: 計算結果を 1 バイトに切り詰めます。左シフトではみ出た上位のビットはここで捨てられます。
- **`%`**: 割り算の余りです。

## 何をしているか

### 1. 長さを数えつつ、不正な文字を探す

```c:line-numbers=1310
    for (len = 0; len < src->len; len++) {
        if (src->data[len] == '=') {
            break;
        }

        if (basis[src->data[len]] == 77) {
            return NGX_ERROR;
        }
    }
```

`=` が出るまで 1 文字ずつ調べ、表の値が 77 ならエラーにします。ループが終わると `len` は「`=` より前の、意味のある文字の数」になります。

### 2. ありえない長さを弾く

```c:line-numbers=1320
    if (len % 4 == 1) {
        return NGX_ERROR;
    }
```

1 文字は 6 ビットなので、最後に 1 文字だけ余ると 6 ビットしかなく、1 バイト（8 ビット）を作れません。`len % 4 == 1` はどんな正しい Base64 でも起きないのでエラーです。余りが 2 なら 1 バイト、3 なら 2 バイトを作れます。

### 3. 4 文字ずつ 3 バイトに戻す

```c:line-numbers=1327
    while (len > 3) {
        *d++ = (u_char) (basis[s[0]] << 2 | basis[s[1]] >> 4);
        *d++ = (u_char) (basis[s[1]] << 4 | basis[s[2]] >> 2);
        *d++ = (u_char) (basis[s[2]] << 6 | basis[s[3]]);

        s += 4;
        len -= 4;
    }
```

`"TWFu"` なら表の値は 19, 22, 5, 46（2 進数で `010011`, `010110`, `000101`, `101110`）です。

- 1 バイト目（`*d++ = (u_char) (basis[s[0]] << 2 | basis[s[1]] >> 4);`）: `010011` を左へ 2 つ、`010110` の上位 2 ビット `01` と重ねて `01001101` = `'M'`
- 2 バイト目（`*d++ = (u_char) (basis[s[1]] << 4 | basis[s[2]] >> 2);`）: `010110` の下位 4 ビットを左へ 4 つ、`000101` の上位 4 ビットと重ねて `01100001` = `'a'`
- 3 バイト目（`*d++ = (u_char) (basis[s[2]] << 6 | basis[s[3]]);`）: `000101` の下位 2 ビットを左へ 6 つ、`101110` と重ねて `01101110` = `'n'`

左シフトではみ出た上位ビットは、`(u_char)` で 1 バイトに切り詰めるときに捨てられます。

### 4. 残りの 2〜3 文字を処理する

```c:line-numbers=1336
    if (len > 1) {
        *d++ = (u_char) (basis[s[0]] << 2 | basis[s[1]] >> 4);
    }

    if (len > 2) {
        *d++ = (u_char) (basis[s[1]] << 4 | basis[s[2]] >> 2);
    }
```

残りが 2 文字なら 1 バイト、3 文字なら 2 バイトを作ります。`if` を 2 つ並べ、3 文字のときは両方が実行される形にしています。

## ここがすごい

- **「77」という番兵**: 6 ビットの値は 0〜63 なので、それ以外の数なら何でも「不正」の印に使えます。表の不正な位置を 77 で埋めておけば、文字の検証は `basis[c] == 77` の 1 回の表引きで済みます。`'A' <= c && c <= 'Z' || ...` のような比較を何度も書く必要がありません。
- **検証と変換を分ける**: 先に全体を走査して不正な文字と長さを確かめてから、変換に取りかかります。変換のループでは、もう不正な文字が来ないと分かっているので、チェックなしで速く回せます。途中まで書いてから失敗する、ということもありません。
- **表を差し替えて URL 版にも対応**: URL 用の `ngx_decode_base64url` は、`'-'` と `'_'` に 62, 63 を入れた別の表を渡すだけです。
- **`=` に寛容**: `if (src->data[len] == '=')` で `=` に出会ったらそこで終わりとみなすので、`=` の有無や個数が多少違っても受け付けます。URL 版のように `=` を付けない形式でも、同じコードがそのまま動きます。

## まとめ

- 正しい値の範囲外にある数（番兵）を表に入れておくと、検証が表引き 1 回で済む。
- まず検証、次に変換、と 2 段に分けると、変換のループが単純で速くなる。
- Base64 の長さが「4 で割って 1 余る」ことはありえない。こうした性質を使うと不正な入力を早く弾ける。
