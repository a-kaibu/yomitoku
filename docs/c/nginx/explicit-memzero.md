## ひとことで

`ngx_explicit_memzero` は、メモリの `n` バイトを 0 で上書きする関数です。中身はたった 2 行で、0 で埋めたあとに **メモリバリア** を置いています。
目的は、TLS のパスワードやセッション情報など **秘密のデータを、使い終わったら確実に消す** ことです。nginx では SSL のパスワード用バッファなどを片付けるときに使われています。

## コード

```c:line-numbers=2109
void
ngx_explicit_memzero(void *buf, size_t n)
{
    ngx_memzero(buf, n);
    ngx_memory_barrier();
}
```

## 前提知識

- **`void *buf`**: 型の決まっていないポインタです。どんなデータの場所でも受け取れます。
- **`ngx_memzero`**: 標準の `memset(buf, 0, n)` を呼ぶマクロで、`buf` から `n` バイトを 0 で埋めます。
- **コンパイラの最適化**: コンパイラは、プログラムの「見た目の結果」が変わらない範囲で、コードを速く書き換えます。たとえば **「書いたあと一度も読まれずに捨てられるメモリへの書き込み」は消してよい** と判断することがあります（不要な書き込みの削除）。
- **メモリバリア**: 「この地点をまたいで、メモリの読み書きの順番を入れ替えたり、省いたりしてはいけない」とコンパイラ（や CPU）に伝える命令です。nginx の `ngx_memory_barrier()` は環境ごとに定義が違い、たとえば x86-64 の GCC 向けには `__asm__ volatile ("" ::: "memory")` です。これは何もしない命令ですが、「メモリの中身がどこかで使われるかもしれない」とコンパイラに伝える効果があります。
- **マクロ**: `#define` で定義された置き換えです。`ngx_memzero(buf, n)` はコンパイル前に `memset` の呼び出しに置き換わります。

## 何をしているか

### 1. 0 で埋める

```c:line-numbers=2112
    ngx_memzero(buf, n);
```

`ngx_memzero(buf, n)` で、`buf` から `n` バイトを 0 にします。

### 2. メモリバリアを置く

```c:line-numbers=2113
    ngx_memory_barrier();
```

`ngx_memory_barrier()` で、「ここまでのメモリへの書き込みは、ちゃんと済ませておくこと」とコンパイラに伝えます。

### なぜバリアが必要なのか

次のような関数を考えます。

```c
char pwd[64];
read_password(pwd);
use(pwd);
memset(pwd, 0, sizeof(pwd));   /* 消したつもり */
return;
```

`pwd` は関数を抜けると使われなくなるので、コンパイラから見ると最後の `memset` は「結果がどこにも影響しない書き込み」です。最適化で **`memset` がまるごと消される** ことがあり、パスワードがメモリに残ってしまいます。
`memset` のあとにメモリバリアを置くと、コンパイラは「この先でメモリが読まれるかもしれない」と考えるため、書き込みを消せなくなります。

## ここがすごい

- **最適化の「正しさ」と、安全の要求のずれを埋める**: 0 で埋める処理は、プログラムの計算結果には影響しません。だからこそ最適化で消されてしまいます。しかしセキュリティ上は、メモリダンプやバグで秘密が漏れるのを防ぐために、確実に消したいのです。この関数は、そのずれを 1 行のバリアで埋めています。
- **移植性を `ngx_memory_barrier` に任せる**: OS やコンパイラによっては `explicit_bzero` や `memset_s` といった専用の関数がありますが、どこにでもあるわけではありません。nginx はすでに環境ごとに用意しているメモリバリアのマクロを再利用することで、追加の設定なしに多くの環境で同じ効果を得ています。
- **名前で意図を伝える**: 中身が 2 行でも、`explicit_memzero`（明示的なゼロクリア）という名前の関数にすることで、「これは消されては困るゼロクリアだ」という意図がコードを読む人に伝わります。後の誰かが「不要な処理」と思って消してしまうのも防げます。

## まとめ

- コンパイラは、後で使われないメモリへの書き込みを消すことがある。秘密データのゼロクリアはその対象になりやすい。
- 書き込みの直後にメモリバリアを置くと、コンパイラはその書き込みを省けなくなる。
- 短い処理でも、名前を付けた関数にすると意図が伝わり、うっかり消されにくくなる。
