## ひとことで

`ngx_strcasecmp` は、2 つの文字列を **大文字と小文字を区別せずに** 比べる関数です。`"Host"` と `"HOST"` は等しいとみなして 0 を返します。等しくなければ、最初に違った文字の差（正か負の数）を返します。
HTTP のヘッダ名のように「大文字小文字を区別しない」と決まっている名前を比べるときに使われます。

## コード

```c:line-numbers=635
ngx_int_t
ngx_strcasecmp(u_char *s1, u_char *s2)
{
    ngx_uint_t  c1, c2;

    for ( ;; ) {
        c1 = (ngx_uint_t) *s1++;
        c2 = (ngx_uint_t) *s2++;

        c1 = (c1 >= 'A' && c1 <= 'Z') ? (c1 | 0x20) : c1;
        c2 = (c2 >= 'A' && c2 <= 'Z') ? (c2 | 0x20) : c2;

        if (c1 == c2) {

            if (c1) {
                continue;
            }

            return 0;
        }

        return c1 - c2;
    }
}
```

## 前提知識

- **C の文字列**: 文字のバイトが並び、最後に値 0 のバイトが置かれたものです。終わりは 0 を見つけて判断します。
- **ポインタと `*s1++`**: `s1` は文字列の場所を指すポインタです。`*s1++` は「`s1` が指す 1 文字を読み、そのあと `s1` を次の文字へ進める」という意味です。
- **`ngx_uint_t`**: nginx の符号なし整数型（ポインタと同じ幅、64 ビット環境なら 8 バイト）です。`(ngx_uint_t) *s1` は 1 バイトの文字をこの型に広げています。
- **`for ( ;; )`**: 条件のない無限ループです。中の `return` で抜けます。
- **三項演算子 `a ? b : c`**: `a` が真なら `b`、偽なら `c` を値とします。
- **`|`（ビット OR）**: 2 つの数を 2 進数で並べ、どちらかが 1 の桁を 1 にします。
- **ASCII**: 文字に番号を振った表です。`'A'` は 65（0x41）、`'a'` は 97（0x61）です。

## 何をしているか

### 1. 1 文字ずつ取り出す

```c:line-numbers=641
        c1 = (ngx_uint_t) *s1++;
        c2 = (ngx_uint_t) *s2++;
```

両方の文字列から 1 文字ずつ読み、ポインタを次へ進めます。

### 2. 大文字なら小文字にする

```c:line-numbers=644
        c1 = (c1 >= 'A' && c1 <= 'Z') ? (c1 | 0x20) : c1;
        c2 = (c2 >= 'A' && c2 <= 'Z') ? (c2 | 0x20) : c2;
```

`'A'`〜`'Z'` の範囲にある文字だけ、`| 0x20` をします。
ASCII では、大文字と小文字は **ちょうど 0x20（32）違い** になるように並んでいます。

- `'H'` は 0x48 = `0100 1000`
- `'h'` は 0x68 = `0110 1000`

違いは右から 6 番目のビット（0x20）だけです。大文字ではこのビットが 0、小文字では 1 なので、`| 0x20` でそのビットを立てると小文字になります。

範囲チェックをしているのは、`'['`（0x5B）や `'@'`（0x40）など英字以外の文字まで変えてしまわないためです。

### 3. 同じなら続け、違えば差を返す

```c:line-numbers=647
        if (c1 == c2) {

            if (c1) {
                continue;
            }

            return 0;
        }

        return c1 - c2;
```

小文字にそろえた `c1` と `c2` が同じなら、まだ文字列が続いているか（0 でないか）を見ます。続いていれば次の文字へ（`continue;`）、両方とも 0 に着いたら完全に一致したので 0 を返します（`return 0;`）。
違っていれば `c1 - c2` を返します。`"abc"` と `"ABD"` なら、3 文字目で `'c'`（99）と `'d'`（100）が違い、結果は負になります。「1 つ目のほうが辞書順で前」という意味です。

なお、片方だけが先に終わった場合（`"ab"` と `"abc"`）は、0 と `'c'` を比べることになり、短いほうが前になります。終端の確認を別に書かなくても、0 がいちばん小さい文字として自然に扱われます。

## ここがすごい

- **ロケールに依存しない**: 標準ライブラリにも大小無視の比較（`strcasecmp`）や `tolower` がありますが、これらは「ロケール」（言語や地域の設定）によって結果が変わることがあります。HTTP のヘッダ名は ASCII の英字だけを対象に比べればよいので、自前で `'A'`〜`'Z'` だけを変換するほうが、どの環境でも同じ結果になり、関数呼び出しのぶん速くもなります。
- **ビット 1 つで変換**: 大文字を小文字にするのに `c + 32` と書くこともできますが、`| 0x20` は「すでに小文字なら何も変えない」性質があります。ここでは範囲チェックがあるのでどちらでも同じですが、ASCII 表の設計（大文字と小文字がビット 1 つ違い）を素直に生かした書き方です。nginx の `ngx_tolower` マクロも同じ式です。
- **終端処理を比較に溶け込ませる**: 「等しくて、かつ 0 なら終わり」とすることで、文字列の終わりの判定と比較を 1 つの流れにまとめています。片方が短い場合の特別な処理もいりません。
- **`ngx_uint_t` に広げてから計算**: `u_char` のまま引き算すると、計算の途中で `int` に変換される規則などが絡んで分かりにくくなります。最初に 1 つの整数型にそろえておくと、比較も差の計算も素直になります。

## まとめ

- ASCII では大文字と小文字は 0x20 のビット 1 つだけ違う。`| 0x20` で小文字、`& ~0x20` で大文字にできる。
- プロトコルの比較など「ASCII だけでよい」場面では、ロケールに頼らない自前の変換が確実。
- 0 を「いちばん小さい文字」として扱うと、文字列の終わりの処理を比較にまとめられる。
