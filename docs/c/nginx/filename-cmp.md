## ひとことで

`ngx_filename_cmp` は、`/images/a.png` のような **パス名** を、先頭から最大 `n` バイトまで比べる関数です。基本はふつうの文字列比較ですが、**`/` をいちばん小さい文字として** 扱います。
また、Windows や macOS のように大文字小文字を区別しないファイルシステムでは、比較の前に小文字にそろえます。nginx の `location` の木を作ったり探したりする処理で使われています。

## コード

::: code-group

```c:line-numbers=926 [日本語訳]
ngx_int_t
ngx_filename_cmp(u_char *s1, u_char *s2, size_t n)
{
    ngx_uint_t  c1, c2;

    while (n) {
        c1 = (ngx_uint_t) *s1++;
        c2 = (ngx_uint_t) *s2++;

#if (NGX_HAVE_CASELESS_FILESYSTEM)
        c1 = tolower(c1);
        c2 = tolower(c2);
#endif

        if (c1 == c2) {

            if (c1) {
                n--;
                continue;
            }

            return 0;
        }

        /* '/' をいちばん小さい文字にしたい */

        if (c1 == 0 || c2 == 0) {
            return c1 - c2;
        }

        c1 = (c1 == '/') ? 0 : c1;
        c2 = (c2 == '/') ? 0 : c2;

        return c1 - c2;
    }

    return 0;
}
```

## 前提知識

- **C の文字列**: 文字のバイトが並び、最後に 0 が来ます。`*s1++` で今の文字を読んで次へ進みます。
- **ASCII の番号**: `'-'` は 45、`'.'` は 46、`'/'` は 47、`'0'` は 48 です。ふつうの比較はこの番号で大小を決めます。
- **`#if (...)` 〜 `#endif`**: コンパイルの前に、条件に合わない部分を取り除く仕組み（プリプロセッサ）です。`NGX_HAVE_CASELESS_FILESYSTEM` が真の環境でだけ、`tolower` を呼ぶ 2 行が有効になります。
- **`tolower`**: 文字を小文字に変える標準関数です。
- **`while (n)`**: `n` が 0 でないあいだ繰り返します。
- **比較関数**: 負・0・正を返して、2 つの値の前後を決める関数です。並べ替えや二分探索に使います。

## 何をしているか

### 1. n バイトまで 1 文字ずつ比べる

```c:line-numbers=931
    while (n) {
        c1 = (ngx_uint_t) *s1++;
        c2 = (ngx_uint_t) *s2++;

#if (NGX_HAVE_CASELESS_FILESYSTEM)
        c1 = tolower(c1);
        c2 = tolower(c2);
#endif

        if (c1 == c2) {

            if (c1) {
                n--;
                continue;
            }

            return 0;
        }
```

`n` が残っているあいだ、1 文字ずつ取り出して比べます。大文字小文字を区別しない環境では、ここで小文字にそろえます（`#if (NGX_HAVE_CASELESS_FILESYSTEM)` の中）。
同じ文字なら、0（文字列の終わり）でなければ `n` を減らして次へ進みます。両方同時に 0 になったら一致なので 0 を返します。

### 2. 片方が終わっていれば、そのまま差を返す

```c:line-numbers=952
        if (c1 == 0 || c2 == 0) {
            return c1 - c2;
        }
```

違う文字が出て、そのどちらかが 0 なら、短いほうを小さいとしてすぐ返します。次の `/` の置き換えより先にこの確認をしているのがポイントです（後述）。

### 3. `/` を 0 に置き換えて差を返す

```c:line-numbers=956
        c1 = (c1 == '/') ? 0 : c1;
        c2 = (c2 == '/') ? 0 : c2;

        return c1 - c2;
```

コメントのとおり `/` を最小にしたいので、`/` を 0 に置き換えてから差を返します。

### 4. n バイトが全部同じなら 0

```c:line-numbers=962
    return 0;
```

### 具体例

`/a/x` と `/a-x` を比べます。3 文字目で `'/'` と `'-'` が違います。ふつうなら `'-'`（45）＜ `'/'`（47）なので `/a-x` が先です。この関数では `'/'` が 0 になるので `/a/x` が先になります。

その結果、`/a`、`/a/x`、`/a/y`、`/a-x`、`/a.b` のように、**`/a` ディレクトリの中身が `/a` のすぐ後ろにまとまって並び** ます。

## ここがすごい

- **木の形にそのまま使える並び**: nginx は前方一致の `location` を、名前の接頭辞でまとめた木にします。`/a/` の下にあるパスが並びの中で連続していると、「`/a` の子孫」を 1 つのかたまりとして切り出しやすくなります。区切り文字を最小にするだけで、文字列の並び順がディレクトリの木の形と一致するのです。
- **終端の確認を先にする理由**: `/` を 0 に置き換えると、本物の終端（0）と区別がつかなくなります。たとえば `/a` と `/a/` を比べると、3 文字目は 0 と `/` です。先に置き換えると両方 0 になって差が 0、つまり「等しい」と誤って判定されてしまいます。`if (c1 == 0 || c2 == 0)` で先に終端を処理しているので、短い `/a` が小さい、と正しく判定できます。
- **移植性をコンパイル時に切り替える**: ファイル名の大文字小文字を区別するかどうかは OS によって違います。`#if` で切り替えることで、区別する OS では余計な変換をまったく行わず、区別しない OS では正しく同じファイルを同じと判定できます。実行時の分岐が増えません。
- **長さの上限 `n`**: 0 終端に加えて長さの上限でも止まるので、パスの先頭部分だけを比べる（接頭辞が一致するか調べる）用途にも使えます。

## まとめ

- 区切り文字を最小の文字として比べると、文字列の並び順が木構造（ディレクトリ）の形と一致する。
- 文字を置き換えて比較するときは、置き換えた値が終端と衝突しないかに注意し、終端の判定を先に済ませる。
- OS ごとの違いは `#if` でコンパイル時に切り替えると、実行時のコストがかからない。
