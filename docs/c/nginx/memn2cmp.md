## ひとことで

`ngx_memn2cmp` は、長さ `n1` のバイト列 `s1` と、長さ `n2` のバイト列 `s2` を **辞書順** に比べる関数です。`s1` が小さければ負、大きければ正、同じなら 0 を返します。
たとえば `"abc"`（長さ 3）と `"abcd"`（長さ 4）なら、先頭 3 バイトは同じなので、短い `"abc"` のほうが小さいとして負の値を返します。
nginx では、赤黒木（後述）の中でキーを並べるときなどに、この比較がよく使われています。

## コード

```c:line-numbers=870
ngx_int_t
ngx_memn2cmp(u_char *s1, u_char *s2, size_t n1, size_t n2)
{
    size_t     n;
    ngx_int_t  m, z;

    if (n1 <= n2) {
        n = n1;
        z = -1;

    } else {
        n = n2;
        z = 1;
    }

    m = ngx_memcmp(s1, s2, n);

    if (m || n1 == n2) {
        return m;
    }

    return z;
}
```

## 前提知識

- **バイト列と長さ**: C の文字列は 0 で終わりますが、nginx では「先頭のポインタ」と「長さ」の組でデータを扱うことが多いです。こうすると途中に 0 を含むデータや、別のバッファの一部も扱えます。
- **`memcmp`（`ngx_memcmp`）**: 2 つのメモリ領域を先頭から `n` バイト比べる標準関数です。等しければ 0、最初に違うバイトで `s1` が小さければ負、大きければ正を返します。0 の終端は気にしません。
- **`ngx_int_t`**: 符号つき整数の型です。比較結果のように負の値もありうるものに使います。
- **`||`（論理 OR）**: どちらかが真なら真です。C では 0 以外の数は真として扱われるので、`if (m || ...)` は「`m` が 0 でないか、または…」という意味です。
- **辞書順**: 先頭から 1 文字ずつ比べ、最初に違う文字で順番を決めます。片方がもう片方の先頭部分そのものなら、短いほうが前です。
- **赤黒木**: キーの大小で並べた木構造の一種で、探す・入れる・消すが速いデータ構造です。並べるには「大小を比べる関数」が必要です。

## 何をしているか

### 1. 短いほうの長さと、引き分けのときの答えを決める

```c:line-numbers=876
    if (n1 <= n2) {
        n = n1;
        z = -1;

    } else {
        n = n2;
        z = 1;
    }
```

`n1 <= n2` なら、比べる長さ `n` を `n1` にし、`z = -1` とします。これは「先頭が全部同じだったら、`s1` が短いぶん小さい」という意味の答えです。
逆に `n1 > n2` なら、`n = n2`、`z = 1` です。

### 2. 共通部分を memcmp で比べる

```c:line-numbers=885
    m = ngx_memcmp(s1, s2, n);
```

短いほうの長さぶんだけ比べます。`"abx"` と `"abcd"` なら、3 バイト比べて 3 バイト目の `'x'` と `'c'` で決着がつき、`m` は正になります。

### 3. 決着がついていればそのまま返す

```c:line-numbers=887
    if (m || n1 == n2) {
        return m;
    }
```

`m` が 0 でなければ、共通部分の中で違いが見つかったので、その結果を返します。また、`n1 == n2` なら長さも同じなので、`m`（この場合は 0 か、違いを表す値）がそのまま答えです。

### 4. 共通部分が同じで長さが違う

```c:line-numbers=891
    return z;
```

ここまで来たのは「短いほうの全バイトが、長いほうの先頭と一致した」ときです。最初に決めた `z` を返します。`"abc"` と `"abcd"` なら `-1` です。

## ここがすごい

- **場合分けを先に済ませる**: 素直に書くと、`memcmp` の後で「どちらが短いか」をもう一度調べることになります。この関数は、比べる長さを決めるのと同時に、引き分けのときの答え `z` も決めてしまいます。1 回の比較で 2 つの情報を用意しているので、後半が `return z;` だけで済みます。
- **memcmp に仕事を任せる**: バイトを 1 つずつ比べるループを自分で書かず、標準の `memcmp` を使っています。`memcmp` は多くの環境で、複数バイトをまとめて比べる速い実装になっています。自前のループより速くなることが期待でき、コードも短くなります。
- **木やソートで使いやすい約束**: 「負・0・正」で返す形は、C の `qsort` などと同じ比較関数の約束です。赤黒木の挿入や探索で `if (rc < 0) 左へ` のように使えます。長さが違うキー（セッション ID や任意の文字列キーなど）を、0 終端に頼らずに安全に並べられます。
- **全順序になっている**: どんな 2 つのバイト列でも順番がきちんと決まり、矛盾がありません。木構造のキー比較にはこれが欠かせません。

## まとめ

- 「ポインタ＋長さ」で持つデータの比較は、短いほうの長さまで `memcmp` し、同じなら長さで決める。
- 後で必要になる答えを、最初の場合分けのときに一緒に決めておくとコードが短くなる。
- 比較関数は「負・0・正」で返すと、ソートや木構造にそのまま使える。
