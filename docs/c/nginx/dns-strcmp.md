## ひとことで

`ngx_dns_strcmp` は、ドメイン名（`example.com` のような名前）を比べるための関数です。基本は大文字小文字を無視した文字列比較ですが、**ドット `.` だけは、どの文字よりも小さいものとして** 扱います。
nginx では `map` や `valid_referers` の設定で、`*.example.com` のようなワイルドカード名を並べ替えるときに使われています。

## コード

```c:line-numbers=895 [日本語訳]
ngx_int_t
ngx_dns_strcmp(u_char *s1, u_char *s2)
{
    ngx_uint_t  c1, c2;

    for ( ;; ) {
        c1 = (ngx_uint_t) *s1++;
        c2 = (ngx_uint_t) *s2++;

        c1 = (c1 >= 'A' && c1 <= 'Z') ? (c1 | 0x20) : c1;
        c2 = (c2 >= 'A' && c2 <= 'Z') ? (c2 | 0x20) : c2;

        if (c1 == c2) {

            if (c1) {
                continue;
            }

            return 0;
        }

        /* ASCII では '.' > '-' だが、'.' をいちばん小さい文字にしたい */

        c1 = (c1 == '.') ? ' ' : c1;
        c2 = (c2 == '.') ? ' ' : c2;

        return c1 - c2;
    }
}
```

## 前提知識

- **C の文字列**: 文字のバイトが並び、最後に値 0 のバイトが来ます。`*s1++` は「今の 1 文字を読んで次へ進む」です。
- **ASCII の番号**: 文字には番号があり、`' '`（空白）は 32、`'-'` は 45、`'.'` は 46、`'0'` は 48、`'a'` は 97 です。比較はこの番号の大小で決まります。
- **`| 0x20`**: ASCII の大文字は、対応する小文字よりちょうど 0x20 小さいので、このビットを立てると小文字になります。
- **三項演算子 `a ? b : c`**: `a` が真なら `b`、偽なら `c` です。
- **比較関数**: 並べ替え（ソート）では「2 つを比べて、負・0・正を返す関数」を渡します。負なら 1 つ目が前です。
- **ラベル**: ドメイン名をドットで区切った 1 つ 1 つの部分です。`www.example.com` なら `www`、`example`、`com` の 3 つです。

## 何をしているか

### 1. 大小無視で 1 文字ずつ比べる

```c:line-numbers=900
    for ( ;; ) {
        c1 = (ngx_uint_t) *s1++;
        c2 = (ngx_uint_t) *s2++;

        c1 = (c1 >= 'A' && c1 <= 'Z') ? (c1 | 0x20) : c1;
        c2 = (c2 >= 'A' && c2 <= 'Z') ? (c2 | 0x20) : c2;

        if (c1 == c2) {

            if (c1) {
                continue;
            }

            return 0;
        }
```

`ngx_strcasecmp` と同じく、`'A'`〜`'Z'` だけを小文字にしてから比べます。同じで、しかも 0（終わり）なら一致として 0 を返し、0 でなければ次の文字へ進みます。

### 2. 違う文字が出たら、ドットを空白に置き換える

```c:line-numbers=916
        /* in ASCII '.' > '-', but we need '.' to be the lowest character */

        c1 = (c1 == '.') ? ' ' : c1;
        c2 = (c2 == '.') ? ' ' : c2;
```

違う文字が見つかったところで、`'.'` を `' '`（32）に置き換えます。コメントのとおり、ASCII では `'.'`（46）は `'-'`（45）より大きいのですが、ここではドットを最小にしたいので、`'-'` や英数字より小さい空白に変えています。

### 3. 差を返す

```c:line-numbers=921
        return c1 - c2;
```

置き換えたあとの値の差を返します。

### 具体例で比べる

ワイルドカード名は、nginx の内部では `com.example` のように **ラベルを逆順にした形** で並べられます。次の 3 つを考えます。

- `com.a`
- `com.a-b`
- `com.a.x`

ふつうの比較では `'-'`（45）＜ `'.'`（46）なので、並びは `com.a`、`com.a-b`、`com.a.x` です。`com.a` とその下の `com.a.x` の間に、無関係な `com.a-b` が割り込んでいます。

`ngx_dns_strcmp` では `'.'` が最小なので、`com.a.x` が `com.a-b` より前に来て、並びは `com.a`、`com.a.x`、`com.a-b` になります。**`com.a` に続くものが隣り合う** ようになりました。

## ここがすごい

- **後の処理の前提を、比較関数で作っている**: nginx の `ngx_hash_wildcard_init` は、並べ替え済みの名前を先頭から読み、最初のラベルが同じものを 1 つのグループにまとめて、ラベルごとの入れ子のハッシュ表を作ります。同じラベルで始まる名前が **連続して並んでいる** ことが、この処理の前提です。比較関数のたった 2 行の工夫が、その前提を保証しています。
- **置き換えは「違ったときだけ」**: ドットの置き換えは、文字が違うと分かった後でだけ行います。等しいかどうかの判定には影響しないので、ドット同士は今まで通り等しく、余計な処理もほとんど増えません。
- **0 との関係も崩さない**: 空白（32）は終端の 0 よりは大きいので、`com.a` は `com.a.x` より前に来ます。「短い名前が先、その子が続く」という順序がちょうど保たれます。
- **ドメイン名の性質に合わせた順序**: ドメイン名は大文字小文字を区別しない、ドットが区切り、という性質を持ちます。汎用の比較を流用せず、データの意味に合った順序を作るのは、ソートを使う処理を正しく速くするうえで大切な考え方です。

## まとめ

- 並べ替えの順序は、比較関数で自由に設計できる。区切り文字を最小にすると、同じ接頭辞を持つものが連続して並ぶ。
- 後の処理が「連続している」ことを前提にできると、グループ分けが 1 回の走査で済む。
- 文字の置き換えは「違ったときだけ」行えば、一致判定を壊さずに順序だけ変えられる。
