## ひとことで

`ngx_hex_dump` は、バイト列を **16 進数の文字列** に変換する関数です。たとえば 2 バイト `0xAB, 0x05` を渡すと、`"ab05"` の 4 文字を書き込みます。
ハッシュ値やランダムな ID を人が読める文字列にするときなどに使われます。戻り値は書き終えた位置（次に書く場所）です。

## コード

```c:line-numbers=1172
u_char *
ngx_hex_dump(u_char *dst, u_char *src, size_t len)
{
    static u_char  hex[] = "0123456789abcdef";

    while (len--) {
        *dst++ = hex[*src >> 4];
        *dst++ = hex[*src++ & 0xf];
    }

    return dst;
}
```

## 前提知識

- **16 進数**: 0〜9 と a〜f の 16 種類の記号で数を表す方法です。1 バイト（0〜255）はちょうど 2 桁で表せます（`255` は `ff`）。
- **ビット**: 1 バイトは 8 ビットです。上位 4 ビットと下位 4 ビットに分けると、それぞれが 16 進数の 1 桁になります。`0xAB` なら上位が `A`、下位が `B` です。
- **`>>`（右シフト）**: ビットを右にずらします。`0xAB >> 4` は `0x0A` です。
- **`&`（ビット AND）**: 両方が 1 の桁だけを 1 にします。`0xAB & 0xf` は `0x0B` で、下位 4 ビットだけが残ります。
- **ポインタと `*dst++ = x`**: `dst` が指す場所に `x` を書き、`dst` を次へ進めます。`*src++` は「今のバイトを読んで次へ進む」です。
- **`static` の配列**: 関数の中で `static` を付けた変数は、プログラムの実行中ずっと 1 つだけ存在し、呼び出しのたびに作り直されません。
- **配列の添字**: `hex[10]` は配列 `hex` の 11 番目（0 から数える）の要素で、ここでは文字 `'a'` です。

## 何をしているか

### 1. 16 文字の表を用意する

```c:line-numbers=1175
    static u_char  hex[] = "0123456789abcdef";
```

`hex` は `"0123456789abcdef"` という文字列です。`hex[0]` が `'0'`、`hex[15]` が `'f'` なので、0〜15 の数をそのまま添字にすれば、対応する 16 進数の文字が取り出せます。

### 2. 1 バイトごとに 2 文字書く

```c:line-numbers=1177
    while (len--) {
        *dst++ = hex[*src >> 4];
        *dst++ = hex[*src++ & 0xf];
    }
```

`len` バイトぶん繰り返します。1 バイト `0xAB`（2 進数で `1010 1011`）なら、

- `*dst++ = hex[*src >> 4];`: `0xAB >> 4` は `0x0A`（10）。`hex[10]` は `'a'`。
- `*dst++ = hex[*src++ & 0xf];`: `0xAB & 0xf` は `0x0B`（11）。`hex[11]` は `'b'`。

`*dst++ = hex[*src >> 4];` では `*src` を読むだけで進めず、`*dst++ = hex[*src++ & 0xf];` の `*src++` で初めて次のバイトへ進めているのがポイントです。同じバイトを 2 回使うためです。

### 3. 書き終えた位置を返す

```c:line-numbers=1182
    return dst;
```

`dst` は書いた文字の次を指しています。これを返すので、呼び出し側は続けて別の文字を書けます。

## ここがすごい

- **`printf` を使わない**: `sprintf(dst, "%02x", byte)` と書くこともできますが、書式文字列を解釈する処理が毎回動くので重くなります。この関数は、シフト、AND、表引きの 3 つだけで 1 文字を作ります。分岐もありません。
- **表引きで分岐を消す**: 0〜9 は `'0' + n`、10〜15 は `'a' + n - 10` と計算することもできますが、その場合は `if` が必要です。16 文字の表を引けば、場合分けがまったくいりません。
- **終端の 0 を書かない**: この関数は文字列の終わりの 0 を書きません。nginx では文字列を「ポインタ＋長さ」で扱うことが多いので、0 は不要なことが多いのです。必要なら呼び出し側が、戻り値の位置に 0 を書けばよい、という役割分担です。書き込む量が `2 * len` バイトと決まるので、バッファの大きさも計算しやすくなります。
- **戻り値で連結しやすい**: 書き終えた位置を返す設計は nginx 全体で共通です。`p = ngx_hex_dump(p, ...);` のように、前から順にバッファを埋めていくコードが自然に書けます。

## まとめ

- 1 バイトは「上位 4 ビット」と「下位 4 ビット」に分けると、16 進数 2 桁になる。
- `x >> 4` と `x & 0xf` は、上位・下位の 4 ビットを取り出す定番の式。
- 小さな変換表を引くと、条件分岐なしで値から文字を作れる。
- 書き終えた位置を返す関数は、バッファを前から埋めていく処理と相性がよい。
