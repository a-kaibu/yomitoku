## ひとことで

`pg_nextpower2_32` は、`num` 以上で最小の **2 のべき乗**（1, 2, 4, 8, 16, …）を返します。
`num = 100` なら `128`、`num = 64` ならそのまま `64` です。
ハッシュ表やバッファの大きさを 2 のべき乗にそろえたいときに使います。2 のべき乗だと「割り算の余り」をビット演算で計算できるので、大きさをそろえておく場面が多いのです。

## コード

::: code-group

```c:line-numbers=181 [日本語訳]
/*
 * pg_nextpower2_32
 *	'num' より大きい次の 2 のべき乗を返す。'num' がすでに
 *	2 のべき乗なら 'num' を返す。
 *
 * 'num' は 0 や PG_UINT32_MAX / 2 + 1 より大きい値であってはならない。
 */
static inline uint32
pg_nextpower2_32(uint32 num)
{
	Assert(num > 0 && num <= PG_UINT32_MAX / 2 + 1);

	/*
	 * 2 のべき乗の数は 1 ビットだけが立っている。そのような数から 1 を引くと
	 * それより下のビットがすべて立ち、num と num-1 の間に
	 * 共通して立っているビットがなくなる。
	 */
	if ((num & (num - 1)) == 0)
		return num;				/* すでに 2 のべき乗 */

	return ((uint32) 1) << (pg_leftmost_one_pos32(num) + 1);
}
```

```c:line-numbers=181 [原文]
/*
 * pg_nextpower2_32
 *		Returns the next higher power of 2 above 'num', or 'num' if it's
 *		already a power of 2.
 *
 * 'num' mustn't be 0 or be above PG_UINT32_MAX / 2 + 1.
 */
static inline uint32
pg_nextpower2_32(uint32 num)
{
	Assert(num > 0 && num <= PG_UINT32_MAX / 2 + 1);

	/*
	 * A power 2 number has only 1 bit set.  Subtracting 1 from such a number
	 * will turn on all previous bits resulting in no common bits being set
	 * between num and num-1.
	 */
	if ((num & (num - 1)) == 0)
		return num;				/* already power 2 */

	return ((uint32) 1) << (pg_leftmost_one_pos32(num) + 1);
}
```

## 前提知識

- **2 のべき乗と 2 進数**: 2 のべき乗は 2 進数で書くと「1 が 1 個だけ」の数です。`64` は `1000000`、`128` は `10000000` です。
- **`&`（ビットごとの AND）**: 2 つの数の同じ位置のビットが両方 1 のときだけ 1 になります。`12 & 10` は `1100 & 1010 = 1000`（8）です。
- **`<<`（左シフト）**: ビットを左へずらします。`1 << 7` は `10000000`（128）です。左へ 1 つずらすと 2 倍になります。
- **`(uint32) 1`**: 定数 `1` を「符号なし 32 ビット整数」として扱うための型変換（キャスト）です。C では型によってシフトの結果が変わることがあるので、明示しています。
- **`Assert`**: 開発用ビルドで条件を確かめるマクロです。`PG_UINT32_MAX` は 32 ビット符号なし整数の最大値（約 42 億）です。
- **`pg_leftmost_one_pos32`**: 同じヘッダにある関数で、最上位の 1 のビットが何番目か（一番下を 0 番として）を返します。`100`（`1100100`）なら 6 です。

## 何をしているか

### 1. 入力の範囲を確かめる


`num` は 1 以上で、`PG_UINT32_MAX / 2 + 1`（2³¹）以下でなければなりません。これより大きいと、答えの 2³² が 32 ビットに入らないからです。0 は「最上位の 1」が存在しないので禁止です。

### 2. すでに 2 のべき乗なら、そのまま返す

```c:line-numbers=197
	 */
	if ((num & (num - 1)) == 0)
```

コードのコメントにある通り、2 のべき乗から 1 を引くと、その 1 より下のビットがすべて 1 になります。

- `num = 64` → `1000000`、`num - 1 = 63` → `0111111`。AND を取ると `0`。
- `num = 100` → `1100100`、`num - 1 = 99` → `1100011`。AND を取ると `1100000`（96）で 0 ではない。

つまり `(num & (num - 1)) == 0` は「1 のビットが 1 個しかない」＝「2 のべき乗」の判定です。`num = 1` も `1 & 0 = 0` なので、2⁰ として正しく扱われます。

### 3. 最上位の 1 の一つ上のビットだけを立てる

```c:line-numbers=200

```

2 のべき乗でなければ、答えは「最上位の 1 よりひとつ上の位置のビットだけが 1 の数」です。
`num = 100` なら最上位の 1 は 6 番目なので、`1 << (6 + 1)` で `128` になります。
`num = 3`（`11`）なら最上位は 1 番目で、`1 << 2 = 4` です。

## ここがすごい

- **ループを使わない**: 素直に書くと「`p = 1` から始めて `p < num` の間 `p *= 2` を繰り返す」ループになり、最大 31 回回ります。この関数は、判定 1 回と最上位ビットの位置（CPU 命令 1 つで求まることが多い）とシフト 1 回だけで終わります。
- **`num & (num - 1)` は覚えておく価値のある技**: この式は「一番下の 1 のビットを消す」操作でもあります。結果が 0 なら、もともと 1 が 1 個だったとわかります。ビットの数を数えるループや、2 のべき乗かどうかの判定で、あちこちのプログラムに登場する定番のイディオムです。
- **境界を明示している**: 2³¹ を超える値を渡すと答えが 32 ビットからあふれます。黙って 0 を返すような作りにせず、`Assert` で「呼ぶ側の責任」として線を引いています。64 ビット版の `pg_nextpower2_64` も同じ形で用意されていて、型ごとに同じ考え方で書かれているのも読みやすさにつながっています。
- **コメントが式の意味を説明している**: ビット演算は一見して意味がわかりにくいものですが、コードのコメントが「なぜこの式で判定できるか」を一言で説明しています。

## まとめ

- 2 のべき乗は「1 のビットが 1 個だけ」の数で、`(x & (x - 1)) == 0` で判定できる。
- 次の 2 のべき乗は、最上位の 1 の一つ上のビットを立てれば求まる。
- ループを使わずビット演算と専用命令で済ませると、手数が一定で速い。
- 答えがあふれる入力は、前提条件として `Assert` で書いておく。
