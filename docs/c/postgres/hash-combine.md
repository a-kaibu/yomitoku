## ひとことで

`hash_combine` は、2 つの 32 ビットのハッシュ値 `a` と `b` を受け取り、**両方の情報を含んだ新しいハッシュ値** を返します。
たとえば「名字」と「名前」の 2 列をキーにした表を作るとき、それぞれのハッシュ値を `hash_combine` でつなげば、2 列ぶんのハッシュ値が得られます。
関数の前のコメントにある通り、C++ のライブラリ Boost の `hash_combine()` と同じ考え方の式です。

## コード

::: code-group

```c:line-numbers=61 [日本語訳]
/*
 * 2 つの 32 ビットのハッシュ値を合成して、そこそこよくビットが混ざった
 * 別のハッシュ値を作る。
 *
 * boost の hash_combine() と似たもの。
 */
static inline uint32
hash_combine(uint32 a, uint32 b)
{
	a ^= b + 0x9e3779b9 + (a << 6) + (a >> 2);
	return a;
}
```

## 前提知識

- **ハッシュ値**: データから計算される「指紋」のような数です。同じデータからは必ず同じ値が出て、違うデータからはなるべく違う値が出るように作ります。ハッシュ表（値をすばやく探すための表）で、どの棚にしまうかを決めるのに使います。
- **`uint32`**: 符号なし 32 ビット整数です。計算が 2³² を超えると上の桁は捨てられます（あふれても壊れずに一周するだけ）。
- **`^=`（排他的論理和の代入）**: `a ^= x` は `a = a ^ x` の略です。`^` はビットごとに「違えば 1、同じなら 0」を計算します。
- **`<<` と `>>`**: ビットを左・右へずらすシフト演算です。`a << 6` は `a` を 64 倍、`a >> 2` は 4 で割って切り捨てるのと同じです（あふれた分は捨てられます）。
- **`static inline`**: ヘッダに置く小さな関数の定番の書き方で、呼び出し元に中身を埋め込んでよいという指示です。

## 何をしているか

### 1. b に定数と a の変形を足す

```c:line-numbers=70
	a ^= b + 0x9e3779b9 + (a << 6) + (a >> 2);
```

右辺は `b + 0x9e3779b9 + (a << 6) + (a >> 2)` です。

- `b`: 新しく混ぜたいハッシュ値そのもの。
- `0x9e3779b9`: 2³² を黄金比で割った値にあたる、よく使われる定数です。ビットが「ほどよくばらばら」に並んでいる数で、`a` や `b` が 0 のように偏った値でも結果を散らしてくれます。
- `(a << 6) + (a >> 2)`: `a` を左右にずらしたもの。`a` の上位ビットと下位ビットの情報を、別の位置へ広げる役目をします。

### 2. それを a に XOR する

```c:line-numbers=70
	a ^= b + 0x9e3779b9 + (a << 6) + (a >> 2);
```

最後に `a ^= ...` で、右辺を `a` に排他的論理和で重ねます。こうして `a` と `b` の両方に依存した値ができ、それを返します。

### 3. 具体例

`a = 1`、`b = 2` なら、右辺は `2 + 0x9e3779b9 + 64 + 0 = 0x9e3779fb` で、`1 ^ 0x9e3779fb = 0x9e3779fa` です。
逆に `a = 2`、`b = 1` なら、右辺は `1 + 0x9e3779b9 + 128 + 0 = 0x9e377a3a` で、`2 ^ 0x9e377a3a = 0x9e377a38` になり、**順番を入れ替えると違う値** になります。

## ここがすごい

- **順序を区別できる**: 素直に `a ^ b` で混ぜると、`(1, 2)` と `(2, 1)` が同じ値になり、`(x, x)` は常に 0 になってしまいます。ハッシュ表では衝突（違うキーが同じ棚に入ること）が増え、遅くなります。この式は `a` だけを左右にずらしてから混ぜるので、引数の役割が非対称になり、順序の違いが値に表れます。
- **安くて十分**: シフト 2 回、足し算 3 回、XOR 1 回だけです。暗号のような強さは求めず、「ハッシュ表で偏らない程度に混ざる」ことを最小の手数で実現しています。
- **定数の役割**: 0 を足しても値は変わりませんが、定数を足すと「0 のハッシュ値」がそのまま残る事態を防げます。また、定数のビットがばらばらなので、繰り上がりを通じて上位ビットまで変化が伝わりやすくなります。
- **よく知られた形をそのまま使う**: 自作の混ぜ方を考えるより、広く使われていて性質が知られた式を採用し、出典をコメントに書いています。読む人も「Boost のあれだ」とすぐわかります。64 ビット版の `hash_combine64` は、定数とシフト量を 64 ビット向けに変えた同じ形になっています。

## まとめ

- 複数のハッシュ値は、XOR だけで混ぜると順序が消えて衝突が増える。
- 片方をシフトしてから足し込むと、引数の役割が非対称になり順序を区別できる。
- 黄金比由来の定数 `0x9e3779b9` は、ビットを散らすためによく使われる。
- 用途に見合った軽さの式を、出典つきで使うのが実用的。
