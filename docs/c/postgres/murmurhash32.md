## ひとことで

`murmurhash32` は、32 ビットの整数 `data` を、**見た目がばらばらな 32 ビットの値** に変換します。
たとえば `1` と `2` のようにほとんど同じ入力でも、出力はまったく似ていない値になります。
有名なハッシュ関数 MurmurHash3 の最後の仕上げ（ファイナライザ）と同じ手順で、整数をキーにしたハッシュ表で使うための、短くて速い関数です。

## コード

::: code-group

```c:line-numbers=87 [日本語訳]
/*
 * 32 ビット整数をハッシュする、性能のための単純なインラインの
 * murmur hash 実装。
 */
static inline uint32
murmurhash32(uint32 data)
{
	uint32		h = data;

	h ^= h >> 16;
	h *= 0x85ebca6b;
	h ^= h >> 13;
	h *= 0xc2b2ae35;
	h ^= h >> 16;
	return h;
}
```

## 前提知識

- **ハッシュ関数**: データから「指紋」となる数を計算する関数です。ハッシュ表では、この値で値をしまう場所を決めます。似た入力から似た出力が出ると、同じ場所に集中してしまい遅くなります。
- **`uint32`**: 符号なし 32 ビット整数です。掛け算で 2³² を超えた部分は捨てられます。符号なし整数でのこの「一周」は C の規格で決まった動作です。
- **`h ^= h >> 16`**: `h` を右に 16 ビットずらしたものを、`h` 自身に XOR（ビットごとの排他的論理和）で重ねます。上半分のビットの情報が下半分に流れ込みます。
- **`h *= 定数`**: `h = h * 定数` の略です。掛け算は、下位ビットの変化を上位ビットへ伝える働きがあります（筆算で、下の桁の数字が上の桁に影響するのと同じ）。
- **雪崩（アバランシェ）効果**: 入力の 1 ビットを変えると、出力のおよそ半分のビットが変わる性質です。良いハッシュ関数の目安です。

## 何をしているか

### 1. 上半分を下半分へ

```c:line-numbers=96
	h ^= h >> 16;
```

`h ^= h >> 16` で、上位 16 ビットの情報を下位 16 ビットに混ぜます。
入力が `0x00010000` のように上位にしか違いがない値でも、下位ビットが変化するようになります。

### 2. 掛け算で下から上へ広げる

```c:line-numbers=97
	h *= 0x85ebca6b;
```

奇数の定数 `0x85ebca6b` を掛けます。掛け算は、ある桁の変化をそれより上の桁すべてに伝えます。ただし下へは伝えません。

### 3. 再び右シフトで上から下へ

```c:line-numbers=98
	h ^= h >> 13;
	h *= 0xc2b2ae35;
	h ^= h >> 16;
```

`>> 13` で上位の変化を下位に戻し、別の定数 `0xc2b2ae35` を掛けて再び上へ広げ、最後に `>> 16` でもう一度下へ混ぜます。
「右シフト XOR（上 → 下）」と「掛け算（下 → 上）」を交互に行うことで、どのビットの変化も最終的に全体へ行き渡ります。

### 4. 具体的に

`data = 0` なら、どの段でも 0 のままなので出力も `0` です。`data = 1` なら、1 段目では `1` のまま、2 段目の掛け算で `0x85ebca6b` になり、以降の段で上位・下位がかき混ぜられて、`1` の面影のない値になります。

## ここがすごい

- **たった 5 行で雪崩効果**: 汎用の `hash_bytes` はバイト列を受け取る長い関数ですが、整数 1 個なら、この 5 行で十分に混ざります。メモリへの読み書きもループもなく、すべてレジスタの中で終わります。
- **逆変換できる**: 右シフト XOR も、奇数の掛け算も、元に戻せる操作（全単射）です。そのため、違う入力が同じ出力になることが **一切ありません**。32 ビットの入力に対して、衝突は「ハッシュ表の棚の数で割ったとき」にしか起きません。
- **定数の選び方**: 掛ける定数は奇数でなければ逆変換できません（偶数を掛けると最下位ビットの情報が消えます）。使われている 2 つの定数は MurmurHash3 で選ばれたもので、自分で決めずに実績のある値を使っているのが堅実です。
- **0 は 0 になる**: 入力 0 の出力が 0 になる点は弱点にも見えますが、全単射なので 0 以外が 0 になることはなく、ハッシュ表の用途では問題になりません。暗号用途には使わない、という割り切りです。64 ビット版の `murmurhash64` も同じ構造で、シフト量と定数だけが違います。

## まとめ

- 右シフト XOR は上位の変化を下位へ、奇数の掛け算は下位の変化を上位へ伝える。
- 2 つを交互に重ねると、少ない手数で全ビットがよく混ざる。
- 元に戻せる操作だけで作ったハッシュは、同じ幅の入力どうしで衝突しない。
- 定数は実績のある値をそのまま使う。
