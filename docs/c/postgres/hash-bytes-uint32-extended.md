## ひとことで

`hash_bytes_uint32_extended` は、32 ビットの整数 `k` と 64 ビットの **シード**（ハッシュの結果を変えるための追加の種）から、64 ビットのハッシュ値を作ります。
シードを変えると、同じ `k` でもまったく違う値が出ます。一方で `seed = 0` のときは、32 ビット版 `hash_bytes_uint32(k)` の結果が、そのまま戻り値の下位 32 ビットに入るように作られています。
PostgreSQL のハッシュ分割（テーブルをハッシュ値で分ける機能）などで 64 ビットのハッシュ値が必要なときに使われます。

```c:line-numbers=625 [日本語訳]
/*
 * hash_bytes_uint32_extended() -- 32 ビット値をシード付きで 64 ビット値にハッシュする
 *
 * hash_bytes_uint32 と同じく、便利のための関数。

uint64
```

```c:line-numbers=625 [原文]
/*
 * hash_bytes_uint32_extended() -- hash 32-bit value to 64-bit value, with seed
 *
 * Like hash_bytes_uint32, this is a convenience function.
 */
uint64
hash_bytes_uint32_extended(uint32 k, uint64 seed)
{
	uint32		a,
				b,
				c;

	a = b = c = 0x9e3779b9 + (uint32) sizeof(uint32) + 3923095;

	if (seed != 0)
	{
		a += (uint32) (seed >> 32);
		b += (uint32) seed;
		mix(a, b, c);
	}

	a += k;

	final(a, b, c);

	/* report the result */
	return ((uint64) b << 32) | c;
}
```

仕上げに使っているマクロ `final` は、同じファイルで次のように定義されています。`rot` は 32 ビットの回転（はみ出したビットを反対側に戻すシフト）です。

```c:line-numbers=116
#define final(a,b,c) \
{ \
  c ^= b; c -= rot(b,14); \
  a ^= c; a -= rot(c,11); \
  b ^= a; b -= rot(a,25); \
  c ^= b; c -= rot(b,16); \
  a ^= c; a -= rot(c, 4); \
  b ^= a; b -= rot(a,14); \
  c ^= b; c -= rot(b,24); \
}
```

## 前提知識

- **ハッシュ値とシード**: ハッシュ値はデータの「指紋」となる数です。シードは計算の最初に混ぜる値で、シードを変えると全体の割り振りが変わります。同じデータに複数の独立したハッシュ値が欲しいときなどに使います。
- **`uint32` と `uint64`**: 符号なしの 32 ビット整数と 64 ビット整数です。
- **`a = b = c = ...`**: 右から順に代入されるので、3 つの変数すべてに同じ値が入ります。
- **`(uint32) (seed >> 32)`**: 64 ビットの `seed` を右に 32 ビットずらして上半分を取り出し、32 ビット整数に変換します。`(uint32) seed` は下半分だけを取り出します。
- **`((uint64) b << 32) | c`**: `b` を 64 ビットにしてから左に 32 ビットずらし、`|`（ビットごとの OR）で `c` を下半分に置きます。2 つの 32 ビット値を 1 つの 64 ビット値に詰める定番の書き方です。
- **マクロ `mix` と `final`**: 同じファイルで定義されている、3 つの 32 ビット変数 `a, b, c` を引き算・XOR・回転でかき混ぜる処理です。関数ではなくマクロなので、変数をその場で書き換えます。

## 何をしているか

### 1. 初期値を決める

```c:line-numbers=637
	a = b = c = 0x9e3779b9 + (uint32) sizeof(uint32) + 3923095;
```

`0x9e3779b9 + 4 + 3923095` を `a, b, c` すべてに入れます。`0x9e3779b9` は黄金比に由来する定数で、`(uint32) sizeof(uint32)` はキーの長さ（4 バイト）です。これは汎用の `hash_bytes` が「長さ 4 のキー」を処理するときの初期値と同じにしてあります。`3923095` も `hash_bytes` と共通の固定値です。

### 2. シードがあれば混ぜる

```c:line-numbers=639
	if (seed != 0)
	{
		a += (uint32) (seed >> 32);
		b += (uint32) seed;
		mix(a, b, c);
	}
```

`seed` が 0 でなければ、上位 32 ビットを `a` に、下位 32 ビットを `b` に足し、`mix` で 3 つの変数をかき混ぜます。たとえば `seed = 0x0000000500000007` なら `a` に 5、`b` に 7 が足されます。
`seed` が 0 ならこのブロック全体を飛ばします。

### 3. キーを足して仕上げる

```c:line-numbers=646
	a += k;

	final(a, b, c);
```

`a += k` でキーを加え、`final` で最終的な混ぜ合わせをします。`final` は `a, b, c` の差がわずかでも、`c` がまったく違う値になるように作られた手順です。

### 4. 64 ビットにまとめて返す

```c:line-numbers=651
	return ((uint64) b << 32) | c;
```

32 ビット版は `c` だけを返しますが、こちらは `b` を上位、`c` を下位に置いて 64 ビットで返します。

## ここがすごい

- **シード 0 の互換性**: `seed = 0` のときに `mix` を飛ばすので、初期値・`a += k`・`final` の流れが 32 ビット版の `hash_bytes_uint32` と完全に同じになります。つまり戻り値の下位 32 ビットは 32 ビット版の結果と一致します。古い 32 ビットのハッシュ値と新しい 64 ビットの値を矛盾なく使い分けられる、よく考えられた設計です。
- **余りの情報を捨てない**: `final` のあと、`c` だけでなく `b` もよく混ざっています。素直に 64 ビットのハッシュを作ろうとすると、もう一度別の計算をしたくなりますが、ここでは手元にある `b` を上位に再利用するだけで 64 ビットを得ています。
- **メモリを使わない近道**: 汎用の `hash_bytes(&k, 4)` でも同じ結果は得られますが、それには `k` をいったんメモリに置き、バイト列として読み直す必要があります。この関数は整数をレジスタに置いたまま計算できるので速く、呼ぶ側も簡単です。
- **シードの 64 ビットを両方使う**: シードの上半分と下半分を別々の変数に足しているので、どちらの半分を変えても結果が変わります。

## まとめ

- シードを混ぜる処理を「シードが 0 でないときだけ」にすると、旧来の結果との互換性を保てる。
- 混ぜ合わせ後の中間変数を再利用すれば、追加の計算なしで出力を 64 ビットに広げられる。
- 2 つの 32 ビット値は `((uint64) hi << 32) | lo` で 64 ビットに詰める。
- 固定長のキーには、汎用関数と同じ結果を返す専用の近道を用意すると速い。
