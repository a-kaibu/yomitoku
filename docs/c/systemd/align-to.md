## ひとことで

`ALIGN_TO(l, ali)` は、数 `l` を **`ali` の倍数に切り上げる** 関数です。`ali` は 2、4、8 のような 2 のべき乗に限ります。
`ALIGN_TO(13, 8)` は `16`、`ALIGN_TO(16, 8)` は `16` のままです。
メモリ上のデータの置き場所（アラインメント）をそろえるときに使います。割り算を使わず、ビット演算だけで計算します。

## コード

::: code-group

```c:line-numbers=75 [日本語訳]
static inline size_t ALIGN_TO(size_t l, size_t ali) {
        assert(ISPOWEROF2(ali));

        if (l > SIZE_MAX - (ali - 1))
                return SIZE_MAX; /* オーバーフローしたことを示す */

        return ((l + (ali - 1)) & ~(ali - 1));
}
```

```c:line-numbers=75 [原文]
static inline size_t ALIGN_TO(size_t l, size_t ali) {
        assert(ISPOWEROF2(ali));

        if (l > SIZE_MAX - (ali - 1))
                return SIZE_MAX; /* indicate overflow */

        return ((l + (ali - 1)) & ~(ali - 1));
}
```

:::

## 前提知識

- **アラインメント（整列）**: CPU は、4 バイトの整数を 4 の倍数のアドレスに、8 バイトの整数を 8 の倍数のアドレスに置くと効率よく（環境によっては「そうしないと正しく」）読み書きできます。データの大きさや置き場所を、こうした倍数にそろえることを「アラインする」と言います。
- **`size_t`**: サイズを表す符号なし整数型です。64 ビット環境では 64 ビットです。`SIZE_MAX` はその最大値です。
- **2 進数とビット演算**: `&` は桁ごとの AND（両方 1 のときだけ 1）、`~` は全ビットの反転です。8 は 2 進数で `1000`、`8 - 1 = 7` は `0111`、`~7` は「下位 3 ビットだけ 0 で、残りがすべて 1」です。
- **`static inline`**: ヘッダファイルに書く小さな関数の定番です。ファイルごとに見え、呼び出し箇所に展開できます。
- **`assert`**: 条件が偽ならプログラムを止めるチェックです。
- **`ISPOWEROF2(x)`**: 同じプロジェクトの `macro.h` にあるマクロで、`x` が正の 2 のべき乗かを `(x) > 0 && ((x) & ((x) - 1)) == 0` で判定します。2 のべき乗は 2 進数で 1 のビットが 1 つしかないので、1 を引くとそのビットより下が全部 1 になり、AND すると 0 になります。

## 何をしているか

### 1. 前提を確かめる

```c:line-numbers=75
static inline size_t ALIGN_TO(size_t l, size_t ali) {
        assert(ISPOWEROF2(ali));
```

`ali` が 2 のべき乗でなければ、以降のビット演算の式は正しくありません。最初に `assert` で確かめています。

### 2. 桁あふれを防ぐ

```c:line-numbers=78
        if (l > SIZE_MAX - (ali - 1))
                return SIZE_MAX; /* indicate overflow */
```

計算では `l + (ali - 1)` を求めます。`l` が `SIZE_MAX` に近いと、この足し算が最大値を超えて 0 付近に戻ってしまいます。
そこで「`l` が `SIZE_MAX - (ali - 1)` より大きいなら」、計算せずに `SIZE_MAX` を返して、あふれたことを知らせます。

### 3. 足してから下位ビットを落とす

```c:line-numbers=81
        return ((l + (ali - 1)) & ~(ali - 1));
```

`(l + (ali - 1)) & ~(ali - 1)` の動きを、`l = 13, ali = 8` で追ってみます。

- `ali - 1 = 7`（2 進数 `0111`）。
- `13 + 7 = 20`（2 進数 `10100`）。
- `~7` は下位 3 ビットが 0 のマスクです。`10100 & ...11000` = `10000` = **16**。

`l = 16` なら `16 + 7 = 23`（`10111`）、下位 3 ビットを落とすと `10000` = **16** で、もともと倍数ならそのまま残ります。

「8 の倍数」とは「下位 3 ビットが 0」のことです。下位ビットを落とすと「切り捨て」になるので、先に `ali - 1` を足しておくことで「切り上げ」に変えています。

## ここがすごい

- **割り算を使わない**: 素直に書くと `(l + ali - 1) / ali * ali` で、割り算と掛け算が 1 回ずつ要ります。整数の割り算は CPU にとって比較的重い命令です。2 のべき乗に限定することで、足し算と AND だけに置き換えています。
- **限定をコードで強制**: 「2 のべき乗に限る」という前提を、コメントではなく `assert(ISPOWEROF2(ali))` で確かめているので、うっかり 12 を渡してもすぐ気づけます。
- **あふれを特別な値で返す**: 桁あふれを黙って小さな値にせず、`SIZE_MAX` で知らせます。呼び出し側は、たとえば「`SIZE_MAX` が返ったら確保しない」と判断できます。
- **関数にした理由**: 同じファイルには定数用の `CONST_ALIGN_TO` マクロもあります。`static inline` 関数にすると、引数の型が `size_t` に揃い、一度だけ評価されることも保証されます。マクロと関数を用途で使い分けています。
- **仲間の関数**: すぐ下には `ALIGN_DOWN`（`l & ~(ali - 1)`、切り捨て）と `ALIGN_OFFSET`（`l & (ali - 1)`、倍数からのずれ）もあり、同じマスクを使い回しています。

## まとめ

- 2 のべき乗 `ali` の倍数は「下位ビットが 0 の数」なので、`& ~(ali - 1)` で切り捨てられる。
- 先に `ali - 1` を足してから切り捨てると、切り上げになる。
- 足し算の前に桁あふれを確かめ、あふれる場合は最大値で知らせる。
- 前提条件（2 のべき乗）を `assert` でコードに書いておくと、誤用にすぐ気づける。
