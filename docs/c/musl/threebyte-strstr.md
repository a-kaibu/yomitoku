## ひとことで

`threebyte_strstr(h, n)` は、文字列 `h` の中から 3 文字の文字列 `n` を探す、musl 内部の関数です。`strstr` が、針が 3 文字のときにこれを呼びます。
3 文字を 1 つの 32 ビット整数にまとめ、山の上を 1 文字ずつずらしながら整数の比較 1 回で一致を調べます。
16 ビットや 32 ビットと違い、ちょうど 24 ビットの整数型はありません。そこで 3 文字を **32 ビットの上位 24 ビット** に置き、下位 8 ビットを空けておくという工夫をしています。

## コード

```c:line-numbers=11
static char *threebyte_strstr(const unsigned char *h, const unsigned char *n)
{
	uint32_t nw = (uint32_t)n[0]<<24 | n[1]<<16 | n[2]<<8;
	uint32_t hw = (uint32_t)h[0]<<24 | h[1]<<16 | h[2]<<8;
	for (h+=2; *h && hw != nw; hw = (hw|*++h)<<8);
	return *h ? (char *)h-2 : 0;
}
```

## 前提知識

- **C の文字列**: 文字の並びの最後に値 0 のバイトを置いたものです。
- **`uint32_t`**: ちょうど 32 ビットの符号なし整数型です。左シフトではみ出たビットは捨てられます。
- **`(uint32_t)n[0]<<24`**: `n[0]` を 32 ビットの数に変換してから 24 ビット左にずらし、最上位のバイトに置きます。変換しないと、`int` のまま 24 ビットずらして符号ビットにかかる問題が起きうるので、先頭だけ明示的に変換しています。
- **`|` と `<<` の順番**: `(hw|c)<<8` は「`c` を下位に入れてから、全体を 8 ビット左へ」です。`hw<<8 | c` とは順番が逆です。
- **`*++h`**: `h` を 1 つ進めてから、その文字を読みます。
- **`(char *)h-2`**: `h` から 2 文字戻った位置です。

## 何をしているか

`h = "xabcd"` から `n = "bcd"` を探す例で追います。

### 1. 針を上位 24 ビットに置く

```c:line-numbers=13
	uint32_t nw = (uint32_t)n[0]<<24 | n[1]<<16 | n[2]<<8;
```

`nw = n[0]<<24 | n[1]<<16 | n[2]<<8` で、`'b' 'c' 'd'`（0x62 0x63 0x64）は `0x62636400` になります。最後の 1 バイトは 0 です。

### 2. 最初の窓も同じ形に

```c:line-numbers=14
	uint32_t hw = (uint32_t)h[0]<<24 | h[1]<<16 | h[2]<<8;
```

山の最初の 3 文字 `'x' 'a' 'b'` から `hw = 0x78616200` を作ります。

### 3. 窓をずらす

```c:line-numbers=15
	for (h+=2; *h && hw != nw; hw = (hw|*++h)<<8);
```

最初に `h+=2` で、`h` を窓の右端（3 文字目）に合わせます。そして、右端が終端でなく、窓と針が違う間、

`hw = (hw|*++h)<<8`

を繰り返します。

- `0x78616200` に次の文字 `'c'`（0x63）を OR すると `0x78616263`。
- それを 8 ビット左にずらすと、先頭の `0x78`（`'x'`）がはみ出て消え、`0x61626300` になる（`"abc"`）。
- 次は `'d'` を足して `0x61626364`、ずらして `0x62636400`（`"bcd"`）。これは `nw` と同じなので止まる。

### 4. 結果を返す

```c:line-numbers=16
	return *h ? (char *)h-2 : 0;
```

右端 `*h` が終端でなければ一致で止まったので、窓の先頭 `h-2` を返します。終端なら 0 です。

## ここがすごい

- **24 ビットの型がなくても窓が作れる**: 3 文字を下位 24 ビットに置くと、ずらすたびに `& 0xffffff` で上のはみ出しを消す必要があります。上位 24 ビットに置き、「入れてからずらす」ことで、捨てたい古い文字が自動的に 32 ビットの外へ出ていきます。マスク演算が要りません。
- **下位 8 ビットは常に 0**: シフトした直後の `hw` は、針 `nw` と同じく下位 8 ビットが 0 です。だから比較は 32 ビットまるごとの `hw != nw` で正しく、余分な 1 バイトが比較を邪魔しません。
- **2 文字版・4 文字版との対比**: 同じファイルの `twobyte_strstr` は `uint16_t`、`fourbyte_strstr` は `uint32_t` をちょうど使い切るので、`hw<<8 | 次の文字` という素直な順番で書けます。3 文字版だけが「OR してからシフト」という逆の順番になっているのは、型の幅に合わない長さを、置き場所の工夫で吸収しているからです。
- **各文字を 1 回だけ読む**: 窓の更新は 1 文字読むだけなので、山の長さに比例する時間で探索が終わります。

## まとめ

- ぴったりの幅の型がなければ、大きい型の「上の方」に詰めると、シフトではみ出た部分が自然に捨てられる。
- 「入れてからずらす」と「ずらしてから入れる」で、値の置き場所が変わる。目的に合わせて選ぶ。
- 比較する 2 つの値の「空き部分」をそろえておけば、そのまま整数比較できる。
