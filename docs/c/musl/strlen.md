## ひとことで

`strlen` は、C の文字列の **長さ（文字数）** を返す標準関数です。たとえば `strlen("hello")` は `5` を返します。
C の文字列は「最後に値 `0` のバイトが置かれた、バイトの並び」なので、長さを知るには **先頭から 0 のバイトを探す** しかありません。
musl の実装は、この探索を 1 バイトずつではなく **8 バイト（64 ビット環境の場合）をまとめて** 行うことで高速化しています。

## コード

```c:line-numbers=10
size_t strlen(const char *s)
{
	const char *a = s;
#ifdef __GNUC__
	typedef size_t __attribute__((__may_alias__)) word;
	const word *w;
	for (; (uintptr_t)s % ALIGN; s++) if (!*s) return s-a;
	for (w = (const void *)s; !HASZERO(*w); w++);
	s = (const void *)w;
#endif
	for (; *s; s++);
	return s-a;
}
```

このコードは、同じファイルの 5〜8 行目で定義されている次のマクロを使っています。

```c
#define ALIGN (sizeof(size_t))
#define ONES ((size_t)-1/UCHAR_MAX)
#define HIGHS (ONES * (UCHAR_MAX/2+1))
#define HASZERO(x) ((x)-ONES & ~(x) & HIGHS)
```

## 前提知識

- **C の文字列**: C には「文字列型」がありません。文字（`char`、1 バイト）がメモリ上に並び、最後に値 `0` のバイト（ヌル文字、`'\0'`）が置かれたものを文字列として扱います。`"hello"` は実際には `h e l l o \0` の 6 バイトです。
- **ポインタ**: メモリ上の場所（アドレス）を指す値です。`const char *s` は「文字が並んでいる場所を指すポインタ」で、`*s` と書くとその場所の 1 文字を読み出せます。`s++` でとなりの文字に進みます。`const` は「この関数は中身を書き換えない」という約束です。
- **ポインタの引き算**: 同じ並びを指す 2 つのポインタを引き算すると、その間にある要素の個数になります。`s-a` は「進んだ文字数」＝長さです。
- **`size_t`**: 長さやサイズを表すための符号なし整数型です。64 ビット環境ではたいてい 8 バイトです。`sizeof(size_t)` はその大きさ（バイト数）です。
- **`#define`（マクロ）**: コンパイル前に文字を置き換える仕組みです。`HASZERO(x)` と書くと、その場所に `((x)-ONES & ~(x) & HIGHS)` が埋め込まれます。
- **`#ifdef __GNUC__`**: GCC 系のコンパイラ（GCC や Clang）でコンパイルしているときだけ、`#endif` までのコードを有効にします。
- **アラインメント（整列）**: CPU は、8 バイトの値を「8 の倍数のアドレス」から読むのが得意です。`(uintptr_t)s % ALIGN` はアドレスを整数にして 8 で割った余りで、0 なら 8 の倍数の位置にいます。
- **ビット演算**: `&` は桁ごとの AND、`~` は全ビットの反転です。

## 何をしているか

### 1. 8 の倍数の位置まで 1 文字ずつ進む（16 行目）

`for (; (uintptr_t)s % ALIGN; s++) if (!*s) return s-a;` は、アドレスが 8 の倍数になるまで 1 バイトずつ進みます。その途中で 0 のバイトが見つかれば、その時点で長さを返します。
たとえば文字列がアドレス 0x1003 から始まっていれば、0x1003〜0x1007 の 5 バイトをこのループで調べ、0x1008 から先をまとめて調べる準備が整います。

### 2. 8 バイトずつ調べる（14〜17 行目）

14 行目で `word` という型を作り、15 行目で「`word` を指すポインタ」`w` を用意します。17 行目の `for` は、`w` が指す 8 バイトを **1 つの整数として読み込み**、`HASZERO` が 0 でない（＝ 0 のバイトを含む）まで `w++` で 8 バイトずつ進みます。ループの本体は空で、条件式だけで仕事をしています。

### 3. HASZERO のしくみ

64 ビットの場合、`ONES` は `0x0101010101010101`（各バイトが 1）、`HIGHS` は `0x8080808080808080`（各バイトの最上位ビットだけ 1）になります。`(size_t)-1` は全ビットが 1 の最大値で、それを `UCHAR_MAX`（255）で割ると各バイトに 1 が並ぶ、という計算です。

各バイトについて考えると、`(x - ONES)` は「そのバイトから 1 を引く」操作です。

- バイトが `0x00` なら、1 を引くと繰り下がって `0xFF` になり、最上位ビットが 1 になります。
- バイトが `0x01`〜`0x80` なら、1 を引いても最上位ビットは 0 か、もともと 1 だったものです。

ここで `& ~(x)` を掛けると、「もともと最上位ビットが 1 だったバイト」（`0x80` 以上）が除外されます。最後に `& HIGHS` で各バイトの最上位ビットだけを残すと、**0 のバイトがあるときだけ結果が 0 でなくなる** のです。

たとえば 8 バイトが `"abc\0defg"` の一部なら、`\0` の位置のバイトだけ `0x80` が立ち、ループが止まります。

（繰り下がりが上のバイトへ伝わって誤判定が出ることもありますが、それは本物の 0 より上のバイトでしか起きないため、「0 があるかどうか」の判定は正しく保たれます。）

### 4. 最後の数バイトを 1 文字ずつ（18〜21 行目）

0 を含む 8 バイトが見つかったら、`s` をその先頭に戻し（18 行目）、20 行目のループで 1 文字ずつ正確な位置を探します。最後に `s-a` で長さを返します。GCC 以外のコンパイラでは 14〜18 行目が無くなり、この 20 行目のループだけが残る、素直な `strlen` になります。

## ここがすごい

- **8 倍少ないループ回数**: 1 バイトずつなら 1000 文字の文字列で 1000 回比較しますが、この方法ならおよそ 125 回の読み込みと数回の演算で済みます。
- **分岐なしで「0 のバイトがあるか」を判定**: 8 回の比較をする代わりに、引き算・反転・AND の 3 演算で 8 バイト同時に判定しています。整数 1 個を「8 個の小さな箱」として扱う、SWAR（SIMD Within A Register）と呼ばれる技法です。
- **定数を型の大きさから計算している**: `ONES` や `HIGHS` を `0x0101...` と直接書かず、`(size_t)-1/UCHAR_MAX` から導いているので、32 ビット環境でも 64 ビット環境でも同じコードで正しい値になります。
- **はみ出して読んでも安全な理由**: 8 バイトずつ読むと、文字列の終わりより後ろのメモリまで読むことがあります。しかし先に 8 の倍数の位置にそろえているので、8 バイトのかたまりがメモリのページ（OS が管理する区切り）の境目をまたぐことがなく、読んではいけない領域に触れずに済みます。16 行目の「先にそろえる」処理は、速さだけでなく安全のためにも必要なのです。
- **`__may_alias__` で最適化の罠を避ける**: C には「`char` の並びを別の型として読んではいけない」という規則（strict aliasing）があり、破るとコンパイラの最適化でおかしな結果になる可能性があります。14 行目の `__attribute__((__may_alias__))` は「この型はほかの型と重ねて読んでよい」と GCC に伝える指定で、規則違反を避けています。使えないコンパイラでは `#ifdef` で素直な実装に切り替わります。

## まとめ

- C の文字列は「0 で終わるバイトの並び」で、長さは 0 を探して数える。
- 整数 1 個を 8 個のバイトの箱とみなすと、8 バイトを一度に調べられる（SWAR）。
- `(x - 0x01..01) & ~x & 0x80..80` は「0 のバイトを含むか」を調べる有名なビット演算の式。
- まとめて読む前にアドレスをそろえると、速くなるだけでなく安全にもなる。
- 速いコードと素直なコードを `#ifdef` で切り替え、移植性を保っている。
