## ひとことで

`cycle(width, ar, n)` は、ポインタの配列 `ar[0]`〜`ar[n-1]` が指す `n` 個の要素（各 `width` バイト）の中身を、**1 つずつ前へ回転** させる関数です。
3 つの要素 A、B、C を指しているなら、実行後は `ar[0]` の場所に B、`ar[1]` に C、`ar[2]` に A が入ります。
musl の `qsort` は、要素の入れ替えを「交換の繰り返し」ではなく、この回転 1 回で行います。

## コード

```c:line-numbers=45
static void cycle(size_t width, unsigned char* ar[], int n)
{
	unsigned char tmp[256];
	size_t l;
	int i;

	if(n < 2) {
		return;
	}

	ar[n] = tmp;
	while(width) {
		l = sizeof(tmp) < width ? sizeof(tmp) : width;
		memcpy(ar[n], ar[0], l);
		for(i = 0; i < n; i++) {
			memcpy(ar[i], ar[i + 1], l);
			ar[i] += l;
		}
		width -= l;
	}
}
```

## 前提知識

- **`qsort` と要素の大きさ**: C の `qsort` は、どんな型の配列でも並べ替えられるよう、要素を「`width` バイトのかたまり」としてしか知りません。`int` なら 4 バイト、構造体なら 100 バイトかもしれません。
- **`unsigned char* ar[]`**: 「バイトを指すポインタ」の配列です。`ar[i]` は `i` 番目の要素の先頭の場所です。
- **`memcpy(d, s, l)`**: `s` から `l` バイトを `d` にコピーする標準関数です。
- **`sizeof(tmp)`**: 配列 `tmp` のバイト数で、ここでは 256 です。
- **三項演算子 `a ? b : c`**: `a` が真なら `b`、偽なら `c` になる式です。`sizeof(tmp) < width ? sizeof(tmp) : width` は「`width` と 256 の小さいほう」を求めています。
- **ポインタに足し算**: `ar[i] += l` は、ポインタを `l` バイト先へ進めます。
- **`static`**: この関数がこのファイルの中だけで使われることを示します。

## 何をしているか

### 1. 要素が 1 個以下なら何もしない

```c:line-numbers=51
	if(n < 2) {
		return;
	}
```

1 個の回転は何も変わらないので、すぐに戻ります。

### 2. 一時領域を「n 番目の要素」とみなす

```c:line-numbers=55
	ar[n] = tmp;
```

`ar[n] = tmp;` で、配列の末尾に一時領域 `tmp` を追加します。これで、`ar[0]` の中身を `ar[n]` に退避し、あとは `ar[i] ← ar[i+1]` を `i = 0〜n-1` で繰り返すだけで回転が完成します。最後の `ar[n-1] ← ar[n]` で、退避した元の `ar[0]` が末尾に入ります。

### 3. 256 バイトずつ繰り返す

```c:line-numbers=56
	while(width) {
		l = sizeof(tmp) < width ? sizeof(tmp) : width;
		memcpy(ar[n], ar[0], l);
		for(i = 0; i < n; i++) {
			memcpy(ar[i], ar[i + 1], l);
			ar[i] += l;
		}
		width -= l;
	}
```

要素が 256 バイトより大きいと、一度に全部は退避できません。そこで、

1. `l` を「残りのバイト数と 256 の小さいほう」にする
2. `ar[0]` の先頭 `l` バイトを `tmp` へ
3. 各 `ar[i]` へ `ar[i+1]` の `l` バイトをコピーし、`ar[i]` を `l` バイト進める
4. 残りを `l` 減らす

を、`width` が 0 になるまで繰り返します。`width = 600` なら 256、256、88 バイトの 3 回に分けて回転します。`tmp` を指す `ar[n]` だけは進めないので、毎回同じ一時領域が使われます。

## ここがすごい

- **交換より少ないコピー**: 要素を 1 段ずつ交換していくと、1 回の交換で 3 回のコピー（退避・上書き・戻し）が要ります。k 段ずらすなら 3k 回です。回転なら、退避 1 回とずらし k 回の k+1 回で済みます。
- **要素の大きさに上限がない**: 一時領域を `width` バイト確保すれば簡単ですが、`width` が大きいと関数呼び出しのたびにスタック（関数が使う作業領域）を大きく使い、`malloc` を使えば失敗の可能性が出てきます。固定 256 バイトに分割して回すことで、どんな大きさの要素でも安全に扱えます。
- **分割しても結果は同じ**: 回転は「バイトの位置ごと」に独立した操作なので、前半 256 バイトを回してから後半を回しても、一度に全部を回したのと同じ結果になります。この性質を使っているから、分割できるのです。
- **ポインタを進めて次の区画へ**: 区画ごとに `ar[i] + オフセット` を計算するのではなく、ポインタ自体を `l` ずつ進めています。ループの中の計算が単純になります。

## まとめ

- 複数の要素を 1 つずつずらすなら、交換の連続より「回転」のほうがコピーが少ない。
- 汎用のソートでは、要素の大きさに依存しない固定サイズの作業領域が安全。
- バイト単位で独立した処理は、小さな区画に分けて繰り返しても結果が変わらない。
