## ひとことで

`strspn(s, accept)` は、文字列 `s` の先頭から、`accept` に含まれる文字だけが何文字続くかを返します。
たとえば `strspn("123abc", "0123456789")` は `3` です。先頭の `1 2 3` は数字ですが、`a` は含まれないのでそこで止まります。
musl は `accept` の文字を **256 ビットの表（ビットセット）** に書き込み、1 文字ごとの判定をビット 1 つの確認だけで済ませています。

## コード

```c:line-numbers=6
size_t strspn(const char *s, const char *c)
{
	const char *a = s;
	size_t byteset[32/sizeof(size_t)] = { 0 };

	if (!c[0]) return 0;
	if (!c[1]) {
		for (; *s == *c; s++);
		return s-a;
	}

	for (; *c && BITOP(byteset, *(unsigned char *)c, |=); c++);
	for (; *s && BITOP(byteset, *(unsigned char *)s, &); s++);
	return s-a;
}
```

同じファイルの先頭で、ビット集合を操作するマクロが定義されています。

```c:line-numbers=3
#define BITOP(a,b,op) \
 ((a)[(size_t)(b)/(8*sizeof *(a))] op (size_t)1<<((size_t)(b)%(8*sizeof *(a))))
```

## 前提知識

- **C の文字列**: 文字の並びの最後に値 0 のバイトを置いたものです。`!c[0]` は「1 文字目が終端＝空文字列」を意味します。
- **配列とポインタ**: `c[1]` は「`c` が指す場所の 2 文字目」です。C では配列の添字とポインタの足し算は同じ意味です。
- **`size_t byteset[32/sizeof(size_t)] = { 0 };`**: 32 バイト（＝ 256 ビット）ぶんの配列を、すべて 0 で初期化しています。64 ビット環境では 8 バイトの整数が 4 個です。
- **マクロ**: `#define` で定義した文字の置き換えです。`BITOP(a, b, |=)` のように、演算子そのもの（`|=` や `&`）を引数として渡せます。
- **シフト `<<`**: `1 << 5` は `0b100000`（32）です。「5 番目のビットだけ 1」の値を作れます。
- **`|=` と `&`**: `x |= m` は `m` のビットを `x` に立てる、`x & m` は `m` のビットが `x` で立っているかを調べる演算です。
- **ポインタの引き算**: `s-a` は「`a` から `s` まで何文字進んだか」です。

## 何をしているか

### 1. BITOP マクロのしくみ

ビット集合は「256 個のスイッチ」です。文字 `b`（0〜255）の番号のスイッチを操作します。64 ビット環境では整数 1 個が 64 ビットなので、

- どの整数か: `b / 64`
- その中の何ビット目か: `b % 64`

で場所が決まります。`'A'`（65）なら、`byteset[1]` の 1 ビット目です。`8*sizeof *(a)` は「配列の要素 1 個のビット数」で、32 ビット環境でも正しい値になります。

### 2. 特別なケース

```c:line-numbers=11
	if (!c[0]) return 0;
	if (!c[1]) {
		for (; *s == *c; s++);
		return s-a;
	}
```

`accept` が空なら、どの文字も許されないので 0 を返します。`accept` が 1 文字だけ（`!c[1]`）なら、表を作るまでもなく `*s == *c` の間だけ進めば十分です。たとえば `strspn("   x", " ")` は 3 です。

### 3. 表を作る

```c:line-numbers=17
	for (; *c && BITOP(byteset, *(unsigned char *)c, |=); c++);
```

`accept` の各文字について `BITOP(byteset, 文字, |=)` でビットを立てます。この式の値は「ビットを立てたあとの整数」で、必ず 0 以外なので、`for` の条件として「真」になり続けます。終わりの判定は `*c`（終端に来たか）だけが担っています。

### 4. 表を引きながら進む

```c:line-numbers=18
	for (; *s && BITOP(byteset, *(unsigned char *)s, &); s++);
```

`s` の各文字について `BITOP(byteset, 文字, &)` で、ビットが立っているかを調べます。立っている間だけ進み、立っていない文字か終端で止まります。最後に `s-a` で進んだ文字数を返します。

## ここがすごい

- **1 文字の判定が定数時間**: 素直に書くと、`s` の 1 文字ごとに `accept` の全文字と比較する二重ループになり、`accept` が 10 文字なら最大 10 回比較します。ビット集合なら何文字あっても 1 回の表引きです。
- **表が小さい**: `bool` の配列で 256 個用意すると 256 バイトですが、ビットで持てば 32 バイトで済み、初期化も速く済みます。
- **`(unsigned char)` で負の添字を防ぐ**: `char` は環境によって負の値になり得ます（`0xE3` が `-29` になるなど）。`*(unsigned char *)c` と読むことで、必ず 0〜255 の番号として扱っています。
- **よくある入力を先に片付ける**: 空白だけを飛ばす `strspn(s, " ")` のような使い方は多いので、表を作らない近道を用意しています。
- **ループの条件に処理を埋め込む**: 表を作る `for` は本体が空の `for` で、表の作成という「処理」を条件式の中で行っています。C らしい簡潔な書き方です。

## まとめ

- 0〜255 の値の集合は、256 ビット（32 バイト）のビット集合で表せる。
- 「何番目の整数の何ビット目か」は、割り算と余りで求まる。
- 集合の作成コストを払えば、各文字の判定は表引き 1 回になる。
- よくある小さな入力には、表を作らない近道を用意すると速い。
