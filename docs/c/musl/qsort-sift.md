## ひとことで

`sift` は、ヒープ（親が子以上になるよう並べた木）の根に置かれた要素を、正しい位置まで沈める「ふるい落とし」を行う関数です。
musl の `qsort` は、エドガー・ダイクストラが考案した **smoothsort** というヒープソートの変種で、木として **レオナルド木** を使います。
この `sift` は、沈める途中で要素を交換せず、通り道だけを記録しておき、最後に `cycle` 関数で一気に動かします。

## コード

```c:line-numbers=100
static void sift(unsigned char *head, size_t width, cmpfun cmp, void *arg, int pshift, size_t lp[])
{
	unsigned char *rt, *lf;
	unsigned char *ar[AR_LEN];
	int i = 1;

	ar[0] = head;
	while(pshift > 1) {
		rt = head - width;
		lf = head - width - lp[pshift - 2];

		if(cmp(ar[0], lf, arg) >= 0 && cmp(ar[0], rt, arg) >= 0) {
			break;
		}
		if(cmp(lf, rt, arg) >= 0) {
			ar[i++ & AR_MASK] = lf;
			head = lf;
			pshift -= 1;
		} else {
			ar[i++ & AR_MASK] = rt;
			head = rt;
			pshift -= 2;
		}
	}
	cycle(width, ar, i & AR_MASK);
}
```

関数の前で、作業配列の長さとマスクが定義されています。

```c:line-numbers=97
#define AR_LEN  (16 * sizeof(size_t))
#define AR_MASK (AR_LEN - 1)
```

## 前提知識

- **ヒープ**: 木の各ノードが子ノード以上の値を持つように並べたデータ構造です。根がいちばん大きい値になります。
- **レオナルド木**: 大きさが「レオナルド数」L(k)（1, 1, 3, 5, 9, 15, …、L(k) = L(k-1) + L(k-2) + 1）の木です。次数 k の木は「次数 k-1 の左の木」「次数 k-2 の右の木」「根」をこの順に配列に並べたもので、**根が末尾** に来ます。
- **`lp[]`**: 次数ごとの木の大きさを、要素のバイト数を掛けて持つ配列です。`lp[k]` は次数 k の木が占めるバイト数です。
- **ポインタの計算**: 要素は `width` バイトずつ並んでいます。`head - width` は 1 つ前の要素です。
- **比較関数 `cmp`**: `cmp(a, b, arg)` は `a` が `b` より大きければ正、等しければ 0、小さければ負を返す、利用者が渡す関数です。関数ポインタ（関数の場所を入れた変数）として受け取ります。
- **`i++ & AR_MASK`**: `i` を使ってから 1 増やし、AR_LEN（2 のべき）で割った余りを添字にします。

## 何をしているか

### 1. 子の場所を求める

```c:line-numbers=107
	while(pshift > 1) {
		rt = head - width;
		lf = head - width - lp[pshift - 2];
```

`head` は次数 `pshift` の木の根です。木は「左の木・右の木・根」の順に並ぶので、

- 右の子（右の木の根）は、根の直前: `rt = head - width`
- 左の子（左の木の根）は、右の木の大きさぶんさらに前: `lf = head - width - lp[pshift - 2]`

です。次数 0 と 1 の木は要素 1 個なので、`pshift > 1` の間だけ続けます。

### 2. 根が両方の子以上なら終わり

```c:line-numbers=111
		if(cmp(ar[0], lf, arg) >= 0 && cmp(ar[0], rt, arg) >= 0) {
			break;
		}
```

`ar[0]`（沈めている元の根の要素）が左右の子の両方以上なら、そこが正しい位置です。

### 3. 大きいほうの子へ降りる

```c:line-numbers=114
		if(cmp(lf, rt, arg) >= 0) {
			ar[i++ & AR_MASK] = lf;
			head = lf;
			pshift -= 1;
		} else {
			ar[i++ & AR_MASK] = rt;
			head = rt;
			pshift -= 2;
		}
```

左の子が右の子以上なら左へ。左の木の次数は `pshift - 1` です。そうでなければ右へ。右の木の次数は `pshift - 2` です。降りた先の子の場所を `ar` に記録し、`head` を更新します。
ここでは **要素を書き換えていません**。比較には常に `ar[0]`（動かしていない元の根）を使います。

### 4. 記録した道に沿って回転

```c:line-numbers=124
	cycle(width, ar, i & AR_MASK);
```

たとえば「根 R → 左の子 A → その右の子 B」と降りたなら、`ar = {R の場所, A の場所, B の場所}` です。`cycle` で回転すると、R の場所に A、A の場所に B、B の場所に元の R が入ります。大きい子が 1 段ずつ上がり、R が正しい深さに収まります。

## ここがすごい

- **書き込みは最後に 1 回だけ**: 教科書的なふるい落としは、1 段降りるたびに親と子を交換します。要素が大きいと、交換のたびに 3 回のコピーが発生します。道を記録して最後に回転すれば、k 段降りても k+1 回のコピーで済みます。
- **配列の中に木を埋め込む**: 子へのポインタを持たず、「左・右・根」の並び方と大きさの表 `lp` から、子の場所を引き算で求めています。追加のメモリを使わないソート（O(1) メモリ）を実現する鍵です。
- **添字のマスクで安全を保証**: `AR_LEN` の定義の前のコメントにあるとおり、作業配列の長さを 2 のべきにし、添字を `& AR_MASK` で必ず範囲内に収めています。アルゴリズムの性質上あふれないはずでも、比較関数が矛盾した結果を返すなどして前提が崩れたときに、配列の外へ書き込まないようにする守りです。
- **ほぼ整列済みなら速い**: 根と子を比べる最初の判定ですぐ抜けられることが多いので、もともと並んでいる入力では仕事がほとんどありません。ファイル冒頭のコメントにも「ほぼ整列済みなら O(n) に近い」とあります。

## まとめ

- ふるい落としは、交換を繰り返す代わりに「道を記録して最後に回転」すると書き込みが減る。
- 木を配列に埋め込めば、子の位置は大きさの表から計算できる。
- 「起きないはず」のあふれも、マスクで物理的に起きなくしておくと安全。
