## ひとことで

`memchr(p, c, n)` は、アドレス `p` から始まる `n` バイトの中で、値が `c` のバイトが最初に現れる場所を返す標準関数です。見つからなければ `NULL`（0）を返します。
たとえば `memchr("abcabc", 'c', 6)` は 3 バイト目（先頭から数えて 0, 1, 2 番目）を指すポインタを返します。
musl は「探したい値を整数の全バイトに並べ、XOR して 0 を探す」という変換で、8 バイトずつまとめて探します。

## コード

```c:line-numbers=11
void *memchr(const void *src, int c, size_t n)
{
	const unsigned char *s = src;
	c = (unsigned char)c;
#ifdef __GNUC__
	for (; ((uintptr_t)s & ALIGN) && n && *s != c; s++, n--);
	if (n && *s != c) {
		typedef size_t __attribute__((__may_alias__)) word;
		const word *w;
		size_t k = ONES * c;
		for (w = (const void *)s; n>=SS && !HASZERO(*w^k); w++, n-=SS);
		s = (const void *)w;
	}
#endif
	for (; n && *s != c; s++, n--);
	return n ? (void *)s : 0;
}
```

同じファイルの先頭で、次のマクロが定義されています。

```c:line-numbers=5
#define SS (sizeof(size_t))
#define ALIGN (sizeof(size_t)-1)
#define ONES ((size_t)-1/UCHAR_MAX)
#define HIGHS (ONES * (UCHAR_MAX/2+1))
#define HASZERO(x) ((x)-ONES & ~(x) & HIGHS)
```

## 前提知識

- **ポインタ**: メモリ上の場所（アドレス）を表す値です。`*s` でその場所の値を読み、`s++` で次の要素へ進みます。
- **`const void *`**: 「何の型かは決めない、読み取り専用のポインタ」です。`memchr` はどんなデータでも受け取れるように `void *` を使い、中で `unsigned char *`（0〜255 のバイトとして読むポインタ）に変換しています。
- **`size_t`**: 大きさや個数を表す符号なし整数型です。64 ビット環境では 8 バイトです。
- **`unsigned char` へのキャスト**: `(unsigned char)c` は、`int` で渡された値の下位 8 ビットだけを取り出し 0〜255 にします。`-1` を渡しても 255 として探せます。
- **XOR（`^`）**: 2 つの値のビットが違うところだけ 1 になる演算です。**同じ値どうしを XOR すると 0** になります。
- **`HASZERO(x)`**: 整数 `x` の中に値 0 のバイトが 1 つでもあれば 0 以外になるマクロです（strlen と同じ技）。
- **`#ifdef __GNUC__`**: GCC 系コンパイラのときだけ有効になる部分です。`__may_alias__` は「別の型として重ねて読んでよい」とコンパイラに伝える指定です。
- **`for (...;...;...);`**: 本体が空の `for` 文です。条件式と更新式だけで仕事をします。

## 何をしているか

### 1. 探す値を 0〜255 にそろえる

```c:line-numbers=14
	c = (unsigned char)c;
```

`c = (unsigned char)c;` で、比較に使う値をバイトの範囲に収めます。こうしないと、たとえば `c = -1` のときにバイト `0xFF`（255）と一致しなくなります。

### 2. 8 の倍数のアドレスまで 1 バイトずつ

```c:line-numbers=16
	for (; ((uintptr_t)s & ALIGN) && n && *s != c; s++, n--);
```

`(uintptr_t)s & ALIGN` はアドレスを 8 で割った余りです（`ALIGN` は 7）。余りが 0 になるか、残りが無くなるか、見つかるまで 1 バイトずつ進みます。

### 3. 探す値を全バイトに並べる

```c:line-numbers=20
		size_t k = ONES * c;
```

`ONES` は 64 ビットなら `0x0101010101010101` です。`k = ONES * c` とすると、`c = 'c'`（0x63）なら `k = 0x6363636363636363` になります。

### 4. XOR して 0 のバイトを探す

```c:line-numbers=21
		for (w = (const void *)s; n>=SS && !HASZERO(*w^k); w++, n-=SS);
```

`*w ^ k` を計算すると、`c` と同じバイトだけが 0 になり、ほかは 0 以外になります。つまり「`c` を探す問題」が「0 を探す問題」に変わります。あとは `HASZERO` で 8 バイト同時に判定し、見つからなければ `w++` で次の 8 バイトへ、`n -= SS` で残りを減らします。`n>=SS` の条件で、残りが 8 バイト未満になったら止まります。

### 5. 最後は 1 バイトずつ

```c:line-numbers=25
	for (; n && *s != c; s++, n--);
	return n ? (void *)s : 0;
```

候補の 8 バイト、または端数の数バイトを 1 つずつ調べます。`n` が 0 でなければ見つかった場所を、0 なら `NULL` を返します。

## ここがすごい

- **問題の変換**: strlen の「0 のバイトを探す」技は、そのままでは 0 しか探せません。XOR で「一致 → 0」に変換することで、同じマクロをどんな値の検索にも使えるようにしています。追加コストは XOR 1 回だけです。
- **定数を掛け算で作る**: `k` を作るのにシフトと OR を 8 回繰り返す必要はなく、`ONES * c` の掛け算 1 回で全バイトに `c` が並びます。各バイトが 1 の数に 0〜255 を掛けても繰り上がりが起きないからです。
- **長さ制限との両立**: strlen と違い、`memchr` には「`n` バイトより先を読んではいけない」制約があります。8 バイトずつのループの条件 `n>=SS` で、8 バイト丸ごと範囲内のときだけまとめ読みしているので、範囲外を読みません。
- **見つかった後の処理を共通化**: 8 バイトの中のどこにあるかは、最後の 1 バイトずつのループに任せています。ビット演算で位置まで求めることもできますが、ループに任せたほうがコードが短く、どの環境でも正しく動きます。

## まとめ

- 同じ値どうしの XOR は 0 になるので、「値 c を探す」を「0 を探す」に変えられる。
- `0x0101...01 * c` で、c を全バイトに並べた定数が作れる。
- まとめて読むときは、アドレスの整列と「残りの長さ」の両方を守る。
- 速い道（8 バイトずつ）と確実な道（1 バイトずつ）を組み合わせると、コードが短く正しく保てる。
