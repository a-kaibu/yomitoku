## ひとことで

`shl(p, n)` は、2 つの `size_t` を並べた `p[0]`（下位）と `p[1]`（上位）を、1 つの大きなビット列とみなして `n` ビット左にずらします。64 ビット環境なら 128 ビットのシフトです。
musl の `qsort` は、ヒープの森の「どの大きさの木があるか」をこのビット列で表しており、木を足したり分けたりするたびにずらします。
すぐ下にある `shr`（右シフト）と対になっています。

## コード

::: code-group

```c:line-numbers=67 [日本語訳]
/* shl() と shr() は n > 0 が必要 */
static inline void shl(size_t p[2], int n)
{
	if(n >= 8 * sizeof(size_t)) {
		n -= 8 * sizeof(size_t);
		p[1] = p[0];
		p[0] = 0;
		if (!n) return;
	}
	p[1] <<= n;
	p[1] |= p[0] >> (sizeof(size_t) * 8 - n);
	p[0] <<= n;
}
```


## 前提知識

- **ビットシフト `<<` `>>`**: `x << 3` は `x` のビットを 3 桁左に、`x >> 3` は右にずらします。はみ出たビットは消え、空いたところには 0 が入ります。
- **`size_t p[2]`**: `size_t`（64 ビット環境では 64 ビットの符号なし整数）2 個の配列です。関数に配列を渡すと、中身はコピーされず、呼び出し元の配列そのものが書き換わります。
- **`8 * sizeof(size_t)`**: `size_t` のビット数です（64 ビット環境なら 64）。
- **`|=`**: ビットを合成して代入します。
- **未定義動作**: C の規格が「どうなるか決めていない」操作です。**型のビット数以上のシフト**（64 ビットの値を 64 ずらすなど）はその 1 つで、環境によって結果が変わったり、最適化で予想外のコードになったりします。
- **`static inline`**: このファイル専用で、呼び出し元に展開してよいという指定です。小さな関数を速く使うための書き方です。

## 何をしているか

64 ビット環境で、`p[1] = 0x0`、`p[0] = 0xC000000000000001`（最上位の 2 ビットと最下位ビットが 1）の例で追います。

### 1. 64 ビット以上ずらす場合

```c:line-numbers=70
	if(n >= 8 * sizeof(size_t)) {
		n -= 8 * sizeof(size_t);
		p[1] = p[0];
		p[0] = 0;
		if (!n) return;
	}
```

`n` が 64 以上なら、まず下位ワードをまるごと上位ワードへ移し（`p[1] = p[0]`）、下位を 0 にします。これで 64 ビットぶんずれたことになるので、`n` から 64 を引きます。ちょうど 64 だった場合は、もうずらすものがないのでここで戻ります。

### 2. 上位ワードをずらし、下位からの「繰り上がり」を入れる

```c:line-numbers=76
	p[1] <<= n;
	p[1] |= p[0] >> (sizeof(size_t) * 8 - n);
```

`n = 2` なら、

- `p[1] <<= 2` で上位ワードをずらします。
- `p[0] >> (64 - 2)` は、下位ワードの **上から 2 ビット**（左シフトで押し出される部分）です。例では `0b11` になります。これを `p[1]` の下位に OR で入れます。

結果、`p[1] = 0x3` になります。

### 3. 下位ワードをずらす

```c:line-numbers=78
	p[0] <<= n;
```

`p[0] <<= 2` で、`p[0] = 0x0000000000000004` になります。合わせて見ると、128 ビットの値が正しく 2 ビット左へずれています。

## ここがすごい

- **「64 ビットずらし」を必ず避ける**: `p[0] >> (sizeof(size_t) * 8 - n)` は、`n` が 0 だと 64 ビットずらしになり、未定義動作です。そこで、

  - 関数の前のコメントで「`n > 0` が必要」と呼び出し側に約束させる
  - `n` が 64 以上のときはワード移動で処理し、残りが 0 なら `if (!n) return;` で即座に戻る

  という 2 段構えで、どの経路でも 0 や 64 でのシフトが起きないようにしています。
- **128 ビット整数型に頼らない**: GCC などには 128 ビットの整数型がありますが、すべてのコンパイラや環境にあるわけではありません。`size_t` 2 個で表すことで、32 ビット環境（64 ビットの列）でも 64 ビット環境（128 ビットの列）でも同じコードが動きます。
- **必要な大きさに合っている**: smoothsort の木の大きさの種類は、要素数に対して対数的にしか増えないので、2 ワードあれば十分です。そのため、汎用の多倍長シフトではなく、2 ワード専用の短いコードで済ませています。

## まとめ

- 複数ワードのシフトは、「ワード単位の移動」と「ワード内のシフト + 隣への繰り上がり」に分けて書く。
- 型のビット数以上のシフトは未定義動作。境界の値（0 や 64）を通らないように設計する。
- 関数の前提条件はコメントで明示し、呼び出し側と約束する。
