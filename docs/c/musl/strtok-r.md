## ひとことで

`strtok_r` は、文字列を区切り文字で分割して、トークン（区切られた 1 つ 1 つの部分）を順番に取り出す関数です。
`"  a,b,,c"` を区切り `" ,"` で分けると、呼ぶたびに `"a"`、`"b"`、`"c"` が返り、最後は `NULL` が返ります。
musl の実装は、標準関数 `strspn` と `strcspn` を組み合わせただけの、わずか 9 行です。

## コード

```c:line-numbers=3
char *strtok_r(char *restrict s, const char *restrict sep, char **restrict p)
{
	if (!s && !(s = *p)) return NULL;
	s += strspn(s, sep);
	if (!*s) return *p = 0;
	*p = s + strcspn(s, sep);
	if (**p) *(*p)++ = 0;
	else *p = 0;
	return s;
}
```

## 前提知識

- **C の文字列**: 文字の並びの最後に値 0 のバイトを置いたものです。文字列の途中に 0 を書き込むと、そこで文字列が「切れた」ことになります。
- **ポインタ**: `char *s` は文字の場所です。`*s` でその文字を読み書きします。
- **ポインタへのポインタ `char **p`**: 「ポインタを入れておく場所」を指すポインタです。`*p` で中のポインタを読み書きできます。関数が「次にどこから始めるか」を呼び出し側の変数に覚えさせるために使います。
- **`**p` と `*(*p)++ = 0`**: `**p` は `*p` が指す文字です。`*(*p)++ = 0` は「`*p` が指す文字に 0 を書き込み、そのあと `*p` を 1 つ進める」です。
- **`restrict`**: 「この 3 つのポインタは重なった領域を指さない」という約束で、コンパイラの最適化を助けます。
- **代入は値を持つ**: C では `*p = 0` という代入式自体が値（0）を持ちます。`return *p = 0;` は「`*p` に 0 を入れてから 0 を返す」です。
- **`strspn(s, sep)` / `strcspn(s, sep)`**: 前者は `sep` の文字が先頭から何文字続くか、後者は `sep` の文字が現れるまで何文字あるかを返します。

## 何をしているか

`char buf[] = "  a,b,,c"; char *save;` として、`strtok_r(buf, " ,", &save)` を呼ぶ例で追います。

### 1. どこから始めるか

```c:line-numbers=5
	if (!s && !(s = *p)) return NULL;
```

`s` が `NULL` なら「前回の続き」なので、`*p`（前回覚えた位置）を使います。それも `NULL` なら、もう何も残っていないので `NULL` を返します。1 回目は `s` が `buf` なのでそのまま進みます。

### 2. 先頭の区切りを飛ばす

```c:line-numbers=6
	s += strspn(s, sep);
	if (!*s) return *p = 0;
```

`strspn(s, sep)` は先頭の `"  "` の長さ 2 を返すので、`s` は `a` を指します。もし区切りを飛ばした先が終端なら、トークンはもうないので、`*p` を 0 にして `NULL` を返します。

### 3. トークンの終わりを探す

```c:line-numbers=8
	*p = s + strcspn(s, sep);
```

`strcspn(s, sep)` は `a` から区切りまでの長さ 1 を返すので、`*p` は `a` の直後の `,` を指します。

### 4. 区切りを 0 で潰し、続きの位置を覚える

```c:line-numbers=9
	if (**p) *(*p)++ = 0;
	else *p = 0;
```

`*p` が終端でなければ（`**p` が 0 以外）、その `,` に 0 を書き込んで文字列を切り、`*p` を 1 つ進めて `b` を指させます。終端だった場合は、次の呼び出しで終わるように `*p` を 0 にします。

### 5. トークンを返す

```c:line-numbers=11
	return s;
```

`s` は `"a"` を指しています。2 回目は `strtok_r(NULL, " ,", &save)` で `"b"`、3 回目は `,,` が飛ばされて `"c"`、4 回目は `NULL` です。

## ここがすごい

- **部品の組み合わせだけでできている**: 「区切りを飛ばす」「区切りまで進む」をそれぞれ標準関数に任せているので、ループが 1 つも書かれていません。各関数はビット集合を使った高速な実装なので、速さもそのまま受け継ぎます。
- **状態を呼び出し側に持たせる**: 昔からある `strtok` は「続きの位置」を関数内部の `static` 変数に覚えるため、2 つの文字列を交互に分割したり、複数のスレッドから同時に使ったりできません。`strtok_r` は位置を引数 `p` で受け取るので、何本でも同時に分割できます（`_r` は reentrant＝再入可能の意味です）。musl の `strtok` は、この関数の `*p` を内部の `static` 変数 `p` に置き換えただけの、ほぼ同じコードです。
- **終わりを NULL で表す**: 続きがないことを `*p = 0` で記録するので、最初の `if (!s && !(s = *p))` の 1 つの条件で「もう何もない」を判定できます。
- **トレードオフ**: 元の文字列に 0 を書き込むので、文字列定数（書き換え禁止）は渡せません。また連続する区切り（`,,`）は空のトークンにならず、まとめて飛ばされます。空の項目も扱いたいなら `strsep` を使います。

## まとめ

- 文字列の分割は「区切りを飛ばす」と「区切りまで進む」の繰り返しで書ける。
- 途中に 0 を書き込むと、コピーせずに文字列を切り出せる。
- 関数内部の `static` で状態を持つ代わりに、呼び出し側のポインタに持たせると再入可能になる。
