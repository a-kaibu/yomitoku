## ひとことで

`sqlite3LogEst` は、整数 `x` を **LogEst**（対数見積もり）という形に変換する関数です。LogEst は、だいたい `10 × log2(x)` の値を 16 ビットの整数で表したものです。
たとえば `x = 100` なら 66、`x = 1000000` なら 199 になります（10×log2(1000000) は約 199.3）。
SQLite のクエリプランナ（SQL をどの順番・どの索引で実行するかを決める部分）は、行数やコストの見積もりをこの形で扱っています。

## コード

::: code-group

```c:line-numbers=2088 [日本語訳]
/*
** 整数を LogEst に変換する。言いかえると、10*log2(x) の
** 近似値を計算する。
*/
LogEst sqlite3LogEst(u64 x){
  static LogEst a[] = { 0, 2, 3, 5, 6, 7, 8, 9 };
  LogEst y = 40;
  if( x<8 ){
    if( x<2 ) return 0;
    while( x<8 ){  y -= 10; x <<= 1; }
  }else{
#if GCC_VERSION>=5004000
    int i = 60 - __builtin_clzll(x);
    y += i*10;
    x >>= i;
#else
    while( x>255 ){ y += 40; x >>= 4; }  /*最適化: 真になることがある*/
    while( x>15 ){  y += 10; x >>= 1; }
#endif
  }
  return a[x&7] + y - 10;
}
```

## 前提知識

- **対数 `log2(x)`**: 「2 を何乗すると `x` になるか」です。`log2(8) = 3`、`log2(1024) = 10` です。値が 2 倍になると対数は 1 増えます。
- **LogEst の考え方**: `10 × log2(x)` なら、2 倍が +10、約 1.07 倍が +1 に相当します。大きな数の掛け算は対数の足し算になるので、見積もりの計算が足し算だけで済みます。精度はざっくりですが、見積もりには十分です。
- **`LogEst`**: SQLite で `typedef`（型に別名を付ける機能）された 16 ビットの符号付き整数です。
- **`static` の配列**: 関数の中で `static` を付けた変数は、呼び出しのたびに作り直されず、プログラムの実行中ずっと 1 つだけ存在します。表を毎回作らずに済みます。
- **`__builtin_clzll(x)`**: GCC の組み込み関数で、64 ビット整数の **上位から続く 0 のビットの数**（count leading zeros）を返します。多くの CPU では 1 命令で計算できます。
- **`<<` と `>>`**: 左シフトは 2 倍、右シフトは 2 で割ることに相当します。
- **`x&7`**: 下位 3 ビット（0〜7）を取り出します。

## 何をしているか

基本の考え方は、`x` を **8〜15 の範囲** に縮めて（または広げて）、縮めた回数を `y` に記録することです。8〜15 の範囲なら `10 × log2(x)` は 30〜39 なので、表で補正できます。

### 1. 小さな値

```c:line-numbers=2095
  if( x<8 ){
    if( x<2 ) return 0;
    while( x<8 ){  y -= 10; x <<= 1; }
```

`x` が 0 か 1 なら 0 を返します（`log2(1) = 0`）。
2〜7 なら、8 以上になるまで `x` を 2 倍し、そのたびに `y` から 10 を引きます。
`x = 3` なら、6、12 と 2 回倍にして `x = 12`、`y = 40 - 20 = 20` です。

### 2. 大きな値

```c:line-numbers=2099
#if GCC_VERSION>=5004000
    int i = 60 - __builtin_clzll(x);
    y += i*10;
    x >>= i;
```

`i = 60 - clz(x)` は、`x` を何ビット右にずらせば 8〜15 に収まるかです。64 ビット整数で 8〜15 の値は上位に 0 が 60 個並ぶので、それとの差を取っています。
`x = 100` なら、100 は 7 ビットの数なので `clz = 57`、`i = 3` です。`y = 40 + 30 = 70`、`x = 100 >> 3 = 12` になります。

### 3. 組み込み関数がない場合

```c:line-numbers=2104
    while( x>255 ){ y += 40; x >>= 4; }  /*OPTIMIZATION-IF-TRUE*/
    while( x>15 ){  y += 10; x >>= 1; }
```

255 より大きいあいだは 4 ビットずつ（`y += 40`）、15 より大きいあいだは 1 ビットずつ（`y += 10`）ずらします。大きく縮めてから細かく合わせる 2 段構えです。

### 4. 表で端数を補う

```c:line-numbers=2093
  static LogEst a[] = { 0, 2, 3, 5, 6, 7, 8, 9 };
```

```c:line-numbers=2108
  return a[x&7] + y - 10;
```

表 `a[] = {0, 2, 3, 5, 6, 7, 8, 9}` は、`x = 8, 9, …, 15` のときの `10 × log2(x) - 30` を丸めた値です。たとえば `10 × log2(12) ≈ 35.8` なので、`a[4] = 6`（≈ 36 − 30）です。
最後に `a[x&7] + y - 10` を返します。`x = 100` の例では `a[4] + 70 - 10 = 66` で、`10 × log2(100) ≈ 66.4` とほぼ一致します。

`y` の初期値 40 と最後の `-10` を合わせると、8〜15 の範囲の基準値 30 になります。

## ここがすごい

- **浮動小数点を使わない**: `log2` を `double` で計算すると、浮動小数点の計算が重い環境や、使わずにビルドする場合（`SQLITE_OMIT_FLOATING_POINT`）に困ります。整数のシフトと 8 要素の表だけで対数の近似を求めています。
- **先頭の 0 を数える命令で一発**: 「何桁あるか」は `clz` 1 回でわかります。ループで 1 ビットずつずらす必要がなく、どんなに大きな値でも一定の時間で終わります。組み込み関数がない環境には 4 ビットずつ縮めるループを用意していて、ここでも移植性と速度を両立しています。
- **「8〜15 に正規化」という発想**: 2 進数の上位 4 ビットを見れば、対数の整数部（何桁か）と小数部（先頭付近の並び）がわかります。浮動小数点数が「指数部」と「仮数部」に分かれているのと同じ考え方を、整数だけで再現しています。
- **見積もりに十分な精度で割り切る**: 返す値は約 7% 刻みの精度しかありません。しかし行数の見積もりはもともと大ざっぱなので、それで十分です。そのかわり、掛け算が足し算になるなど、見積もり同士の計算がとても軽くなります。

## まとめ

- 大きな数の見積もりは、対数で持つと掛け算が足し算になり、扱いやすくなる。
- 値を決まった範囲（ここでは 8〜15）にずらして、ずらした回数と小さな表で対数を近似できる。
- 上位の 0 の数を数える `clz` は、「何ビットの数か」を一瞬で求める道具。
- 用途に必要な精度を見極めれば、浮動小数点なしで済ませられる。
