## ひとことで

`sqlite3LogEstAdd` は、**LogEst**（`10 × log2(x)` を整数にした見積もり値）で表した 2 つの数 `a` と `b` について、元の値の和の LogEst を求める関数です。
たとえば `a = b = 66`（どちらも約 100）なら、和の約 200 に相当する 76 を返します。
コード中のコメントにあるとおり、LogEst は対数なので、単純な `+` では足し算になりません。

## 前提知識

- **LogEst**: SQLite のクエリプランナが行数やコストの見積もりに使う値で、`10 × log2(x)` を丸めた 16 ビット整数です。2 倍が +10 に当たります。
- **対数と掛け算・足し算**: 対数の世界では、掛け算は足し算になります（`log(x×y) = log x + log y`）。しかし **元の値の足し算** は、対数のままでは簡単に表せません。
- **和の公式**: `a ≥ b` のとき、`x + y` の対数は `a + 10 × log2(1 + 2^(-(a-b)/10))` です。足す補正値は、差 `a - b` だけで決まります。
- **`static const unsigned char x[]`**: 関数の中で 1 つだけ作られる、書き換えない表です。`unsigned char` は 0〜255 の小さな整数です。
- **`LogEst`**: `typedef` で付けた型の別名で、中身は 16 ビットの符号付き整数です。

## 何をしているか

### 1. 補正表

```c:line-numbers=2066
  static const unsigned char x[] = {
     10, 10,                         /* 0,1 */
      9, 9,                          /* 2,3 */
      8, 8,                          /* 4,5 */
      7, 7, 7,                       /* 6,7,8 */
      6, 6, 6,                       /* 9,10,11 */
      5, 5, 5,                       /* 12-14 */
      4, 4, 4, 4,                    /* 15-18 */
      3, 3, 3, 3, 3, 3,              /* 19-24 */
      2, 2, 2, 2, 2, 2, 2,           /* 25-31 */
  };
```

表 `x[d]` は、差が `d` のときに大きいほうへ足す値です。上の公式の `10 × log2(1 + 2^(-d/10))` を整数に丸めたものになっています。

- `d = 0`（同じ大きさ）なら、和は 2 倍なので +10。表の先頭は 10 です。
- `d = 10`（片方が半分）なら、和は 1.5 倍で、`10 × log2(1.5) ≈ 5.8` なので 6。表の 10 番目は 6 です。
- `d = 31` なら、和は約 1.12 倍で、`10 × log2(1.12) ≈ 1.6` なので 2。表の最後は 2 です。

各行のコメント（`/* 0,1 */` など）が、どの差の範囲がその値になるかを示しています。

### 2. 大きいほうを基準にする

```c:line-numbers=2077
  if( a>=b ){
```

```c:line-numbers=2081
  }else{
```

`a >= b` かどうかで分岐し、大きいほうに補正値を足します。2 つの枝は `a` と `b` を入れ替えただけで、同じ形です。

### 3. 差が大きいときは近似する

```c:line-numbers=2078
    if( a>b+49 ) return a;
    if( a>b+31 ) return a+1;
```

- 差が 49 より大きい（元の値が約 30 倍以上違う）なら、小さいほうは無視できるので、大きいほうをそのまま返します。
- 差が 32〜49 なら、本来の補正値は 0.5〜1.5 程度なので、+1 で済ませます。
- 差が 31 以下なら、表を引いて足します。

`a = 66`（約 100）、`b = 56`（約 50）で追うと、差は 10 なので `66 + x[10] = 66 + 6 = 72` です。`10 × log2(150) ≈ 72.3` なので、ほぼ正確です。

## ここがすごい

- **対数のまま足せる**: 元の値に戻して足し、また対数を取る、という手順を踏むと、浮動小数点の `pow` や `log` が必要になります。差だけで決まる補正を表にしておけば、比較と表引きと足し算だけで済みます。
- **表が小さい**: 補正値は差が大きくなるとすぐ 0 に近づくので、必要なのは差 31 までの 32 要素だけです。それより先は「+1」か「そのまま」で近似しています。表の大きさと精度のバランスを、値の性質から決めています。
- **元の精度に見合った近似**: LogEst はもともと約 7% 刻みの粗い値です。補正値も整数に丸めていますが、元の値の精度以上の誤差は生みません。必要以上に正確にしないことで、処理を軽く保っています。
- **見積もりの合成に使える**: クエリの計画では「この索引で探す場合のコスト」と「ソートのコスト」を足す、といった計算が頻繁に出てきます。掛け算は LogEst 同士の `+`、足し算はこの関数、と使い分けることで、見積もりをすべて小さな整数のまま計算できます。

## まとめ

- 対数で持った値の掛け算は足し算になるが、足し算には補正が要る。
- その補正値は 2 つの値の差だけで決まるので、小さな表にしておける。
- 差が大きければ小さいほうは無視する、という近似で表の大きさを抑えられる。
- 近似の精度は、扱うデータそのものの精度に合わせれば十分。
