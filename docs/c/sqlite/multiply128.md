## ひとことで

`sqlite3Multiply128` は、64 ビットの符号なし整数 `a` と `b` を掛けて、**128 ビットの正確な積** を求める関数です。
下位 64 ビットは `*pLo` に書き込み、上位 64 ビットを戻り値で返します。
SQLite は文字列と浮動小数点数を相互に変換するときにこの関数を使っています。

## コード

::: code-group

```c:line-numbers=475 [日本語訳]
/*
** 2 つの入力を掛けて 128 ビットの結果を得る。結果の
** 下位 64 ビットを *pLo に書き込み、上位
** 64 ビットを返す。
*/
static u64 sqlite3Multiply128(u64 a, u64 b, u64 *pLo){
#if defined(SQLITE_USE_UINT128)
  __uint128_t r = (__uint128_t)a * b;
  *pLo = (u64)r;
  return (u64)(r>>64);
#elif defined(_WIN64) && !defined(SQLITE_DISABLE_INTRINSIC)
  *pLo = a*b;
  return __umulh(a, b);
#else
  u64 a0 = (u32)a;
  u64 a1 = a >> 32;
  u64 b0 = (u32)b;
  u64 b1 = b >> 32;
  u64 a0b0 = a0 * b0;
  u64 a1b1 = a1 * b1;
  u64 a0b1 = a0 * b1;
  u64 a1b0 = a1 * b0;
  u64 t = (a0b0 >> 32) + (u32)a0b1 + (u32)a1b0;
  *pLo = (a0b0 & UINT64_C(0xffffffff)) | (t << 32);
  return a1b1 + (a0b1>>32) + (a1b0>>32) + (t>>32);
#endif
}
```

## 前提知識

- **`u64` と `u32`**: SQLite が定義している符号なし 64 ビット整数と 32 ビット整数の型名です。符号なし整数は負の数を持たず、範囲を超えた分は切り捨てられます（2 の 64 乗で割った余りになる）。
- **掛け算のあふれ**: 64 ビット同士を掛けると、答えは最大で 128 ビットになります。C の `a * b` は下位 64 ビットしか残さないので、上位の部分は失われます。
- **`u64 *pLo`**: 「`u64` を指すポインタ」です。関数は `*pLo = ...` と書くことで、呼び出し側の変数に値を書き込めます。C の関数は戻り値を 1 つしか返せないので、2 つ目の結果をこうして返します。
- **`__uint128_t`**: GCC や Clang が持っている 128 ビットの符号なし整数型です。C の標準ではありません。
- **`__umulh`**: Microsoft のコンパイラが提供する組み込み関数で、64 ビット同士の積の上位 64 ビットを返します。
- **`#if` / `#elif` / `#else`**: コンパイル前に条件で使うコードを選ぶ仕組みです。上から順に条件を調べ、最初に当てはまった部分だけが残ります。
- **`>>` と `&`**: `>>` は右シフト、`&` はビットごとの AND です。`a >> 32` は上位 32 ビット、`(u32)a` は下位 32 ビットを取り出します。

## 何をしているか

### 1. 128 ビット型が使える場合

```c:line-numbers=481
#if defined(SQLITE_USE_UINT128)
  __uint128_t r = (__uint128_t)a * b;
  *pLo = (u64)r;
  return (u64)(r>>64);
```

`SQLITE_USE_UINT128` は、関数の直前の `#if` で「GCC 系で 64 ビット CPU（x86_64、aarch64、64 ビット RISC-V）」のときに定義されます。
このときは 128 ビット型で掛け算して、下位をそのまま `*pLo` に、64 ビット右へずらした上位を戻り値にします。
コンパイラはこれを CPU の 64×64→128 ビットの掛け算命令 1 つにしてくれるのが普通です。

### 2. Windows の 64 ビット環境

```c:line-numbers=485
#elif defined(_WIN64) && !defined(SQLITE_DISABLE_INTRINSIC)
  *pLo = a*b;
  return __umulh(a, b);
```

下位 64 ビットは普通の `a*b` で求まります。上位は `__umulh` に任せます。

### 3. どれも使えない場合は筆算

```c:line-numbers=488
#else
  u64 a0 = (u32)a;
  u64 a1 = a >> 32;
  u64 b0 = (u32)b;
  u64 b1 = b >> 32;
  u64 a0b0 = a0 * b0;
  u64 a1b1 = a1 * b1;
  u64 a0b1 = a0 * b1;
  u64 a1b0 = a1 * b0;
  u64 t = (a0b0 >> 32) + (u32)a0b1 + (u32)a1b0;
  *pLo = (a0b0 & UINT64_C(0xffffffff)) | (t << 32);
  return a1b1 + (a0b1>>32) + (a1b0>>32) + (t>>32);
```

64 ビットの数を「上位 32 ビット」と「下位 32 ビット」に分けます。
`a = a1×2^32 + a0`、`b = b1×2^32 + b0` と書けるので、

`a×b = a1b1×2^64 + (a0b1 + a1b0)×2^32 + a0b0`

になります。32 ビット同士の積は必ず 64 ビットに収まるので、4 つの積 `a0b0`〜`a1b0` はあふれずに計算できます。

あとは筆算の「繰り上がり」をどう扱うかです。

- `t` は、2^32 の桁に集まる値の合計です。`a0b0` の上位 32 ビットと、`a0b1`・`a1b0` の下位 32 ビットを足します。32 ビットの値 3 つの合計なので最大でも 34 ビットほどで、64 ビットに収まります。
- `*pLo = ...` で、下位 64 ビットを「`a0b0` の下位 32 ビット」と「`t` の下位 32 ビットを上に置いたもの」から組み立てます。
- `return` の式で、上位 64 ビットに `a1b1`、`a0b1` と `a1b0` の上位 32 ビット、そして `t` からの繰り上がり `t>>32` を足します。

小さな例で確かめます。`a = b = 2^32`（`a1=1, a0=0`）なら、`a1b1 = 1` 以外は 0 で、`t = 0` です。下位は 0、上位は 1 となり、2^64 という正しい答えになります。

## ここがすごい

- **速い方法から順に選ぶ 3 段構え**: 128 ビット型や組み込み関数があればそれを使い、CPU の専用命令の速さを活かします。どれもなければ、標準の C だけで書かれた筆算で同じ結果を出します。どの環境でも動き、使える環境では速い、という SQLite の移植性の考え方がよく表れています。
- **繰り上がりを 1 つの変数に集める**: 筆算で難しいのは、途中の足し算があふれないようにすることです。真ん中の桁の 3 つの値を、あらかじめ 32 ビットずつに切ってから足すことで、64 ビットの変数 `t` に安全に収めています。上位 32 ビットの部分は `return` の式で直接上位側に足すので、あふれる心配がありません。
- **戻り値とポインタで 2 つの結果を返す**: 上位を戻り値、下位を `*pLo` に分けて返すことで、呼び出し側は上位だけが必要な場合（戻り値を `>>32` してすぐ使う呼び出しもあります）にも書きやすくなっています。
- **定数の書き方**: `UINT64_C(0xffffffff)` は、定数を確実に 64 ビットの型として扱わせるための標準マクロです。

## まとめ

- 64 ビット同士の積は 128 ビットになり、C の `*` は下位 64 ビットしか残さない。
- 大きな数の掛け算は、半分の幅に分けて 4 つの積を足す「筆算」で組み立てられる。
- 途中の和は、あふれない大きさに切ってから足すのがこつ。
- 速い専用機能を優先し、ないときは標準 C の実装に落とす、という切り替えで移植性と速度を両立できる。
