## ひとことで

`compare2pow63` は、ちょうど 19 桁の数字の文字列を、**2 の 63 乗 = `9223372036854775808`** と比べる関数です。
小さければ負、等しければ 0、大きければ正を返します。
SQLite が文字列を 64 ビット整数に変換するとき（`sqlite3Atoi64` の中）、結果が整数の範囲に収まるかを確かめるために使われます。

## コード

::: code-group

```c:line-numbers=1133 [日本語訳]
/*
** 19 文字の文字列 zNum を、2^63 の値を文字で表したもの
** 9223372036854775808 と比べる。zNum がその文字列より小さい、
** 等しい、大きいに応じて、負・0・正を返す。
** zNum はちょうど 19 文字でなければならない。
**
** memcmp() と違い、この関数は、違いが最後の桁だけのときには
** 最後の桁の値の差を返すことが保証されている。
** たとえば、
**
**      compare2pow63("9223372036854775800", 1)
**
** は -8 を返す。
*/
static int compare2pow63(const char *zNum, int incr){
  int c = 0;
  int i;
                    /* 012345678901234567 */
  const char *pow63 = "922337203685477580";
  for(i=0; c==0 && i<18; i++){
    c = (zNum[i*incr]-pow63[i])*10;
  }
  if( c==0 ){
    c = zNum[18*incr] - '8';
    testcase( c==(-1) );
    testcase( c==0 );
    testcase( c==(+1) );
  }
  return c;
}
```

```c:line-numbers=1133 [原文]
/*
** Compare the 19-character string zNum against the text representation
** value 2^63:  9223372036854775808.  Return negative, zero, or positive
** if zNum is less than, equal to, or greater than the string.
** Note that zNum must contain exactly 19 characters.
**
** Unlike memcmp() this routine is guaranteed to return the difference
** in the values of the last digit if the only difference is in the
** last digit.  So, for example,
**
**      compare2pow63("9223372036854775800", 1)
**
** will return -8.
*/
static int compare2pow63(const char *zNum, int incr){
  int c = 0;
  int i;
                    /* 012345678901234567 */
  const char *pow63 = "922337203685477580";
  for(i=0; c==0 && i<18; i++){
    c = (zNum[i*incr]-pow63[i])*10;
  }
  if( c==0 ){
    c = zNum[18*incr] - '8';
    testcase( c==(-1) );
    testcase( c==0 );
    testcase( c==(+1) );
  }
  return c;
}
```

## 前提知識

- **64 ビット符号付き整数の範囲**: `-9223372036854775808`（-2^63）から `9223372036854775807`（2^63-1）までです。正の側は 2^63 に 1 足りません。そのため、`9223372036854775808` は負の符号が付いていれば収まり、付いていなければあふれます。
- **`const char *zNum`**: 文字の並びの先頭を指すポインタです。`zNum[i]` で `i` 番目の文字を読めます。
- **文字の引き算**: C では文字は数値（文字コード）です。`'7' - '2'` は 5 になります。数字の文字同士を引けば、その数字の差が求まります。
- **`incr`**: 文字の間隔です。普通の文字列（UTF-8）なら 1 ですが、UTF-16（1 文字が 2 バイト）の文字列では 2 になります。`zNum[i*incr]` で、どちらの形式でも `i` 番目の数字を読めます。
- **`for(i=0; c==0 && i<18; i++)`**: `c` が 0 のあいだ、かつ `i` が 18 未満のあいだ繰り返します。違う桁が見つかった時点で止まります。
- **`testcase`**: SQLite のテスト用マクロで、その条件が成り立つ場合がテストで通ったかを記録します。普通のビルドでは何もしません。

## 何をしているか

### 1. 比べる相手の文字列

```c:line-numbers=1150
                    /* 012345678901234567 */
  const char *pow63 = "922337203685477580";
```

`pow63` は `"922337203685477580"` で、2^63 の **最初の 18 桁** だけです。最後の `8` はあえて入れていません。
その上のコメント `012345678901234567` は、各文字の添字を示す目盛りです。

### 2. 上から 18 桁を比べる

```c:line-numbers=1152
  for(i=0; c==0 && i<18; i++){
    c = (zNum[i*incr]-pow63[i])*10;
  }
```

1 桁ずつ「入力の数字 − 2^63 の数字」を計算し、**10 倍して** `c` に入れます。
差が 0 でなければループが止まり、その時点の `c` が答えになります。

たとえば `zNum = "9300000000000000000"` なら、`i=0` で `9-9=0`、`i=1` で `3-2=1` なので `c = 10` となり、正の値が返ります。
19 桁の数どうしなので、上の桁で大きいほうが全体でも大きい、というのが比較の根拠です。

### 3. 18 桁まで同じなら最後の桁

```c:line-numbers=1155
  if( c==0 ){
    c = zNum[18*incr] - '8';
    testcase( c==(-1) );
    testcase( c==0 );
    testcase( c==(+1) );
  }
```

最後の桁は `'8'` と比べ、その差を **10 倍せずに** そのまま `c` にします。

コメントの例 `"9223372036854775800"` では、18 桁目までは一致し、最後が `'0'` なので `0 - 8 = -8` が返ります。
`"9223372036854775808"` ならちょうど 0、`"9223372036854775809"` なら 1 です。

### 4. 呼び出し側での使い方

`sqlite3Atoi64` では `j = i>19*incr ? 1 : compare2pow63(zNum, incr);` として、19 桁より多ければ比べるまでもなく「大きい」、19 桁ちょうどならこの関数で比べます。
負なら収まる、正ならあふれ、0 なら「負の数なら収まるが、正の数なら 1 だけあふれる」という特別扱いになります。

## ここがすごい

- **数値に変換せずに範囲を調べる**: 範囲外かどうかを知りたいのに、先に 64 ビット整数へ変換するとその時点であふれてしまいます。文字列のまま比べれば、あふれの心配はありません。19 桁ちょうどのときだけ比較が要る、と桁数で場合分けしているのも無駄がありません。
- **10 倍の小技**: 上の 18 桁の差は 10 倍し、最後の桁の差はそのまま返します。こうすると、上の桁で差がついたときは戻り値の絶対値が必ず 10 以上になり、最後の桁だけが違うときは -8〜+1 の範囲になります。コメントにあるとおり、`memcmp` と違って「最後の桁だけが違う場合は、その桁の差そのもの」を返すことが保証されます。
- **`incr` で UTF-8 と UTF-16 を共通化**: SQLite は UTF-16 の文字列も扱います。数字はどちらの形式でも同じ文字コードなので、読む間隔だけを変えれば同じ関数で処理できます。
- **境界の値を丁寧に扱う**: 2^63 そのものは、負なら最小値として収まり、正ならあふれます。この「ちょうど境界」を 0 という戻り値で区別できるので、呼び出し側は符号を見て正しく判断できます。

## まとめ

- 64 ビット整数に収まるかは、変換する前に文字列のまま調べると安全。
- 同じ桁数の数字列は、上の桁から比べれば大小がわかる。
- 差に重みを付ける（10 倍する）と、どの桁で差がついたかを戻り値に込められる。
- 整数の範囲は負の側が 1 つ広い。境界の値は特別に扱う必要がある。
