## ひとことで

`sqlite3Strlen30` は、C の文字列の長さを返す関数です。ただし標準の `strlen` と違い、**結果を下位 30 ビットに切り詰めて** 返します。
`sqlite3Strlen30("abc")` は `3` ですが、1 GiB を超えるような巨大な文字列では、本当の長さより小さい値が返ることがあります。
その代わり、**結果は絶対に負にならず、`int` で計算しても簡単にはあふれない** ことが保証されます。

## コード

::: code-group

```c:line-numbers=91 [日本語訳]
/*
** 32 ビット符号付き整数の下位 30 ビットに収まる範囲に制限した、
** 文字列の長さを計算する。
**
** 返す値は決して負にならない。また、実際の文字列の長さより大きく
** なることもない。とても長い文字列（1GiB を超えるもの）では、
** 返す値が本当の文字列の長さより小さくなることがある。
*/
int sqlite3Strlen30(const char *z){
  if( z==0 ) return 0;
  return 0x3fffffff & (int)strlen(z);
}
```

```c:line-numbers=91 [原文]
/*
** Compute a string length that is limited to what can be stored in
** lower 30 bits of a 32-bit signed integer.
**
** The value returned will never be negative.  Nor will it ever be greater
** than the actual length of the string.  For very long strings (greater
** than 1GiB) the value returned might be less than the true string length.
*/
int sqlite3Strlen30(const char *z){
  if( z==0 ) return 0;
  return 0x3fffffff & (int)strlen(z);
}
```

:::

## 前提知識

- **C の文字列**: `char` の並びの最後に値 `0` のバイトを置いたものです。長さは先頭から `0` を探して数えます。
- **`const char *z`**: 「文字（`char`）の並びの先頭を指すポインタ」です。ポインタはメモリ上の場所（アドレス）を持つ変数で、`const` は「この関数の中では中身を書き換えない」という約束です。
- **`z==0`**: ポインタが 0（ヌルポインタ、どこも指していない状態）かどうかの判定です。ヌルポインタを `strlen` に渡すとプログラムが落ちるので、先に調べています。
- **`strlen`**: 標準ライブラリの関数で、文字列の長さを `size_t`（長さを表す符号なし整数型。64 ビット環境ではふつう 64 ビット）で返します。
- **`(int)` キャスト**: 値を `int`（ふつう 32 ビットの符号付き整数）に変換します。`int` に入りきらない大きな値を変換すると、下位のビットだけが残るのが一般的です。
- **`0x3fffffff`**: 16 進数で、2 進数にすると下位 30 ビットがすべて 1、上位 2 ビットが 0 の値です。10 進数では 1073741823（約 10 億）です。
- **`&`（ビットごとの AND）**: 両方のビットが 1 のところだけ 1 を残します。マスクと AND を取ると、マスクで 1 になっている部分だけが残ります。

## 何をしているか

### 1. ヌルポインタなら 0

```c:line-numbers=100
  if( z==0 ) return 0;
```

`if( z==0 ) return 0;` で、文字列がない場合は長さ 0 として扱います。
呼び出し側でいちいちヌルかどうかを確かめなくて済むので、使う側のコードが短くなります。

### 2. 長さを数えて、下位 30 ビットだけ残す

```c:line-numbers=101
  return 0x3fffffff & (int)strlen(z);
```

`strlen(z)` で長さを求め、`int` に変換してから `0x3fffffff` と AND を取ります。

- `z = "hello"` なら `strlen` は 5。2 進数で `101` なので、マスクしても 5 のままです。
- 1 GiB（2 の 30 乗 = 1073741824 バイト）ちょうどの文字列なら、長さは 2 進数で「1 の後に 0 が 30 個」です。下位 30 ビットはすべて 0 なので、結果は 0 になります。

ふつうの用途では文字列が 1 GiB を超えることはないので、実質的には `strlen` と同じ値が返ります。

## ここがすごい

- **負にならないことが型の外で保証される**: 符号付きの `int` は最上位ビットが 1 だと負の数になります。マスクで上位 2 ビットを必ず 0 にしているので、結果が負になることはありません。長さが負になると、配列の添字やメモリ確保のサイズ計算で深刻なバグになるため、その芽を最初から摘んでいます。
- **足し算をしてもあふれにくい**: 30 ビットの値は最大で約 10 億です。`int` の最大値は約 21 億なので、30 ビットの長さ同士を 1 回足しても `int` の範囲に収まります。SQLite の内部では長さを `int` で扱う場面が多く、「2 つの文字列をつなぐ長さを計算したら負になった」という事故を防げます。
- **コメントで約束をはっきり書いている**: 関数の上のコメントは、「負にならない」「本当の長さより大きくならない」「1 GiB を超えると短く返ることがある」という 3 つの性質を明言しています。関数の限界を隠さず、使う側が判断できるようにしているのが SQLite らしいところです。
- **本当の長さより大きくはならない**: マスクはビットを消すだけなので、結果は必ず元の値以下です。長さを小さく見積もる分には、バッファ（データを入れる領域）の外を読み書きする危険はありません。安全側に倒れる設計です。
- **SQLite 自体にも上限がある**: SQLite は文字列や BLOB の長さに上限（既定で 10 億バイト）を設けています。その範囲なら 30 ビットで足りるので、この切り詰めが実害になることはまずありません。

素直に `return (int)strlen(z);` と書くと、2 GiB を超える文字列で負の値が返ることがあり得ます。たった 1 つの AND で、その可能性を消しているのです。

## まとめ

- 長さやサイズは「負にならない」「足してもあふれない」範囲に収めておくと、後の計算が安全になる。
- `0x3fffffff` のようなマスクで上位ビットを消すと、値の範囲を簡単に制限できる。
- ヌルポインタを 0 として扱う小さな気配りで、呼び出し側のコードが短くなる。
- 関数の限界は、コメントで正直に書いておく。
