## ひとことで

`Curl_timestrcmp` は 2 つの文字列が同じかどうかを調べる関数です。ふつうの `strcmp` と違い、**最初に違う文字を見つけても途中で抜けません**。かかる時間が「どこで違ったか」に左右されないので、比較にかかった時間から秘密を推測する攻撃（タイミング攻撃）を難しくします。

## コード

::: code-group

```c:line-numbers=112 [日本語訳]
/*
 * Curl_timestrcmp() は 2 つの文字列が同じなら 0 を返す。この関数にかかる
 * 時間は短い方の文字列の長さで決まり、中身では決まらない。
 */
int Curl_timestrcmp(const char *a, const char *b)
{
  int match = 0;
  int i = 0;

  if(a && b) {
    while(1) {
      match |= a[i] ^ b[i];
      if(!a[i] || !b[i])
        break;
      i++;
    }
  }
  else
    return a || b;
  return match;
}
```

## 前提知識

- **`const char *a`**: 文字が並んでいる場所（アドレス）を指すポインタです。`a[i]` で先頭から `i` 番目の文字を読めます。`const` は「この関数は中身を書き換えない」という約束です。
- **C の文字列**: 文字の並びの最後に値 0 のバイト（`'\0'`、ヌル文字）を置いて終わりを示します。長さは別に持っていません。
- **`NULL`**: 「どこも指していない」ことを表す特別なポインタの値です。条件式で `if(a && b)` と書くと「a も b も NULL でない」という意味になります。
- **`^`（XOR、排他的論理和）**: ビットごとに「違えば 1、同じなら 0」を計算します。`'A' ^ 'A'` は 0、`'A' ^ 'B'` は 0 でない値になります。
- **`|=`（OR 代入）**: `match |= x` は `match = match | x` の略です。OR は「どちらかが 1 なら 1」なので、一度 1 になったビットは二度と 0 に戻りません。
- **`while(1)`**: 条件が常に真の無限ループです。中の `break` で抜けます。
- **`!a[i]`**: `a[i]` が 0（文字列の終わり）なら真になります。
- **`return a || b;`**: `||` は「どちらかが真なら 1、両方偽なら 0」を返します。

## 何をしているか

### 1. 両方が NULL でないときだけ比べる

```c:line-numbers=121
  if(a && b) {
```

`if(a && b)` で、2 つとも実際の文字列を指しているかを確かめます。どちらかが `NULL` なら、最後の `else` に進んで `return a || b;` を返します。両方 `NULL` なら 0（同じとみなす）、片方だけ `NULL` なら 1（違う）です。

### 2. 差分を貯め続けるループ

```c:line-numbers=122
    while(1) {
      match |= a[i] ^ b[i];
      if(!a[i] || !b[i])
        break;
      i++;
    }
```

ループの最初の `match |= a[i] ^ b[i];` が心臓部です。同じ文字なら XOR は 0 なので `match` は変わりません。違う文字なら XOR が 0 でない値になり、そのビットが `match` に OR で残ります。

`a = "abc"`, `b = "abd"` で追ってみます。

- `i = 0`: `'a' ^ 'a'` = 0 → `match = 0`
- `i = 1`: `'b' ^ 'b'` = 0 → `match = 0`
- `i = 2`: `'c' ^ 'd'` = 0x63 ^ 0x64 = 0x07 → `match = 7`
- `i = 3`: 両方 `'\0'`。`0 ^ 0` = 0 で `match` は 7 のまま。次の `if` で終わりを検出して抜ける

最後に `return match;` で 7 を返します。0 でないので「違う」と判定されます。

### 3. どちらかの終わりで止まる

```c:line-numbers=124
      if(!a[i] || !b[i])
        break;
```

`if(!a[i] || !b[i]) break;` は、どちらかの文字列が終わった時点でループを抜けます。比較の **後** にこの判定があるのがポイントです。`a = "ab"`, `b = "abc"` なら `i = 2` で `'\0' ^ 'c'` が `match` に入ってから抜けるので、長さが違うことも正しく「違う」と判定されます。

## ここがすごい

- **早期終了しない**: 素直な比較は `if(a[i] != b[i]) return 1;` と書き、違いを見つけた瞬間に戻ります。すると「1 文字目から違う入力」は速く、「途中まで合っている入力」は遅く返ってきます。攻撃者は時間の差を手がかりに、1 文字ずつ正解を当てていけます。この関数はループを抜ける条件が「文字列の終わり」だけなので、どこで違っても同じ回数だけ回ります。
- **分岐を減らす XOR と OR**: 比較の結果で `if` を分けず、ビット演算で差分を一つの変数にまとめています。OR は一度立ったビットを消さないので、「どこかで一度でも違った」という事実がループの最後まで残ります。
- **割り切りもはっきりしている**: 関数直前のコメントに「かかる時間は短い方の文字列の長さで決まり、中身では決まらない」と書かれています。つまり長さは隠せません。中身の一致・不一致を時間に出さない、という目的に絞った設計です。
- **戻り値は「0 かどうか」だけに意味がある**: `strcmp` のような大小関係は返しません。秘密の比較では「同じか違うか」だけが必要なので、それで十分です。

## まとめ

- 秘密の値を比べるときは、違いを見つけても途中でやめない比較を使う。
- `match |= a ^ b` は「一度でも違ったら 0 でなくなる」差分の貯め方。
- 終了判定を比較の後に置くと、長さの違いも同じ仕組みで検出できる。
- 何を隠せて何を隠せないか（ここでは長さ）をコメントで明示しておくと、使う側が誤解しにくい。
