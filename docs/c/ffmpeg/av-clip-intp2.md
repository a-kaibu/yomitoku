## ひとことで

`av_clip_intp2_c(a, p)` は、符号付き整数 `a` を **−2^p 〜 2^p−1 の範囲** に収める関数です。
たとえば `p = 7` なら範囲は −128〜127（符号付き 8 ビットの範囲）で、`200` は `127` に、`-300` は `-128` になります。
音声のサンプル値を「符号付き 16 ビットに収める」「24 ビットに収める」といった場面で使われます。比較を使わず、足し算・AND・XOR だけで書かれています。

## コード

::: code-group

```c:line-numbers=260 [日本語訳]
/**
 * 符号付き整数を -(2^p),(2^p-1) の範囲に収める。
 * @param  a 収める値
 * @param  p 収める境界のビット位置
 * @return 収めた値
 */
static av_always_inline av_const int av_clip_intp2_c(int a, int p)
{
    if (((unsigned)a + (1U << p)) & ~((2U << p) - 1))
        return (a >> 31) ^ ((1 << p) - 1);
    else
        return a;
}
```


## 前提知識

- **`int` と `unsigned`**: `int` は符号付き 32 ビット整数、`unsigned`（`unsigned int`）は符号なし 32 ビット整数です。`(unsigned)a` は `a` のビット列はそのままに「符号なしとして見る」変換です。符号なし整数の足し算はあふれても 2^32 で割った余りになり、エラーになりません。
- **`1U << p`**: `1U` は符号なしの 1 です。`<<` は左シフトで、`1U << p` は 2^p になります。`p = 7` なら 128 です。
- **`(2U << p) - 1`**: 2^(p+1) − 1、つまり下位 p+1 ビットがすべて 1 の値です。`p = 7` なら `0xFF` です。`~` を付けるとその逆で、「下位 p+1 ビット以外がすべて 1」になります。
- **2 の補数と右シフト**: 負の数は符号ビット（最上位ビット）が 1 です。`a >> 31` は、負なら全ビット 1 の `-1`、0 以上なら `0` になります（主要なコンパイラは符号を埋める算術シフトをします）。
- **XOR `^`**: 桁ごとに「違えば 1」の演算です。`0 ^ x = x`、`-1 ^ x = ~x`（全ビット反転）になります。
- **`static`、`av_always_inline`、`av_const`**: ファイル内専用の関数で、必ずインライン展開してほしい、副作用がない、という指定です。

## 何をしているか

### 1. 範囲を 0 始まりにずらす

```c:line-numbers=268
    if (((unsigned)a + (1U << p)) & ~((2U << p) - 1))
```

範囲 −2^p〜2^p−1 に 2^p を足すと、0〜2^(p+1)−1 になります。
そこで `(unsigned)a + (1U << p)` を計算し、その結果が下位 p+1 ビットに収まるかを `& ~((2U << p) - 1)` で調べます。0 なら範囲内です。

`p = 7` で具体的に見ます。

- `a = 100`: `100 + 128 = 228`。`228 & ~0xFF = 0` → 範囲内なので `return a;` で `100` を返す
- `a = 200`: `200 + 128 = 328`（`0x148`）。`0x148 & ~0xFF = 0x100` → 範囲外
- `a = -300`: 符号なしとして見ると非常に大きな数（2^32 − 300）です。128 を足しても大きいままなので、上位ビットが立ち範囲外

負の側にはみ出した値も、符号なしの世界では「大きすぎる値」になるので、**上下両方のはみ出しを 1 回の判定で捕まえられます**。

### 2. 端の値を XOR で作る

```c:line-numbers=269
        return (a >> 31) ^ ((1 << p) - 1);
```

範囲外のときは `(a >> 31) ^ ((1 << p) - 1)` を返します。`(1 << p) - 1` は 2^p−1（`p = 7` なら 127）です。

- `a = 200`（正）: `a >> 31 = 0`。`0 ^ 127 = 127` → 上限
- `a = -300`（負）: `a >> 31 = -1`。`-1 ^ 127` は 127 の全ビット反転で `-128` → 下限

2 の補数では `~(2^p − 1) = −2^p` なので、上限をビット反転するとちょうど下限になります。この性質のおかげで、上限と下限を 1 つの式で切り替えられます。

## ここがすごい

- **はみ出し判定が 1 回**: 素直に書くと `if (a < -(1 << p)) ... else if (a > (1 << p) - 1) ...` と 2 回比較します。範囲を 0 始まりにずらして符号なしで見る、というひと手間で判定が 1 回になります。これは「`lo <= x && x <= hi` を `(unsigned)(x - lo) <= hi - lo` に変える」という定番の技の応用です。
- **符号なしで計算してあふれを安全にしている**: 符号付き整数の足し算があふれると C では未定義動作ですが、`(unsigned)a` に変えてから足しているので、あふれても決まった結果になります。
- **上限と下限が補数の関係**: 上限 2^p−1 と下限 −2^p はビット反転の関係にあります。`a >> 31` で「0 か全ビット 1」を作り、XOR で「そのまま」か「反転」を選ぶので、分岐なしに正しい端の値が出ます。
- **p を引数にした汎用版**: 8 ビット版・16 ビット版を別々に書く代わりに、p で範囲を指定できます。p が定数で呼ばれれば、インライン展開後に定数がたたみ込まれて、専用版と同じ効率になります。

## まとめ

- 範囲チェック `lo <= x <= hi` は、`x - lo` を符号なしで見て 1 回の比較（ここでは AND）にできる。
- 2^(p+1) の範囲に収まるかは「下位 p+1 ビット以外が 0 か」で判定できる。
- `a >> 31` で作った 0 / −1 と XOR を組み合わせると、「そのまま」と「反転」を分岐なしに選べる。
- 2 の補数では 2^p−1 の反転が −2^p になる。符号付き範囲の上限と下限はこの関係にある。
