## ひとことで

`ff_log2_c(v)` は、符号なし整数 `v` の **最上位の 1 が何桁目にあるか**、つまり floor(log2(v)) を返します。`v = 1000` なら 2^9 = 512 ≤ 1000 < 1024 = 2^10 なので `9` です。
32 ビットを 1 ビットずつ調べる代わりに、「上半分に 1 があるか」で 2 回範囲を絞り、最後の 8 ビットは **あらかじめ作った 256 要素の表** を引いて答えます。

## コード

```c:line-numbers=50
#ifndef ff_log2
#define ff_log2 ff_log2_c
static av_always_inline av_const int ff_log2_c(unsigned int v)
{
    int n = 0;
    if (v & 0xffff0000) {
        v >>= 16;
        n += 16;
    }
    if (v & 0xff00) {
        v >>= 8;
        n += 8;
    }
    n += ff_log2_tab[v];

    return n;
}
#endif
```

`ff_log2_tab` は 0〜255 それぞれの floor(log2) を並べた表で、関数の少し上で `extern const uint8_t ff_log2_tab[256];` と宣言されています。CPU に「先頭の 0 を数える」命令があるときは、同じファイルの上のほうで次の定義が先に作られ、この C 版は使われません。

```c:line-numbers=38
#if defined(__GNUC__) || AV_HAS_BUILTIN(__builtin_clz)
#ifndef ff_log2
#   define ff_log2(x) (31 - __builtin_clz((x)|1))
```

## 前提知識

- **`unsigned int`**: 符号なし 32 ビット整数です。
- **16 進数とマスク**: `0xffff0000` は上位 16 ビットだけが 1、`0xff00` は 8〜15 ビット目だけが 1 の値です。`v & 0xffff0000` が 0 でなければ「上位 16 ビットに 1 がある」とわかります。
- **右シフト `>>=`**: `v >>= 16` は `v = v >> 16` の短縮形で、ビットを 16 桁右にずらします。上位 16 ビットが下位に降りてきます。
- **配列**: `ff_log2_tab[v]` は表の v 番目の要素です。`extern` は「本体は別のファイルにある」という宣言です。
- **`#ifndef` / `#define` / `#endif`**: 「まだ `ff_log2` が定義されていなければ」この部分を使う、という条件付きコンパイルです。CPU 別のヘッダや組み込み関数の版が先に定義していれば、この C 版は飛ばされます。
- **`static`、`av_always_inline`、`av_const`**: ファイル内専用、必ずインライン展開、副作用なし、という指定です。

## 何をしているか

### 1. 他の実装がなければ C 版を使う

```c:line-numbers=50
#ifndef ff_log2
#define ff_log2 ff_log2_c
```

`#ifndef ff_log2` で、まだ速い版が定義されていないときだけ、`ff_log2` を `ff_log2_c` に置き換えるよう定義します。

### 2. 上位 16 ビットで絞る

```c:line-numbers=55
    if (v & 0xffff0000) {
        v >>= 16;
        n += 16;
    }
```

`v & 0xffff0000` が 0 でなければ、最上位の 1 は 16 桁目以上にあります。そこで `v` を 16 ビット右にずらし、答えの `n` に 16 を足します。0 なら何もしません。

### 3. さらに 8 ビットで絞る

```c:line-numbers=59
    if (v & 0xff00) {
        v >>= 8;
        n += 8;
    }
```

残った 16 ビットのうち、上位 8 ビット（`0xff00`）に 1 があれば、8 ビットずらして `n` に 8 を足します。これで `v` は 0〜255 に収まります。

### 4. 表を引く

```c:line-numbers=63
    n += ff_log2_tab[v];
```

`ff_log2_tab[v]` で、0〜255 の floor(log2) を一度に得て `n` に足します。

`v = 1000`（16 進数 `0x3E8`）で追います。

- 上位 16 ビットの判定: `0x3E8 & 0xffff0000 = 0` → 何もしない
- 上位 8 ビットの判定: `0x3E8 & 0xff00 = 0x300` → `v = 0x3E8 >> 8 = 3`、`n = 8`
- 表引き: `ff_log2_tab[3] = 1` → `n = 9`

## ここがすごい

- **二分探索と表のいいとこ取り**: 32 ビットすべてを表で引くと 2^32 要素の表が必要で、現実的ではありません。逆に 1 ビットずつ調べると最大 32 回のループです。この実装は 2 回の絞り込みで 8 ビットまで減らし、残りを 256 バイトの小さな表に任せています。表は CPU のキャッシュに収まる大きさです。
- **分岐の回数が一定に近い**: どんな入力でも `if` は 2 回、表引きは 1 回です。入力によって処理時間が大きく変わりません。
- **0 でも壊れない**: `v = 0` のとき、どちらの `if` にも入らず `ff_log2_tab[0]` を返します。表の 0 番目を 0 にしておけば、log2(0) という数学的には定義できない入力でも安全な値が返ります。組み込み関数版も `(x)|1` として 0 を 1 として扱い、同じく 0 を返すよう合わせています。
- **速い版が自動で優先される**: `#ifndef` の仕組みで、CPU 専用の実装や `__builtin_clz`（先頭の 0 の数を数える組み込み関数）が使えればそちらが選ばれます。C 版は「どこでも動く最後の砦」です。16 ビット版の `ff_log2_16bit_c`（すぐ下にある）は、最初の絞り込みを省いた同じ形です。

## まとめ

- 最上位ビットの位置は「上半分に 1 があるか」を繰り返す二分探索で求められる。
- 範囲を小さくしてから表を引くと、表を小さく保てる。
- 0 のような数学的に未定義な入力にも、安全な値を決めておくと使いやすい。
- `#ifndef` で「速い版がなければ汎用版」を選ぶと、移植性と速さを両立できる。
