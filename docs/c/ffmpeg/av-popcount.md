## ひとことで

`av_popcount_c(x)` は、32 ビット整数 `x` の **1 になっているビットの個数**（population count、popcount）を返します。`x = 0xDA`（2 進数 `11011010`）なら `5` です。
32 回ループして 1 ビットずつ数える代わりに、**隣り合うビットの個数を足し合わせて、2 ビット → 4 ビット → 8 ビット → … と範囲を倍々に広げる** ことで、5 行の計算で答えを出します。

## コード

::: code-group

```c:line-numbers=430 [日本語訳]
/**
 * x の中で 1 になっているビットの数を数える
 * @param x ビットを数える値
 * @return x の中で 1 になっているビットの数
 */
static av_always_inline av_const int av_popcount_c(uint32_t x)
{
    x -= (x >> 1) & 0x55555555;
    x = (x & 0x33333333) + ((x >> 2) & 0x33333333);
    x = (x + (x >> 4)) & 0x0F0F0F0F;
    x += x >> 8;
    return (x + (x >> 16)) & 0x3F;
}
```

## 前提知識

- **`uint32_t`**: 符号なし 32 ビット整数です。
- **ビット演算**: `&` は桁ごとの AND、`>>` は右シフト（ビットを右にずらす）です。`x >> 1` は全ビットを 1 桁右へずらします。
- **マスク**: 特定のビットだけを取り出すための定数です。16 進数の `0x55555555` は 2 進数で `0101…0101`（2 ビットごとに下の 1 ビット）、`0x33333333` は `0011…0011`（4 ビットごとに下の 2 ビット）、`0x0F0F0F0F` は `00001111…`（8 ビットごとに下の 4 ビット）です。
- **`x -= y`、`x += y`**: `x = x - y`、`x = x + y` の短縮形です。
- **SWAR**: SIMD Within A Register の略で、1 つの整数を「小さな箱の並び」とみなし、全部の箱を一度の演算で同時に処理する技法です。
- **`static`、`av_always_inline`、`av_const`**: ファイル内専用で、必ずインライン展開してほしい、副作用がない、という指定です。

## 何をしているか

8 ビットだけ使う例 `x = 11011010`（10 進数 218、1 は 5 個）で追います。上位 24 ビットは 0 なので省略します。

### 1. 2 ビットごとの個数にする

```c:line-numbers=437
    x -= (x >> 1) & 0x55555555;
```

`x -= (x >> 1) & 0x55555555;` で、2 ビットの箱それぞれが「その 2 ビットに含まれる 1 の個数」に置き換わります。
2 ビットの値 `b1 b0` の 1 の個数は `b1 + b0` で、これは「2 ビットの値 − 上のビット」（`2*b1 + b0 − b1`）に等しい、という性質を使っています。

- 箱: `11 01 10 10` → 個数 `2 1 1 1` → `10 01 01 01`
- 計算: `x >> 1 = 01101101`、`& 0x55` で `01000101`。`11011010 − 01000101 = 10010101` ✓

### 2. 4 ビットごとに足す

```c:line-numbers=438
    x = (x & 0x33333333) + ((x >> 2) & 0x33333333);
```

`(x & 0x33333333) + ((x >> 2) & 0x33333333)` で、隣の 2 ビットの箱どうしを足して 4 ビットの箱にします。

- `10010101 & 00110011 = 00010001`、`(x >> 2) & 00110011 = 00100001`
- 足すと `00110010` → 上の 4 ビットが 3、下の 4 ビットが 2 ✓

### 3. 8 ビットごとに足す

```c:line-numbers=439
    x = (x + (x >> 4)) & 0x0F0F0F0F;
```

`(x + (x >> 4)) & 0x0F0F0F0F` で、隣の 4 ビットの箱を足して 8 ビットの箱にします。

- `00110010 + 00000011 = 00110101`、`& 0x0F` で `00000101` = 5 ✓

各箱の値は最大でも 8 なので 4 ビットに収まり、足す **前** にマスクしなくてもあふれません。そのため 4 ビットにまとめる段と違ってマスクが 1 回で済んでいます。

### 4. 16 ビット、32 ビットに広げる

```c:line-numbers=440
    x += x >> 8;
    return (x + (x >> 16)) & 0x3F;
```

`x += x >> 8` で隣の 8 ビットの箱を足し、`x + (x >> 16)` でさらに隣の 16 ビットを足します。最終的な答えは最大 32 で 6 ビットに収まるので、最後に `& 0x3F`（下位 6 ビット）だけを取り出します。途中で上位に残るごみは、この最後のマスクでまとめて捨てています。

## ここがすごい

- **ループも分岐もない**: 素直に書くと 32 回のループ（または「最下位の 1 を消す」ループ）になります。この方法は、ビット数が倍になっても段数が 1 つ増えるだけ（32 ビットで 5 段）です。分岐がないので、CPU の分岐予測の失敗も起きません。
- **マスクを省ける場所を見極めている**: 1 段目は引き算の性質で AND を 1 回減らし、3 段目は「足してもあふれない」ことを使って足した後にまとめてマスクし、4〜5 段目は最後のマスク 1 回にまとめています。必要な場所だけにマスクを置いた、無駄のない形です。
- **専用命令の代わり**: 関数名の `_c` は C で書いた汎用版の印です。CPU に popcount 命令があってコンパイラが使える場合、FFmpeg は別の定義を使い、ないときにこの版が使われます。
- **64 ビット版は 2 回呼ぶだけ**: 同じファイルの `av_popcount64_c` は、上下 32 ビットそれぞれにこの関数を呼んで足しています。部品を小さく保つと、組み合わせも簡単です。

## まとめ

- 1 の個数は「隣どうしを足して、箱を倍々に大きくする」分割統治で数えられる。
- 2 ビット `b1 b0` の個数は「値 − 上のビット」で求まる。
- 各段で箱があふれるかを考えると、マスクを省ける。
- 1 つの整数を小さな箱の並びとして同時に計算するのが SWAR の考え方。
