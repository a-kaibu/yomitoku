## ひとことで

`av_clip_uint8_c` は、整数 `a` を **0〜255 の範囲に押し込める**（クリップする）関数です。`300` なら `255`、`-20` なら `0`、`100` ならそのまま `100` を返します。
画像の画素値は 1 色あたり 0〜255 の 1 バイトで表すことが多く、計算の途中で範囲をはみ出した値を戻すために、動画処理ではこの操作が何百万回も呼ばれます。
FFmpeg はこれを「比較 2 回」ではなく、**ビット演算 1 回の判定** と **シフト 1 回** で書いています。

## コード

::: code-group

```c:line-numbers=205 [日本語訳]
/**
 * 符号付き整数を 0〜255 の範囲に収める。
 * @param a 収める値
 * @return 収めた値
 */
static av_always_inline av_const uint8_t av_clip_uint8_c(int a)
{
    if (a&(~0xFF)) return (~a)>>31;
    else           return a;
}
```

```c:line-numbers=205 [原文]
/**
 * Clip a signed integer value into the 0-255 range.
 * @param a value to clip
 * @return clipped value
 */
static av_always_inline av_const uint8_t av_clip_uint8_c(int a)
{
    if (a&(~0xFF)) return (~a)>>31;
    else           return a;
}
```

## 前提知識

- **`int` と `uint8_t`**: `int` は符号付き整数（ふつう 32 ビット）です。`uint8_t` は「符号なし 8 ビット整数」で、0〜255 の値だけを持てます。`uint8_t` を返す関数で `int` を返すと、下位 8 ビットだけが残ります。
- **2 の補数**: 負の数は「全ビットを反転して 1 を足す」形で表します。そのため負の数は必ず最上位ビット（符号ビット、32 ビットなら 31 番目）が 1 です。
- **ビット演算**: `&` は桁ごとの AND、`~` は全ビットの反転です。`0xFF` は 16 進数で 255、2 進数で下位 8 ビットがすべて 1 の値です。`~0xFF` は逆に「下位 8 ビットだけ 0、ほかは全部 1」になります。
- **右シフト `>>`**: `x >> 31` はビットを 31 桁右にずらします。符号付きの負の数を右シフトすると、ほとんどのコンパイラは空いた上位を符号ビットで埋めます（算術シフト）。その結果、負の数 `>> 31` は全ビット 1 の `-1`、0 以上の数 `>> 31` は `0` になります。
- **`static`、`av_always_inline`、`av_const`**: `static` はこのファイルの中だけで見える関数にする指定です。`av_always_inline` は「呼び出し元に必ず埋め込んで（インライン展開して）ほしい」、`av_const` は「引数だけで結果が決まり副作用がない」とコンパイラに伝える FFmpeg のマクロです。
- **`/** ... */`**: 複数行のコメントです。ここではドキュメント生成ツール向けの説明が書かれています。

## 何をしているか

### 1. 範囲外かどうかを 1 回で調べる

```c:line-numbers=212
    if (a&(~0xFF)) return (~a)>>31;
```

`a & (~0xFF)` は「`a` の下位 8 ビット以外に 1 が立っているか」を調べています。
0〜255 の値は下位 8 ビットに収まるので、結果は 0 です。
256 以上なら 9 ビット目より上に 1 があり、負の数なら符号ビットが 1 なので、どちらも結果が 0 以外になります。
つまり `a < 0 || a > 255` という 2 回の比較が、AND 1 回にまとまっています。

- `a = 100`（`0x64`）: `0x64 & ~0xFF = 0` → 範囲内なので `return a;` でそのまま返す
- `a = 300`（`0x12C`）: `0x12C & ~0xFF = 0x100` → 範囲外
- `a = -20`: 上位ビットがすべて 1 なので範囲外

### 2. 上と下のどちらに外れたかをシフトで決める

```c:line-numbers=212
    if (a&(~0xFF)) return (~a)>>31;
```

範囲外のとき、返す値は `(~a) >> 31` です。

- `a = 300` のとき、`~a` は負の数（符号ビットが 1）になります。これを 31 ビット右シフトすると全ビット 1 の `-1` になり、`uint8_t` に変換すると下位 8 ビットの `0xFF`、つまり **255** になります。
- `a = -20` のとき、`~a` は `19` で 0 以上です。31 ビット右シフトすると **0** になります。

「`a` が負なら 0、正なら 255」という場合分けを、`if` を使わず `~` とシフトだけで済ませています。

## ここがすごい

- **比較を減らす**: 素直に書けば `if (a < 0) return 0; if (a > 255) return 255; return a;` で、比較が 2 回あります。この実装は「範囲内かどうか」を 1 回の AND で判定するので、よくある「範囲内」の場合に分岐が 1 回で済みます。画素ごとに呼ばれる関数なので、この差が効いてきます。
- **答えをビットから作る**: 範囲外の場合も「どちらにはみ出したか」をもう一度比較せず、`~a` の符号ビットをそのまま全ビットに広げて 0 か 255 を作っています。返り値が `uint8_t` なので、`-1` の下位 8 ビットが自然に 255 になる点もうまく利用しています。
- **定数が範囲そのもの**: `0xFF` は「8 ビットに収まる最大値」なので、同じ形で 16 ビット版（`av_clip_uint16_c`、`0xFFFF` を使う）もすぐ作れます。実際に同じファイルに並んでいます。
- **アーキテクチャ別の差し替え**: 関数名の末尾 `_c` は「C で書いた汎用版」の印です。FFmpeg では、CPU によっては専用命令を使った版が `av_clip_uint8` として使われ、なければこの C 版が使われます。

注意点として、負の数の右シフトの結果は C の規格では「処理系定義」です。FFmpeg が対象にしている主要なコンパイラは算術シフトをするので、この書き方が成り立っています。

## まとめ

- 「範囲 0〜2^n−1 に入っているか」は `a & ~(2^n − 1)` が 0 かどうかで 1 回で判定できる。
- 負の数を 31 ビット右シフトすると `-1`、0 以上なら `0` になる。符号で場合分けしたいときに便利。
- 返り値の型（`uint8_t`）への変換で下位ビットだけが残ることも、計算の一部として使える。
- よく呼ばれる小さな関数ほど、分岐の数を減らす工夫が効く。
