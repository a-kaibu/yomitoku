## ひとことで

`PUT_UTF8(val, tmp, PUT_BYTE)` は、Unicode の文字番号（コードポイント）`val` を **UTF-8 のバイト列** に変換するマクロです。
たとえば `é`（U+00E9）は `C3 A9` の 2 バイト、`あ`（U+3042）は `E3 81 82` の 3 バイトになります。
1 バイトできるたびに、呼び出し側が渡した `PUT_BYTE` という「出力のしかた」を実行します。バイト数は `(av_log2(in) + 4) / 5` という 1 本の式で決めています。

## コード

```c:line-numbers=530
#define PUT_UTF8(val, tmp, PUT_BYTE)\
    {\
        int bytes, shift;\
        uint32_t in = val;\
        if (in < 0x80) {\
            tmp = in;\
            PUT_BYTE\
        } else {\
            bytes = (av_log2(in) + 4) / 5;\
            shift = (bytes - 1) * 6;\
            tmp = (256 - (256 >> bytes)) | (in >> shift);\
            PUT_BYTE\
            while (shift >= 6) {\
                shift -= 6;\
                tmp = 0x80 | ((in >> shift) & 0x3f);\
                PUT_BYTE\
            }\
        }\
    }
```

## 前提知識

- **UTF-8**: Unicode の文字を 1〜4 バイトで表す方式です。0x7F 以下は 1 バイトそのまま、それより大きい文字は「先頭バイト」と「続きのバイト」に分けます。先頭バイトは上位ビットに `110`（2 バイト）、`1110`（3 バイト）、`11110`（4 バイト）という印を持ち、続きのバイトは `10xxxxxx` の形で 6 ビットずつ値を運びます。
- **マクロ `#define`**: コンパイル前にコードを置き換える仕組みです。引数には値だけでなく **文（コードの断片）** も渡せます。ここでは `PUT_BYTE` に `*output++ = tmp;` のような文を渡します。行末の `\` は「マクロの定義が次の行に続く」という意味です。
- **`{ ... }` ブロック**: マクロ全体を波かっこで囲み、中で宣言した変数（`bytes`、`shift`、`in`）が外にもれないようにしています。
- **`av_log2(v)`**: v の最上位の 1 が何桁目かを返す FFmpeg の関数（floor(log2(v))）です。
- **ビット演算**: `>>` は右シフト、`|` は OR、`&` は AND です。`0x3f` は下位 6 ビットが 1 のマスク、`0x80` は 2 進数 `10000000` です。
- **`uint32_t`**: 符号なし 32 ビット整数です。

## 何をしているか

### 1. 入力を 1 回だけ評価する

```c:line-numbers=533
        uint32_t in = val;\
```

`uint32_t in = val;` で入力をローカル変数にコピーします。マクロでは引数が式のまま何度も埋め込まれるので、`val` に関数呼び出しを渡されたとき何度も実行されてしまいます。最初にコピーすることで 1 回だけにしています（ドキュメントにも「If val is given as a function it is executed only once」とあります）。

### 2. ASCII はそのまま

```c:line-numbers=534
        if (in < 0x80) {\
            tmp = in;\
            PUT_BYTE\
```

0x80 未満なら 1 バイトでそのまま出力します。

### 3. バイト数を 1 本の式で決める

```c:line-numbers=538
            bytes = (av_log2(in) + 4) / 5;\
            shift = (bytes - 1) * 6;\
```

UTF-8 では、n バイトで運べる値のビット数は 1 バイト目が 7−n ビット、続きが 6 ビットずつなので、2 バイトで 11 ビット、3 バイトで 16 ビット、4 バイトで 21 ビットです。
値のビット数は `av_log2(in) + 1` なので、`(av_log2(in) + 4) / 5` は次のようになります。

- `é`（0xE9）: log2 = 7 → (7 + 4) / 5 = 2 バイト
- `0x7FF`（11 ビット）: log2 = 10 → 14 / 5 = 2 バイト
- `0x800`（12 ビット）: log2 = 11 → 15 / 5 = 3 バイト
- `0x10000`（17 ビット）: log2 = 16 → 20 / 5 = 4 バイト

1 バイト増えるごとに運べるビットが 5 ずつ増える（11 → 16 → 21）ので、5 で割ると境界がぴったり合います。
`shift = (bytes - 1) * 6` は、先頭バイトに入れるために値を何ビット右にずらすかです。

### 4. 先頭バイトの印を作る

```c:line-numbers=540
            tmp = (256 - (256 >> bytes)) | (in >> shift);\
            PUT_BYTE\
```

`256 - (256 >> bytes)` は、bytes = 2 なら 256 − 64 = 192 = `11000000`、3 なら 224 = `11100000`、4 なら 240 = `11110000` です。**上位 bytes 個のビットが 1** の値がこの式で作れます。これに値の上位ビットを OR します。
`é` なら shift = 6、`0xE9 >> 6 = 3` なので先頭バイトは `0xC0 | 3 = 0xC3` です。

### 5. 続きのバイトを 6 ビットずつ

```c:line-numbers=542
            while (shift >= 6) {\
                shift -= 6;\
                tmp = 0x80 | ((in >> shift) & 0x3f);\
                PUT_BYTE\
            }\
```

`shift` を 6 ずつ減らしながら、`0x80 | ((in >> shift) & 0x3f)` で `10xxxxxx` の形のバイトを出します。`é` では `0x80 | (0xE9 & 0x3f) = 0x80 | 0x29 = 0xA9` となり、`C3 A9` が完成します。

## ここがすごい

- **表も分岐の連鎖もない**: 素直に書くと「0x800 未満なら 2 バイト、0x10000 未満なら 3 バイト…」と比較を並べます。この実装は、UTF-8 のビット数が 5 ずつ増える規則性を使い、`av_log2` と割り算 1 回でバイト数を出します。先頭バイトの印も同じ bytes から式で作るので、場合ごとのコードがありません。
- **出力方法を差し込める**: `PUT_BYTE` に文を渡す設計なので、配列に書く、ファイルに書く、バッファの終端を検査しながら書く、といった使い方を 1 つのマクロでまかなえます。関数ポインタを使うより呼び出しの手間がなく、インラインで展開されます。
- **マクロの落とし穴を避けている**: 入力を最初に `in` へコピーし、ブロックで変数を閉じ込めています。引数が複数回評価される、変数名がぶつかる、というマクロの典型的な問題への対策です。
- **一般の範囲にも対応**: ドキュメントにあるとおり、Unicode の範囲を超える値でも同じ式で（古い仕様の 5〜6 バイト形式として）出力できます。式が規則そのものを表しているからです。

## まとめ

- UTF-8 は 1 バイト増えるごとに運べるビットが 5 増える。`(log2 + 4) / 5` でバイト数がわかる。
- 上位 n ビットが 1 の 8 ビット値は `256 - (256 >> n)` で作れる。
- マクロの引数に「文」を渡すと、処理の一部を呼び出し側が決められる。
- マクロでは引数を一度ローカル変数にコピーし、ブロックで囲むのが安全な書き方。
