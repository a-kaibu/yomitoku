## ひとことで

`ff_ctz_c(v)` は、整数 `v` の **末尾（最下位側）に続く 0 のビットの数**（count trailing zeros）を返します。`v = 12`（2 進数 `1100`）なら末尾の 0 は 2 個なので `2` です。
ループを使わず、**最下位の 1 だけを取り出す → 特別な定数を掛ける → 上位 5 ビットを表の番号にする** という 3 手で答えを出します。この定数は De Bruijn（ド・ブラウン）列と呼ばれるビット列です。

## 前提知識

- **2 の補数と `-v`**: 負の数は「全ビット反転して 1 を足す」で表します。そのため `v & -v` を計算すると、**v の最下位の 1 だけが残ります**。`v = 12`（`1100`）なら `-v` は `…10100` で、AND すると `0100` = 4 です。
- **`(uint32_t)` キャスト**: 値を符号なし 32 ビットとして扱う変換です。符号なしの掛け算はあふれても 2^32 で割った余りになり、未定義動作になりません。`-(uint32_t)v` も符号なしの世界での「2 の補数の反転」です。
- **`>> 27`**: 32 ビット値を 27 桁右にずらすと、**上位 5 ビット** だけが残り、0〜31 の値になります。
- **`static const uint8_t debruijn_ctz32[32]`**: 関数の中に置いた、変更しない 32 要素の表です。`static` を付けると、呼ばれるたびに作り直さず、プログラム全体で 1 つだけ存在します。
- **`#ifndef ff_ctz`**: 速い版（CPU の命令や `__builtin_ctz`）が定義されていなければこの C 版を使う、という条件付きコンパイルです。
- **`av_always_inline`、`av_const`**: 必ずインライン展開、副作用なし、という指定です。

## 何をしているか

### 1. 最下位の 1 だけを残す

```c:line-numbers=120
    return debruijn_ctz32[(uint32_t)((v & -(uint32_t)v) * 0x077CB531U) >> 27];
```

`v & -(uint32_t)v` で、`v` の最下位の 1 だけが立った値、つまり 2^k（k が答え）を作ります。これで問題は「2^k から k を求める」に変わります。

### 2. De Bruijn 定数を掛ける

```c:line-numbers=120
    return debruijn_ctz32[(uint32_t)((v & -(uint32_t)v) * 0x077CB531U) >> 27];
```

2^k を掛けることは、左に k ビットずらすことと同じです。つまり `2^k * 0x077CB531` は、**定数 `0x077CB531` を k ビット左にずらした値** です。
この定数は、2 進数で書いたとき「どこから 5 ビットを切り出しても、32 通りすべて違う並びになる」ように作られた特別な列（De Bruijn 列）です。そのため、k ビットずらしたあとの上位 5 ビットは、k ごとに必ず違う値になります。

### 3. 上位 5 ビットで表を引く

```c:line-numbers=116
    static const uint8_t debruijn_ctz32[32] = {
        0, 1, 28, 2, 29, 14, 24, 3, 30, 22, 20, 15, 25, 17, 4, 8,
        31, 27, 13, 23, 21, 19, 16, 7, 26, 12, 18, 6, 11, 5, 10, 9
    };
    return debruijn_ctz32[(uint32_t)((v & -(uint32_t)v) * 0x077CB531U) >> 27];
```

`>> 27` で上位 5 ビット（0〜31）を取り出し、それを番号にして表 `debruijn_ctz32` を引きます。表は「上位 5 ビットが i になるのは k がいくつのときか」をあらかじめ逆算して並べたものです。

`v = 12` で追います。

- `v & -v = 4`（k = 2）
- `4 * 0x077CB531 = 0x1DF2D4C4`
- 上位 5 ビット: `0x1DF2D4C4` を 2 進数にすると `00011 101…` なので `3`
- `debruijn_ctz32[3] = 2` → 答えは 2 ✓

## ここがすごい

- **掛け算が「位置の名札」を作る**: 2^k を掛けると定数が k ずれる、という当たり前の事実と、「どの 5 ビット窓も重ならない」列を組み合わせることで、32 通りの位置を 32 通りの番号に一対一で対応させています。これは完全ハッシュ（衝突しないハッシュ）を、掛け算 1 回で作っているとも言えます。
- **ループも分岐もない**: 素直に書くと「最下位ビットが 0 の間シフトして数える」ループで、最大 31 回回ります。この方法は入力に関係なく、AND・掛け算・シフト・表引きの一定の手順です。
- **表が小さい**: 2^k の値を直接表の番号にすると 2^32 要素必要ですが、上位 5 ビットに縮めたので 32 バイトで済みます。
- **出典がコメントにある**: 関数の前のコメントに手法の論文の URL が書かれています。魔法の定数が何なのか、後から読む人がたどれるようにしてあります。64 ビット版の `ff_ctzll_c` も、すぐ下で同じ方法（64 要素の表と 64 ビットの定数）で書かれています。

注意点として、ドキュメントにあるとおり `v = 0` のときの結果は未定義です。0 には「最下位の 1」がないからです。

## まとめ

- `v & -v` で最下位の 1 だけを取り出せる。
- 2^k を掛けるのは k ビットの左シフトと同じ。
- De Bruijn 列を使うと、ずらした量ごとに違う「窓の値」が出るので、表引きで位置がわかる。
- 汎用 C 版は専用命令がない環境のための実装で、速い版があれば `#ifndef` でそちらが選ばれる。
