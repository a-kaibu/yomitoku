## ひとことで

`ffs`（find first set）は、整数を 2 進数で見たとき **1 になっている一番下のビットが何番目か** を、1 から数えて返す関数です。0 なら 0 を返します。
たとえば `ffs(40)` は、40 が 2 進数で `101000` なので、下から 4 番目のビットが最初の 1 で、答えは `4` です。
CPU の専用命令が使えるならそれを使い、使えない場合は **ビット演算と表引き** で計算します。

## 前提知識

- **2 進数とビット**: 整数はビット（0 か 1）の並びです。一番下のビットを 1 番目と数えるのが `ffs` の約束です。
- **2 の補数**: C の符号付き整数は、ほぼすべての環境で「2 の補数」という形で負の数を表します。`-i` は「`i` の全ビットを反転して 1 を足したもの」です。
- **`&`（AND）**: 2 つの整数を桁ごとに比べ、両方 1 の桁だけ 1 にします。
- **`>>`（右シフト）**: ビットを右にずらします。`x >> 8` は 256 で割るのと同じです（符号なしの場合）。
- **`static const unsigned char table[]`**: 関数の中に置いた読み取り専用の配列です。`static` なので呼ぶたびに作り直されず、プログラムの中に 1 つだけ存在します。`unsigned char` は 0〜255 の値を入れる 1 バイトの型です。
- **三項演算子 `a ? b : c`**: `a` が真なら `b`、偽なら `c` の値になる式です。入れ子にすることもできます。
- **`#if USE_FFS_BUILTIN`**: コンパイル前に、条件に合う側のコードだけを残す仕組みです。
- **`__builtin_ffs`**: GCC や Clang の組み込み関数で、CPU に専用命令があればそれに置き換わります。

## 何をしているか

### 1. 組み込み命令が使える場合

```c:line-numbers=28
#if USE_FFS_BUILTIN
  return __builtin_ffs (i);
#else
```

使える環境では `__builtin_ffs` を呼ぶだけです。`#else` 以降は使えない環境向けの汎用版です。

### 2. 最下位の 1 だけを残す

```c:line-numbers=42
  unsigned int a;
  unsigned int x = i & -i;
```

`x = i & -i` は、`i` の **一番下の 1 だけを残した値** になります。
`i = 40`（`0b101000`）の場合、`-i` は全ビットを反転（`...11010111`）して 1 を足すので `...11011000` です。`i` と AND を取ると `0b001000` = 8 が残ります。
反転すると一番下の 1 より下の 0 はすべて 1 になり、1 を足すと繰り上がりがちょうど元の位置で止まる、という仕組みです。

### 3. どの 8 ビットにあるかを決める

```c:line-numbers=45
  a = x <= 0xffff ? (x <= 0xff ? 0 : 8) : (x <= 0xffffff ?  16 : 24);
```

`x` は 2 のべき乗（1 ビットだけが 1）です。`x <= 0xff` なら下位 8 ビット、`x <= 0xffff` なら次の 8 ビット、というように、2 回の比較で `a` を 0・8・16・24 のどれかに決めます。

### 4. 表を引く

```c:line-numbers=47
  return table[x >> a] + a;
```

`x >> a` で、1 のビットを 0〜255 の範囲に持ってきます。`table[n]` には「`n` の一番上の 1 のビットが何番目か」が入っています（`table[1] = 1`、`table[8] = 4`、`table[128] = 8`）。それに `a` を足せば答えです。
例: `i = 40` なら `x = 8`、`a = 0`、`table[8] = 4` で `4`。
例: `i = 0x30000` なら `x = 0x10000`。`0xffff` より大きく `0xffffff` 以下なので `a = 16`、`x >> 16 = 1`、`table[1] = 1` で答えは `17` です。
`i = 0` なら `x = 0`、`a = 0`、`table[0] = 0` で、ちゃんと 0 が返ります。

## ここがすごい

- **`i & -i` の一発芸**: 最下位の 1 を取り出すのに、ループで 1 ビットずつ調べる必要がありません。2 の補数の繰り上がりを利用した有名な技で、Fenwick 木（区間の和を高速に求めるデータ構造）などでも使われます。
- **表を小さく保つ**: 32 ビット全部を表にすると 40 億要素になり、とても置けません。8 ビットごとに区切れば 256 バイトの表で済み、残りは比較 2 回で補えます。表引きと分岐の、ちょうどよい折り合いです。
- **表の作り方の工夫**: `x` は 2 のべき乗なので、本来は表の 1, 2, 4, …, 128 番目しか使いません。しかしこの表は「一番上のビットの位置」をすべての値について持っているので、たとえ 2 のべき乗以外が来ても意味のある値を返します。また 0 の場合も特別扱いなしで 0 を返せます。
- **専用命令に道を譲る**: 最近の CPU には最下位ビットの位置を求める命令があり、組み込み関数の方が速く確実です。`#if` で切り替えることで、移植性と性能を両立しています。

## まとめ

- `i & -i` で、一番下の 1 のビットだけを取り出せる。
- 大きな範囲は「どの区画か」を比較で決め、区画の中は小さな表で引くと、表のサイズを抑えられる。
- 表の 0 番目に 0 を入れておけば、0 の入力も特別扱いせずに済む。
- 専用命令が使えるならそちらを使い、汎用版は保険として残す。
