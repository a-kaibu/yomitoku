## ひとことで

`isPercentEncoded` は、URL の中の **指定した位置から、`%41` のような「パーセント符号化」の並びが始まるか** を調べる関数です。`%` の後に、16 進数の文字が 2 つ続いていれば `true` を返します。

URL では、空白や日本語などの文字を、`%` と 2 桁の 16 進数で表すことがあります。OkHttp は URL を正規化するとき、すでに符号化されている `%` の並びはそのまま残します。`strict` の指定があるときは、この関数で正しい形の `%` かを確かめ、そうでなければ符号化し直します。

## コード

```kotlin:line-numbers=237
internal fun String.isPercentEncoded(
  pos: Int,
  limit: Int,
): Boolean =
  pos + 2 < limit &&
    this[pos] == '%' &&
    this[pos + 1].parseHexDigit() != -1 &&
    this[pos + 2].parseHexDigit() != -1
```

## 前提知識

- **パーセント符号化**: URL に使えない文字を、`%` と 2 桁の 16 進数で表す方法です。たとえば空白は `%20` になります。
- **16 進数**: 0 から 9 と、A から F（または a から f）の 16 種類の数字です。2 桁で 1 バイトを表せます。
- **`parseHexDigit()`**: 文字が 16 進数の 1 桁なら、その値を返します。そうでなければ `-1` を返します。
- **`limit`**: 文字列の範囲の終わりです。`limit` より後ろの文字は、読んではいけません。
- **`&&`**: 左から順に評価され、途中で `false` になったら、その先は評価されない論理積です。

## 何をしているか

### 1. 範囲の確認を先に行う

```kotlin:line-numbers=241
  pos + 2 < limit &&
```

`pos + 2` が `limit` より小さいかを、まず確かめます。これで、残りの 2 文字が範囲の中にあることが保証されます。範囲の外の文字を読むことを、ここで防いでいます。

### 2. 先頭が % かを確かめる

```kotlin:line-numbers=242
    this[pos] == '%' &&
```

位置 `pos` の文字が `%` かを調べます。`%` でなければ、ここで `false` になり、それ以降は調べません。

### 3. 続く 2 文字が 16 進数かを確かめる

```kotlin:line-numbers=243
    this[pos + 1].parseHexDigit() != -1 &&
    this[pos + 2].parseHexDigit() != -1
```

`%` の後の 2 文字が、どちらも 16 進数の 1 桁であるかを、それぞれ調べます。どちらも `-1` ではなければ、全体が `true` になります。

## ここがすごい

- **条件を左から並べて、安全な順番にする**: 範囲を確かめてから文字を読むので、添字が範囲を超えることがありません。`&&` の性質を使って、後ろの条件を必要なときだけ評価しています。
- **1 つの式で完結する**: 3 つの条件が縦に並んでいて、読めば「範囲」「%」「16 進数 2 桁」の順に確かめていることが分かります。
- **例外を使わない**: 16 進数でない文字を見つけても、例外を投げず `-1` で判定しています。通常の入力を調べるだけなので、この方が速く、扱いやすい作りです。
- **呼び出し側が長さを決める**: `limit` を引数で受け取るので、文字列の一部だけを調べることもできます。

## まとめ

- 文字を読む前に範囲を確かめると、添字の事故を防げる。
- `&&` を左から順に並べると、前の条件が偽なら後ろを調べない、安全な判定になる。
- 16 進数かどうかは、例外ではなく特別な値（`-1`）で判定すると、通常の入力に対して軽く書ける。
