## ひとことで

Wire の `varint`（小さい数ほど短く書ける整数の形式）は、**非負の数** にだけ効率がよいものです。負の数は、32 ビットすべてが 1 に見えるので、そのまま書くと 5 バイトもかかってしまいます。

`encodeZigZag32` は、符号付きの整数を **絶対値が小さいほど小さい非負の数** に写す変換です。`0` は `0`、`-1` は `1`、`1` は `2`、`-2` は `3` になります。

## コード


::: code-group

```kotlin:line-numbers=180 [日本語訳]
    internal fun encodeZigZag32(n: Int): Int {
      // 注意: 右シフトは算術シフト（符号を保つもの）でなければならない
      return (n shl 1) xor (n shr 31)
    }
```

```kotlin:line-numbers=180 [原文]
    internal fun encodeZigZag32(n: Int): Int {
      // Note: the right-shift must be arithmetic
      return (n shl 1) xor (n shr 31)
    }
```

:::

## 前提知識

- **`shl` と `shr`**: `shl` は左へずらす、`shr` は右へずらす操作です。`shr` は、最上位の符号ビットを保ったまま右へずらします（算術シフト）。
- **`xor`**: 2 つのビットが違うときだけ 1 になる演算です。
- **符号付き 32 ビット整数**: 最上位ビット（1 ビット目）が符号を表します。負の数は、その最上位ビットが 1 になっています。
- **変換の逆**: `decodeZigZag32` が、この変換を元に戻します。

## 何をしているか

### 1. 左に 1 ビットずらす

```kotlin:line-numbers=182
      return (n shl 1) xor (n shr 31)
```

`n shl 1` で、全体を左に 1 ビットずらします。符号ビットは一番上へ押し出され、その位置の値が 1 つ下へ来ます。

### 2. 符号ビットの全体を作る

`n shr 31` は、符号ビットを全部のビットへ広げた値です。正の数なら `0`、負の数なら `-1`（すべてのビットが 1）になります。

### 3. 2 つを xor する

2 つを `xor` すると、正の数は左にずらした値そのもの（偶数）になり、負の数は、ずらして反転した値（奇数）になります。

例として `-1` を見ます。

- `n shl 1` は `-2`（ビットは `…1110`）
- `n shr 31` は `-1`（ビットは `…1111`）
- `xor` の結果は `1`

## ここがすごい

- **分岐がない**: 正か負かで `if` を使わず、ビットの計算だけで変換できます。条件によって速さが変わらず、単純な命令だけで済みます。
- **小さい数が小さくなる**: `-1` も `1` も、どちらも少ないバイトで書けます。負の数が多いデータでも、サイズが大きく増えません。
- **算術シフトの前提**: コメントにあるように、右シフトが符号を保つことが大事です。符号を保たない（論理）シフトを使うと、負の数の変換が正しくなりません。
- **可逆な変換**: 変換は全部の整数で 1 対 1 に対応しています。読み出しのときに、必ず元の値へ戻せます。

## まとめ

- 負の数を小さく書くには、符号を含めて「絶対値が小さいほど小さい非負の数」へ写す。
- 符号ビットの広げた値と左シフトの `xor` で、分岐なしに変換できる。
- 右シフトは符号を保つものを使うと、変換が正しく働く。
