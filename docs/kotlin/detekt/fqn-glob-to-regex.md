## ひとことで

`fullyQualifiedNameGlobToRegex()` は、`com.example.**.Foo` のような **完全修飾名（パッケージ名とクラス名をつなげた名前）のパターン** を、正規表現（Regex）に変える関数です。

ワイルドカードの `*` は、ひとつの名前の区間だけを表します。`**` だけが、区切りの `.` をまたいで何段でも続けられます。この違いを、いくつかの置き換えを順番に行うことで実現しています。

detekt（Kotlin のコードを静的に調べるツール）で、不要な完全修飾名を見つけるルールが、除外する名前のパターンを正規表現にするときに使っています。

## コード

```kotlin:line-numbers=19
fun String.fullyQualifiedNameGlobToRegex(): Regex =
    this
        .replace(".", """\.""")
        .replace("**", "//")
        .replace("*", "[^.]*")
        .replace("?", "[^.]")
        .replace("//", """.*(?=\.)""")
        .toRegex()
```

## 前提知識

- **グロブ（glob）**: ファイル名などのパターンを書くための簡単な記法です。`*` は任意の文字列、`?` は 1 文字を表すことが多いです。
- **正規表現（Regex）**: 文字列の形を細かく表す記法です。`.` は任意の 1 文字、`.*` は任意の文字列を表します。
- **`\.`**: 正規表現で、ドットそのものを表すための書き方です。ドットのままだと「任意の 1 文字」の意味になります。
- **`[^.]`**: ドット以外の 1 文字を表す記法です。`[^.]*` は、ドットを含まない名前の区間を表します。
- **先読み `(?=\.)`**: その位置の後ろにドットがあることを確かめるだけで、ドットは消費しない記法です。

## 何をしているか

### 1. 区切りのドットを先にエスケープする

```kotlin:line-numbers=21
        .replace(".", """\.""")
```

まず、すべての `.` を `\.` にします。以降の置き換えは `*` と `?` だけを扱うので、ここでエスケープしたドットが二度と書き換えられることはありません。

### 2. `**` を一時的な目印にする

```kotlin:line-numbers=22
        .replace("**", "//")
```

`**` を先に別の記号 `//` に置き換えます。`*` の置き換えを先にすると、`**` が `[^.]*[^.]*` になり、区切りをまたげなくなってしまうからです。完全修飾名には `//` はほとんど現れないので、目印として選ばれています。

### 3. 1 つの `*` と `?` は区切りの中だけ

```kotlin:line-numbers=23
        .replace("*", "[^.]*")
```

単独の `*` は、ドットを含まない名前の区間だけを表すようになります。`com.example.*.Foo` は、`com.example.Bar.Foo` にはマッチしますが、`com.example.a.b.Foo` にはマッチしません。

### 4. 目印を正規表現に戻す

```kotlin:line-numbers=25
        .replace("//", """.*(?=\.)""")
```

目印の `//` を、「任意の文字列。ただし後ろにドットが続く位置まで」の形に戻します。先読みを使うので、直後のドットは次のパターンのためにそのまま残ります。

例として `com.example.**.Foo` を見ると、`com.example.a.b.Foo` にマッチします。`**` が `a.b` の部分を受け持ち、その後ろの `.Foo` と結び付いています。

## ここがすごい

- **順番で意味が決まる**: エスケープ、`**` の退避、`*` と `?` の変換、目印の復元、という 4 段の順番があって初めて、`**` と `*` の違いが出ます。順番を入れ替えると、すぐ壊れます。
- **先読みでドットを残す**: `.*(?=\.)` は、ドットを食べずに「この位置の後ろにドットがある」と言えるので、続くパターンと正しくつながります。
- **文字列の置き換えだけで済む**: 小さなパーサーを書かずに、`replace` の連続で変換しています。パターンの数が少ない用途では、これで十分わかりやすいです。
- **目印の衝突に注意**: 目印 `//` が、元のパターンに含まれていると、その部分も書き換えられてしまいます。目印の選び方には、この前提が隠れています。

## まとめ

- 完全修飾名のパターンでは、`*` は 1 区間、`**` は複数区間を表すように、置き換えの順番で区別する。
- `**` は一時的な目印 `//` にしてから、先読みを使った正規表現に戻す。
- 目印を使う方法は短く書けるが、目印と衝突しない前提が必要になる。
