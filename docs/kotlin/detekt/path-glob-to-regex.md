## ひとことで

`pathGlobToRegex()` は、名前の文字列に含まれる `*` と `?` を、正規表現（Regex）の書き方に置き換える関数です。`*` は「任意の文字列」、`?` は「任意の 1 文字」を表します。

detekt（Kotlin のコードを静的に調べるツール）が、設定ファイルに書かれた禁止するクラス名や除外する関数名のパターンを、正規表現にするときに使っています。

## コード

```kotlin:line-numbers=12
fun String.pathGlobToRegex(): Regex =
    this
        .replace(".", "\\.")
        .replace("*", ".*")
        .replace("?", ".")
        .toRegex()
```

## 前提知識

- **グロブ（glob）**: `src/*.kt` のように、ワイルドカードでファイル名を指定する記法です。
- **正規表現（Regex）**: 文字列の形を表す記法です。`.` は任意の 1 文字、`.*` は任意の長さの文字列を表します。
- **`toRegex()`**: 文字列を正規表現の型 `Regex` に変換するメソッドです。
- **メソッドの連鎖**: `this.replace(...).replace(...)` のように、戻り値に続けて別のメソッドを呼ぶ書き方です。
- **エスケープ**: 特別な意味を持つ記号を、ただの文字として扱うための書き方です。ここでは `.` を `\.` にします。

## 何をしているか

### 1. ドットをエスケープする

```kotlin:line-numbers=14
        .replace(".", "\\.")
```

ファイル名のドットは、正規表現では「任意の 1 文字」の意味になってしまいます。そこで、`.` を `\.` にして、ドットそのものを表すようにします。これを最初に行うのが、この関数の大事な点です。

### 2. `*` を任意の文字列にする

```kotlin:line-numbers=15
        .replace("*", ".*")
```

`*` を `.*` に置き換えます。`.*` は「任意の長さの文字列」を意味します。

### 3. `?` を任意の 1 文字にする

`?` は、正規表現の `.`（任意の 1 文字）にそのまま置き換えられます。この関数の最後の行で行われます。

## ここがすごい

- **順番が結果を決める**: もし `*` を先に `.*` にしていたら、その中の `.` が次のエスケープで `\.*` になってしまいます。ドットのエスケープを最初に行うことで、この事故を防いでいます。
- **変換の範囲を絞っている**: `.`、`*`、`?` だけを扱うので、コードは 1 つのチェーンで読み切れます。正規表現の記号は他にもありますが、この関数の入力は、その限られた形式を前提にしています。
- **ドキュメントが仕様を示す**: 関数の上のコメントには、`*` と `?` の意味が書かれています。実装を読まなくても、どんな入力を想定するかが分かります。
- **`toRegex()` で型が決まる**: 戻り値の型が `Regex` なので、呼び出し側は一致の判定にそのまま使えます。文字列のまま扱って、毎回変換する必要がありません。

## まとめ

- `pathGlobToRegex` は、`*` を `.*`、`?` を `.` に変えて、名前のパターンを正規表現にする。
- ドットのエスケープを最初に行うことで、後から入れた `.` が書き換えられないようにする。
- 扱う記号を絞った単純な変換なので、入力の形式を前提として使う。
