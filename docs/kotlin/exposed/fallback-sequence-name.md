## ひとことで

`fallbackSequenceName` は、連番（シーケンス）に **名前を指定しなかったときの既定の名前** を作る関数です。`users` という表の `id` 列なら、`users_id_seq` という名前になります。

Exposed は、データベースの連番を自動で作ることがあり、その名前を明示しないことがあります。そのときに、表と列の名前から、いつも同じ規則で名前を作るために使われます。

## コード

```kotlin:line-numbers=2303
internal fun fallbackSequenceName(tableName: String, columnName: String): String {
    val q = if (tableName.contains('.')) "\"" else ""
    return "$q${tableName.replace("\"", "")}_${columnName}_seq$q"
}
```

## 前提知識

- **連番（シーケンス）**: データベースが、1 から順に番号を作るための仕組みです。PostgreSQL などで、自動採番の列に使われます。
- **表名の点（`.`）**: `schema.users` のように、スキーマ名と表名を点でつなぐ書き方があります。点を含む名前は、そのままでは正しく扱えないことがあります。
- **引用符（`"`）**: SQL で、名前を特別な文字を含む識別子として囲むための記号です。
- **三項演算子に相当する `if`**: Kotlin では、`if (条件) 値1 else 値2` が値を返す式として使えます。
- **文字列テンプレート**: `"$q${...}_${...}"` のように、変数や式の値を文字列に埋め込む書き方です。

## 何をしているか

### 1. 点を含むときだけ引用符を付ける準備

```kotlin:line-numbers=2304
    val q = if (tableName.contains('.')) "\"" else ""
```

表名に点が含まれていれば、引用符 `"` を `q` に入れます。含まれていなければ、空の文字列にします。点を含む名前は、引用符で囲んでおくと、データベースが 1 つの名前として読めるからです。

### 2. 表名から引用符を外して、名前を組み立てる

```kotlin:line-numbers=2305
    return "$q${tableName.replace("\"", "")}_${columnName}_seq$q"
```

表名に含まれる引用符は、いったん取り除きます。そのあと、表名、列名、`_seq` を `_` でつなぎ、前後に `q` を付けます。`users` と `id` なら `users_id_seq` です。

## ここがすごい

- **同じ入力から、いつも同じ名前が決まる**: 名前の規則が 1 行で決まっているので、どこで呼んでも同じ名前になります。後から名前を探すときにも、規則から予測できます。
- **引用符の扱いを 1 か所にまとめる**: 点を含むかどうかの判断と、引用符の除去は、この関数の中だけにあります。呼び出し側は、名前を気にせず渡せます。
- **名前の形が読み取れる**: `表名_列名_seq` という形を見るだけで、何の連番かが分かります。データベースを直接見るときにも、迷いにくい作りです。
- **引数に名前を付けて呼ぶ**: 呼び出し側は `tableName = ...` と名前を付けて書いています。どの値がどの役割かが、読んだだけで分かります。

### 注意点: 長すぎる名前や、衝突の可能性

データベースには、名前の長さの上限があります。表名と列名がとても長いと、上限を超えて問題になることがあります。また、別の表と同じ名前が作られる可能性もゼロではありません。この関数は、そうした上限や衝突の確認は行っていません。

## まとめ

- 既定の名前は、表名と列名の規則で作ると、予測しやすく再現しやすい。
- 特別な文字を含む名前は、引用符で囲んで 1 つの名前として扱えるようにする。
- 名前の規則には、長さの上限と衝突の可能性がつきものなので、必要な場面では確認が要る。
