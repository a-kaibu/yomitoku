## ひとことで

`encodeRgb16` は、色の 3 つの成分を、16 ビットの 16 進数の文字列にして書き出す関数です。端末が色を問い合わせるときの、`rgb:ffff/8080/0000` の形式で書きます。

## コード

```zig:line-numbers=631
    pub fn encodeRgb16(self: RGB, writer: *std.Io.Writer) !void {
        try writer.print(
            "rgb:{x:0>4}/{x:0>4}/{x:0>4}",
            .{
                @as(u16, self.r) * 257,
                @as(u16, self.g) * 257,
                @as(u16, self.b) * 257,
            },
        );
    }
```

## 前提知識

- **8 ビットの色**: 赤、緑、青の各成分が 0 から 255 の値です。`RGB` の型では `u8` で持っています。
- **16 ビットの色**: 各成分が 0 から 65535 の値です。端末の仕様では、この精度で色を書くことがあります。
- **16 進数の書式（`{x:0>4}`）**: 値を 16 進数で書き、足りない桁を `0` で埋める書式です。`0>4` は、右寄せで 4 桁にする指定です。
- **`writer.print`**: 書式付きの文字列を、書き込み先へ出す関数です。
- **`@as(u16, x)`**: 値を `u16` の型として扱う組み込み関数です。掛け算の結果が大きくなるので、先に型を広げます。

## 何をしているか

### 1. 各成分を 257 倍する

```zig:line-numbers=634
            .{
                @as(u16, self.r) * 257,
                @as(u16, self.g) * 257,
                @as(u16, self.b) * 257,
            },
```

`@as(u16, self.r) * 257` の式で、0 から 255 の値を 0 から 65535 に広げます。`257` は `0x101` で、`0xff` を掛けると `0xffff` になります。1 つの成分を、上位と下位に同じ値を並べた形にするのと同じ意味です。

### 2. 16 進数で書き出す

```zig:line-numbers=632
        try writer.print(
            "rgb:{x:0>4}/{x:0>4}/{x:0>4}",
```

`{x:0>4}` で、各成分を 4 桁の 16 進数にして書きます。`rgb:` の後に、赤、緑、青の順で、`/` で区切って並べます。

## ここがすごい

- **257 倍が正しく 255 を 65535 に変える**: `0x00` は `0x0000` に、`0xff` は `0xffff` になります。端数を捨てずに、最大値を一致させられる数です。
- **型を先に広げる**: 掛け算の結果が `u8` に収まらないので、`@as(u16, ...)` で先に型を広げています。オーバーフローを防ぐ書き方です。
- **書式が一か所にまとまる**: 1 回の `print` で 3 つの成分を書くので、区切り文字の付け忘れが起きにくくなっています。
- **端末の仕様に合わせている**: `rgb:` で始まる形式は、端末が色を問い合わせるときに使われる仕様の形です。

## まとめ

- `encodeRgb16` は、各成分を 257 倍して 16 ビットに広げ、16 進数で書きます。
- 257 倍は、255 を 65535 に一致させる、もっとも簡単な変換です。
- 型を先に広げてから掛けるので、結果が溢れません。
