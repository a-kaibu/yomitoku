## ひとことで

`update` は、バイトの列を少しずつ読み込んで、ハッシュの値を更新する関数です。1 バイトごとに「XOR してから素数を掛ける」だけを繰り返します。ハッシュは、データを短い数値に変えた指紋のようなものです。同じ入力なら同じ値になり、少しでも違うと別の値になりやすくなります。

## コード

```zig:line-numbers=24
        pub fn update(self: *Self, input: []const u8) void {
            for (input) |b| {
                self.value ^= b;
                self.value *%= prime;
            }
        }
```

## 前提知識

- **ハッシュ**: 任意の長さのデータを、固定の大きさの整数に変える計算です。辞書（ハッシュマップ）の添字の決定などに使われます。
- **FNV-1a**: Fowler–Noll–Vo という人たちが考えた、非暗号のハッシュです。計算が軽く、短い文字列の扱いにも向いています。
- **XOR（`^`）**: 同じビットなら 0、違うなら 1 になる演算です。
- **`*%=`（ラップする掛け算）**: 結果が型の範囲を超えたら、上位を捨てて折り返す掛け算です。Zig では、通常の `*=` と違い、オーバーフローでエラーにならずに値が回り込みます。
- **ジェネリック**: `Fnv1a(comptime T: type, ...)` の `T` は型の引数です。同じ計算を 32 ビット、64 ビット、128 ビットの型で作れます。

## 何をしているか

関数は、`self.value` という状態を持っています。`update` を何度呼んでも途中までの値が残るので、長いデータを分けて渡せます。ループの中では、2 つの操作をします。

### 1. バイトを XOR して値に混ぜる

```zig:line-numbers=25
            for (input) |b| {
                self.value ^= b;
```

`self.value ^= b` で、現在の値とバイトを XOR します。これで、バイトの内容が値のビットに混ざります。

### 2. 素数を掛けて広げる

```zig:line-numbers=27
                self.value *%= prime;
```

`self.value *%= prime` で、素数を掛けます。64 ビット版の `prime` は `0x100000001b3` です。掛けると、混ざったビットが上位に広がっていきます。`*%=` はオーバーフローしても折り返すだけで止まらないので、ハッシュに必要な性質を満たします。

## ここがすごい

- **たった 2 行**: ループの中身は XOR と掛け算だけです。標準ライブラリのコードでも、とても読みやすい形になっています。
- **順序で値が変わる**: XOR してから掛けるので、同じバイトでも並び方が違うと、最終的な値が変わります。
- **型の違いを 1 つの定義で作る**: `Fnv1a` は `comptime` の引数で素数とオフセットを受け取るので、32 ビット、64 ビット、128 ビットの版を同じ関数から作れます。
- **途中経過を保てる**: `init` と `final` があるので、データを分割して順に渡せます。テストでは、一度に渡した結果と分けて渡した結果が一致するか確かめています。

## まとめ

- FNV-1a は、1 バイトずつ XOR して素数を掛けるだけのハッシュです。
- `*%=` の折り返しの掛け算が、ハッシュの広がりを作ります。
- `comptime` の引数で、ビット幅ごとの版をまとめて定義しています。
