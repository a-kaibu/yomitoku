## ひとことで

`utf8Decode` は、1 文字分の UTF-8 のバイト列を、Unicode の **文字番号（コードポイント）** を表す `u21` の値に変換する関数です。
たとえば `"あ"` は 3 バイトで、文字番号は `0x3042` です。

UTF-8 では、文字によってバイト数が 1 から 4 まで違います。この関数は、まずバイト数を見て、どの専用の変換関数に渡すかを決めています。

## コード

```zig:line-numbers=101
pub fn utf8Decode(bytes: []const u8) Utf8DecodeError!u21 {
    return switch (bytes.len) {
        1 => bytes[0],
        2 => utf8Decode2(bytes[0..2].*),
        3 => utf8Decode3(bytes[0..3].*),
        4 => utf8Decode4(bytes[0..4].*),
        else => unreachable,
    };
}
```
## 前提知識

- **UTF-8**: Unicode の文字を、1 文字あたり 1 から 4 バイトで表す方式です。英数字は 1 バイト、ひらがなや漢字は 3 バイトです。
- **コードポイント**: Unicode の 1 文字に割り当てられた番号です。`u21` で表せる範囲（0 から 0x10FFFF）の値です。
- **`[]const u8`**: バイトの列（スライス）です。`bytes.len` で長さを取り出せます。
- **`switch` 式**: 値の場合分けを式として書く方法です。`switch (bytes.len) { 1 => ..., 2 => ... }` のように、各場合の値がそのまま結果になります。
- **`bytes[0..2].*`**: スライスの一部を、長さの決まった配列の値にする書き方です。
- **`unreachable`**: 「ここには来ない」という約束を書く特別な値です。もし来てしまったら、安全モードではエラーになります。
- **エラー集合（`Utf8DecodeError!u21`）**: 失敗する可能性のある戻り値を表す型です。`!` の前がエラーの種類、後ろが成功したときの値の型です。

## 何をしているか

### 1. バイト数で分岐する

```zig:line-numbers=102
    return switch (bytes.len) {
        1 => bytes[0],
        2 => utf8Decode2(bytes[0..2].*),
        3 => utf8Decode3(bytes[0..3].*),
        4 => utf8Decode4(bytes[0..4].*),
        else => unreachable,
    };
```

`bytes.len` が 1 のときは、そのバイトをそのまま文字番号として返します。英数字はこの場合で、ASCII と同じ値になります。

2 バイト、3 バイト、4 バイトの場合は、それぞれ専用の関数に渡します。たとえば `"あ"`（`E3 81 82`）は 3 バイトなので、`utf8Decode3` に渡されます。

5 バイト以上や 0 バイトは、この関数の使い方として間違っています。`unreachable` と書いてあるのは、呼び出し側がこの範囲を守ることを前提にしているからです。

### 2. 1 バイトの文字はそのまま使う

```zig:line-numbers=103
        1 => bytes[0],
```

1 バイトの UTF-8 は、ASCII の範囲（0 から 127）だけです。そのため、バイトの値がそのまま文字番号になります。`u8` が `u21` に広がって返されるので、戻り値の型に合わせて変換されています。

### 3. 2 バイト以上は、専用の関数で検査する

```zig:line-numbers=104
        2 => utf8Decode2(bytes[0..2].*),
```

2 バイト以上の文字は、バイトの並びに決まりがあります。先頭バイトの形（`110xxxxx` など）と、続きのバイトの形（`10xxxxxx`）が合っているか、同じ文字を無駄に長く書いていないか（オーバーロング）、などを専用の関数が確かめます。

そのため、この関数は「バイト数で振り分ける」役目に集中し、検査や値の計算は各専用の関数に任せています。`utf8Decode2` から `utf8Decode4` は、それぞれ別のエラー集合を持っています。

## ここがすごい

- **役割を分けている**: 振り分けの関数は 9 行の `switch` だけです。実際の検査は、型で長さが決まった `[2]u8` や `[3]u8` を受け取る関数が担当します。配列の長さが型に入っているので、範囲外の読み取りが起きません。
- **型で長さを保証する**: 専用の関数は `bytes: [3]u8` のように長さを型で指定します。呼び出し側は必ず正しい長さの配列を渡すので、長さの確認を重ねる必要がありません。
- **1 バイトを特別扱い**: ASCII の文字は、計算なしで 1 バイトの値を返します。英語の多い文章では、この近道が速さに効きます。
- **間違いを隠さない**: 予期しない長さには `unreachable` を使い、「ありえない入力」を明示しています。黙って間違った値を返すことはありません。

## まとめ

- UTF-8 は、文字によって 1 から 4 バイトで表されます。
- バイト数を見て、専用の変換関数に振り分けるのが基本の形です。
- 型で配列の長さを決めると、範囲外の読み取りを防げます。
- 「ありえない長さ」は `unreachable` で表し、誤った値を黙って返さないようにします。
