## ひとことで

`growCapacity` は、動的配列（伸び縮みする配列）の容量が足りなくなったときに、新しい容量を決める関数です。
引数の `minimum` は、最低限必要な容量です。戻り値は、それより大きい値になります。

新しい容量は、`minimum` の約 1.5 倍に、初期容量を足した値です。毎回ちょっとずつ増やすのではなく、大きく増やすので、要素の追加が速くなります。

## コード

```zig:line-numbers=1370
        pub fn growCapacity(minimum: usize) usize {
            return minimum +| (minimum / 2 + init_capacity);
        }
```
## 前提知識

- **動的配列**: 要素を追加すると、必要に応じて大きくなる配列です。`ArrayList` が代表的です。
- **容量（capacity）**: 今の配列が、メモリの確保をし直さずに入れられる要素数の上限です。
- **再確保（reallocation）**: 容量が足りなくなったとき、より大きいメモリを確保して、要素を移す処理です。移すときのコストが大きいので、回数を減らしたいところです。
- **`minimum / 2`**: 割り算で半分を取ります。`minimum / 2 + init_capacity` は、約 1.5 倍に相当する増やし方です。
- **`+|`**: 飽和加算（saturating add）です。結果が型の最大値を超えたら、その最大値で止まります。折り返しません。
- **`init_capacity`**: 配列の初期容量として、型の引数で決まる定数です。

## 何をしているか

### 1. 関数の目的と引数

```zig:line-numbers=1370
        pub fn growCapacity(minimum: usize) usize {
```

引数 `minimum` は、今の要素数に 1 つ追加するなどして、少なくとも必要になる容量です。この関数は、その値より大きい容量を返します。

### 2. 半分ずつ増やし、初期容量を足す

```zig:line-numbers=1371
            return minimum +| (minimum / 2 + init_capacity);
```

`minimum / 2` は、必要な容量の半分です。`minimum` にこの半分を足すと、約 1.5 倍になります。さらに `init_capacity` を足すので、小さい配列でも一定の大きさまで一気に増えます。

たとえば `minimum = 10` で、`init_capacity = 8` なら、`10 + 5 + 8 = 23` になります。小さい配列から、いきなり十分な大きさを確保できます。

### 3. 溢れを飽和で止める

`+|` は、通常の `+` と違い、結果が `usize` の最大値を超えたら最大値で止めます。非常に大きい値を指定されても、折り返して小さな値になることはありません。

## ここがすごい

- **増やす量が比例する**: 毎回 1 ずつ増やすと、要素を追加するたびに再確保が起きて、全体のコストが二乗に近くなります。比例して増やすと、1 回あたりの平均のコストが一定になります（償却 O(1)）。
- **2 倍ではなく 1.5 倍に近い**: 2 倍にすると、使い終わったメモリがすぐ大きすぎる、という問題が起きやすくなります。1.5 倍に近い増やし方は、古いメモリを再利用しやすく、メモリの無駄を減らせます。
- **初期容量の加算**: 小さい配列で何回も再確保が起きないように、最初の増加幅を底上げしています。
- **飽和加算で安全**: 通常の足し算だと、大きな値で折り返して、確保する量が極端に小さくなる恐れがあります。`+|` は、そのような誤動作を防ぎます。

## まとめ

- 動的配列は、満杯になったときに容量を大きく増やすことで、追加の平均コストを抑えます。
- 新しい容量は、必要量の約 1.5 倍に初期容量を足すという形で決められています。
- 増え方が比例しているので、要素を何個追加しても、1 回あたりの再確保の手間は一定になります。
- 大きな値でも折り返さないように、飽和加算で計算しています。
