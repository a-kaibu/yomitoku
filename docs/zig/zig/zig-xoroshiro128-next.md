## ひとことで

`next` は、Xoroshiro128+ という乱数生成器の 1 回分の出力を作る関数です。2 つの `u64` の状態 `s[0]` と `s[1]` から、出力 `r` を足し算で作ります。そのあと、XOR（違うビットだけ 1 になる演算）と回転で、状態を次へ進めます。

状態が 2 つだけなので、同じ仕組みの Xoshiro256 より軽く、速く動きます。

## コード

```zig:line-numbers=22
pub fn next(self: *Xoroshiro128) u64 {
    const s0 = self.s[0];
    var s1 = self.s[1];
    const r = s0 +% s1;

    s1 ^= s0;
    self.s[0] = math.rotl(u64, s0, @as(u8, 55)) ^ s1 ^ (s1 << 14);
    self.s[1] = math.rotl(u64, s1, @as(u8, 36));

    return r;
}
```
## 前提知識

- **状態（`s`）**: 乱数の次の値を決めるための内部の値です。ここでは `u64` が 2 つあります。
- **`+%`**: 溢れたら折り返して足す演算です。
- **`^=` と `^`**: XOR の代入と演算です。同じビットは 0、違うビットは 1 になります。
- **`<<`**: 左にずらす演算です。`s1 << 14` は 14 ビット左にずらします。
- **`math.rotl(u64, x, n)`**: `x` を `n` ビット左に回転させます。はみ出したビットは右から戻ってきます。
- **`@as(u8, 55)`**: 回転の量を、`u8` の定数として明示する書き方です。

## 何をしているか

### 1. 出力を先に作る

```zig:line-numbers=23
    const s0 = self.s[0];
    var s1 = self.s[1];
    const r = s0 +% s1;
```

現在の 2 つの状態を取り出し、その和 `r` を出力にします。`s0` は後で使うので、一時的な変数に入れておきます。

出力は状態を足しただけの値です。状態を更新する前の値から作るので、出力と次の状態がずれます。

### 2. s1 を s0 と混ぜる

```zig:line-numbers=27
    s1 ^= s0;
```

`s1` に `s0` を XOR します。これで、`s1` は 2 つの状態の違いを表す値になります。

### 3. 新しい s0 を作る

```zig:line-numbers=28
    self.s[0] = math.rotl(u64, s0, @as(u8, 55)) ^ s1 ^ (s1 << 14);
```

古い `s0` を 55 ビット回転させ、`s1` と、`s1` を 14 ビット左にずらした値を、XOR で合わせます。ここで、`s0` の情報と `s1` の情報が、互いの位置へ混ざります。

### 4. 新しい s1 を作る

```zig:line-numbers=29
    self.s[1] = math.rotl(u64, s1, @as(u8, 36));

    return r;
```

`s1` を 36 ビット回転させて、新しい `s1` にします。最後に、前もって作っておいた出力 `r` を返します。

## ここがすごい

- **状態が 2 つだけ**: 128 ビットの状態で、乱数の列が長く続きます。状態が小さいので、メモリや、並列に使うときの管理が簡単です。
- **命令が少ない**: 足し算、XOR、シフト、回転だけで構成されています。掛け算を使わないので、CPU によらず安定して速く動きます。
- **回転量で混ぜ方を決める**: 55、14、36 という数字は、状態のビットを十分に混ぜるように選ばれています。この数字を変えると、性能が大きく変わります。
- **ジャンプ関数の存在**: 同じファイルには `jump` 関数もあり、列を 2^64 個先へ飛ばせます。並列に使うときに、列が重ならないようにできます。
- **暗号には使わない**: 出力は状態の足し算なので、予測しやすい性質があります。統計的な用途やゲームに向いています。

## まとめ

- Xoroshiro128+ は、2 つの 64 ビットの状態から乱数を作る軽い方式です。
- 出力は 2 つの状態の和で、更新は XOR と回転で行います。
- 掛け算を使わないので、速さが安定しています。
- 予測しやすいので、暗号用の乱数には使えません。
