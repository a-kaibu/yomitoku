## ひとことで

`eqlBytes` は、2 つのバイト列（スライス）の中身が完全に同じかを調べる関数です。
Zig 標準ライブラリの `std.mem.eql` が、中身の比較に使っている内部関数です。

長さが 16 バイト以下のときは、1 バイトずつ比べる代わりに、**4 バイトの窓を 4 つだけ** 比べて答えを出します。ループも分岐も最小限です。

## コード

```zig:line-numbers=759
fn eqlBytes(a: []const u8, b: []const u8) bool {
    comptime assert(use_vectors_for_comparison);

    if (a.len != b.len) return false;
    if (a.len == 0 or a.ptr == b.ptr) return true;

    if (a.len <= 16) {
        if (a.len < 4) {
            const x = (a[0] ^ b[0]) | (a[a.len - 1] ^ b[a.len - 1]) | (a[a.len / 2] ^ b[a.len / 2]);
            return x == 0;
        }
        var x: u32 = 0;
        for ([_]usize{ 0, a.len - 4, (a.len / 8) * 4, a.len - 4 - ((a.len / 8) * 4) }) |n| {
            x |= @as(u32, @bitCast(a[n..][0..4].*)) ^ @as(u32, @bitCast(b[n..][0..4].*));
        }
        return x == 0;
    }
```
## 前提知識

- **スライス（`[]const u8`）**: 配列の一部を指す「先頭の位置と長さ」の組みです。`a.len` で長さを取り出せます。
- **`a.ptr == b.ptr`**: 同じメモリ上の同じ位置を指しているかどうかを調べます。同じなら、中身は必ず同じです。
- **`^`（XOR）と `|`（OR）**: XOR は、ビットが違うところだけ 1 にします。同じ値どうしの XOR は 0 です。OR は、どこかが 1 なら 1 にします。
- **`@bitCast`**: 同じ大きさのデータを、別の型として読み直す組み込み関数です。`[4]u8` を `u32` として読めます。
- **`a[n..][0..4].*`**: `n` の位置から 4 バイトを取り出して、配列として値にする書き方です。
- **`comptime assert(...)`**: コンパイル時に条件を確かめる文です。この関数は、ベクトル演算が使える環境でだけ呼ばれる前提を確かめています。

## 何をしているか

### 1. 長さや位置が同じなら、すぐ答えを出す

```zig:line-numbers=762
    if (a.len != b.len) return false;
    if (a.len == 0 or a.ptr == b.ptr) return true;
```

長さが違えば、中身を見る前に `false` です。長さが 0 か、同じメモリを指しているなら、比べる必要がないので `true` です。

### 2. 3 バイト以下は、3 か所を比べる

```zig:line-numbers=765
    if (a.len <= 16) {
        if (a.len < 4) {
            const x = (a[0] ^ b[0]) | (a[a.len - 1] ^ b[a.len - 1]) | (a[a.len / 2] ^ b[a.len / 2]);
            return x == 0;
        }
```

長さが 1 から 3 のときは、先頭、末尾、真ん中の 3 か所だけを比べます。長さが 3 以下なら、この 3 か所で全バイトをカバーできます。たとえば長さ 2 なら、位置 0、1、1 を見ることになり、両方のバイトが対象です。

3 か所の差を OR でまとめます。どこか 1 つでも違えば、その部分は 0 でなくなるので、全体の `x` も 0 ではなくなります。全部同じときだけ `x` は 0 になります。

### 3. 4 バイトの窓を 4 つ重ねる

```zig:line-numbers=770
        var x: u32 = 0;
        for ([_]usize{ 0, a.len - 4, (a.len / 8) * 4, a.len - 4 - ((a.len / 8) * 4) }) |n| {
            x |= @as(u32, @bitCast(a[n..][0..4].*)) ^ @as(u32, @bitCast(b[n..][0..4].*));
        }
        return x == 0;
```

長さが 4 から 16 のときは、4 バイトの窓を 4 か所読みます。位置は `0`、`a.len - 4`（末尾の 4 バイト）、そして真ん中あたりの 2 つです。たとえば長さ 16 なら、位置は `0`、`12`、`8`、`4` で、それぞれ 4 バイトずつ読みます。

窓は重なってもかまいません。ここで大事なのは、**すべてのバイトがどれかの窓に入っている** ことです。窓同士の XOR を OR でまとめ、最後に `x == 0` なら、すべての窓が完全に一致しています。

`a` の 4 バイトを `u32` に変換してから XOR すると、1 回の計算で 4 バイト分の比較ができます。1 バイトずつ比べるより、命令の数が少なくなります。

### 4. それ以外は、ベクトル演算で比べる

```zig:line-numbers=779
    const Scan = if (std.simd.suggestVectorLength(u8)) |vec_size|
```

17 バイト以上の長さのときは、CPU が一度に扱える大きさ（ベクトル）で、同じように比べていきます。ここから先の部分は、この CPU が使える大きさに合わせて読む単位を変えています。

## ここがすごい

- **分岐を減らす**: 1 バイトずつ `if` で比べると、データによって分岐の予測が外れて遅くなります。固定の 4 回の計算で済ませると、データに関係なく同じ速さで動きます。
- **全バイトが対象になることを保証**: 窓の位置は、長さから計算されています。短い列でも長い列でも、読み飛ばしや読み過ぎがない位置が選ばれています。
- **「同じ」ならすぐ戻る**: `a.ptr == b.ptr` の判定は、同じメモリを比べるときの近道です。中身を見ずに答えを出せます。
- **型の変換で一気に比べる**: `@bitCast` で 4 バイトを `u32` とみなすと、XOR 1 回で 4 バイトの違いが分かります。

## まとめ

- 2 つのバイト列が同じかは、長さを比べたあと、中身を効率よく比べます。
- 短い列は、先頭、末尾、真ん中の 3 か所だけで全バイトを確かめられます。
- 16 バイト以下は、重なった 4 バイトの窓 4 つで、分岐を少なくして比べられます。
- 窓が全バイトをカバーするように位置を選ぶと、速さと正しさを両立できます。
