## ひとことで

`next` は、PCG という乱数生成器の 1 回分の出力を作る関数です。内部の状態 `s` を掛け算と足し算で進め、進める前の値 `l` のビットを XOR とシフトで並べ替えて、32 ビットの乱数を返します。

状態の進め方は、昔からある **線形合同法** と同じ形です。しかし、そのまま出すと下のビットの周期性が目立つので、PCG は出力の前に、ビットを回転させる工夫を入れています。

## コード

```zig:line-numbers=27
fn next(self: *Pcg) u32 {
    const l = self.s;
    self.s = l *% default_multiplier +% (self.i | 1);

    const xor_s: u32 = @truncate(((l >> 18) ^ l) >> 27);
    const rot: u32 = @intCast(l >> 59);

    return (xor_s >> @as(u5, @intCast(rot))) | (xor_s << @as(u5, @intCast((0 -% rot) & 31)));
}
```
## 前提知識

- **線形合同法**: `s = s * a + c` のように、掛け算と足し算で状態を進める乱数の作り方です。単純で速い反面、下のビットは規則性が見えやすいという弱点があります。
- **`@truncate`**: 大きい整数の下位だけを取り出して、小さい型に変換します。ここでは 64 ビットの値から 32 ビットを取ります。
- **`@intCast`**: 型を別の整数型に変換します。値が範囲外なら安全モードでエラーになります。
- **`@as(u5, ...)`**: 5 ビットの整数型（0 から 31）に変換します。回転の量を 0 から 31 にするために使います。
- **`(0 -% rot) & 31`**: 32 から `rot` を引いた値を、0 から 31 の範囲にそろえる計算です。
- **`|`（OR）と `<<`、`>>`**: OR は 2 つの値のビットを合わせます。`<<` と `>>` はビットをずらします。

## 何をしているか

### 1. 状態を進める

```zig:line-numbers=28
    const l = self.s;
    self.s = l *% default_multiplier +% (self.i | 1);
```

まず、今の状態 `l` を取っておきます。そして、`l` に定数を掛け、`self.i | 1` を足して、次の状態にします。`self.i | 1` は、必ず奇数になる増分です。奇数の増分にすると、状態が全部の値を巡るように作れます。

出力は、この `l`（進める前の状態）から作ります。

### 2. ビットを混ぜて、32 ビットに縮める

```zig:line-numbers=31
    const xor_s: u32 = @truncate(((l >> 18) ^ l) >> 27);
```

`l` を 18 ビット右にずらしたものと、`l` 自身を XOR します。そのあと 27 ビット右にずらし、下位 32 ビットを取ります。こうすると、64 ビットの状態の上の方のビットが、下の方に混ざり込みます。

線形合同法の弱点は、下のビットが上のビットほど規則的なことです。この XOR とシフトで、上のビットを下に持ってきています。

### 3. 回転の量を決める

```zig:line-numbers=32
    const rot: u32 = @intCast(l >> 59);
```

`l` の上位 5 ビットを取り出し、回転の量 `rot` とします。`rot` は 0 から 31 のどれかの値です。状態によって、出力の回転量が毎回変わります。

### 4. 右に回転させる

```zig:line-numbers=34
    return (xor_s >> @as(u5, @intCast(rot))) | (xor_s << @as(u5, @intCast((0 -% rot) & 31)));
```

`xor_s` を右に `rot` ビットずらした値と、左に `32 - rot` ビットずらした値を OR で合わせます。これは、32 ビットの値を右に `rot` ビット回転させる計算です。

たとえば `xor_s` が `0b0001` で `rot = 1` なら、右に 1 ビット回すと `0b1000...` になり、はみ出した 1 が上位へ戻ります。

## ここがすごい

- **速さと品質の両立**: 状態は掛け算と足し算だけで進むので、とても速く動きます。出力の段階で XOR と回転を入れるので、統計的な品質が大きく上がります。
- **回転量を状態から決める**: 回転量を固定にせず、状態の上位ビットから決めることで、出力のパターンが毎回変わります。
- **奇数の増分**: `| 1` によって、増分が必ず奇数になります。これで、状態の周期が 2 の冪（べき）の長さになり、すべての値を巡れます。
- **0 から 31 の範囲に収める**: `& 31` で回転量を範囲内にそろえるので、シフトの量が 32 以上になることを防いでいます。

## まとめ

- PCG は、線形合同法の状態を進め、その状態のビットを並べ替えて乱数を作ります。
- XOR とシフトで上位のビットを下位へ混ぜ、その後、状態に応じた量で回転させます。
- 増分を奇数にすることで、状態が全部の値を巡るように作られています。
- 予測しにくさは十分ですが、暗号用の乱数としては使えません。
