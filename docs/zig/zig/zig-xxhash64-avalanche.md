## ひとことで

`avalanche` は、ハッシュの最後に値を混ぜ直す関数です。入力の 1 ビットが違うだけでも、出力のビットが全体に大きく変わるようにします。この性質を「雪崩効果（avalanche effect）」と呼びます。名前は、小さな変化が雪崩のように広がる様子から来ています。

## コード

```zig:line-numbers=167
    fn avalanche(value: u64) u64 {
        var result = value ^ (value >> 33);
        result *%= prime_2;
        result ^= result >> 29;
        result *%= prime_3;
        result ^= result >> 32;

        return result;
    }
```

## 前提知識

- **ハッシュの品質**: 似た入力が、似ていない出力になるほど良いハッシュです。出力の下位ビットが偏ると、辞書の添字が集中して遅くなります。
- **XXH64**: xxHash という、速さを重視した非暗号のハッシュの 64 ビット版です。
- **右シフト（`>>`）**: ビットを下位に移動する演算です。上位のビットが、下位に混ざるようになります。
- **ラップする掛け算（`*%=`）**: オーバーフローを折り返す掛け算です。
- **素数の定数**: `prime_2` と `prime_3` は、XXH64 で決められた大きな奇数の定数です。奇数の掛け算は、ビットを上位へ広げるのに向いています。

## 何をしているか

関数は、`value` を次の 5 段階で混ぜます。シフトと掛け算は、お互いに性質を補い合っています。掛け算はビットを上に広げ、シフトはその上位を下に戻します。

### 1. 上位を下位に混ぜる

```zig:line-numbers=168
        var result = value ^ (value >> 33);
```

`value ^ (value >> 33)` で、上位のビットを下位に XOR します。上位の変化が下位に伝わります。

### 2. 掛け算で広げる

```zig:line-numbers=169
        result *%= prime_2;
        result ^= result >> 29;
```

`prime_2` を掛けて、ビット全体を広げます。続く `>> 29` で、再び上位のビットを下位に混ぜます。

### 3. 最後の混ぜ方と返り値

```zig:line-numbers=171
        result *%= prime_3;
        result ^= result >> 32;

        return result;
```

`prime_3` を掛けてもう一度広げ、`>> 32` で最後に上位と下位を混ぜて結果を返します。掛け算 2 回とシフト 3 回で、64 ビットの広がりを作ります。

## ここがすごい

- **シフトと掛け算の組み合わせ**: 掛け算だけでは下位ビットが上位に届きません。シフトで下に戻すことで、上下の両方向に混ざります。
- **少ない計算で広がる**: 掛け算 2 回とシフト 3 回だけで、64 ビットの広がりを作ります。短い計算なので、ハッシュ全体の速さを落としません。
- **ラップする掛け算を使う**: `*%=` は、オーバーフローしても止まりません。ハッシュには、この折り返しが必要です。
- **関数を分けている**: 入力の処理（`round`）と、最後の混ぜ方（`avalanche`）を分けています。読むときに、役割を分けて理解できます。

## まとめ

- `avalanche` は、ハッシュの最後の値を、ビット全体に行き渡らせる関数です。
- シフトで上位を下位に混ぜ、掛け算で上位へ広げる、という操作を組み合わせています。
- 定数は XXH64 で決められた値を使い、速さと広がりの両方を満たしています。
