## ひとことで

`hashWithSeed` は、バイト列（文字列）から 64 ビットの「指紋」（ハッシュ値）を作る関数です。同じ入力からは必ず同じ値が出て、入力が少し違うだけでも値が大きく変わるように作られています。
ハッシュテーブルや、データが同じかどうかの素早い比較によく使われます。

このコードは MurmurHash2 の 64 ビット版（MurmurHash64A）を Zig で書いたものです。速さと、値のばらつきの良さを両立させています。

## コード

```zig:line-numbers=100
    pub fn hashWithSeed(str: []const u8, seed: u64) u64 {
        const m: u64 = 0xc6a4a7935bd1e995;
        var h1: u64 = seed ^ (@as(u64, str.len) *% m);
        for (@as([*]align(1) const u64, @ptrCast(str.ptr))[0 .. str.len / 8]) |v| {
            var k1: u64 = v;
            if (native_endian == .big)
                k1 = @byteSwap(k1);
            k1 *%= m;
            k1 ^= k1 >> 47;
            k1 *%= m;
            h1 ^= k1;
            h1 *%= m;
        }
        const rest = str.len & 7;
        const offset = str.len - rest;
        if (rest > 0) {
            var k1: u64 = 0;
            @memcpy(@as([*]u8, @ptrCast(&k1))[0..rest], str[offset..]);
            if (native_endian == .big)
                k1 = @byteSwap(k1);
            h1 ^= k1;
            h1 *%= m;
        }
        h1 ^= h1 >> 47;
        h1 *%= m;
        h1 ^= h1 >> 47;
        return h1;
    }
```
## 前提知識

- **ハッシュ値**: 任意の長さのデータを、決まった長さの数値にしたものです。ここでは `u64`（0 から 2 の 64 乗マイナス 1 までの整数）です。
- **`seed`（種）**: ハッシュの計算を始めるときの初期値です。同じ文字列でも種が違えば別の値になるので、攻撃者が衝突を狙いにくくなります。
- **`*%=` と `^=`**: `*%=` は、オーバーフロー（範囲外になること）を折り返して掛け算する代入です。`^=` は XOR（ビットの違いを取る演算）の代入です。
- **`>>`**: ビットを右にずらします。`k1 >> 47` は、上位のビットを下位へ持ってくる操作です。
- **`[]const u8`**: 読み取り専用のバイト列（スライス）です。`str.len` でその長さがわかります。
- **`@ptrCast` と `align(1)`**: 配列のバイト列を、8 バイト単位の整数として読むための型変換です。`align(1)` は、メモリ上の並びが 8 の倍数の位置にないかもしれないことを示します。
- **`native_endian`**: この CPU がバイトを小さい順に並べるか（リトルエンディアン）、大きい順か（ビッグエンディアン）を表す定数です。

## 何をしているか

### 1. 初期値を作る

```zig:line-numbers=101
        const m: u64 = 0xc6a4a7935bd1e995;
        var h1: u64 = seed ^ (@as(u64, str.len) *% m);
```

`m` は、MurmurHash2 で決められている乗数です。`h1` は、種と文字列の長さを混ぜた初期値です。長さを入れておくと、末尾に 0 を足しただけの文字列とも区別しやすくなります。

### 2. 8 バイトずつ混ぜる

```zig:line-numbers=103
        for (@as([*]align(1) const u64, @ptrCast(str.ptr))[0 .. str.len / 8]) |v| {
            var k1: u64 = v;
            if (native_endian == .big)
                k1 = @byteSwap(k1);
            k1 *%= m;
            k1 ^= k1 >> 47;
            k1 *%= m;
            h1 ^= k1;
            h1 *%= m;
        }
```

文字列の先頭から 8 バイトずつ、`u64` として読みます。ビッグエンディアンの CPU では、`@byteSwap` でバイトの順番を入れ替えて、どの CPU でも同じ結果になるようにしています。

そのあと、`k1` を掛け算、右シフトと XOR、掛け算の順に混ぜます。たとえば `k1 ^= k1 >> 47` は、上位のビットを下位にも影響させる操作です。こうすると、少しの違いが全体に広がります。最後に `h1` と混ぜて、次のブロックへ進みます。

### 3. 余りのバイトを処理する

```zig:line-numbers=113
        const rest = str.len & 7;
        const offset = str.len - rest;
        if (rest > 0) {
            var k1: u64 = 0;
            @memcpy(@as([*]u8, @ptrCast(&k1))[0..rest], str[offset..]);
            if (native_endian == .big)
                k1 = @byteSwap(k1);
            h1 ^= k1;
            h1 *%= m;
        }
```

`str.len & 7` は、8 で割った余りです。`str.len` が 8 の倍数でないとき、末尾の 1 から 7 バイトが残ります。残りのバイトを 0 で埋めた `k1` に入れて、同じように混ぜます。`@memcpy` で必要なバイトだけをコピーするので、読み過ぎることはありません。

### 4. 最後の仕上げ

```zig:line-numbers=123
        h1 ^= h1 >> 47;
        h1 *%= m;
        h1 ^= h1 >> 47;
        return h1;
```

すべてのバイトを混ぜ終わったあと、`h1` をもう一度シフトと掛け算で混ぜ直します。最後にもう一度シフトして XOR すると、下位のビットにも上位の変化が伝わります。この仕上げによって、ハッシュ値のばらつきが良くなります。

`"abc"` という 3 バイトの文字列を例にすると、ループは 1 回も回らず、`rest = 3` の部分だけが動きます。3 バイトを 1 つの `u64` にまとめて、同じ混ぜ方をしてから仕上げを行う、という流れです。

## ここがすごい

- **速さと品質の両立**: 1 バイトずつ混ぜる方法より、8 バイトまとめて扱うほうがずっと速いです。一方で、掛け算とシフトを組み合わせるので、値のばらつきも十分に保たれます。
- **エンディアンの違いを吸収**: `native_endian` の判定と `@byteSwap` によって、リトルエンディアンでもビッグエンディアンでも同じハッシュ値になります。ハッシュ値を保存したり、別の機械と比べたりするときに重要です。
- **`@memcpy` で安全に読む**: 8 バイトに満たない部分は、ポインタで直接読まず、必要な分だけコピーしています。配列の範囲外を読まずに済みます。
- **溢れを気にしない掛け算**: `*%=` は範囲外になっても折り返すので、ハッシュの計算に向いています。通常の `*=` だと、溢れたときにエラーになってしまいます。

## まとめ

- ハッシュ関数は、入力を決まった長さの数値にまとめる道具です。
- 8 バイトずつ読んで、掛け算、シフト、XOR で混ぜるのが MurmurHash の基本です。
- 余りのバイトと最後の仕上げを忘れないことで、ばらつきの良い値になります。
- エンディアン（バイトの並び順）の違いを `@byteSwap` で吸収すると、どの CPU でも同じ結果になります。
