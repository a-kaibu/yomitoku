## ひとことで

Scala の MurmurHash3 で、計算の最後に一度だけ呼ばれる `avalanche` です。ハッシュ値の上位ビットと下位ビットを何度も混ぜ合わせ、どのビットが 1 でも結果の全ビットがばらばらに変わるように仕上げます。

## コード

```scala:line-numbers=43
  private final def avalanche(hash: Int): Int = {
    var h = hash

    h ^= h >>> 16
    h *= 0x85ebca6b
    h ^= h >>> 13
    h *= 0xc2b2ae35
    h ^= h >>> 16

    h
  }
```

## 前提知識

- `>>>` は符号なし右シフトです。`h >>> 16` は、32 ビットの値を右に 16 ビット動かし、空いた上位は 0 で埋めます。
- `^=` は「右辺と XOR して代入する」演算子です。`h ^= x` は `h = h ^ x` と同じです。
- `*=` は掛け算して代入する演算子です。`h *= 0x85ebca6b` は `h = h * 0x85ebca6b` と同じです。
- 「アバランシェ効果」は、入力のビットを 1 つ変えたときに、出力の約半分のビットが変わる性質のことです。ハッシュ関数の品質を測る基準の 1 つです。
- `private final def` は、このクラスの中からだけ呼べる、上書きできない関数です。

## 何をしているか

### 1. 上位 16 ビットを下位へ混ぜる

最初の `h ^= h >>> 16` は、上位 16 ビットを下位 16 ビットへ XOR で混ぜます。下位ビットだけでハッシュバケットを決める仕組みでは、上位ビットの変化を下位に伝えることが大事になります。

```scala:line-numbers=46
    h ^= h >>> 16
```

### 2. 掛け算で下位ビットを散らす

次の行では、`h` を定数で掛けます。掛け算は下位ビットから上位ビットへ影響を広げるので、ここでビットが大きく動きます。

```scala:line-numbers=47
    h *= 0x85ebca6b
```

### 3. シフトと掛け算を繰り返す

同じ「シフトして XOR、掛け算」を 2 回繰り返します。段数を増やすほど、1 ビットの変化が全体に行き渡ります。最後の `h ^= h >>> 16` で仕上げ、戻り値にします。

```scala:line-numbers=48-50
    h ^= h >>> 13
    h *= 0xc2b2ae35
    h ^= h >>> 16
```

## ここがすごい

- 掛け算は上位ビットから下位ビットへ影響を伝えられません。そこで XOR と右シフトを交互に入れ、上位の情報を下位へ戻しています。この組み合わせが、短い命令列で全ビットを混ぜる鍵です。
- 定数の `0x85ebca6b` や `0xc2b2ae35` は奇数で、掛けた結果が一対一に近い変換になります。これにより、情報を捨てずにビットを散らせます。
- 関数名の `finalizeHash` は、長さを XOR してから `avalanche` を呼ぶ構造になっています。同じ内容でも長さが違えば別の値になるので、文字列の末尾の処理と組み合わせても衝突しにくくなります。
- 関数は `private` で外から直接呼べません。混ぜ方の細かい手順を、ハッシュを使う側から切り離しておけます。

## まとめ

- ハッシュの最後は、上位と下位を交互に混ぜる仕上げが効果的です。
- XOR と右シフトで上位の情報を下位へ運び、掛け算で値全体を散らします。
- 定数は奇数を選ぶと、情報を失わずに変換できます。
