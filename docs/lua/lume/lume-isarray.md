## ひとことで

`lume.isarray(x)` は、値 `x` が配列かどうかを判定する関数です。`x` が表で、かつ番号 `1` の位置に値があれば、配列とみなして `true` を返します。Lua には配列の型がないので、この約束で配列らしさを調べます。

## コード

```lua:line-numbers=160
function lume.isarray(x)
  return type(x) == "table" and x[1] ~= nil
end
```

## 前提知識

- **Lua に配列の型はない**: Lua の配列は、番号の鍵を持つ表として表されます。配列専用の型はありません。
- **`type(x) == "table"`**: 値が表かどうかを調べる書き方です。表でなければ、配列にはなりません。
- **`x[1] ~= nil`**: 番号 `1` に値があるかを調べます。配列なら、先頭の要素があるはずです。
- **`and` の短絡評価**: 左側が偽なら、右側は評価されません。表でない値に対して `x[1]` を読もうとすると、エラーになるので、この順番が大切です。

## 何をしているか

### 1. 表かどうかを確かめる

`type(x) == "table"` が偽なら、数や文字列などは配列ではありません。その時点で、結果は `false` になります。

```lua:line-numbers=161
  return type(x) == "table" and x[1] ~= nil
```

### 2. 先頭の要素があるかを確かめる

表なら、`x[1] ~= nil` を調べます。番号 `1` に値があれば、配列らしい表と判定されます。

```lua:line-numbers=161
  return type(x) == "table" and x[1] ~= nil
```

## ここがすごい

- **一行で判定**: 型の確認と先頭の確認を、`and` でつないでいます。判定の条件が、一目で読めます。
- **順番が安全**: 表でない値に対して `x[1]` を読まないように、型の確認が先に来ています。エラーを避けられます。
- **簡易的な判定**: 番号 `1` の有無だけで判定するので、速いです。ただし、穴の有無や、鍵の種類までは調べません。
- **注意点**: 空の表は配列とみなされません。また、先頭が `nil` で、後ろに値がある表も、配列とみなされません。

## まとめ

- 型の判定は、先に型を確かめてから中身を読むと、エラーを防げる。
- 配列の判定は、先頭の要素があるかで簡単に済ませられるが、その限界も知っておく。
- 空の表の扱いは、目的に合わせて決めると、判定の意図がはっきりする。
