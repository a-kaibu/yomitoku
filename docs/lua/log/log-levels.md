## ひとことで

`levels` は、ログの重要度の名前から、その順番の番号を引くための表です。`modes` という配列を一度だけ回し、名前をキー、位置を値にして作ります。「`warn` は `warn` 以上だけを出す」のような比較を、名前ではなく番号でできるようにする準備です。

## コード

```lua:line-numbers=27
local levels = {}
for i, v in ipairs(modes) do
  levels[v.name] = i
end
```

## 前提知識

- **配列と連想配列**: `modes` は、要素を順に並べた配列です。`levels` は、名前をキーにした連想配列です。二つの形の表を、一度の回しで変換しています。
- **`ipairs`**: 配列の番号 `1, 2, 3...` を順に回す標準関数です。途中で `nil` があると止まります。
- **`levels[v.name] = i`**: キーに名前、値に番号を入れる代入です。`v.name` で、各要素の名前を取り出しています。
- **重要度の順番**: 配列の並びが、そのまま重要度の順番になります。`trace` が最も小さく、`fatal` が最も大きな番号です。

## 何をしているか

### 1. 配列を順に回す

`ipairs(modes)` で、各レベルの要素を、番号 `i` と一緒に順に受け取ります。

```lua:line-numbers=28
for i, v in ipairs(modes) do
```

### 2. 名前から番号を引けるようにする

`levels[v.name] = i` で、名前をキーとして、番号を値に入れます。たとえば `levels["warn"]` は `4` になります。

```lua:line-numbers=29
  levels[v.name] = i
```

## ここがすごい

- **比較が数で済む**: 「この出力レベルは、設定より大きいか」を、番号の比べ方で書けます。名前の文字列を比べる必要がありません。
- **一度だけ作る**: 表は、モジュールの読み込み時に一度だけ作られます。毎回の出力のときに、並べ替えや探索をする必要がありません。
- **順番を一か所で決める**: 重要度の順番は、`modes` の並びだけで決まります。新しいレベルを足すときも、配列に一行足すだけです。
- **注意点**: 存在しない名前を引くと、`nil` が返ります。`levels[log.level]` のような比較では、名前が正しいかを事前に確かめておく必要があります。

## まとめ

- 名前で指定されたものを比べるときは、名前から番号を引く表を作ると、比較が簡単になる。
- 順番を配列の並びで表すと、順番の定義と追加が一か所で済む。
- 表は起動時に一度だけ作ると、実行中の無駄な処理を省ける。
