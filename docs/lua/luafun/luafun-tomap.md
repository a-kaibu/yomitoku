## ひとことで

`tomap(gen, param, state)` は、キーと値の組を返すイテレータを、テーブルに変える関数です。`pairs` のように 2 つの値を返すイテレータを、そのまま辞書にできます。同じキーが複数回出てくると、後のものが前の値を上書きします。

## コード

```lua:line-numbers=818
local tomap = function(gen_x, param_x, state_x)
    local tab, key, val = {}
    while true do
        state_x, key, val = gen_x(param_x, state_x)
        if state_x == nil then
            break
        end
        tab[key] = val
    end
    return tab
end
```

## 前提知識

- **複数の戻り値**: Lua の関数は、複数の値を同時に返せます。イテレータはキーと値を 2 つ返すことがよくあります。
- **テーブルへの代入**: `tab[key] = val` は、キーに値を登録します。同じキーがあれば、古い値は消えます。
- **`nil` でない状態**: イテレータは、次の状態が `nil` なら終わりです。

## 何をしているか

### 1. 状態と、キーと値をまとめて受け取る

`gen_x` は、次の状態、キー、値の 3 つを返します。3 つ同時に受け取るのがポイントです。

```lua:line-numbers=821
        state_x, key, val = gen_x(param_x, state_x)
```

### 2. 終わりでなければ登録する

状態が `nil` でなければ、`tab[key] = val` で登録します。

```lua:line-numbers=825
        tab[key] = val
```


補足として、`tomap` は `pairs` と同じく、キーの順番を保証しません。出来上がったテーブルを順番どおりに使いたいときは、キーを別の配列に集めて並べ直す必要があります。


もう一つの注意として、`tomap` の使い方は、キーの重複を前提にするかどうかで変わります。たとえば単語の出現回数を数えたいときは、同じキーに値を足していく別の集計が必要です。`tomap` は「最後に出た値を残す」ための道具なので、集計には向きません。目的に合わせて、登録の方法を選んでください。


まとめると、`tomap` は「キーと値の列を辞書に変える」という単純な役割だけを持っています。重複の扱いや順番の扱いは、Lua のテーブルの性質がそのまま表に出ます。そのため、使う前に、元の列にキーの重複があるか、順番が必要かを考えておくと安心です。

## ここがすごい

- **キーの重複は後勝ち**: 同じキーが来たら、後の値で上書きされます。最初の値を残したいなら、登録の前に存在を確かめる必要があります。
- **値を 1 つずつ登録するだけ**: 途中の結果を持たず、テーブルへ直接入れるので、簡潔です。
- **注意点**: キーに `nil` を使うと、登録できません。キーは `nil` 以外の値にしてください。

## まとめ

- 2 つの値を返すイテレータは、テーブルに直接入れると辞書として使える。
- 重複するキーは後の値で上書きされるので、その仕様を前提にする。
