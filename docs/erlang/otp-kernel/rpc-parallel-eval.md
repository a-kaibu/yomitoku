## ひとことで

`rpc:parallel_eval/1` は、複数の関数呼び出しを、複数のノードで並列に実行し、その結果をリストで返します。
引数の `ArgL` は、呼び出しの一覧です。ノードは、自分と、接続している他のノード（`nodes()`）を使います。

## コード

```erlang:line-numbers=1102
parallel_eval(ArgL) ->
    Nodes = [node() | nodes()],
    Keys = map_nodes(ArgL,Nodes,Nodes),
    [yield(K) || K <- Keys].
```

## 前提知識

- **ノード**: Erlang の実行環境の 1 つです。ネットワークで複数のノードをつなげます。
- **`node()` と `nodes()`**: 自分のノード名と、接続しているほかのノードの一覧です。
- **非同期の呼び出し**: 要求を送っても、答えを待たずに先へ進む呼び出しです。
- **`[yield(K) || K <- Keys]`**: リスト内包表記です。`Keys` の要素 `K` を 1 つずつ取り出し、`yield/1` で答えを受け取ります。
- **`map_nodes/3`**: 各ノードへ呼び出しを割り当てて、その識別子（`Keys`）のリストを作る補助関数です。ここでは詳しく説明しません。

## 何をしているか

### 1. 使うノードを決める

```erlang:line-numbers=1103
    Nodes = [node() | nodes()],
```

`node()` と `nodes()` を並べて、呼び出しに使うノードの一覧 `Nodes` を作ります。自分自身も、呼び出し先に含めます。

### 2. 全部の呼び出しを開始する

```erlang:line-numbers=1104
    Keys = map_nodes(ArgL,Nodes,Nodes),
```

`map_nodes/3` で、引数の一覧 `ArgL` を、ノードへ順に割り当てます。この時点では、呼び出しを開始して、その識別子（`Keys`）を受け取るだけです。結果はまだ待っていません。

### 3. 結果を順番に受け取る

```erlang:line-numbers=1105
    [yield(K) || K <- Keys].
```

`Keys` の各要素について `yield/1` を呼び、結果を受け取ります。結果は、呼び出しの順番どおりに並びます。すでに終わっている呼び出しは、待たずに答えが返ります。

## ここがすごい

### 送るのを先に全部済ませる

1 つずつ「送って、待って、次を送る」とすると、ノードの数だけ待ち時間が積み重なります。
この関数は、先に全部の呼び出しを開始してから、結果を集めます。待ち時間は、いちばん遅いノードの分だけで済みます。

### 開始と回収を分けると、順番と並列性を両立できる

`Keys` を作る段階と、`yield` で受け取る段階を分けています。そのため、結果の順番は引数の順番と揃いつつ、実際の実行は並列に進みます。
「開始」と「回収」を分けるのは、非同期の処理で広く使われる書き方です。

## まとめ

- 複数の呼び出しを並列にするには、開始と回収を分けると、待ち時間を短くできます。
- 結果の順番を引数に合わせると、呼び出し側が結果を対応させやすくなります。
- 呼び出しの識別子を先に集めておくと、後からまとめて受け取れます。
