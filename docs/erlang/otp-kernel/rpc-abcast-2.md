## ひとことで

`rpc:abcast/2` は、登録された名前のプロセスに、すべてのノードでメッセージを送ります。
対象は、自分のノードと、いま接続しているすべてのノードです。送った後は、何も待たずに戻ります。

## コード

```erlang:line-numbers=676
abcast(Name, Mess) ->
    abcast([node() | nodes()], Name, Mess).
```

## 前提知識

- **登録名**: `register/2` で、プロセスに付けられた名前です。名前を使えば、プロセスの ID を知らなくても、メッセージを送れます。
- **`node()`**: 自分自身のノードの名前です。
- **`nodes()`**: 接続しているほかのノードの一覧です。
- **`abcast/3`**: 指定したノードの一覧に、メッセージを送る関数です。この関数は、その入り口にあたります。

## 何をしているか

### 1. 自分と、接続中の全ノードの一覧を作る

```erlang:line-numbers=677
    abcast([node() | nodes()], Name, Mess).
```

`[node() | nodes()]` で、自分のノードを先頭に、接続しているほかのノードを続けた一覧を作ります。
その一覧と、登録名 `Name`、メッセージ `Mess` を、`abcast/3` に渡します。

## ここがすごい

### 一覧の作り方を、一行で書く

「自分」と「ほかのノード」を、別々に送る必要はありません。
リストの先頭に `node()` を置き、続きに `nodes()` を並べれば、全体の一覧になります。読み手は、一行で、対象が全部だと分かります。

### 応答を待たない

送るだけで、相手の返事は受け取りません。
「全員に知らせる」ことが目的の場面で、呼び出し側を止めずに済みます。結果を集めたいときは、別の仕組みを使う必要があります。

### 入口と実体を分ける

この関数は、対象の一覧を作るだけです。実際に送る仕事は、`abcast/3` が担当します。
二つの引数で済む入口を用意し、細かい指定は、三引数の関数に任せる、という分担です。

### 届かなかったノードは、気にしない

接続していないノードや、応答しないノードには、メッセージが届きません。送り手は、それを知る方法を持ちません。
この関数は、届いたかどうかを報告しないので、「全員に届いた」ことを保証するものではありません。確実さが必要な場合は、別の確認の仕組みを足します。

### 自分のノードにも届く

一覧の先頭に `node()` があるので、送る側のノードにある同じ名前のプロセスにも、メッセージが届きます。
「全部のノードの同じ仕組み」に知らせる、という書き方になります。自分だけを外したいときは、一覧を別に作る必要があります。

## まとめ

`rpc:abcast(my_server, hello)` は、自分と接続中のノードにある `my_server` へ、`hello` を送ります。
返事は待たず、戻り値も使いません。
