## ひとことで

`string:find/2` は、文字列の中から検索パターンを探し、その位置から後ろの部分を返します。
見つからなければ、空の文字列を返します。

## コード

```erlang:line-numbers=1000
find(String, SearchPattern) ->
    find(String, SearchPattern, leading).
```

## 前提知識

- **検索パターン**: 探したい文字列です。空のパターンのときは、元の文字列を返します。
- **`find/3`**: 三つ目の引数で、探す方向や位置を指定する関数です。`find/2` は、その既定の指定 `leading` を使っています。
- **`leading`**: 最初に現れた位置から、と指定する値です。
- **空の文字列の戻り値**: 見つからなかったときに、呼び出し側が判断しやすいよう、空の文字列を返します。

## 何をしているか

### 1. `find/2` は、`find/3` を既定値で呼ぶ

```erlang:line-numbers=1000
find(String, SearchPattern) ->
    find(String, SearchPattern, leading).
```

`find/2` の本体は、一行です。検索パターンを、三つ目の引数 `leading` で `find/3` に渡します。
同じ探し方を、引数を一つ省いて使えるようにしています。

### 2. 空のパターンは、そのまま返す

```erlang:line-numbers=1028
find(String, "", _) -> String;
```

検索パターンが空の文字列なら、どこで区切るかが決まりません。その場合は、元の文字列をそのまま返します。

### 3. 空のパターンが、バイナリのときも同じ

```erlang:line-numbers=1029
find(String, <<>>, _) -> String;
```

検索パターンがバイナリの空の値であっても、同じ扱いになります。文字列としての形が違っても、判断は変わりません。

## ここがすごい

### 既定の振る舞いを、一行で用意する

`find/2` は、よく使う指定を既定値として持っています。
呼び出し側は、「最初の一致から後ろ」という意味を、引数の数で選べます。ほとんどの場合は、この関数で足ります。

### 見つからないことを、空で表す

文字列を探すときに、見つからない場合を例外にすると、呼び出し側は毎回 `try` で囲む必要があります。
この関数は、空の文字列を返すことで、見つからないことを普通の値として扱えるようにしています。

### 空のパターンの扱いを、先に決めておく

空の検索パターンは、どこにも一致するので、扱いが曖昧になりがちです。
この関数は、その場合を先頭の節で処理し、元の文字列を返すと決めています。

### 既定値を使うと、呼び出しが読みやすくなる

`string:find(String, Pattern)` と書くだけで、「最初に現れた場所から」という意味が伝わります。
方向や位置の指定が要らない場面では、三つ目の引数を省けるので、コードの意図がすぐに読めます。

### 見つからないときの値は、判定に使いやすい

空の文字列が返るので、呼び出し側は、結果が空かどうかで「見つからなかった」を判定できます。
ただし、元の文字列が空だったときも同じ結果になるので、その違いが問題になる場合は、事前に入力の長さを確かめておくと安心です。

## まとめ

`string:find("hello world", "o")` は、`"o world"` を返します。
`string:find("hello", "x")` は、見つからないので、空の文字列を返します。
