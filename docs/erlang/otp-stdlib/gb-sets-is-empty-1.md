## ひとことで

`gb_sets:is_empty/1` は、集合に要素が一つも無いかを調べます。
空なら `true`、要素が一つでもあれば `false` を返します。木の中身を一つずつ見る必要はありません。

## コード

```erlang:line-numbers=178
is_empty({0, nil}) ->
    true;
is_empty(_) ->
    false.
```

## 前提知識

- **gb_sets（一般化平衡集合）**: 集合を、要素数と、根の木の組として持ちます。
- **`{0, nil}`**: 要素数が 0 で、木の根が空であることを表す形です。空の集合は、この形になります。
- **`nil`**: 枝が空であることを表す値です。

## 何をしているか

### 1. 要素数が 0 で、木も空なら、空

```erlang:line-numbers=178
is_empty({0, nil}) ->
    true;
```

集合の形が `{0, nil}` なら、要素が一つも無いので、`true` を返します。

### 2. それ以外は、空でない

```erlang:line-numbers=180
is_empty(_) ->
    false.
```

どの場合にも当たらなければ、要素が一つ以上あるので、`false` を返します。

## ここがすごい

### 要素を数えずに、形で判定する

集合の中身を調べなくても、形を見れば空かどうかは分かります。
要素数の欄が 0 のとき、木も必ず空なので、`{0, nil}` という一つの形だけを調べれば十分です。

### 節を二つだけにする

判定は、「空の形」と「それ以外」の二つに分けられています。
読み手は、`true` を返す節を読めば、空の条件がすぐ分かります。

### 空の判定は、後の処理の目印になる

空かどうかを先に確かめておくと、要素を取り出す関数などで、空の場合を避けられます。
この関数は、そのような確かめの入り口として、よく使われる形です。

### 空の集合の形を、一か所で決める

空の集合は、必ず `{0, nil}` の形です。この形を、関数の中で一度だけ書いています。
集合を作る関数と、この判定が、同じ形を前提にしています。形を変えるときは、この一か所を見れば分かります。

### 空かどうかを先に確かめると、安全に進める

要素を一つ取り出す関数などは、空の集合では失敗します。
先に `is_empty/1` で確かめておけば、呼び出し側は、失敗を避けた分岐を書けます。小さな判定ですが、後の処理を守るための大事な入り口です。

### 要素数の欄と、木の根を同時に比べる

パターン `{0, nil}` は、要素数の欄が `0` で、木の根が `nil` の両方を一度に確かめます。
どちらか一方だけでは、空かどうかは決められません。二つの欄を一つの形で書いているので、判定が一行で済みます。

## まとめ

`gb_sets:is_empty(gb_sets:new())` は、`true` を返します。
要素が一つでもある `gb_sets:is_empty(gb_sets:from_list([1]))` は、`false` を返します。
