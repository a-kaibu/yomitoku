## ひとことで

`queue:len/1` は、キューの中に入っている要素の数を返します。
キューは二つのリストで表されているので、それぞれの長さを足すだけで答えが出ます。キューの中身を取り出したり、並べ替えたりする必要はありません。

## コード

```erlang:line-numbers=197
len({R,F}) when is_list(R), is_list(F) ->
    length(R)+length(F);
len(Q) ->
    erlang:error(badarg, [Q]).
```

## 前提知識

- **キューの表現**: `{R, F}` の二つのリストで、一列の要素を持ちます。どちらか一方が空でも、もう一方に要素があれば、それが全体です。
- **`length/1`**: リストの要素の数を返す関数です。
- **`erlang:error(badarg, ...)`**: キューの形でない値が渡されたときに、エラーを投げます。

## 何をしているか

### 1. キューの形なら、二つの長さを足す

```erlang:line-numbers=197
len({R,F}) when is_list(R), is_list(F) ->
    length(R)+length(F);
```

`R` と `F` が、どちらもリストであれば、それぞれの `length` を求めて足します。
その和が、キューの要素の数です。

### 2. 形が正しくなければ、badarg

```erlang:line-numbers=199
len(Q) ->
    erlang:error(badarg, [Q]).
```

キューの形でない値が渡されたときは、`badarg` のエラーを投げます。投げるときは、引数を一緒に残します。

## ここがすごい

### 中身を見ずに、数だけを答える

キューの要素を一つずつ取り出して、数えることはしていません。
`length/1` は、リストの長さを先頭から数えるだけです。元のキューは、呼び出しの前と後で、同じ内容のままです。

### 二つのリストの和で、全体を表す

キューは、二つのリストに分かれているので、全体の数は、それぞれの数の和です。
どちらのリストが空でも、和の式は正しく働きます。分割の仕方を気にせず、数を求められます。

### 形の確認を、関数の頭で行う

`when is_list(R), is_list(F)` のガードで、キューの形を確かめてから、数えます。
形が違う値は、二つ目の節で弾かれ、`badarg` として呼び出し元に知らされます。

### 数えるための作業量

`length/1` は、リストの長さに比例した時間がかかります。キューの要素が多いほど、数える作業は増えます。
ただし、キューの要素を一つずつ取り出して数えるより、ずっと単純な作業です。数だけが必要な場面では、この関数で十分です。

### 数える前に、形を確かめる理由

キューの形でない値を数えても、意味のある答えは出ません。
そのため、関数は、先に形を確かめてから数えます。形が正しくなければ、誤った数を返すより、エラーにするほうが安全です。

## まとめ

`queue:len(queue:from_list([1, 2, 3]))` は、`3` を返します。
空のキュー `queue:len(queue:new())` は、`0` を返します。
