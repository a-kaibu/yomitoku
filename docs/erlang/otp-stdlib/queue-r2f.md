## ひとことで

`queue:r2f/1` は、入れ側（`In`）のリストを、取り出し側（`Out`）のリストに変えるための補助関数です。戻り値は `{RR, FF}` という組で、そのまま新しいキューの 2 本のリストになります。
`In` は新しい要素ほど先頭に並んでいます。この関数は、それを半分に割って、一方を反転します。

## コード

```erlang:line-numbers=1292
r2f([]) ->
    {[],[]};
r2f([_]=R) ->
    {[],R};
r2f([Y,X]) ->
    {[Y],[X]};
r2f(List) ->
    {RR,FF} = lists:split(length(List) div 2, List),
    {RR,lists:reverse(FF, [])}.
```

## 前提知識

- **`In` と `Out`**: 前の記事で見たとおり、キューは 2 本のリストで表します。`In` は新しい要素、`Out` は取り出す順番の要素を入れます。
- **`lists:split/2`**: リストを、指定した位置で 2 つに分けます。`lists:split(N, L)` は `{先頭 N 個, 残り}` を返します。
- **`div`**: 整数の割り算です。`length(List) div 2` で、長さの半分を求めます。
- **`lists:reverse/2`**: 第 1 引数を反転して、第 2 引数の前につなぎます。
- **パターン `[_]=R`**: 要素が 1 つのリストを、名前 `R` で受け取ります。

## 何をしているか

### 1. 空のリストと、1 要素のリスト

```erlang:line-numbers=1292
r2f([]) ->
    {[],[]};
r2f([_]=R) ->
    {[],R};
```

空なら、2 本とも空です。要素が 1 つなら、その要素を `RR` 側（新しい方）に残します。`FF` は空のままです。取り出しの側（`FF`）を空にしたまま、後の処理で補えるようにしています。

### 2. 要素が 2 つのリスト

```erlang:line-numbers=1296
r2f([Y,X]) ->
    {[Y],[X]};
```

要素が 2 つのときは、先頭の `Y` と後ろの `X` を、それぞれ 1 つずつの 1 要素リストにします。`X` が古い方、`Y` が新しい方になるので、`{[Y], [X]}` の形になります。

### 3. 3 つ以上の要素のとき

```erlang:line-numbers=1298
r2f(List) ->
    {RR,FF} = lists:split(length(List) div 2, List),
    {RR,lists:reverse(FF, [])}.
```

`lists:split/2` で、リストの長さの半分の位置で 2 つに分けます。前半 `RR` は、そのまま新しい入れ側になります。後半 `FF` は反転して、取り出し側の順番にします。

## ここがすごい

### 反転するのは半分だけ

取り出し側を作るために、`In` 全体を反転することもできます。しかしそれだと、要素が多いときに一度に大きな仕事になります。
この関数は、半分だけを反転します。残りの半分は、入れ側として反転せずに使います。作業を半分ずつに分けて、どの取り出しでも大きな仕事が出ないようにしています。

### 分けた後のバランス

入れ側と取り出し側の大きさを、ほぼ同じにそろえます。そのため、取り出し側がすぐ空になって、次の大きな反転が起きる、という状況を避けられます。
ならし計算量で速さを保つための、小さいけれど重要な工夫です。

## まとめ

- 2 本のリストで作るキューは、大きな反転を一度に行わないよう、半分ずつ分けると安定します。
- 入れ側を半分に割って片方だけ反転すると、作業量を平均化できます。
- 空、1 要素、2 要素、それ以上で場合分けすると、特別な大きさを安全に扱えます。
