## ひとことで

`lists:zip/2` は、二つのリストの要素を先頭から一つずつ組にして、`{X, Y}` のリストを返します。
長さが違うときは、既定の扱いである `fail` になり、失敗します。

## コード

```erlang:line-numbers=739
zip(Xs, Ys) -> zip(Xs, Ys, fail).
```

## 前提知識

- **zip（ジップ）**: 二つのリストを、ファスナーのように、前から一つずつ組み合わせる操作です。
- **`How`**: 長さが違うときの扱いを決める値です。`fail`、`trim`、`{pad, {X, Y}}` のいずれかです。
- **`fail`**: 長さが違えば、どの節にも当たらず、呼び出しが失敗する扱いです。
- **`zip/3`**: `How` を指定して組にする関数です。`zip/2` は、これを `fail` で呼んでいます。

## 何をしているか

### 1. 既定の扱いを、`zip/3` に渡す

```erlang:line-numbers=739
zip(Xs, Ys) -> zip(Xs, Ys, fail).
```

`zip/2` の本体は一行です。`fail` を指定して、`zip/3` を呼びます。
呼び出し側は、長さが違うときの扱いを書かずに済みます。

### 2. 両方に要素があれば、組にして進む

```erlang:line-numbers=786
zip([X | Xs], [Y | Ys], How) ->
    [{X, Y} | zip(Xs, Ys, How)];
```

両方の先頭を組にして、残りについて再帰します。`How` は、そのまま次の呼び出しに渡します。

### 3. 両方が空になれば、終わる

```erlang:line-numbers=788
zip([], [], fail) ->
    [];
```

両方が空で、`How` が `fail` のときは、空のリストを返します。ここで、組の作成が完了します。

## ここがすごい

### 短い形を、既定値で用意する

`zip` は、長さの違いにどう対応するかを、引数で選べる関数です。
しかし、多くの場合は、長さが同じリストを扱います。その場合、`zip/2` を使えば、`fail` の指定を毎回書く必要がありません。

### 失敗を、明示的な例外にしない

長さが違うときは、`zip/2` は、わざわざ `error` を投げません。
どの節にも当たらないことで、失敗させます。Erlang では、この形が、関数の入力の前提を表すよくある方法です。

### 組を作る処理は、一つの再帰

先頭の組を作り、残りに同じ関数を当てるだけです。
入力が長くなっても、読む量が増えるだけで、処理の形は変わりません。

### 長さの違いは、呼び出し側の誤りとして扱う

`fail` は、長さが違うことを、普通のデータとして扱わない選択です。
入力の前提が崩れたときに、黙って片方を切り捨てたり、既定値で埋めたりしません。どちらのリストが長いかは、呼び出し側が知っているはずだという考え方です。

## まとめ

`lists:zip([a, b], [1, 2])` は、`[{a, 1}, {b, 2}]` を返します。
`lists:zip([a], [1, 2])` は、長さが違うので、`fail` の扱いで失敗します。
