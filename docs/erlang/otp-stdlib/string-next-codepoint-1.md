## ひとことで

`string:next_codepoint/1` は、文字列の先頭から、Unicode のコードポイントを一つ取り出します。
戻り値は、そのコードポイントと、残りの文字列の組の形です。

## コード

```erlang:line-numbers=1141
next_codepoint(CD) -> unicode_util:cp(CD).
```

## 前提知識

- **コードポイント**: Unicode の一つ一つの文字番号です。一つの番号が、一つの文字に対応します。
- **書記素クラスタとの違い**: 見た目の一文字は、複数のコードポイントでできていることがあります。この関数は、その区切りを見ません。
- **`unicode_util:cp/1`**: 文字列の先頭から、一つのコードポイントを取り出す関数です。
- **`next_grapheme/1`**: 見た目の一文字を、一つの単位として取り出す関数です。対になる関数です。

## 何をしているか

### 1. 本体は、`unicode_util:cp/1` に任せる

```erlang:line-numbers=1141
next_codepoint(CD) -> unicode_util:cp(CD).
```

この関数の本体は、一行だけです。引数 `CD` を、そのまま `unicode_util:cp/1` に渡します。
戻り値の形は、`unicode_util` の規則に従います。

## ここがすごい

### 書記素とコードポイントを、別の関数で分ける

見た目の一文字で読みたいなら `next_grapheme/1` を、番号の単位で読みたいなら `next_codepoint/1` を使います。
同じ文字列でも、結果の数が違うことがあります。用途に応じて、どちらを使うかを選びます。

### 結合文字の扱いが、目に見える

結合文字を含む文字は、コードポイントの単位では、複数の要素に分かれて現れます。
それを確かめるための道具としても、この関数は使えます。見た目と、内部の表し方の違いを、比べられます。

### 一つずつ読む処理の土台になる

コードポイントの単位で読む処理は、解析器や、文字コードの変換でよく使われます。
この関数は、その土台として、残りの文字列を返します。繰り返すと、文字列を順に読み進められます。

### 取り出しの単位を、呼び出し側が選ぶ

文字列を読むとき、番号の単位で読むか、見た目の単位で読むかは、用途によって違います。
文字の数を数える場合や、文字の並びを検索する場合は、どちらを使うかで結果が変わります。目的を決めてから、対応する関数を選ぶのが安全です。

## まとめ

`string:next_codepoint("ab")` は、先頭の `a` のコードポイントと、残りの `b` を組にした形の値を返します。
見た目の一文字でも、複数のコードポイントなら、この関数は複数回に分けて返します。
