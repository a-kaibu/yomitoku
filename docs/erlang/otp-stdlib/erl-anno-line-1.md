## ひとことで

`erl_anno:line/1` は、Erlang のソースコードの位置を表す注釈から、行番号だけを取り出します。
注釈は、行と列の組で書かれている場合もあれば、行番号だけの場合もあります。どちらでも、結果は行番号の整数になります。

## コード

```erlang:line-numbers=329
line(Anno) ->
    case location(Anno) of
        {Line, _Column} ->
            Line;
        Line ->
            Line
    end.
```

## 前提知識

- **注釈（annotation）**: コンパイラや、ツールが、ソースの位置や情報を付け加えたものです。
- **`location/1`**: 注釈から、位置の情報を取り出す関数です。行と列の組、または行番号だけを返します。
- **`{Line, _Column}`**: 行と列の組です。列は捨てて、行だけを残します。
- **`Line`**: 行番号だけの形です。そのまま返します。

## 何をしているか

### 1. 行と列の組なら、行だけを返す

```erlang:line-numbers=330
    case location(Anno) of
        {Line, _Column} ->
            Line;
```

`location/1` の結果が `{Line, _Column}` の組なら、行番号 `Line` を取り出して返します。列は使いません。

### 2. 行番号だけなら、そのまま返す

```erlang:line-numbers=333
        Line ->
            Line
```

結果が、ただの整数 `Line` なら、そのまま返します。

## ここがすごい

### 二つの形を、一つの関数で受け止める

注釈の形が違っても、呼び出し側は、`line/1` を呼ぶだけで済みます。
形の違いは、この関数の中の二つの枝で吸収されています。

### 同じ名前の変数で、結果をそろえる

どちらの枝でも、最後に返すのは `Line` という同じ名前の値です。
枝を抜けた後の結果が、同じ型の整数になることを、変数の名前そのものが示しています。

### 列の情報を、読まずに捨てる

`_Column` は、アンダースコアで始まる名前です。使わないことを、名前で明示しています。
列の情報は、この関数の目的では要らないので、読み手は、一行目だけを見れば必要な仕事が分かります。

### 注釈が、どちらの形で来ても使える

コンパイラの出力は、場面によって、行と列の両方を持つことも、行だけのこともあります。
呼び出し側が形を気にせず、行番号が欲しいときに、この関数を使えます。形の違いを、ここで一度だけ扱うのが、この関数の役割です。

### 列を捨てることは、情報を失うこと

列の番号は、この関数の結果には残りません。行番号だけで十分な場面では、問題になりません。
しかし、列まで必要なときは、`location/1` を直接使うと、両方の情報を取り出せます。関数を選ぶときに、必要な情報の量で判断してください。

## まとめ

`erl_anno:line(erl_anno:new({3, 5}))` は、`3` を返します。
行番号だけの注釈 `erl_anno:line(erl_anno:new(3))` も、同じく `3` を返します。
