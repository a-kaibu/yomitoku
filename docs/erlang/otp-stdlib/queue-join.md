## ひとことで

`queue:join/2` は、2 つのキューを前後につないで 1 つのキューにします。前のキュー `Q1` の要素が先に取り出され、その後に `Q2` の要素が取り出されるようになります。
空のキューとつなぐ場合は、もう一方をそのまま返します。どちらも空でなければ、2 本のリストを組み直して作ります。

## コード

```erlang:line-numbers=618
join({R,F}=Q, {[],[]}) when is_list(R), is_list(F) ->
    Q;
join({[],[]}, {R,F}=Q) when is_list(R), is_list(F) ->
    Q;
join({R1,F1}, {R2,F2}) when is_list(R1), is_list(F1), is_list(R2), is_list(F2) ->
    {R2,F1++lists:reverse(R1,F2)};
join(Q1, Q2) ->
    erlang:error(badarg, [Q1,Q2]).
```

## 前提知識

- **2 本のリストのキュー**: 入れ側（`R`、新しい要素が先頭）と取り出し側（`F`、取り出す要素が先頭）の組です。
- **`++`**: リストどうしを連結する演算子です。左のリストを全部コピーするので、左が長いと時間がかかります。
- **`lists:reverse/2`**: 第 1 引数を反転して、第 2 引数の前につなぎます。`lists:reverse(R1, F2)` は、`R1` の反転に `F2` をつないだ形です。
- **`{[], []}`**: 空のキューです。

## 何をしているか

### 1. 片方が空のとき

```erlang:line-numbers=618
join({R,F}=Q, {[],[]}) when is_list(R), is_list(F) ->
    Q;
join({[],[]}, {R,F}=Q) when is_list(R), is_list(F) ->
    Q;
```

どちらかが空のキューなら、もう一方をそのまま返します。何もつなぐ必要がないので、速く終わります。

### 2. 両方に要素があるとき

```erlang:line-numbers=622
join({R1,F1}, {R2,F2}) when is_list(R1), is_list(F1), is_list(R2), is_list(F2) ->
    {R2,F1++lists:reverse(R1,F2)};
```

結果の入れ側は、後ろのキュー `Q2` の入れ側 `R2` をそのまま使います。取り出し側は、`F1 ++ lists:reverse(R1, F2)` です。

この式を、取り出される順番で読みます。まず `F1` の要素が、次に `R1` の要素が古い順（反転したもの）で続きます。その後ろに `F2` の要素が来ます。`R2` は、`Q2` の入れ側なので、最後に取り出されます。
つまり、`Q1` の要素が全部 `Q2` の要素より先に出てくる、正しい順番の連結になっています。

### 3. キューでないとき

```erlang:line-numbers=624
join(Q1, Q2) ->
    erlang:error(badarg, [Q1,Q2]).
```

引数がキューでないときは、`badarg` の例外を起こします。

## ここがすごい

### 入れ側は 1 本ぶん、取り出し側は 2 本をつなぐだけ

キューを連結するのに、両方の入れ側と取り出し側をすべて組み直すこともできます。しかし、この関数は、後ろのキューの入れ側をそのまま使い、前のキューの入れ側だけを反転して取り出し側につなぎます。
作業の量を、前のキューの大きさに限っています。

### 反転と連結を 1 つの式で書く

`F1 ++ lists:reverse(R1, F2)` という 1 行に、「前のキューの残りを順番どおり並べて、後ろのキューの取り出し側へつなぐ」という意味が詰まっています。
読むときは、取り出される順番を考えると、式の意図がつかみやすくなります。

## まとめ

- キューの連結は、後ろの入れ側をそのまま使うと、作業を減らせます。
- 前のキューの入れ側は反転して、取り出し側につなげば、順番が保たれます。
- 空のキューとの連結は、もう一方をそのまま返すだけで済みます。
