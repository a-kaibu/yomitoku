## ひとことで

`array:size/1` は、配列が持つ大きさ（要素を入れられる数）を返します。
配列の中身は見ず、大きさの欄だけを読み出します。配列でない値を渡したときは、`badarg` のエラーになります。

## コード

```erlang:line-numbers=391
size(#array{size = N}) -> N;
size(_) -> erlang:error(badarg).
```

## 前提知識

- **配列（array）**: 添字で要素を持つデータ構造です。大きさは、作ったときに決まっています。
- **レコード `#array{size = N}`**: 配列の内部を表す形です。`size` という欄に、大きさが入っています。
- **`badarg`**: 引数の形が正しくないときに投げられる、標準的なエラーです。

## 何をしているか

### 1. 配列なら、大きさの欄を返す

```erlang:line-numbers=391
size(#array{size = N}) -> N;
```

引数が配列の形をしていれば、その `size` 欄の値 `N` を返します。配列の要素には触れません。

### 2. 配列でなければ、badarg

```erlang:line-numbers=392
size(_) -> erlang:error(badarg).
```

配列の形でない値には、どの節も当たらないので、`badarg` のエラーを投げます。

## ここがすごい

### 欄を読むだけの、速い関数

大きさは、配列の中に、すでに記録されています。
この関数は、その値を取り出すだけです。配列が大きくても、要素を数えたりはしないので、時間は一定です。

### 形の確かめと、取り出しを、一つの節で

`#array{size = N}` のパターンが、配列の形の確かめと、大きさの取り出しを同時に行っています。
読み手は、節の頭を読むだけで、受け付ける入力と、返す値が分かります。

### 型を偽らない、失敗の形

配列でない値に対して、適当な数を返すことはしません。
`badarg` で知らせるので、呼び出し側は、誤った大きさを使い続けることがありません。

### 大きさは、作った時から変わらない

配列の大きさは、作るときに決まり、以後の操作で変わりません。
そのため、この関数が返す値は、配列を作った時の大きさと同じです。添字の上限を知りたいときは、`size - 1` を使えば十分です。

### 配列の大きさと、要素の数は違う

大きさは、添字の範囲の広さです。要素が入っていない場所も、大きさに数えられます。
「入っている要素の数」を知りたいなら、別の方法で数える必要があります。この関数の答えは、あくまで配列の枠の広さです。

## まとめ

`array:size(array:new(5))` は、`5` を返します。
配列ではない値 `array:size(5)` は、`badarg` のエラーになります。
