## ひとことで

`gb_trees:delete_any/2` は、木からキーを削除します。ただし、キーがなくてもエラーにはならず、木をそのまま返します。
`delete/2` は、キーがないとエラーになるので、その違いを吸収する関数です。

## コード

```erlang:line-numbers=540
delete_any(Key, T) ->
    case is_defined(Key, T) of
	true ->
	    delete(Key, T);
	false ->
	    T
    end.
```

## 前提知識

- **`gb_trees`**: 釣り合いを保つ二分探索木で、キーと値の辞書を表します。
- **`delete/2`**: キーを削除します。キーがない場合は、例外を起こします。
- **`is_defined/2`**: キーが木にあるかを、真偽値で返します。
- **`case ... of`**: 結果の真偽で、2 通りの処理を分けます。
- **「存在しないなら何もしない」**: 冪等（べきとう）と呼ばれる考え方で、同じ操作を何度繰り返しても結果が変わらないことです。

## 何をしているか

### 1. キーがあるとき

```erlang:line-numbers=541
    case is_defined(Key, T) of
	true ->
	    delete(Key, T);
```

`is_defined/2` が `true` なら、キーは木にあります。`delete/2` でキーを削除して、新しい木を返します。

### 2. キーがないとき

```erlang:line-numbers=544
	false ->
	    T
```

`false` なら、削除するものはありません。`delete/2` を呼ぶと例外になるので、呼ばずに、元の木 `T` をそのまま返します。

## ここがすごい

### 例外を避けるための、事前の確認

`delete/2` は、キーがないことを例外で知らせます。その例外を、呼び出し側で捕まえるのは、手間がかかります。
この関数は、先に存在を確かめるだけで、例外を起こさずに済ませています。小さな関数ですが、「無くても困らない削除」を 1 つの名前で表しています。

### 同じ操作を繰り返しても結果が変わらない

`delete_any/2` を 2 回呼んでも、1 回目と同じ木になります。このような性質を冪等と呼びます。
後片付けの処理は、何度呼ばれても安全であることが望ましく、この関数はその要求を満たしています。

例えば、期限切れの項目を一覧から消す処理を考えます。同じ項目が 2 回候補に入っても、2 回目の削除は何もしないので、処理全体が安全に続きます。`delete/2` を使うと、そのたびに存在を確かめる必要がありますが、`delete_any/2` なら呼び出し側の分岐が要りません。

## まとめ

- 削除のような操作は、対象があるかを先に確かめると、例外を避けられます。
- 「無ければ何もしない」版を用意すると、呼び出し側が例外処理を書かずに済みます。
- 冪等な操作は、後片付けや再試行で安全に使えます。
